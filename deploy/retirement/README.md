# 官网与旧后台迁出准备

本轮只准备新服务器。经理最后修改域名解析；旧机及旧微信收发保持运行。禁止把准备成功当作可以关闭旧机。

## 新机组成

- `weiban-entry`：官网、正式安装包、旧安卓检查更新、旧网页跳转、原后台历史查看。只开放管理登录/退出及查询，其他旧业务仍停用。独立SQLite副本不覆盖新版PostgreSQL。
- `weiban-entry-relay`：复用现有微信兼容收发程序，独立数据库。准备时 `ENTRY_RELAY_ACTIVE=0`，没有微信轮询、发消息或模型调用。只有新机准备完成、经理改好解析且完成旧收发交接，才能启用。
- 系统盘 `/var/lib/weiban-entry` 放代码、历史库及加密运行材料；空余更大的项目盘 `/srv/weiban-history-media` 放历史媒体。既有安装包继续从 `/var/lib/weiban-downloads` 读取。
- 旧源码只复制运行需要的代码、官网/后台素材及角色包，不复制旧 `.env`、日志、杂项脚本或旧安卓测试包。管理员运行配置与旧数据密钥经过临时RSA接收者加密传输，再由香港主密钥密封；没有明文凭据文件、仓库凭据或工具输出。香港主密钥未来轮换时，需一并重封这些材料。
- 原后台旧数据作为历史副本；原管理员密码保留。登录会话及运行计数可以写入副本，不能把“历史查看”误称为数据库绝对零写入。实时生产业务仍在新版管理后台。

## 官网兼容范围

- 主域名与 `www` 继续官网，`dl` 承接历史下载链接。
- `/download`、`/download/` 和根页面同样可用。
- `/download-assets/` 先读取新机正式包；旧包文件名转到当前正式包。安装包响应明确为附件下载，避开聊天站点的Service Worker。
- `/api/app/config` 保留旧安卓响应格式，版本来源读取新版公开版本策略；当前正式3.0.0构建127，旧构建强制升级，当前/更高构建不会循环升级。补齐文件大小与SHA256/SHA1校验值。
- `/api/download-config` 保留旧官网配置结构。
- `/app` 及其旧网页地址转到 `https://app.weiban.online/`，不携带旧查询参数。
- 旧Flutter Worker更新地址返回仅用于迁出的Worker，接续后只导航旧 `/app/` 窗口，不清空浏览器存储，不操作旧后台窗口。
- 官网去除旧“内测阶段”文字；布局沿用原页面。

## 微信交接：不得提前执行

先确认官网解析、正式下载、旧升级响应和历史后台在新机正常，再执行下列操作。旧服务器本身继续开着。

1. 只暂停旧 `weiban-server` 的微信与兼容转发：将实际运行环境的 `WECHAT_CHANNEL_ENABLED=0`、`LEGACY_CHANNEL_RELAY_ENABLED=0` 持久保留并重新加载该进程；原生成、付款和后台任务禁用标记继续保留。不要停整台机器，也不要清空绑定。
2. 旧轮询停妥后，重新运行 `stage-secrets.mjs wechat` 获取最新加密快照，不能用准备时的旧游标。导出同时记录旧轮询是否已停、待转发入站和待处理送达数量。微信旧成功送达状态是 `submitted`，不是只有 `sent`。
3. 待处理入站/送达必须为0。若有 `ambiguous` 等未决记录，保留并查清，不能丢弃或盲目重发。还要在新机只读核对这批绑定的 `offered_seq=after_seq`，保证旧接收端已确认全部取走的回复页；不满足时不得继续。
4. 新机待命转接容器保持关闭收发，运行 `handoff-relay.cjs plan <最新快照文件名>`，复核归属、角色、代次和数量；然后在完成上一步核对后才运行 `apply <最新快照文件名> --target-acknowledged`。工具拒绝旧轮询未停、队列未排空、超过五分钟的快照、归属改变和重复接管。
5. apply仅更新新机兼容库的现有绑定与最新游标、留下接管回执，不自动启动收发。将 `ENTRY_RELAY_ACTIVE=1` 后再启动新机转接容器；没有有效接管回执时入口会拒绝启动。原新站 `legacy_bindings` 及消息去重身份保留，不重建用户、钱包或聊天。
6. 核实旧轮询已停、新轮询工作、入出站队列与正常业务消息后，再另行安排旧机停机验证。用户未授权前不要主动给真实用户发测试消息，不重新收费重放历史。

一条已失效授权保持失效，需要本人重新扫码；不伪造有效凭据。另五份材料只是具备接管条件，签名status成功不等于已经验证微信供应商真实收发。用户模型选择保持本人原设置，不擅自替其选择付费模型。

## 本轮检查与留存

- 旧客户端升级格式、后续新版策略、加密材料防篡改、旧Worker迁出共4项直接用例通过。
- 交接保护在一次性容器内以虚构资料验证：旧端未停、未排空、旧快照、归属不符、未确认目标游标、正确接管和防重复；不用线上用户测试。
- 真实历史副本通过SQLite检查；用户、角色、单聊、群聊关键表计数与源快照相同。没有输出聊天正文。
- 官网、安装包响应、旧升级格式、原密码后台登录/查看/退出、写入阻断已在新机独立服务核对。随后只检查新增旧Worker路线与正式版文案，不重复全库扫描。
- 五条签名status被新站接受，一条本地已失效跳过；没有向微信发消息或调用模型。
- 媒体复制、最终镜像/提交、主域名配置加载及公网切换结果以本次PR最终回执为准。准备时未改解析、未关闭旧机。

旧机快照、工作副本、加密材料及历史媒体均先保留。传输程序只使用固定目录；大文件服务器间直传，SSH私钥仅由短期内存agent提供，不复制到服务器。临时agent在传输结束后退出。
