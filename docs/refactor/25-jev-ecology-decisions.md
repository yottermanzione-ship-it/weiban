## 推荐结构

沿用「角色定时醒来，看上下文，自主挑动作」的产品方向。唤醒频次由已有四档活跃程度控制（17 号），Jev 不做时钟计算或无限轮询。每次读取同一版本的上下文快照，由角色所选的生态生成模型提出动作意向，再由代码生成当次可执行工具清单。动作清单由执行器注册，不固定成七种永远不变的动作。

代码先裁掉生态未开、会员 / 余额不满足、动作关闭、资格不符、重复、冷却或人数条件不满足的候选。私密 / 健康信息仍只走其已授权范围；Jev 只收到允许出境的结构化特征与干净摘要。模型意向不是工具执行凭证；执行前再次检查权限和余额，成功拿到结果后才能说「做了」。

Jev 只回答窄问题，例如「这个已经通过开关检查的候选，是否与当前话题相关」「这条线索属于新公开作品，还是私人自拍」。每个问题有完整语义的候选描述，包含 skip。不问「你现在想做些什么」并期待它生成参数、解释和内容。多题共享 state，但相互独立；后一个动作依赖前一个结果时由代码分两步，不在同批题中互相引用。

所有精确日期、余额、配额、去重和时段由代码算好。每次唤醒最多一次批量语义判断，最多执行一个主动动作；后续动作在新的快照下重评。无候选直接休眠，不调用模型。执行带稳定 action ID，重试同一动作不重复发送或扣费。用户「发个朋友圈」这类明确指令沿用受控工具执行链，不必再付费询问 Jev 是否同意。

## H4 微博同步

资格仍是：有微博昵称与头像标记，至少有人添加且开启生态。先按角色而不是用户领取公开资料检查租约。所有用户的生态唤醒可提出「这个角色是否有值得更新的公开线索」的候选，但同一角色只有一个拥有租约的执行者。

建议流程：代码确认缓存新鲜度和已知线索 → 缓存新鲜且无新线索时直接复用 → 缓存过期且有新公开线索时进入语义候选 → Jev / 生态模型在已有描述中判断相关性 → 搜索 / 抓取 → 按来源 URL、内容指纹去重 → 更新近期公开动态与私人朋友圈，并只推给合资格用户。

频率由「生态唤醒 + 新线索 + 决策」决定，缓存 TTL 是去重和费用保护，不是每天固定同步一次。建议另有角色级最短间隔、每日供应商调用硬上限和失败退避；这些是后台保护，不作为用户新的频率开关。初值和正式阈值需在任务实施时登记并覆盖边界用例，不把本次六个模板当校准集。

**本轮不批准降低 0.55 的全局门槛。** 先把「有没有新作品线索」与「此刻要不要发布给用户」分成不同窄问题，建立中文和口语反例集后逐题校准。低置信度：先延后；缓存存在时自然复用缓存。不得用「让它一定能触发」作验收标准。

搜索费用按已确认 H4 原则，由调用开始时「添加且开启该角色生态」的用户快照平摊，保留不足 0.01 积分的累计尾差。缓存命中不重复分摊；同一调用只有一个结算 ID。注销、关生态、余额 ≤ 0、欠费并发锁、实际搜索零结果、供应商失败和未知成本都需有明确结算路径。

**实现前置缺口**：当前 S 搜索只支持平台付费，尚无多人分摊端口；必须先扩展 billing / model-access 契约和幂等分摊结算，不能由生态模块循环手工扣余额。语义判断计入提出候选的那次用户生态唤醒（已有行为规划用途）；共享调度负责租约、缓存与执行，不再另发一次付费决策。搜索费用另走已确认的多人分摊，不计入 S 的平台补贴候选次数。

公开动态生成只用公开事实并保留出处，不把个人记忆写进公共朋友圈。H4 的私人朋友圈路径与现有公开动态待审核路径分别实现；不能通过改现有待审核定时器实现自动发布。

## P3 图片智能搜索触发

当轮照常使用 H3 同次回复产生的图片描述。新增触发应先用本地描述提取「公开作品、海报文字、未知作品名、是否需要新公开事实」等特征；原图、私人身份线索、健康图和私密内容不发给境外决策模型。私人朋友自拍、表情包、家庭照片默认没有站外身份搜索候选。

已有出处 / 本地知识可回答 → 直接回答。用户明确询问作品且有可用公开作品名 → 列出作品查询候选。只有语义不确定时才请 Jev 判断「描述是否涉及可公开查询的作品线索」；确定后由代码构造最小查询，不带用户名、私聊原话或整段图片描述。搜索到的网页当不可信参考，不能当提示词指令。

本次中英文海报题标签不同且置信度低，说明还不能直接启用。下一步需补旧版未触发样本、同人图 / 截图 / 角色本人海报 / 普通自拍的成对数据，比较窄题与生态模型方案，再校准触发条件。本方案遵守「先确认再实施 P3」；本批没有开启聊天当场联网，也没有假称角色已认出自己。

## 切换与验证

先保持已有运行配置。优先固定 `jev-1.13.0` 作为评测版本；latest 仅作兼容检查。除协议自测外，执行 `eval-plan.md` 3.15 / 3.16 和真实资金 / 并发验证后，才按决策类型小范围切换，保留规则退路与报告编号。阈值按问题、语言、版本校准，不沿用另一个版本或通用模型的概率门槛。

回退：关闭对应模型实现，恢复规则 / 原生态模型；已执行的动作不重放。保留用量和动作 ID，故障只影响额外动作，不阻断聊天回复。
