## 0. 结论先说

1. **现在是「六个场景、六个脑子」**：私聊用的是精心整理过的新结构（人设 + 长期记忆 + 今天的日常 + 圈子资料）；群聊、主动消息、通话、朋友圈、角色生态各自拼一份，大多只塞一段人设原始资料（JSON），**看不到长期记忆或只看到一点点**，也**互相不知道对方场景里发生了什么**。所以会出现「群里刚聊过的事，私聊里不知道」「自己发过的朋友圈，被问起来不记得」「打过电话，私聊只记得一句 60 字的摘要」。
2. **目标：一个角色一份「大脑」，所有场景共用**。大脑 = **公共底子**（同一段文字：守则核心、人设、说话方式、示例、关系阶段、长期记忆、近期「共同经历」、今天的日常）+ **场景补充**（群聊 / 通话 / 主动消息各自的几句规则和现场内容）。
3. **新增「共同经历」时间线**：App 里发生的一切动作（发朋友圈、评论、发语音 / 照片、打电话、群聊、主动找你、生态里改签名……）**由系统按模板直接记一条**，基本**不花模型钱**；所有场景都读同一份。
4. **长期记忆的来源从「只有私聊」扩到「私聊 + 群聊 + 通话」**。
5. **私密模式严格隔离**：私密内容（原文、记忆、经历、摘要）只进私密模式这一个场景、只交给该用户的私密模式模型。**排查中发现两处现有代码不符合这条**（见 §2.3），建议第一阶段先修。
6. **花费**：群聊、主动消息、通话从「JSON 人设」换成「短行人设 + 记忆」后，每次请求的总字数大致持平或略增；新增「群聊记忆整理」约每 20 条群消息 1 次调用。按 DeepSeek 官方价举例，一个重度用户每天多花约 **1～3 积分**（§5）。
7. **分 5 个阶段做**，第 0 阶段（修隐私问题、补测量工具）不需要数据库迁移；共需约 **2 个新迁移、1 次契约小版本**，工作量约 **9～10 个工作日**（§6）。

### 1.1 用户能感受到的问题

1. 群里聊了周末去爬山，私聊问「周末干嘛」角色不知道；反过来私聊说过的事，群里角色像陌生人。
2. 角色自己发的朋友圈、评论过你的朋友圈，私聊问起来接不上。
3. 电话里聊了半小时，私聊只剩一句「我们打了电话，……」60 字。
4. 主动消息看不到长期记忆，开场容易泛泛（「在干嘛」）而不是接上你们的事。
5. 每个场景人设写法不同（JSON vs 短行），同一角色在不同场景语气略有出入。

### 1.2 现有可复用的东西

- 私聊的新请求结构（`09` 号文档：稳定开头 → 聊天记录 → 动态结尾）已经验证过，命中缓存率约 83%。
- 记忆库（`ai_runtime.memories`，加密，带 `scope` 普通 / 私密，带向量检索）。
- 时间线读取服务 `TimelineListService`（已经把日常、朋友圈、互动、公开动态按时间合并）。
- 系统直接写记忆的入口 `MemoryService.addEpisode`（通话、宠物在用）。

## 2. 目标设计

### 2.1 一个大脑 = 公共底子 + 场景补充

```
┌──────────────── 公共底子（所有场景一字不差，放请求最前面）────────────────┐
│ 平台守则核心（不写「私聊」等场景字眼；场景规则放后面）                    │
│ 【你是谁】【说话方式】【说话示例 6 条】【公开资料（世界书常驻）】         │
│ 【关系与设置】好感度阶段、称呼、关系、情景模式                            │
│ 用户补充设定、角色自述                                                    │
│ 【记忆】常驻长期记忆 + 更早往事摘要（冻结，只在窗口前移 / 记忆被改时变） │
│ 【最近一起经历的】共同经历近况（冻结，一天最多重算一次）★新              │
│ 今天是 X 月 X 日周X                                                       │
└──────────────────────────────────────────────────────────────────────────┘
┌──────────────── 场景补充（每个场景自己的几句）────────────────────────────┐
│ 私聊：只输出聊天纯文本、短句换行……（现有私聊专用句）                      │
│ 群聊：你在群「XX」里；群成员与你的关系；最多 60 字一条；                   │
│       用户私下告诉你的事不当众说出来，除非用户自己在群里先提起 ★新         │
│ 通话：你说的话会直接合成语音，一次 1～3 句……                              │
│ 主动消息：这次由你主动开口，理由：……；不做情感操纵……                     │
│ 私人朋友圈：只有这位用户看得到；≤100 字；不复述隐私……                     │
└──────────────────────────────────────────────────────────────────────────┘
┌──────────────── 场景内容 ─────────────────────────────────────────────────┐
│ 私聊原文 / 群聊最近 30 条 / 通话各轮 / 私聊最近几条（主动消息）            │
└──────────────────────────────────────────────────────────────────────────┘
┌──────────────── 动态结尾（每次变）────────────────────────────────────────┐
│ 这轮可能用得上的记忆（检索）、刚刚发生的共同经历（冻结之后新增的）★新    │
│ 今天的日常、圈子资料、宠物、公开资料触发条目、现在几点……                 │
└──────────────────────────────────────────────────────────────────────────┘
```

做法：把私聊 `reply-context.ts` 里「① 稳定开头」的拼装抽成一个公共函数（暂名 `brainPrefix()`），群聊、主动消息、通话、私人朋友圈、生态决策都调用它，再拼各自的场景补充。

- **私聊**：基本不变，只是守则里「以角色口吻和用户私聊」一句挪到场景补充。
- **群聊**：每个发言角色用**自己的**公共底子（自己的人设、自己对这位用户的记忆、自己的经历），群里其他成员的资料只给关系一行。
- **公共朋友圈**例外：所有用户看同一条，**不接个人大脑**，保持现状（只用人设 + 公开素材）。
- **生态决策**：用公共底子的精简版（人设核心 + 记忆 + 经历近况），不带示例对话，控制决策模型的花费。

### 2.2 「共同经历」时间线

**和长期记忆的区别**：长期记忆记的是「关于用户的事实」（喜欢什么、几号考试）；共同经历记的是「我们之间 / 我身上发生过的事」（我发了朋友圈、我们打了 20 分钟电话、我在群里和林夕一起逗你）。前者靠模型从聊天里抽，后者大部分由系统按模板直接写。

**数据结构**（新表 `ai_runtime.shared_episodes`，一个迁移）：

| 字段 | 说明 |
|---|---|
| `id` | 主键（时间序 UUID） |
| `user_id` / `character_id` | 这条属于哪个用户和哪个角色的大脑 |
| `occurred_at` | 发生时间 |
| `kind` | 类型：`moment_posted` 我发朋友圈、`moment_commented` 我评论 / 点赞你的朋友圈、`moment_replied` 我回复了你的评论、`voice_sent` 我发了语音、`photo_sent` 我发了照片、`call` 通话、`group_chat` 群聊一段、`proactive` 我主动找你、`profile_changed` 我改了签名 / 状态、`pet` 宠物、`play` 每日一问 / 慢信 / 心愿 / 纪念日、`daily_highlight` 我日常里的大事（可选） |
| `scope` | `normal` / `adult`（私密模式里发生的记 adult） |
| `source_type` + `source_id` | 来源（朋友圈 ID、通话 ID、群会话 + 批次……），**唯一约束**，同一件事只记一次 |
| `ciphertext` | 加密的正文：一句话 ≤120 字 + 可选「谁一起」（角色 ID 列表）；和记忆一样用信封加密 |
| `importance` | 1～10，模板给默认值（通话 6、朋友圈 4、点赞 2……） |
| `embedding` | 向量（和记忆同一套 256 维），用于按话题检索 |
| `created_at` | 写入时间 |

**谁写入、写什么**（基本不调用模型）：

| 发生的事 | 写入方（在原功能成功之后、同一事务或事件订阅里） | 写的内容（模板） |
|---|---|---|
| 角色发私人 / 公共朋友圈 | moments 模块发帖成功 → 事件 → ai-runtime | 「我发了一条朋友圈：『正文前 40 字』」（公共朋友圈对每个加了该角色的用户各记一条，读时现取，不复制正文） |
| 角色点赞 / 评论用户朋友圈，回复用户评论 | 同上 | 「我评论了你的朋友圈『…』：『我的评论』」 |
| 角色发语音 / 照片 | 回复发送时 | 「我给你发了一条语音：『原文』」「我给你发了张照片：生图提示的简述」 |
| 通话结束 | `call-agent.ts summarize()` | 现在的通话摘要升级为「抽记忆 + 写一条经历」：「我们打了 18 分钟电话，聊了……」（这一步本来就要调模型，不新增调用） |
| 群聊 | 新的「群聊整理」任务（§2.3） | 「在群『周末约饭』里，我和林夕一起……」每 20 条左右一条 |
| 角色主动找你 | proactive 发送成功 | 「我主动找你，因为……（理由）」 |
| 生态里改签名 / 状态 | ecology 执行成功 | 「我把签名改成了『…』」 |
| 宠物、每日一问、慢信、心愿、纪念日 | 现在写记忆的地方改写经历（宠物现在用 `addEpisode`） | 原有文字 |

**怎么读（检索与预算）**：

- **近况块**（放公共底子末尾，冻结）：最近 7 天、按「重要度 × 新近」取前 8 条，**≤600 字**（约 420 token）。一天最多重算一次，或在私聊窗口前移时顺带重算——这样开头稳定，缓存不受影响。
- **刚刚发生**（放动态结尾）：近况块冻结之后新增的经历，≤5 条、≤300 字。
- **按话题检索**（放动态结尾，和「这轮可能用得上的记忆」合并预算 700 字）：用户提到「电话」「朋友圈」「上次群里」时，按向量 + 关键词从更早的经历里捞。
- **更早的**：超过 90 天的经历并入现有的月摘要（`memory_states.monthly_summaries`），原条目删除，防止无限增长。
- **用户可见、可删**：「TA 的动态」时间线增加「我们一起」来源；用户删除一条，角色也随之忘记（和删记忆同样的语义）。

### 2.3 长期记忆：从私聊 + 群聊 + 通话抽取

| 来源 | 现在 | 改后 |
|---|---|---|
| 私聊 | 每 10 条或离开 3 分钟抽一次（已有） | 不变；记忆条目里加「来源：私聊」 |
| 群聊 | **不抽** | 新任务「群聊整理」：每个群每 **20 条用户消息**或**安静 10 分钟**整理一次，**一次调用**同时产出：① 给每个在群角色的记忆操作（用户在群里公开说的事，群里每个角色都可以记）；② 一条群聊经历。按用户付费、后台模型、计入记忆（不受生态开关限制） |
| 通话 | 结束后写一条 ≤60 字摘要 | 结束后用与私聊同一套抽取提示词处理通话文字：产出记忆操作 + 一条通话经历；**范围跟随通话**（私密通话记 adult） |

记忆页的每条记忆增加「来源：私聊 / 群聊 / 电话」小字（契约加一个可选字段）。

### 2.4 私密模式的隔离（必须守住）

规则一句话：**私密模式里发生的一切，只在私密模式里被想起，只交给该用户的私密模式模型。**

1. **打标签**：私密模式产生的原文、记忆、经历、摘要一律 `scope = adult`（记忆已有；经历表新增同名字段；摘要已分 normal / adult 两份）。
2. **读的规则**：
   - 私密模式私聊：读 normal + adult。
   - 其他一切场景（日常私聊、群聊、主动消息、通话、朋友圈、生态、你不在时）：**只读 normal**。
   - 私密模式下的主动消息 / 通话：可以读 adult，但只用私密模型（现有逻辑如此，保留）。
3. **模型规则**：只要请求里含 adult 内容，`modelRole` 必须是 `adult`（私密模式模型）。建议在拼装函数里加一道硬检查：拼出的内容含 adult 来源而模型角色不是 adult → 直接拒绝发送并记错误。
4. **跨角色转述**（朋友转述）：adult 永不参与（现有 `memoryShareable` 已排除，补测试）。
5. **群聊**：私密模式「仅单角色」（G1 保留），群聊不会产生 adult 内容；群聊永远只读 normal。

> **2026-10-21 H2 已实施**（总经理 C14）：问题 1 改为隔离——日常范围只读 normal；切出私密模式时由私密模型生成一份去露骨的「私密模式期间的经历整理」，写成日常范围记忆代替（见 `docs/handoffs/2026-10-21-h2.md`）。问题 2 已由 call-scope-fix 修复。私密模式的安全关怀、生态动作也只用私密模型。

| 2 | **私密模式通话的摘要被写成普通记忆**：摘要已用私密模型生成（G1），但 `addEpisode` 写库时 `scope` 写死为 `normal` | `memory.ts addEpisode` / `call-agent.ts summarize` | 私密通话内容会出现在日常私聊、群聊、生态里 | 直接修：`addEpisode` 增加 scope 参数，私密通话传 adult。属于 bug，不需拍板 |

## 3. 各场景改后会发什么（对照）

| 场景 | 改后 |
|---|---|
| 私聊 | 现结构 + 公共底子多一段「最近一起经历的」+ 动态结尾多「刚刚发生」 |
| 群聊 | 自己的公共底子 + 群聊补充（群名、成员关系、60 字、不当众说私事）+ 群里最近 30 条 + 结尾（检索记忆、刚刚发生、今天的日常） |
| 主动消息 | 公共底子 + 主动补充（理由、不做情感操纵、早晚安规则）+ 私聊最近几条 + 结尾 |
| 通话 | 公共底子 + 通话补充（口语、1～3 句、关怀）+ 通话各轮 + 结尾（只放时间与少量检索，通话每轮要快） |
| 私人朋友圈 | 公共底子精简版（不带示例）+ 朋友圈补充 + 生态给的「想写的」 |
| 生态决策 | 公共底子精简版（人设核心 + 记忆 + 经历近况）+ 现有的状态快照 |
| 公共朋友圈 | 不变（不接个人大脑） |

## 4. 对缓存命中的影响

1. **公共底子在同一角色的各场景里一字不差**，理论上群聊、主动消息能吃到私聊留下的缓存。但有三个前提：**同一个模型**（群聊、主动消息与私聊都用「文本聊天模型」，可以；通话用「语音通话」模型、生态用后台 / 决策模型，吃不到）、**同一个上游账号**、**在缓存有效期内**（几分钟到几小时，各家不同）。
2. 现在账号池按「会话」粘性调度（ADR-0032），群聊和私聊是不同会话，可能被分到不同账号 → 建议第 4 阶段把粘性键改成「用户 + 角色」，让同一个角色的大脑尽量走同一个账号。
3. 共同经历近况冻结在开头、一天最多变一次；新发生的放结尾——**私聊的命中率基本不受影响**（估计从 83% 降到 81%～82%，因为开头多了约 400 token 但大部分时间不变）。
4. 群聊现在把人设塞在系统消息、群记录塞在一条用户消息里，每个发言角色的开头本来就稳定；改后开头变长（多了记忆），但同样稳定，可缓存的比例更高。

## 5. 对花费（积分）的影响估算

> 按 DeepSeek 官方价举例：输入未命中 2 元 / 百万 token、命中 0.2 元 / 百万、输出 3 元 / 百万；1 元 = 100 积分。实际再乘后台倍率，换成别的模型按比例放大。数字是样本卡的粗估，第 0 阶段会把 `tools/prompt-compare.ts` 扩到群聊 / 主动 / 通话，给出实测前后对比再动手。

**每次请求的输入（约 token）**

| 场景 | 现在 | 改后 | 说明 |
|---|---|---|---|
| 私聊每条回复 | ~1,820（命中 ~83%） | ~2,000（命中 ~81%） | 多了经历近况和刚刚发生 |
| 群聊每次发言 | ~2,800（JSON 人设 ~1,800 + 30 条记录 ~700 + 规则） | ~3,300（短行人设 ~1,300 + 记忆 ~700 + 经历 ~400 + 记录 ~700 + 规则结尾 ~200） | 开头稳定部分 ~2,400，可缓存 |
| 主动消息 | ~2,500 | ~2,600 | JSON 换短行省下的，差不多被记忆补回 |
| 通话每轮 | ~3,000 | ~2,900 | 记忆从 JSON 换成冻结块，略省 |
| 私人朋友圈 | ~800 | ~1,500 | 为了「和你们的聊天有关」必须加记忆和经历 |
| 生态决策 | ~1,500 | ~1,800 | 加经历近况 |

**新增的调用**

- 群聊整理：约每 20 条群里的用户消息 1 次，输入 ~3,000、输出 ~500 token ≈ **0.0075 元 ≈ 0.75 积分 / 次**。
- 通话：不新增调用（原摘要调用改成抽取，输出从 150 增到 ~500 token，每通电话多约 0.1 积分）。
- 共同经历写入：系统模板，**0 积分**。

**一个重度用户一天大约**（私聊 150 条、群聊发言 40 次 / 用户群消息 40 条、主动消息 3 条、通话 1 通、私人朋友圈 1 条）：

| 项 | 增加 |

| 群聊发言（多 ~500 token，若命中私聊缓存则几乎不增） | ≈ 0.4～4 积分（无缓存 4、有缓存 0.4） |

| 其他 | < 0.5 积分 |
| **合计** | **约 1～3 积分 / 天**（群聊用得少的用户 < 1 积分） |

## 8. 需要总经理拍板的点（含推荐）

1. **日常模式还要不要记得私密模式里发生的事？**（原产品规则 MODE-05 是「记得」，与 C13「私密内容只进私密场景」冲突）
   **推荐：不记得细节。** 日常模式只多一句固定的话「你们之间也有私密模式的相处，日常里不提」，不带任何具体内容；私密模式里仍然记得全部日常的事。理由：守住「私密内容只给私密模型」这条底线最简单可靠，普通模型也不会因为看到成人内容而拒答。
2. **群聊里的角色知道你私聊说过的事，但不当众说出来**（除非你自己在群里先提）。**推荐：同意。** 像真人朋友一样「心里知道、嘴上有分寸」。
3. **群聊整理会额外扣积分**（约每 20 条群消息 0.75 积分，按 DeepSeek 价），计入「记忆」（不受角色生态开关控制，关了生态群聊也照样记得）。**推荐：同意。**
4. **「共同经历」给用户看、可删除**（放在「TA 的动态」里，删了角色就忘）。**推荐：同意。**
5. **公共朋友圈不接个人大脑**（所有人看同一条，不能出现任何一个用户的事）。**推荐：保持。**
