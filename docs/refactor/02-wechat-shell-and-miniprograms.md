## 1. 结论（先看这 6 条）

1. **底部 4 个标签不变：微伴 / 通讯录 / 发现 / 我**，每个标签里的页面顺序、分组、长按菜单都照参照产品排。参照产品有、微伴也有的功能放在老位置；参照产品有、微伴用不上的（视频号、直播、扫一扫、听书、看一看、游戏、二维码、卡包、青少年模式等）**直接不放**，不做「暂未开放」的空壳。
2. **11 个微伴专属功能统一做成小程序**：卡册、成就、宠物、每日一问、心愿清单、慢信、陪你专注、TA 的提醒、经期日记、人设广场、导入角色。入口有三处主入口（发现 › 小程序、会话列表下拉、聊天「+」面板 › 小程序）和若干顺路入口（聊天信息页、资料页、聊天里的卡片）。服务页因此瘦身，只留钱、模型和偏好。
3. **总经理点名的四件事都有了位置**：
   - 通讯录顶部固定行加「新建角色」（和「新的朋友 / 群聊 / 角色广场」排在一起），点开选三种方式：自己写、从聊天记录生成、去人设广场挑。
   - 聊天信息页加「聊天模型」一组，一行「TA 用的模型」。
   - 情景模式挪进聊天「+」面板，改名「情景预设」：**自动、日常聊天、情侣暧昧、树洞分享、傲娇斗嘴、加油打气**，成人内容单独放在弹层最底部的「私密」一栏，只对有资格的角色出现。
   - 宠物重做首次引导和领养：先一屏讲清楚「这是什么」，再把原来 4 个页面的领养流程合成一页，并保证永远有可领养的小动物（不再出现空列表死路）。
4. **旧版 6 个好交互全部保留**：一句一个气泡、按住说话、通话回铃、短会话列表不跳动、好友通过仪式感、我们的瞬间（放进卡册小程序）。
5. **版权**：只学布局和交互顺序。图标继续用 Phosphor Icons（MIT 开源），颜色用现有令牌（默认绿 `#0AA35A` 已经比参照产品深一档），提示音、回铃音、文案全部原创，不出现参照产品的名字、图标和声音。
6. **先改什么**：P0 是导航骨架、通讯录新建角色、聊天信息模型选择、情景预设、宠物领养；P1 是小程序外壳和小程序主页、服务页瘦身；P2 是下拉小程序面板等手势类改动。详见第 10 节。

## 2. 设计原则（这次换壳的取舍规则）

| # | 规则 | 例子 |
|---|---|---|
| 1 | 参照产品有、微伴也有 → **放老位置、用老手势** | 会话左滑、长按菜单、通讯录字母索引、朋友圈 ·· 点赞 |
| 2 | 参照产品有、微伴没有 → **不放**，不做空壳 | 视频号、扫一扫、游戏 |
| 3 | 微伴专属、每天会用、跟某个 TA 绑定 → **放进聊天**（「+」面板、聊天信息页） | 情景预设、写信、提醒、专注 |
| 4 | 微伴专属、自成一块的功能 → **做成小程序** | 宠物、卡册、经期日记、人设广场 |
| 5 | 钱、模型、全局偏好 → **「我 › 服务」** | 余额、价目表、主动消息与免打扰 |
| 6 | 一个功能只有一个「家」，其他地方都是快捷入口，打开的是同一个页面 | 情景预设：「+」面板和私聊副标题打开的是同一个弹层 |

## 3. 导航树要点

完整树见附录 `02a-navigation-tree.md`。和现有设计（`docs/design/02-interaction-flows.md` 第 2 节）相比，变化集中在下面这些地方：

### 3.1 标签一「微伴」（会话列表）

- 右上 ⊕ 菜单从 2 项变 4 项：**发起群聊、添加角色、新建角色、导入角色**（导入角色占参照产品「扫一扫」的位置）。
- **下拉出现小程序面板**（参照产品下拉会话列表出现最近使用的小程序）。详见 4.3。
- 会话行长按菜单补齐参照产品的「不显示该聊天」（有新消息时会话重新出现）。

### 3.2 私聊

- 「+」面板第 1 页：相册、拍摄、语音通话、**情景预设** / 写信、陪我专注、**提醒**、**小程序**；第 2 页：心愿、名片。每页 4×2、左右翻页、底部分页圆点（这是旧版的做法，也是参照产品的做法）。
- 标题下方副标题显示当前情景预设，点副标题打开同一个情景预设弹层。
- 聊天信息页：加「聊天模型」组；加「和 TA 一起用」一行小程序图标；**去掉**「情景模式」「我们的宠物」「心愿清单」三行（分别搬进「+」面板和小程序）。

### 3.3 标签二「通讯录」

顶部固定行改为四行：**新的朋友 / 新建角色 / 群聊 / 角色广场**（参照产品是「新的朋友 / 仅聊天的朋友 / 群聊 / 标签」，微伴没有标签功能，用「角色广场」占这一格）。

```
┌────────────────────────────────┐
│           通讯录              👤+ │
├────────────────────────────────┤
│ 🔍 搜索                          │
├────────────────────────────────┤
│ [■] 新的朋友                  ●  │  图标方块用点缀色铺底 + 白色线框图标
│ [■] 新建角色                     │  ← 新增：总经理要求
│ [■] 群聊                         │
│ [■] 角色广场                     │
├─ L ────────────────────────────┤
│ [头像] 罗小黑                     │
│ …                              │
└────────────────────────────────┘
```

点「新建角色」→ 底部弹层三选一：

| 选项 | 说明文字 | 去哪 |
|---|---|---|
| 自己写一个 TA | 填名字、性格、说话方式 | 创建自己的角色（编辑器，`pages/contacts-add.md`） |
| 从聊天记录生成 TA | 粘贴、上传文件或截图 | 小程序「导入角色」 |
| 去人设广场挑一个 | 看看大家创作的角色 | 小程序「人设广场」 |

理由：用户脑子里只有「我想要一个新角色」，不会先想「我要导入」还是「我要创建」；一个入口分三条路最好懂。

### 3.4 标签三「发现」

从「直接显示角色广场列表」（网页现状）改成参照产品的菜单列表：

```
朋友圈        [头像]●   ›
─────────────────────────
角色广场                 ›      ← 占「视频号」的位置
─────────────────────────
搜一搜                   ›      ← 只搜本机：角色、群、聊天记录、收藏
─────────────────────────
小程序                   ›      ← 小程序主页
```

### 3.5 标签四「我」与设置

- 「我」页结构不变：头部、服务、收藏、朋友圈、表情、设置。
- **服务页瘦身**：钱包卡（余额、模型）+「模型与花费」宫格 +「偏好」宫格（主动消息与免打扰、聊天偏好、熟悉度总览）。原「陪伴」「互动偏好」「互动玩法」三组里的卡册、成就、宠物和 5 个玩法、经期日记搬进小程序；情景模式总览删除（第 5 节说明原因）。
- 设置照参照产品分组：账号与安全 / 新消息通知 / 隐私 / 通用 / 关于微伴 / 退出登录。

## 4. 小程序方案

### 4.1 有哪些小程序

| 小程序 | 一句话说明（显示在小程序主页） | 图标（Phosphor） | 颜色令牌 | 按 TA |
|---|---|---|---|---|
| 卡册 | 和 TA 的每一个特别时刻 | cards | `tint.pink` | 是 |
| 成就 | 一起走过的里程碑 | medal | `tint.gold` | 否 |
| 宠物 | 和 TA 一起养一只小家伙 | paw-print | `tint.orange` | 是 |
| 每日一问 | 每天一个问题，说给 TA 听 | chat-circle-dots | `tint.gold` | 否 |
| 心愿清单 | 想和 TA 一起做的事 | list-checks | `tint.teal` | 是 |
| 慢信 | 写一封慢慢寄到的信 | envelope-simple | `tint.lilac` | 是 |
| 陪你专注 | 让 TA 陪你专心一会儿 | hourglass-medium | `tint.pink` | 是 |
| TA 的提醒 | 让 TA 到点叫你 | alarm | `tint.blue` | 是 |
| 经期日记 | 记录身体，也让 TA 懂你 | flower-lotus | `tint.pink` | 否 |
| 人设广场 | 看看大家创作的角色 | users-three | `tint.blue` | 否 |
| 导入角色 | 用聊天记录生成一个 TA | download-simple | `tint.teal` | 否 |

- 图标、颜色沿用服务页宫格已经定好的（`pages/me-and-services.md` 2.2），人设广场和导入角色是新分配的，都在现有点缀色里选，**不新增令牌**。
- 「按 TA」= 这个小程序的内容属于某个角色。从聊天里打开时直接进入当前 TA 的那一页；从全局入口打开时先到总览，再点某个 TA。
- 名字：总经理说的「慢递信」沿用 PRD 已有的名字「慢信」（`prd-v1/16-interactive-play.md` PLAY-05），避免同一个东西两个名字。如果总经理更喜欢「慢递信」，由产品改术语表后统一改。
- 小程序图标统一为 **圆角方块**（56px，`radius.md`，点缀色铺底 + 白色 28px 线框图标），和参照产品小程序的圆形图标、和服务宫格的样式都区分开。

### 4.2 小程序外壳

所有小程序共用一个外壳，用户一看就知道「我现在在一个小程序里」：

```
┌────────────────────────────────┐
│ ‹         宠物         [··· | ◯] │  左：返回（只在小程序第 2 层以下显示）
├────────────────────────────────┤  中：小程序名或当前页标题
│                                │  右：胶囊按钮（··· 更多 | ◯ 关闭）
│        小程序内容                │
│                                │
└────────────────────────────────┘
```

| 部件 | 规则 |
|---|---|
| 胶囊按钮 | 宽 88、高 32，圆角 `radius.full`，`bg.surface` 底 + `border.default` 细边框，**不用毛玻璃**（D-09）；左右两格中间一条竖线。位置固定在右上，所有小程序都一样，小程序自己的页面内容不能放在这里 |
| ···（更多） | 底部操作列表：**发给 TA**（P3，见 4.6）/ 添加到我的小程序 · 从我的小程序移除 / 不在最近使用中显示 / 关于这个小程序（一句话说明 + 它会用到哪些数据）/ 重新进入 |
| ◯（关闭） | 一步回到打开小程序之前的地方（会话列表、私聊、发现页……），不管在小程序里走了几层 |
| 返回 ‹ / 系统返回 | 在小程序里退一层；已经在小程序首页时等于关闭 |
| 打开动画 | 从底部升起（`transform: translateY`，沿用 M-03 的时长与曲线），关闭时反向；**不做启动闪屏**。数据 300ms 内没回来才显示骨架块 |
| 标签栏 | 小程序里不显示底部标签栏 |
| 宽屏网页（≥ 900px） | 小程序在右侧详情栏打开，胶囊照样在右上 |

和普通「推入页面」的区别只有两点：多了胶囊（能一步关闭），打开方向是从下往上。这样用户不会迷路——不管点进多深，右上角 ◯ 一下就回去。

### 4.3 入口

| 入口 | 位置 | 显示什么 | 打开后 |
|---|---|---|---|
| **小程序主页** | 发现 › 小程序 | 搜索框、最近使用（横排）、我的小程序（宫格） | 小程序首页 |
| **下拉面板** | 会话列表往下拉 | 同上，但是全屏面板，底部露出一条会话列表 | 小程序首页 |
| **和 TA 一起用** | 私聊「+」面板 › 小程序 | 半屏弹层，只列「按 TA」的小程序，当前 TA 已选好 | 直接进入当前 TA 那一页 |
| 聊天信息页 | 「和 TA 一起用」一行图标 | 同上 | 同上 |
| 资料页 | 「卡册」一行 | — | 卡册里该 TA 的卡 |
| 聊天里的卡片 / 提示 | 每日一问回答卡、信件卡、「获得瞬间卡 ›」「去看看团子 ›」 | — | 小程序对应的那一页 |
| 新建角色弹层 | 通讯录 / ⊕ 菜单 | — | 导入角色、人设广场 |

**下拉面板的手势细节**（性能要求高，放 P2）：

1. 会话列表已经在最顶端时继续下拉，列表整体跟手往下移（只改 `transform`）；
2. 下拉超过 80px 松手 → 面板展开铺满，会话列表缩成底部一条（高 64），显示「微伴」字样；没到 80px 松手 → 弹回；
3. 点底部那一条或在面板上往上滑 → 收起；
4. 面板里的图标用同一个宫格组件，不做逐个弹出的动画；
5. 不做大面积模糊背景（参照产品有，我们不做，D-09）。

**最近使用**：最多 8 个，按最后打开时间排序；长按可移出。经期日记**默认不进入最近使用**（别人借你手机下拉一下就能看到，不合适），用户可以在它的 ··· 菜单里打开。首版「最近使用」只存本机（网页和安卓各自记），如果需要跨设备同步，请架构负责人评估（见第 11 节）。

**我的小程序**：默认 11 个全在，顺序按上表；长按进入整理，可以拖动排序、移出（移出后在小程序主页搜索仍能找到）。功能所在开发层没上线的小程序不显示（沿用 SVC-01 第 6 条做法）。

### 4.4 和聊天的联动

| 场景 | 用户看到 |
|---|---|
| 在私聊里想用某个功能 | 「+」→ 小程序 → 半屏选一个，当前 TA 已选好，不用再选角色 |
| 在小程序里做完一件事 | 聊天里出现对应的会话内提示或卡片（这些在现有设计里已有：领养完成、信寄出、专注开始 / 结束、心愿完成、每日一问回答卡）；点提示回到小程序那一页 |
| TA 在聊天里提议（宠物、心愿） | 快捷回复按钮「去看看」→ 直接打开小程序，TA 已选好 |
| 小程序里想回去聊天 | 小程序内页面底部的「去和 TA 聊聊」行（宠物主页已有），或胶囊 ◯ 关闭（从私聊打开的就回到私聊） |

### 4.5 不做成小程序的

| 功能 | 放哪 | 理由 |
|---|---|---|
| 情景预设 | 聊天「+」面板 | 每次聊天都可能换，要伸手就到（总经理要求） |
| 余额、模型、价目 | 我 › 服务 | 参照产品「服务」也是放钱的地方 |
| 主动消息与免打扰、聊天偏好、熟悉度总览 | 我 › 服务 › 偏好 | 是全局设置，不是「玩」的东西 |
| 朋友圈、角色广场 | 发现 | 参照产品原位置 |
| 记忆、时间线、纪念日、TA 认识的人 | 角色资料页 | 是关于这个 TA 的资料，参照产品资料页的位置 |

### 4.6 以后可加：把小程序「发给 TA」

胶囊 ··· 里的「发给 TA」：在聊天里发一张小程序卡片（例如「我的心愿清单」），TA 看到后会回应。需要一种新的消息类型，属于接口变更，先列为 P3，请架构负责人评估（第 11 节）。首版这一项不显示。

## 5. 情景预设

### 5.1 为什么挪、挪到哪

- 原来在「聊天信息 › 情景模式」，要点两层才能换，还藏在一堆设置中间；用户换风格往往是「聊着聊着想换」，所以挪到输入框旁的「+」面板，**点一下 ⊕ 就看到**。
- 私聊标题下的副标题显示当前预设（「日常聊天」不显示），点副标题也能打开同一个弹层。
- 聊天信息页的「情景模式」行删除；「我 › 服务 › 情景模式总览」删除——每个 TA 的当前预设在各自聊天的副标题上就能看到，总览页使用频率低，留着反而多一个要维护的地方。
- 群聊同样在「+」面板里切，可选范围仍按「所有成员都有资格」（SOC-03 第 4 条）。

```
│ └───────────┘                │
├─ 私密 ─────────────────────────┤  只对有资格的角色显示，见 5.5
│ [🔒] 成人内容            未开启 › │
└────────────────────────────────┘
```

- 选中的卡片：2px `brand.primary` 边框 + 右上角 ✓；点另一张即切换，弹层自动收起。
- 角色没有资格的预设**不显示**（不是灰色，沿用 MODE-01 第 4 条）。例如儿童角色看不到「情侣暧昧」和「私密」。
- 切换后聊天里出现一行会话内提示「已切换到 树洞分享」（MODE-02 第 2 条），TA 不说「好的我进入 XX 模式」这种出戏的话，从下一条回复开始换风格。
- 「+」面板里「情景预设」这个格子：当前不是日常聊天时，格子右上角一个小圆点，提示「现在开着别的预设」。
- 图标全部用 Phosphor（`sparkle`、`sun`、`heart`、`moon`、`lightning`、`arrow-fat-up`、`lock-simple`）；「情侣暧昧」用心形，这是唯一允许出现心形的地方（熟悉度、点赞都不用心形，D-05、D-18）。

### 5.3 每种预设对用户意味着什么

| 预设 | 用户看到的一句说明 | 对用户意味着什么 | 谁能用 | 和现有 PRD 的对应 |
|---|---|---|---|---|
| **自动**（推荐，新账号默认） | TA 看你当下的状态自己调整 | 不用自己选。TA 根据你说话的语气、时间（深夜、刚下班）、聊的内容，在「日常聊天 / 树洞分享 / 加油打气 / 傲娇斗嘴」之间自己调整风格。**自动不会进入「情侣暧昧」和「私密」**，这两个只能你自己选 | 所有角色 | 新增 |
| **日常聊天** | 像朋友一样聊 | 按角色原本的人设相处，什么都能聊 | 所有角色 | = 日常 |
| **情侣暧昧** | 甜一点、黏一点 | 用恋人的口吻和称呼，会撒娇、会想你；不改变你设定的「关系类型」，换回别的预设后不延续恋爱口吻 | 儿童角色除外 | = 恋爱（改显示名） |
| **树洞分享** | 多听少说，不评判 | 适合想倒苦水的时候：TA 少说自己的事、不急着讲道理和给建议、不转移话题、不开玩笑带过；你停下来时会轻轻问一句还想不想继续说。**建议**：树洞里说的事 TA 不会在朋友圈、时间线和其他角色面前提起（规则需产品确认，见第 11 节） | 所有角色 | 新增 |
| **傲娇斗嘴** | 嘴硬心软，爱怼你 | 会损你几句、偶尔已读不回，但最后还是会帮你（仍受小巧思次数上限） | 所有角色 | = 傲娇（改显示名） |
| **加油打气** | 给你打气，也会督促你 | 适合考试、健身、加班：TA 语气更有劲，会问进度、夸你做到的部分，偷懒时会催一下；不会用威胁或让你愧疚的话（原则 6 不操纵） | 所有角色 | 新增 |
| **私密 · 成人内容** | 只在你们俩之间 | 见 5.5 | 仅非真人、非儿童角色 | = 成人 |

安全关怀触发时，任何预设的冷淡、斗嘴表现都暂停（MODE-02 第 7 条、SAFE-06），自动预设也一样。

### 5.4 「自动」怎么显示

- 副标题显示「自动」二字（不随它内部的判断变来变去，避免标题一直闪）。
- 打开情景预设弹层时，「自动」卡片下面一行小字显示它现在偏向哪种风格，用中性说法：「现在：日常」「现在：偏向倾听」「现在：给你打气」「现在：斗斗嘴」。**不写判断理由**（不写「因为你好像很难过」），避免让人觉得被分析、被监视。
- 自动内部换风格时**不在聊天里插提示**（插了会很吵）；只有用户手动切换时才插「已切换到 XX」。
- 用户觉得自动判断不对，直接点另一个预设即可，没有「纠正」之类的额外操作。

### 5.5 成人内容放哪、怎么不越界

放置方式：弹层最底部、和其他预设隔开的「私密」一栏，一行文字、不配图，**不在「+」面板格子上、不在任何列表里露出「成人」二字**。

| 规则 | 依据 |
|---|---|
| 只有成人资格为「是」的角色（非真人、非儿童）才显示这一栏，其他角色连这一栏都没有 | MODE-03 第 1 条、SAFE-03 |
| 没选好成人模式模型时：点这一行显示提示「开启前，请先在『服务 › 模型』中选择成人模式模型」+「去选择」，会话保持原预设 | MODE-03 第 3 条 |
| 已选好模型：第一次点时弹一次说明对话框（「这里的内容只留在你和 TA 之间：不会出现在朋友圈、其他角色那里、分享图和推送里」）+「开启」「取消」；之后直接切换 | MODE-05（把已有的去向规则讲给用户听，不是年龄确认，不违反「不需要年龄确认」） |
| 开启后副标题显示「私密」而不是「成人模式」 | 别人瞄到屏幕时不尴尬；**这条和 MODE-01 第 5 条「显示模式名」有出入，请产品确认** |
| 「自动」永远不会进入私密，也不会进入情侣暧昧 | 原则 6 不操纵：亲密程度只能由用户自己决定 |
| 推送不显示内容、不能选入分享图、不进朋友圈 / 时间线 / 其他角色 | MODE-05 第 2～4 条（不变） |
| 不提供任何绕过模型审核的选项或说明 | ADM-05 第 6 条、不做清单 |
