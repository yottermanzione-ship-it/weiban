## 0. 怎么读

**一行 = 一个节点**（页面、入口、长按菜单的一项、弹窗）。ID 按导航树层级编号：`T1` 微伴（微信标签）、`T2` 通讯录、`T3` 发现、`T4` 我、`G` 全局；`T1.11.5` 就是「微伴 › 私聊 › 消息长按 › 撤回」。

| 列 | 意思 |
|---|---|
| 节点 | 页面或入口的名字，用微信原文案；括号里是复刻文档给的页面代号（如 ChattingUI），方便对照。名字前带 **★** 的是微伴专属新增节点 |
| 路径 | 用户从哪里点进来 |
| 交互 | 点、长按、左滑之后去哪、弹什么 |
| 出处 | 复刻文档哪一份哪一节。简称：**聊天篇** = 社交应用聊天模块复刻文档；**设置篇** = 设置资料朋友圈；**账号篇** = 账号状态；**表情篇** = 表情收藏扫一扫；**视频号篇**；**发现篇** = 发现页；**我篇** = 我页面其他功能。微伴专属节点写它的依据（07、02a、06、PRD） |
| 皮肤（06） | 用旧项目哪个组件 / 样式，引用 `06-old-ui-spec.md` 的节号（如「06 §3.7」= 浅色长按菜单） |
| 微伴内容 | 这里放微伴的什么。「暂未开放（点击提示）」= 微信有、微伴用不上，入口照常显示、点了弹提示。★ 节点在这里说明为什么挂在这个位置 |
| 内核 | 涉及 AI / 聊天时，对应爱语或酒馆的哪种做法；「03 #4」指 `03-aiyu-learnings-ai.md` 第 6 节改进清单第 4 条 |
| 现状 | 当前网页（10-14 第一、二批改完后）：**已有且一致** / **已有需调整** / **缺失** / **不需要**（上级入口没开放，或者微伴没有这个场景，比如角色不会「忙线」；这类节点列出来只是为了证明文档全覆盖，网页不用做） |
| 待决定 | 需要总经理拍板的点，写成一句问题，附推荐。空着 = 按本行直接做 |

**圈改方法**：直接在本文或 JSON 里改「微伴内容」或「待决定」列，或者回复「Q3 同意推荐 / Q5 改成……」即可。

### 1.3 改动量一览（网页一次做完时的工作清单）

**A. 结构调整（照骨架改顺序 / 位置 / 名字，基本不涉及后端）**
