术语（后文直接用）：

- **听写（ASR）**：把声音变成文字。**流式听写**是边听边出字，不用等说完。
- **合成（TTS）**：把文字念成声音。**流式合成**是第一小段声音先到先播，不等整句合完。
- **断句（端点检测）**：判断"用户这句话说完了没有"。判早了会抢话，判晚了会让人觉得反应慢。
- **打断（barge-in）**：角色说话时用户开口，角色立刻停下来听。
- **VAD（语音活动检测）**：判断某一小段声音里"有没有人在说话"的小程序，断句和打断都靠它。
- **回声消除**：外放时，麦克风会录到喇叭里角色自己的声音；回声消除把这部分去掉，否则角色会"自己打断自己"。
- **首声延迟**：用户说完最后一个字，到听见角色第一个字的时间。通话体验最关键的一个数字。
- **LiveKit / WebRTC**：一套专门传实时音视频的媒体服务器和协议，抗网络抖动强，但要单独部署、开 UDP 端口。
- **HTTPS / 安全上下文**：浏览器只在 HTTPS（或 localhost）页面上允许使用麦克风。

## 0. 先看结论

1. **保留新版现在的骨架，不引入 LiveKit。** 新版"每通电话一条 WebSocket 传 PCM 音频 + 服务器上做 听写→角色模型→合成"（ADR-0025）和 papercup 的架构几乎一样，papercup 用它做到了首声 2～3 秒、长通话稳定。香港服务器只有一台 4 核 8G，再部署 LiveKit 只会多一套要维护的东西，而且 LiveKit 在浏览器里同样要 HTTPS，解决不了麦克风问题。
2. **真正慢、真正不像真人的地方在 AI 链路里，要改五处**：
   - 听写从"等用户停 0.7 秒 → 整段上传识别"改成**流式听写**（供应商自带断句与标点），断句判定目标 0.5～0.7 秒、出字几乎不等。
   - 角色回复从"等整段文字生成完再合成"改成**边生成边按小句合成**（papercup 这一步把首声从 8～12 秒压到 2～3 秒）。需要给模型网关加"流式文字生成"接口——**这是一次接口变更申请**。
   - **打断改成两段式**：先把角色音量压低（约 0.25 秒有声），确认真是人在说话（约 0.5 秒）再真正打断；咳嗽、回声误触时恢复音量。并且**被打断时只把"已经播出去的那部分"记进对话**，角色不会以为自己说完了。
   - **合成前统一清洗文字**：去掉括号动作、星号动作、表情、网址、Markdown 符号、思考块，避免被念出来。
   - **自然挂断**：用户说"拜拜/晚安/先挂了"，角色道别、播完后自动收线（契约里已有 `completed` 结局，不用改接口）。
3. **供应商推荐阿里云百炼一家包办听写和合成**（旧版已跑通同一套，香港访问延迟低），备选火山引擎（豆包语音）；另外**硅基流动可以零代码先开通试用**——它的接口和新版现有的"OpenAI 兼容"适配器格式一致，配好密钥就能打通，用来尽早验证整条链路。价格见第 3 节（全部**需核实**）。
4. **成本**：听写 + 合成约 **0.03～0.04 元/分钟**（旧版实测 161 秒 0.103 元，与此吻合）。**大头可能是角色文字模型**：新版每轮都把最长 2 万字的人设整段发过去，一分钟约 6 轮，换成贵的模型一分钟可能 0.1 元以上。通话要用**快速、非思考**的模型，并给通话准备精简版人设。
5. **延迟目标**：首声延迟中位数 ≤ 1.8 秒、九成通话轮 ≤ 2.8 秒（旧版公网实测 3～4 秒，papercup 2～3 秒）。每一轮都记录各阶段耗时，用数字说话。
6. **HTTPS 必须正面解决：推荐买一个域名（几十元/年）开 HTTPS**。香港服务器不需要备案，域名解析过去、运维把 Caddy 切回自动证书模式即可，半天工作量。在这之前：网页端不能通话；安卓原生录音不受浏览器限制，但安卓正式包已设定"没有 HTTPS 拒绝构建"，只能出一个**仅供自测的明文测试包**（登录凭证明文传输，不能给别人用）。
7. **工作量**：合计约 **12～16 个人日**（AI 6～8、后端 1、网页 2～3、安卓 2～3、运维 0.5～1），见第 5 节。总经理需提供：**阿里云百炼账号与密钥（实名、充值）**、**一个域名**；可选：硅基流动密钥（先行试用）、火山引擎账号（备用）。

## 1. 三家参考做法

### 1.1 papercup（开源，AGPL-3.0）

定位："给网关里的 AI 伴侣打电话"的通话层——它只当**耳朵和嘴**，大脑（人设、记忆、历史）全在另一个"网关"服务里。每轮只发 `{通话编号, 用户这句话}` 给网关，网关流式回文字。这和新版 calls（会话与音频）+ ai-runtime（大脑）的分工是同一个思路。

| 环节 | 做法 |
|---|---|
| 传输 | 浏览器 `getUserMedia` 录音 → WebSocket 实时传 16k PCM；服务端回分句音频 + 字幕 |
| 听写 | 服务器本地跑 SenseVoice 小模型（int8，约 230MB，CPU 上约 100 倍实时）+ silero VAD **边说边切段**：每段静音 ≥0.7 秒就先识别存起来，用户说完只剩最后一小段要识别，"说完秒出字、延迟不随说话时长增加"。本地失败回落云端（硅基流动） |
| 断句 | 前端自适应：短句停 0.9 秒收口，长发言（有声累计超 1.8 秒）给 1.35 秒，留思考停顿；单句 60 秒上限；看门狗防环境噪声卡死 |
| 防吞句首 | 前端常备约 0.9 秒环形缓冲，开口时补发（VAD 确认开口要约 0.2 秒，否则第一个字被吞） |
| 打断 | **两段式**：连续有声 240ms 先把角色音量压到 25%，520ms 才真打断；误触在 160ms 内消失则恢复原音量 |
| 文字回复 | 网关 SSE 流式返回 → 流式剥掉 `<think>` 推理块 → **按行切句**，每句独立清洗、独立合成 |
| 合成 | ElevenLabs 逐句流式合成（首句不等全文），MiniMax 备用；**熔断器**：连续 3 次失败停 90 秒，期间只出字幕电话不断 |
| 清洗 | 引号内朗读、引号外只当字幕；语气标记（笑、叹气、停顿）用一套中间写法，再翻译成各家合成的"方言"，换供应商只改映射表 |
| 自然挂断 | 识别到告别词（排除"别挂"这类反例）→ 正常生成道别 → 前端播完 → 宽限 3.5 秒自动收线，30 秒硬截止 |
| 记录 | 每轮实时写库（断线不丢）、每轮分阶段延迟指标、挂断后整通摘要进记忆 |
| 延迟 | 首句流式合成后首轮从 8～12 秒降到 2～3 秒；听写本地化后从 5.5 秒（跨太平洋调用）降到秒级 |

### 1.2 旧版微伴（2026-10 最新方案）

| 环节 | 做法 |
|---|---|
| 传输 | **LiveKit** 媒体服务器（WebRTC，UDP 7881/7882）+ 隔离的通话桥进程（Node，持有供应商密钥，管房间）+ Python 语音工人（LiveKit Agents） |
| 听写 | 阿里百炼流式听写（代码中模型名 `qwen-audio-3.0-asr-flash-streaming`，经通话桥的 WebSocket 中转） |
| 断句与打断 | silero VAD（静音 0.35 秒）+ 最短端点等待 0.2 秒、最长 2 秒；**预先生成**（用户还没说完就开始想）；最短打断 0.5 秒、"误打断后恢复"；只把**实际播出、被打断截断后**的文字写进对话 |

| 教训 | 没有逐轮记录供应商用量，算不出准确账单；旧安卓曾依赖阿里闭源通话 SDK（无许可证文件，高风险）；iPhone Safari 录音 AudioWorklet 不稳，用 ScriptProcessor |

### 1.3 爱语 2.9.5

只有界面文件可看（加壳），以下"推断"均来自布局与文案。

| 环节 | 做法 |
|---|---|
| 听写 | **手机端本地模型**（流式 transducer 架构 ONNX，约 65MB，带"实时识别/最终结果"两级） |
| 合成 | 云端，硅基流动（2026-02 因费用从讯飞超拟人换过来）；每个角色可设专属音色；支持用户自配合成 |
| 文字回复 | 用户自己配置的聊天模型（推断） |
| 界面 | 深色全屏、圆形头像、状态行"正在聆听..."、**双向实时字幕**（默认隐藏，有字才出）、5 根声波柱、麦克风/挂断/扬声器三键、计时 |
| 打断、延迟、稳定性 | 看不到，无从判断 |

结论：爱语对新版的价值主要是**界面（字幕）和"端侧听写省钱"的思路**，通话链路本身没有可学的细节。

### 1.4 许可证：哪些不能直接用

- **papercup 是 AGPL-3.0**（继承自 pai-voice）。AGPL 的要求是：只要把它的代码（或改过的代码）放到网络服务里给别人用，就必须把**整个服务的源代码**按 AGPL 公开。微伴不接受这个条件，所以：
  - **不能复制**：`packages/realtime-core/server.py`、`cleanse.py`、`packages/web-client/voice-call.js`、`orb.js`、`index.html`、`legacy.html`、`tts_cleanse_smoke.py` 的任何代码片段，也不能"翻译"成 TypeScript/Kotlin 照搬结构。
  - **不能使用**：界面美术素材（背景、水晶皮肤、悬浮球）——作者声明本就不随仓库分发，仓库里的是占位图。
  - **可以学**：架构分层、"两段式打断""边说边切段""按句流式合成""熔断""告别词自然挂断""语气标记中间写法"这些**思路**。具体参数（240/520ms、0.9/1.35 秒等）只作起点参考，新版必须用自己的实测重新定。
- 旧版微伴是自家代码，可以参考实现；但其中阿里闭源通话 SDK 不得带入新版。
- papercup 用到的第三方模型：SenseVoice（FunASR 模型许可，商用条款**需核实**）、silero VAD（MIT）、sherpa-onnx（Apache-2.0）。若新版将来做本地听写，需单独核对模型许可。

## 2. 三家与新版对比

新版现状（读代码确认）：calls 模块用 WebSocket 收发 PCM；ai-runtime 的 `CallAgentService` 做"听写 → 角色模型 → 合成"；模型网关的实时听写其实是**服务器上按音量判静音 0.7 秒 → 整段用 OpenAI 兼容接口上传识别**；角色回复是**一次性生成完整文字（最多 200 token）再整段合成**；打断是客户端音量超阈值约 0.12 秒就发 `barge_in`。目前**语音服务未开通**（没有配听写/合成供应商），所以整条链路从没真实跑过。

| 维度 | papercup | 旧版微伴 | 爱语 | 新版现状 |
|---|---|---|---|---|
| 媒体传输 | WebSocket + PCM16 16k | LiveKit（WebRTC） | 不详（推断为 App 内直连） | WebSocket + PCM16（上行 16k，下行 24k） |
| 听写 | 服务器本地 SenseVoice + VAD 边说边切段，云端回落 | 百炼流式听写 | 手机端本地流式模型 | 服务器按音量断句后整段上传（OpenAI 兼容），非流式 |
| 断句 | 前端自适应 0.9/1.35 秒 | silero 0.35 秒 + 端点 0.2～2 秒，平均 0.74 秒 | 不详 | 固定音量阈值 500、静音 0.7 秒；嘈杂环境会断不开或乱断 |
| 打断 | 两段式（先压音量再打断，可恢复） | 0.5 秒、可恢复误打断、只记已播文字 | 不详 | 0.12 秒有声即打断，不可恢复；被打断的整句仍记入对话 |
| 文字回复 | 网关流式，按行切句 | 快速非思考模型，按小句切 | 用户自选模型 | 用户的聊天模型一次性生成，整段返回 |
| 合成 | 逐句流式，熔断 + 备用厂商 | 百炼双向流式 | 硅基流动云端 | 整段一次流式合成（OpenAI 兼容），无备用 |
| 音色 | 单一指定音色 | 角色音色绑定（含克隆） | 每角色专属音色 | 后台音色目录，按角色解析，没有可用音色则不能通话 |
| 字幕 | 双语字幕 | 网页端不画字幕 | 双向实时字幕 | 无（接口里没有字幕帧） |
| 延迟（说完到首声） | 2～3 秒 | 公网 3～4 秒 | 不详 | 未实测；按结构估算 3.5～6 秒 |
| 成本 | 本地听写≈0；ElevenLabs 月度字符额度（贵） | 约 0.038 元/分钟（不含文字） | 端侧听写≈0 + 硅基合成 | 未开通；按百炼估约 0.03～0.04 元/分钟（不含文字） |
| 稳定性措施 | 合成熔断、听写回落、逐轮落库、自然挂断 | 隔离进程（通话崩不影响聊天）、重启恢复 | 不详 | 断线 10 秒重连、每分钟兜底巡检、余额/时长服务器判定，已较完善 |

一句话：**新版的"会话管理与计费"已经比三家都完整，差的是"听写—回复—合成"这条流水线的实时性和自然度。**

## 3. 推荐方案

### 3.1 保留什么

- **传输：保留 WebSocket + PCM（ADR-0025 不变）。** 理由：
  1. 级联方案必须在服务器上拿到原始音频去听写，WebRTC 的优势（端到端低延迟、抗丢包）被抵消大半；papercup 用 WebSocket 已做到可用。
  2. 只有一台香港服务器；LiveKit 要开 UDP 端口、常驻进程，内存与运维成本都增加，旧版因此出现过防火墙全开的问题。
  3. LiveKit 在浏览器里同样要求 HTTPS，解决不了麦克风权限。
  4. 何时重新考虑：真实用户反馈"卡顿/断续"明显、且日志显示是丢包而非服务端慢时，再写新 ADR 评估 LiveKit。
- **会话与计费：全部保留**（calls 的状态机、响铃、断线重连、余额与时长兜底；ai-runtime 的余额道别、55 分钟提醒、安全关怀、通话摘要入记忆、主动来电）。
- **隔离思路换个做法保留**：旧版把通话放独立进程，是怕"通话崩溃拖垮聊天"。新版先不拆进程（单进程更简单），但要求流水线内任何一步出错只结束本通电话、不抛到进程级；如果压测发现通话占 CPU 影响聊天，再由运维把通话流 WebSocket 拆到单独容器（代码已经是独立模块，拆起来不难）。

### 3.2 要改的五处（AI 为主）

**① 流式听写（model-access，AI）**
- 新增"百炼实时听写"适配器：服务器与百炼保持一条 WebSocket，把用户音频原样转过去，供应商返回**中间结果**和带标点的**最终句子**，断句由供应商的语义/静音检测完成（可配置静音阈值，起点 500～700ms，实测调）。
- 契约 `RealtimeAsrSession.results()` 本来就支持中间结果（`final = false`），**不用改接口**。
- 现有"按音量断句 + 整段上传"保留为**回落方案**（供应商连不上时用），音量阈值改为自适应（跟随环境噪声），这一点借鉴 papercup 前端的做法自己实现。
- 按分钟分段冻结/结算不变。注意流式听写按**送去的音频时长**计费，用户静音时也在计（见 3.4 成本）。

**② 边生成边合成（ai-runtime + model-access，AI；需改接口）**
- 给 `ModelGatewayPort` 增加**流式文字生成**（逐段吐字，结束时照常记模型、token、耗时、费用），由架构负责人审批（**接口变更申请**，见第 6 节）。
- 通话里收到文字流 → 按中文小句切（句号、问号、感叹号、换行；逗号在累计超过约 12 个字时也切；超过约 40 字强切）→ 每个小句送合成 → 音频按顺序下发。第一句话合成时，后面的文字还在生成。
- 接口审批前可以先做一个**不改接口的过渡版**：仍一次性生成，但把结果切成小句逐句合成，第一句先播。能省掉一部分合成等待，省不掉模型生成时间。

**③ 打断与对话记录（ai-runtime，AI；客户端配合）**
- **两段式打断**：客户端检测到用户开口先把角色音量压低（不发信号），持续约 0.5 秒才发 `barge_in` 并清空待播音频；若声音很快消失（咳嗽、关门、回声），恢复原音量。具体毫秒数按真机调。
- 服务器端补一道：流式听写出现**有内容的中间结果**时，也视为用户开口（防止客户端阈值太高漏判）。
- **只记"播出去的部分"**：服务器知道每句已下发多少音频，按"已下发时长 ÷ 该句总时长"估算播到哪个字，被打断时把截断后的文字写进对话（旧版就是这么做的，角色下一句才不会接着自己没说完的话）。
- **连说合并**：用户一口气说两句（两次最终结果间隔很短）时合成一轮回复，而不是回两次。现在的代码每个最终句都单独排队回复。

**④ 合成前清洗（ai-runtime，AI）**
统一一个清洗函数，所有送合成的文字都过一遍（语音消息也复用）：去掉半角/全角括号内容、`*动作*`、`【】`、表情符号与颜文字、网址、Markdown 符号、`<think>` 推理块（流式时要能处理标签被切成两半）；"～"改句号；数字、时间、金额交给供应商的文本规范化，不自己转。现在代码只去掉 20 字以内的圆括号。
另外借鉴 papercup 的"语气中间写法"：提示词允许角色用极少量固定标记（如"（笑）"），清洗时按供应商能力翻译成停顿或删除，**不让角色自由写动作描写**。

**⑤ 自然挂断（ai-runtime，AI）**
用户说"拜拜/晚安/先挂了/去忙了"（排除"别挂""不许挂"）→ 角色正常道别 → 服务器按已下发音频时长估算播完时刻 + 宽限约 3 秒 → 发 `end(completed)`。用户在宽限期里又开口则取消挂断。契约已有 `completed`，**不改接口**。

### 3.3 其他 AI 侧调整

- **通话专用模型**：通话默认用后台指定的"快速、非思考"模型（新增模型角色或在网关里给通话请求关闭思考），不跟随用户在私聊选的大模型——慢模型首字要 1～3 秒，通话会明显卡。是否允许用户为通话单独选模型，交产品负责人定。
- **精简人设**：通话请求现在每轮都塞最长 2 万字的角色卡。改为通话开始时生成/读取一份精简版（说话风格 + 关键设定，约 1500 字），并把稳定部分放在请求最前面吃前缀缓存（同 `03-aiyu-learnings-ai.md` 的上下文顺序建议）。
- **秒开场**：接通后先播一句预先合成好的短招呼（按角色音色缓存，例如"喂？"），同时让模型生成真正的开场白，避免接通后 2 秒静默。
- **合成熔断与备用**：同一供应商连续 3 次合成失败 → 切备用供应商；都失败时角色这一轮不出声，本轮文字写进通话记录。
- **逐轮记录**：每轮记录 断句完成、听写出字、模型首字、第一小句、合成首包、首包下发 六个时刻和各自费用（网关已记模型/token/耗时/费用，这里补"一轮"的串联编号），写入日志，后台可看平均和九成分位。
- **评测**：改通话提示词前后跑评测集。新增"通话口语"一组用例（不出括号动作、每次 1～3 句、开场先开口、道别识别、打断后不重复已说内容），用文字模拟即可，不花语音钱。

### 3.4 选哪家听写 / 合成

**以下价格全部来自记忆和旧资料，未逐一核实；采购前由 AI 负责人对照官网价格页更新 `model-catalog.md` 4.3。**

|---|---|---|---|---|---|
| **A 阿里云百炼（推荐主用）** | Paraformer 实时 v2 / Fun-ASR 实时（流式，自带断句标点） | CosyVoice v3（Flash / Plus，支持 WebSocket 流式） | 听写约 0.014～0.02 元/分钟；合成 Flash 约 1 元/万字、Plus 约 2 元/万字 | 旧版已跑通同一套；一个账号同时有文字模型；香港访问延迟低；系统音色多 | 实名认证、需充值；音色克隆另计费 |

推荐：**C 先开（当天打通）→ A 做主用（流式，达到延迟目标）→ B 做合成备用**。MiniMax、讯飞也可用，但前者没有听写、后者价格偏高，暂不列入。

**为什么不用"端到端实时语音大模型"**（百炼、豆包都有：直接语音进、语音出，延迟最低）：它跳过了新版的人设、记忆、硬性边界检查（`outputAllowed`）、安全关怀和逐项计费，等于另起一个大脑，角色会"打电话时像换了个人"。等级联方案稳定后，可以作为"实验性低延迟模式"单独评估。

**为什么暂不做服务器本地听写**（papercup 的做法）：省钱明显，但香港服务器只有 4 核，要和聊天、数据库共用；而且要引入 Python 或 ONNX 运行时，模型商用许可需核实。等通话量上来、听写费用成为大头时再评估。

**音色**：只用供应商**系统音色**。**不克隆真人明星的声音**（涉及《民法典》声音权保护，旧版有 753 条角色音色绑定、用过克隆，不迁移克隆音色）。原创角色可从系统音色里选。

### 3.5 延迟目标与预算

目标：**首声延迟中位数 ≤ 1.8 秒，九成轮次 ≤ 2.8 秒**（手机正常 4G/Wi-Fi）。

| 阶段 | 现在（估算） | 改后目标 | 靠什么 |
|---|---|---|---|
| 断句判定 | 0.7 秒 + 固定阈值误差 | 0.5～0.7 秒 | 流式听写的语义断句 |
| 听写出最终结果 | 整段上传 0.5～1.5 秒 | 0.1～0.2 秒 | 流式，说的同时已在识别 |
| 模型首字 | 不适用（等全文 1～3 秒） | 0.3～0.6 秒 | 快速非思考模型、精简人设、前缀缓存 |
| 凑够第一小句 | — | 0.1～0.2 秒 | 小句切分 |
| 合成首包 | 0.3～0.6 秒 | 0.15～0.3 秒 | 流式合成、连接复用 |
| 网络与播放缓冲 | 0.1～0.3 秒 | 0.1～0.2 秒 | 客户端播放缓冲压到约 100ms |
| **合计** | **约 3.5～6 秒** | **约 1.3～2.2 秒** | |

|---|---|---|

### 3.7 HTTPS：正面处理

浏览器只在 HTTPS 页面给麦克风权限，现在香港服务器是 `http://103.231.58.124`。

| 做法 | 结果 | 推荐度 |
|---|---|---|
| **买域名 + HTTPS**（推荐） | 网页、PWA、推送、麦克风全部恢复；安卓正式包也能构建。香港服务器无需备案。域名约几十元/年，证书由 Caddy 自动申请免费证书 | **首选，越早越好** |

| 电脑浏览器临时开关（Chrome 把某个 HTTP 地址视为安全） | 只对开发者自己的电脑有效 | 只给开发调试 |
| 自签证书 | 浏览器报警告、手机安装证书麻烦、PWA 不认 | 不推荐 |

## 4. 改造后的通话链路

```
手机（网页 / 安卓）
  录音（回声消除、降噪）→ 16k PCM ──WebSocket──┐
  两段式打断：先压音量，确认后发 barge_in       │
  播放：按句排队，打断即清空                    │
                                               ▼
calls 模块（不变）：鉴权、状态、时长、余额兜底、断线重连
                                               │
ai-runtime 通话会话
  ├ 流式听写（百炼）→ 中间结果（=用户开口）/ 最终句子（合并连说）
  ├ 快速模型流式生成（精简人设 + 记忆 + 最近聊天）
  ├ 清洗 → 小句切分 → 逐句流式合成（百炼，失败切备用）
  ├ 打断：停合成、只记已播文字
  ├ 告别词 → 道别 → 播完 + 宽限 → end(completed)
  └ 逐轮记录六个时刻 + 费用；结束时摘要入记忆
```
