## 0. 结论（先看这 7 条）

1. **视觉全面换回旧版**：微信绿 `#07C160`、页面灰 `#EDEDED`、白卡片、带透明度的黑字（日间 90% 黑 / 夜间 80% 白）、行高 56、分组间隔 8、头像小圆角 4。新版现在的粉色 / 翡翠色调色板、Phosphor 图标、圆润卡片风格**全部退场**。
2. **布局和组件按旧版代码 1:1 还原**：本文第 2 节是旧版令牌，第 3 节是 16 个通用组件，第 4 节逐页给出尺寸、颜色、字号、间距、图标文件名和交互。网页（React）和安卓（Compose）都照这一份做，两端视觉一致。
3. **导航树用新版的**（`02a`）：旧版有而新版不要的入口（视频号、直播、扫一扫、企业微信、小店与卡包、会员、微信接入等）不还原；新版有而旧版没有的入口（小程序、情景预设、积分、聊天模型等）按第 5 节「旧版风格」补。
4. **会话列表下拉出小程序面板**旧版没有，按微信手势和动画设计（第 4.3 节），只用 `transform` / `opacity`，不做模糊。
5. **钱改成积分**：1 元 = 100 积分；只显示每条消息消耗多少积分，不分输入 / 输出（第 6 节）。钱包、充值、明细、用量、价目表按旧版「会员 / 购买页」的样子重做。
6. **素材已整理好**：旧版 99 个素材 + 安卓启动图标 / 网页图标 + 新导出的 9 个 SVG（旧版用代码画的彩色线框图标，原来没有文件）共 110 个，复制在 `design-assets/old-ui/`，第 7 节给出每个文件的源路径和网页 / 安卓目标路径。
7. **后台「模型管理」**（第 9 节）：sub2api 不再部署，微伴自己的后台合并出一个「模型管理」菜单（概览 · 上游账号 · 模型 · 调用记录），布局参考 sub2api 的上游账号管理和用量看板。

## 1. 怎么读本文

- **单位**：dp 是安卓的「与密度无关的像素」，网页里直接写成同样数值的 CSS `px`（例如 56dp = 56px）；字号 sp 同理（17sp = 17px）。旧版 Flutter 的逻辑像素与两者一一对应。
- **细线（hairline）**：旧版凡写「1 物理像素」的线，网页用 `0.5px`（设备像素比 ≥ 2 时）或 `1px`（像素比 1 时）；安卓用 `1 / density` dp。写「0.5」的线同样处理。
- **颜色写法**：`#RRGGBB`；带透明度的写成 `rgba()`。旧版 Flutter 的 `0xAARRGGBB` 已换算。
- **日 / 夜**：每个颜色都给日间和夜间两个值，用「/」隔开，左日右夜。
- **出处**：`〔文件:行〕` 指旧版 `lib/` 下的文件，方便开发对照原代码。
- **图标**：写文件名（如 `chevron_right.svg`），完整路径见第 7 节。`着色` 表示图标按单色使用、颜色由代码指定（网页 `mask` / `currentColor`，安卓 `tint`）；`原色` 表示彩色图，不能着色。

旧版没有这个功能。手势与动画按微信，视觉用旧版令牌。实现只改 `transform` / `opacity`，满足 60 帧。

**手势阶段**

| 阶段 | 条件 | 表现 |
|---|---|---|
| 0 静止 | 列表不在最顶端 | 正常滚动，下拉不触发面板 |
| 1 跟手 | 列表已在顶端，继续下拉 | 顶栏以下整块（搜索条 + 列表）跟手 `translateY`，阻尼系数 0.5（手指移动 100，内容移动 50）。安卓关闭系统的越界拉伸效果，网页设 `overscroll-behavior-y: contain` |
| 2 提示点 | 手指下移 ≥ 24 | 露出的空隙中央出现 **3 个小圆点**（直径 6，`text.placeholder`），间距从 0 线性张开到 12（到阈值时张满），透明度 0→1 |
| 3 到阈值 | 手指下移 ≥ 80 | 三个点变成实心 `text.secondary`；安卓给一次轻触感反馈（`CLOCK_TICK`），网页支持时 `navigator.vibrate(10)` |
| 4a 松手（未到阈值） | < 80 | 内容 200ms 弹回原位，`cubic-bezier(0.2,0.8,0.2,1)` |
| 4b 松手（已到阈值） | ≥ 80 | 打开面板（见下） |

3. 底部标签栏同时 `translateY(100%)` 隐藏（面板是全屏的）；

## 5. 新版新增页面：按旧版风格的做法

总原则：**新增的页面也只用第 3 节的组件**——灰底、白卡分组、MenuRow、GroupHeader、旧版按钮和弹层。新版各页设计说明（`docs/design/pages/*.md`）里的**内容、状态、流程照旧有效**，只把视觉换成旧版：

| 新版写法 | 换成旧版 |
|---|---|
| 圆角卡片（radius.lg / xl）、卡片间留白 12–16 | 通栏白卡分组，组间 8 灰缝 |
| `bg.surface` / `bg.canvas` / 粉色或翡翠色调 | `bg.card` / `bg.page`；强调色一律 `brand` 微信绿 |
| Phosphor 图标 | 优先第 7 节旧版素材；没有的按「24 网格、线宽 1.7、圆头圆角、单色」补画 |
| 胶囊标签（Tag） | 「@我」式小标签（圆角 3、11 字）或右侧值文字 |
| 主按钮 lg | 3.17 主按钮（高 48、圆角 10） |
| 底部弹层（Sheet）带拖拽把手 | 白底、顶部圆角 12、无把手；标题栏高 56：左「取消」/ 中标题 17 / 500 / 右操作 |

## 6. 金额展示改积分

### 6.1 规则

| 项 | 规则 |
|---|---|
| 换算 | **1 元 = 100 积分**。服务器仍按元记账（`docs/architecture/billing.md` 不变），界面显示时 × 100 |
| 小数 | 最多 2 位，去掉末尾的 0（1 积分 = 0.01 元；服务器金额精度 0.0001 元 = 0.01 积分，不会丢精度）。例：¥0.0089 → 0.89 积分；¥12.34 → 1,234 积分；¥0.00004 → 「< 0.01」积分 |
| 千位分隔 | 整数部分 ≥ 1,000 时加逗号：1,234.5 |
| 单位 | 数字后空一格写「积分」；列表里单位可省略，标题行里写一次「单位：积分」 |
| 显示粒度 | **只显示每条消息消耗多少积分**，不区分输入、输出，不显示 token 数 |
| 正负 | 消耗写「−0.89」（全角减号 `−`，`text.primary`）；增加写「+1,000」（`brand`） |
| 不出现的地方 | 聊天、通话、朋友圈里不出现积分数（沿用 billing.md 原则 4）；唯一例外是积分不足横条和通话页剩余额度说明，它们不写具体数字 |
| 数字字体 | 网页 MiSans 数字（等宽数字 `font-variant-numeric: tabular-nums`），安卓系统字体 + `fontFeatureSettings = "tnum"` |

## 9. 管理后台「模型管理」页（微伴自己的后台，参考 sub2api 布局）

> 总经理 10-13 新裁定：**sub2api 不再部署使用**，只借鉴它后台里「上游账号管理」和「用量看板」的做法。所以上游密钥、多账号、故障切换、用量统计都在**微伴自己的后台**里做，`05-sub2api-integration.md` 里「上游全部在 sub2api 后台配」的方案作废（见 10.1 第 10 条）。
> 本节只定界面。需要的接口（上游账号增删改、连通测试、按账号统计用量）由架构 / 后端评估后写进契约；接口没到位的区块先显示空状态。

### 9.1 结论

- 把现在后台分散的「上游」「模型目录」「价目表」「用量与费用」里和模型有关的部分，收成**一个菜单「模型管理」**，页内 4 个标签：**概览 · 上游账号 · 模型 · 调用记录**。
- **概览**学 sub2api 仪表盘：先一排汇总数字，再趋势图和分布，最后排行——一眼看出今天花了多少、哪个上游 / 模型在出问题。
- **上游账号**学 sub2api 账号管理：一张表管理所有上游账号（同一个供应商可以有多个账号），每行能看到状态、今日用量、最近错误，能一键测试、停用、编辑；同一模型多个账号时按优先级和权重自动切换。
- **模型**取代难懂的「模型目录」：一页向导「添加模型」——选上游账号 → 从该账号拉取可用模型列表下拉选 → 填显示名、是否识图、默认给谁用、售价（每百万 token 元价，保存时自动折算出「约每条 X 积分」）。
- **调用记录**学 sub2api 使用记录：逐条调用，可按用户、角色、模型、上游账号、状态筛选；每条同时显示**上游成本（元）**和**用户扣除（积分）**。
- 视觉：后台是电脑网页（最小宽 1200），沿用后台现有框架和组件（`components.md` 第 20 节：AdminShell、FilterPanel、StatTile、DataTable、TrendChart、RankList、DetailDrawer），**颜色和圆角换旧版令牌**：内容区底 `bg.page`、卡片 `bg.card` 圆角 8、强调色 `brand` 微信绿、危险 `danger`、表格分割线 `line`、字号正文 14 / 表头 13 `text.secondary`。
