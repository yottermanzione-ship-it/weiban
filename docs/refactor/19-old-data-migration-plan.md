## 2. 新旧格式怎么换（核心）

| 旧 | 新 | 换法 |
|---|---|---|
| `app_users` 账号 | identity 用户 | 用户名、昵称、头像、性别、地区、生日、签名照搬；旧 `uid` 保留为「旧版编号」。**密码**：新版用 argon2id，旧版是 bcrypt——导入时原样保存旧 bcrypt 哈希，用户第一次登录时用 bcrypt 校验，通过后立即改存 argon2id（用户无感，不用重设密码）。恢复码同理。 |
| 会员等级 | PRO+ | 见 §4 ★1 |
| `user_friends` | 通讯录 / 陪伴关系 | 旧版按角色**名字**关联，先建「旧名字 → 新角色 ID」对照表，再导入；对不上的列进报告人工处理。添加时间 = 认识第 1 天。 |
| `characters_v2` 等 | 角色卡（ADR-0009） | 写一个转换器：核心人设 → persona，说话风格 → speech，知识 / 世界书 → knowledge.entries，示例对话 → examples，开场白、身份边界、群聊风格、朋友圈风格各自对应字段。先转成草稿，后台逐个上架检查后再发布。**不迁移任何克隆声音样本**（Claude 保留例外），音色改从音色库重选。 |
| `persona_customizations` | 用户补充设定 | 旧版是「补丁」，转换成新版补充设定文本，保留版本号。 |
| `chat_history` | 私聊消息 | 按用户 × 角色建会话，按时间顺序导入；**导入时用该用户的密钥加密**（新版聊天全部加密存储，ADR-0027）。文字、引用照搬；表情按表情库对照；图片、语音的文件从旧服务器拷贝到新媒体存储（已过期 / 丢失的标为「已失效」）；通话记录转为通话卡片；已删除（`deleted_at`）的不导；系统消息只保留有意义的（如「加为好友」）。 |
| 群聊三张表 | 群聊 | 群、成员、消息同上方式导入；群头像拷贝。 |
| `user_memories` | 记忆库 | 类型、内容、可信度、是否启用照搬；被替代的旧记忆（`supersedes_id`）只导最新版。 |
| `conversation_summaries` | 聊天摘要 | 作为「月摘要」导入，让角色一上来就记得以前的事。 |
| `relationship_states` | 熟悉度 + 关系 | 旧分数按比例换算到新版 0～700 点（换算表导入前给总经理看）；恋人称呼 → 专属称呼；恋爱暂停状态照搬。 |
| `user_stickers` | 我的表情 | 图片拷贝到私有媒体。 |
| 外部渠道绑定 | 插件 | 新版接入尚未完成，**不迁移**，上线后用户重新绑定。 |
| 订单、用量、设备、推送订阅、客服、风控、调度日志 | — | 不迁移（订单留档备查）。设备与推送要用户重新登录。 |
| 旧朋友圈 | — | 见 §4 ★3 |

## 3. 怎么做（步骤）

1. **导出（只读）**：通过 SSH 用 `sqlite3 -readonly` 把数据流式导出到本机加密目录，不在旧服务器上写任何文件；媒体文件同样只读拷贝。全程不改旧服务器（遵守「旧服务器只读」约定）。
2. **转换（离线）**：在仓库里写一个转换工具（`tools/legacy-import`），把旧数据转成「按用户分包」的导入文件，先出一份**演练报告**：每类导入多少、哪些角色名对不上、哪些媒体丢失、熟悉度换算结果。
3. **导入（服务器端命令）**：在新版容器里跑导入命令，**走新版的正规写入逻辑**（加密、事件、计数都对），每个用户一个事务，按旧 ID 去重——可以反复跑，重跑只补新增的部分。
4. **演练**：先导到香港的临时验证库（DR-001），抽几个真实账号登录检查聊天记录、记忆、好感、群聊是否正常；有问题改转换器再来。
5. **正式切换**：
   - 时机：新版做完、香港服务器格式化重装干净之后（与总经理「做完后重装」的计划合并成一次）。
   - 先全量导入一次；切换当天通知用户，旧版进入「只读 / 维护」（**需要总经理同意才能动旧服务器**），再跑一次补齐切换前的新消息；然后把用户引导到新版网址，用原账号密码登录。
6. **收尾**：导出的本机副本在确认无误后删除；旧服务器保留一段时间作备份，之后再决定是否关停。

## 4. 需要总经理拍板（★ 为推荐）

1. **还没到期的付费会员怎么办**（plus 13 人、pro 35 人）：★ 转为 PRO+，到期日沿用，不送开通积分。这不是额外补偿，只是把用户已经付过钱的时间兑现。
2. **迁移范围**：★ 全部 542 个账号都迁（数据量不大），而不是只迁活跃用户。
3. **旧朋友圈、通话文字记录、客服记录**：★ 不迁。新版朋友圈逻辑不同（公共 / 私人），旧内容放进去会乱。
4. **老用户的积分**：★ 和新用户一样按注册赠送处理（数额同 16 号 §7，待定）。
5. **告知用户**：★ 切换前在旧版发公告，说明数据会搬到新版、加密保存、外部渠道需要重新绑定。

## 5. 风险

- **角色对不上**：旧版用名字关联角色，同名、改名、自定义角色要靠对照表和人工核对，这是最费工的部分。
- **媒体文件**：语音 1.27 万条、图片 1684 张，部分可能已过期，需要先盘点旧服务器上的实际文件。
- **加密导入耗时**：28 万条消息逐条加密写入，预计要几十分钟，正式切换时要留出时间窗口。
- **隐私**：这些是用户私密聊天，导出副本必须加密保存、用完即删，不能出现在仓库或日志里。
