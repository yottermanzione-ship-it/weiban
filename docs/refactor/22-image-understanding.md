术语：

- **一步看图**：把图片原图直接塞进「角色回复」那次请求，模型边看图边按人设回话。
- **两步看图**：先让模型把图写成一段文字描述，再把描述交给角色回复。
- **多模态模型**：能同时看文字和图片的模型。

## 0. 结论先说

1. **新版最大的问题不是「看不懂」，而是「看完就忘」**：用户发的图只在**当轮**被描述一次，下一轮起就变成「[对方之前发过一张图片]」；群聊、朋友圈评论里**根本看不到图**；记忆也不会记住图里的事（比如你发过自家猫的照片）。旧版 8 月起就做了「描述回填」：图片描述存进聊天记录，后面每一轮都能看懂。**第一优先：把描述存下来，所有场景共用。**
2. **新版比旧版好的地方要保留**：认人用「封闭名单」（只能认角色本人和有公开关系的人，宁可不认），比旧版「先判断像不像某某」更安全；看不到图时明确告诉角色「别猜」。
3. **旧版值得学的三点**：① 针对角色定制看图提示（「用户常发这位公众人物的照片 / 路透 / 现场图，先判断是剧照、路透、自拍、周边还是无关风景」）；② 表情包 / 梗图单独处理（「这是表情动作，不是要你分析的照片」）；③ 一步看图（角色直接看原图回话，更自然、少等一次）。
4. **推荐做法**：**默认「两步看图 + 描述存档」**（描述本来就要存给后面用，顺便给当轮回复，花费最低）；后台按模型提供「一步看图」开关，给效果好的模型打开（多花约一张图的钱，回复更贴画面）。
5. **另外修两处小问题**：角色卡里早就有的「认人线索」（本人公开形象、外貌特征）运行时没用上；表情包识别的开通判断依赖已删除的「图片识别」场景，需要确认是否还有效。
6. **工作量**约 **4 个工作日**，**1 个迁移**（图片描述存档表），不改用户端契约。

## 4. 改进方案

### 4.1 描述存档：一次看懂，到处可用（最优先）

1. **新表** `media.image_descriptions`（1 个迁移）：图片 ID、所有者、范围（普通 / 私密）、加密的描述 JSON（描述、类型、图中文字、认出的人）、用的模型、生成时间。和聊天记录一样加密；用户删除图片 / 消息 / 账号时一并删除。
2. **什么时候写**：用户发图后，回复流程里的那次「看图」结果直接存档；不在回复流程里的图（群聊、朋友圈、转发记录里的图）在**第一次被某个场景读到时**看一次并存档。
3. **谁来读**：
   - 私聊历史：图片显示为「[对方发过一张图片：描述]」，不再是「之前发过一张图片」；
   - 群聊：同样显示描述；
   - 角色评论用户朋友圈：附上每张图的描述；
   - 记忆抽取：把图片描述当作一条消息参与（「用户发了自家橘猫的照片，名叫团子」能被记住）；
   - 翻聊天记录、聊天搜索：可以搜到图片描述。
4. **私密模式**：私密模式里发的图由私密模式模型描述，存档范围 = 私密，只在私密模式里被读到（与 20 号文档 §2.4 同一规则）。
5. **认人名单变化时**：存档里只存「认出的人」，回复时仍按**当时的**名单过滤（名单收紧后不会多认）。

### 4.2 看图提示词升级（学旧版 + 用上角色卡）

把现在的「图片描述服务」提示词改为分角色类型：

- **公众人物 / 真人角色**：加一句旧版的经验——「用户在和『某某』聊天，常发这位本人的照片、剧照、路透、现场图、杂志、周边。先判断图的来源类型，再描述」；并把角色卡的 `appearanceCues`（外貌特征）、`selfPublicImages`（公开形象：杂志、海报、剧照的标题与视觉线索）作为认人参考。**名单规则不变**：只能认名单里的人，不确定就不认。`selfEnabled = false` 的角色（如原创角色「不做识图认人」）不认人。
- **原创 / 虚构角色**：通用描述，强调「画面细节、情绪氛围、可以聊的点」。
- **图片类型细分**：自拍 / 生活照、食物、宠物、风景、截图（聊天截图要逐字读出关键文字并说明「这是用户和别人的聊天截图」）、表情包 / 梗图、证件 / 文档、角色本人相关（剧照 / 路透 / 杂志 / 周边）。
- **描述长度**：从 150 字放宽到 **250 字**，多写「可以接话的细节」（旧版把描述截到 500 字，效果明显更好）。
- **按类型给回复提示**（放在动态结尾）：
  - 表情包 / 梗图 →「这是表情动作，不是要你分析的照片，按它表达的情绪回应」（学旧版）；
  - 聊天截图 →「这是用户转述别人的话，不是用户本人说的」；
  - 用户自拍 →「可以夸、可以关心，不评论身材，不性化」；
  - 图里有儿童 →「不作任何与外貌有关的亲密评价」。

### 4.3 一步看图：做成按模型的开关

| 方式 | 回复效果 | 等待 | 花费（每张图） | 描述存档 |
|---|---|---|---|---|
| 两步（推荐默认） | 好（描述放宽到 250 字后接近一步） | 多等一次（约 2～4 秒） | 1 份图片的钱 + 很短的描述输出 | 顺带就有 |
| 一步 | 最好（直接看原图，能接细节） | 少等一次 | **约 2 份图片的钱**（回复看一次，后台写存档再看一次） | 需要后台补一次 |

推荐：**默认两步**；后台「模型管理」里给模型加「看图方式：先描述 / 直接看」，给效果好的高级模型打开「直接看」。直接看时：图片作为最后一条用户消息的图片块发给回复模型（只在当轮，不进稳定开头，不影响缓存）；回复后后台再写存档。真人角色需要「先认出本人才联网补充」时，仍先走一次分析（为了拿到搜索依据）。

不学旧版的「多条线路并行挑最好」：同一张图花两三份钱，成本不划算。

### 4.4 表情包

1. 用户自定义表情：按**图片内容的指纹**缓存含义（同一个熊猫头被一万个用户发，只看一次），平台统一存档。
2. 用户直接当图片发的梗图（不是从表情面板发的）：看图类型判断为「表情包 / 梗图」时，按表情包的方式交给角色（4.2）。
3. 开通判断改为「文本聊天模型能看图」（不再依赖已删除的「图片识别」场景），实施时先验证现状。

### 4.5 一次发多张

一次连发多张（≤4 张）合并成**一次**看图调用（共用一份提示词），每张输出一段描述；超过 4 张的只描述前 4 张，其余写「另外还有 N 张图」。转发记录里的图沿用「最多看 3 张」的上限。

### 4.6 兜底与安全（保持）

- 模型不能看图 / 调用失败 →「你看不到图片内容，不要猜，可以自然地问问是什么」（现有）；后台运行提醒记一次「缺识图能力」。
- 普通模式下的裸露 / 色情图片：描述只写「画面含不适合日常聊天的内容」，角色按关怀口吻岔开；不存细节。
- 经期报告、病历等健康类图片：描述可以给当轮回复用，但**不进记忆**（沿用健康隐私规则）。
- 回复里出现名单外真人姓名照旧拦截重写。

## 5. 花费影响

- 描述存档：**不增加**调用（当轮本来就要看一次）；群聊 / 朋友圈里的图是**新增**的看图调用（以前根本不看），每张约一份图片的钱。按常见多模态模型，一张手机照片约 1,000～1,500 token 输入，DeepSeek 级价格下约 **0.2～0.3 积分 / 张**。
- 描述放宽到 250 字：每张多约 70 token 输出，可忽略。
- 表情包按指纹缓存：常用表情只付一次，**省钱**。
- 一步看图（仅打开开关的模型）：每张多约一份图片的钱。

## 7. 需要总经理拍板的点（含推荐）

1. **看图方式默认用「两步（先描述再回复）」，高级模型可在后台单独开「直接看」。** **推荐：同意。** 描述反正要存给后面几轮、群聊和记忆用，两步最省钱；「直接看」留给您想要更好效果的模型。
2. **群聊和朋友圈评论也开始看图**（每张约 0.2～0.3 积分，按用户扣，和私聊看图一样）。**推荐：同意。** 否则群里发图没人接、评论你的照片只能说空话。
3. **图片里的内容进记忆**（如宠物名字、家人照片里的信息；健康类图片除外）。**推荐：同意**，用户可以在记忆页删除。
