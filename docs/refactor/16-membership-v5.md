## 1. 核心原则（总经理原话归纳）

1. **所有模型消耗都扣积分，由用户支付**。不再有「会员默认模型无限量」。
2. 后台由总经理**逐个模型登记价格**；用户只看到**积分消耗倍率**和大约每条多少积分。
3. **只保留一个会员档：PRO+**。不为老业务做善后、补偿或迁移方案（新方案，从零开始）。
4. 会员给的是两样东西：**没有额外成本的服务**（权限、容量、身份类）+ **折扣积分**（20 元买 30 元积分）。

## 2. 计价方式

### 2.1 后台登记（每个模型）

| 字段 | 含义 | 来源 |
|---|---|---|
| 售价：输入 / 输出 / 缓存命中（元/百万 token） | 用户实际按这个扣积分（1 元 = 100 积分） | 表格「官方输入/输出」列，即按官方价卖 |
| 成本：输入 / 输出（元/百万 token） | 只给后台对账、算毛利，用户看不到 | 表格「中转输入/输出」列 |
| 展示倍率 | 给用户看的「×1.0」「×2.0」 | 表格「官方倍率」，基准 GPT-6 Sol = 1.00× |
| 是否上架、适用场景 | 聊天 / 决策 / 语音 / 图片等 | 后台勾选 |

- **扣费按实际 token 用量**（输入、输出、缓存分开算），**不按倍率扣**——倍率只是展示，和表格备注一致。
- 选模型页同时显示「×倍率」和「约每条 X 积分」（按最近 7 天该模型的平均消耗估算）。

### 2.2 每条消息大概多少积分（按售价估算）

假设一条普通回复：发给模型约 1 万 token（其中八成命中缓存）、回复约 200 token。

| 模型（例） | 展示倍率 | 约每条积分 | 老 Pro 重度用户一个月（约 940 条） |
|---|---|---|---|
| deepseek-v4.1-flash | ×0.13 | 约 0.8 | 约 750 积分 |
| gemini-3.8-flash | ×0.38 | 约 2 | 约 2000 积分 |
| claude-sonnet-5-5 / gpt-6.1-sol | ×1.0 | 约 5.5 | 约 5300 积分 |
| claude-opus-5-5 | ×2.0 | 约 11 | 约 1.1 万积分 |
| claude-fable-5 / gpt-6-astra | ×5.0 | 约 28 | 约 2.6 万积分 |

结论：**3000 积分 ≈ 重度用户用便宜模型（如 gemini-3.8-flash）聊满一个月**，用中档模型约半个月。

### 2.3 平台赚不赚钱（成本按表格中转价）

- 用户把 3000 积分（标价 30 元）全花掉，平台实际付给上游：用 gemini-3.8-flash 约 3 元；用 Claude/GPT 低价线路约 1～3 元；最贵的是 gemini-4-argon（约 10.6 元）和 kimi-k3（约 9.3 元），因为这两家中转价是官方价的三成多。
- 所以月费 20 元（首月 12.9 元）**在最坏情况下也不亏**。
- 风险：表格里不少线路标着「超低价 / 不过检」、`needs_validation: true`，可能不是原版模型或不稳定。**上架前每条线路都要先试聊、跑评测**；中转价一旦上涨，毛利会变薄，用后台对账页盯。

## 4. 朋友圈与角色生态

- **公共朋友圈（旧版那种，所有人看到同一份）保留**：只属于官方角色，所有用户都能看。每个角色每天生成一次、所有人共用，成本极低，**由平台承担**。
- **自定义人设的角色（用户自己建的）没有朋友圈**，必须开启角色生态才会发（总经理 10-19）。
- **私人朋友圈**：属于角色生态，**PRO+ 专属**，内容和你们的聊天相关，生成时扣**你的**积分。官方角色开生态后，你看到的是「公共 + 写给你的私人」两种混排。
- 角色生态：PRO+ 专属 + 扣积分；形态按 10-18 构想（定时醒来 → 看上下文 → 自己挑动作 → 执行）。**开关、黏人程度、作息、动作清单、碎碎念**见 `17-ecology-settings.md`。
- 粗估：一次「想一想」用便宜决策模型约 1 积分，真发一条朋友圈约 2～5 积分；一个角色一天想 6 次，约 10～20 积分/天，即每个角色每月约 300～600 积分。

## 5. 记忆：免费与 PRO+ 的区别（不用百万上下文）

### 5.1 为什么不用百万上下文

每条回复都要把这一百万 token 发给模型。按 gemini-3.8-flash 售价一条约 500 积分（5 元），命中缓存也要几十积分；而且上下文越长模型越容易记混。总经理 10-19 同意不做。

### 5.2 现在的记忆体系（已实现，见 09 号 §4、§8）

每次回复发给模型的「记忆」由五层组成：

1. **最近聊天原文**：最近 12～30 轮原话（约 1 万 token 以内）。
2. **常驻记忆**：最重要的事实（名字、生日、重要约定），最多 8 条，每次都带。
3. **聊天摘要**：更早的聊天被整理成摘要（每段 ≤250 字），再往前有日摘要、月摘要。
4. **检索记忆**：每次按你这句话，从记忆库里找最相关的 8 条（≤700 字）。
5. **记忆库**：聊天中每 10 条自动抽取一次「关于你的事」存起来，可在记忆页查看和修改。

### 5.3 免费用户的限制（推荐，后台可调）

原则：**不降低当下聊天的质量**（最近原文两档一样），限制的是「能记多久、记多少」。

| 层 | 免费 | PRO+ |
|---|---|---|
| 最近聊天原文 | 12～30 轮 | 同左 |
| 常驻记忆 | 8 条 | 16 条 |
| 记忆库容量（每个角色） | 最多 100 条，满了先淘汰最旧、最不重要的 | 不限 |
| 检索范围 | 只找最近 **90 天**的记忆 | 从认识第一天起的全部记忆 |
| 每次检索条数 | 4 条 | 8 条 |
| 摘要保留 | 日摘要 30 天，月摘要 3 个月 | 全部保留，并多一层「年度回忆」 |
| 往事片段 | 无 | 检索时额外带最多 3 段相关的旧聊天原话（新做，见 5.5） |

- 用户看到的说法：免费「TA 记得最近三个月的事」，PRO+「从认识第一天起的事 TA 都记得」。
- PRO+ 每条多带约 500～1000 token，都在结尾、缓存不上；用 gemini-3.8-flash 约**每条多 0.5 积分**。
- 免费用户的超出部分不删数据：只是「暂时想不起来」，开通 PRO+ 立即恢复。（淘汰的 100 条之外同理：标记为不参与检索，而不是物理删除；用户主动删除仍立即删除。）

### 5.4 长上下文模式（PRO+ 可选，已定）

某个角色可以单独打开：最近聊天原文从约 1 万 token 加大到约 10 万 token。打开时明确提示「每条大约 X 积分（是平时的 N 倍）」。

### 5.5 需要架构确认的一点

「往事片段」要检索旧聊天原文，但聊天内容是加密存的（ADR-0027），不能直接做全文向量库。实施前由架构负责人选方案（例如抽取记忆时顺带存一段加密的「原话摘录」并向量化），不在本文定。
