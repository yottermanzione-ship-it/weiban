# 25 用户端 UI 质感整体优化：现状核实与建议（总负责人，2026-10-26）

> 输入：Codex 图册 `C:\wb-dev\logs\uiux-full-20261026\用户端UI分类图册-重做版.html`（48 组流程、103 张目标界面图、8 条视觉结论）；总负责人抽看截图与源码复核；总经理整理的「大厂交互细节」要点。本文只给现状与建议，未改代码。

## 1. 结论

1. **Codex 图册的 8 条结论我抽查后都成立**，根子不是某个页面丑，而是**同一类交互没有统一的组件和使用规则**：确认框有 4 种做法、删除按钮红 / 蓝 / 黑三种颜色、单选有 4 套、单字段编辑有 3 套、输入框有 6 种样子。只改全局 CSS 修不好，必须先定「组件 + 规则」，再逐页换上。
2. **角色广场 / 自建角色确实是全站最差的一块**（下文 §3）：创建页是一张「网页表单」（原生日期框、原生下拉、灰底大单选卡、带边框文本框、必填星号单独占一行），作品详情是一串「灰色小字标签 + 黑色大字」的字段堆叠，没有层次。
3. **缺一个统一的「人设卡」展示组件**：同一个角色的人设在广场详情、角色资料、补充设定、后台预览里各自拼字段，没有一处好看。建议做一个组件全站复用（§4）。
4. 底层样式也散：13 个样式文件约 1.07 万行，圆角有 2/3/4/5/6/8/9/10px 八种、硬边框 20 处。要先收成一套设计令牌（颜色、圆角、间距、字号）。

## 2. 先「叫对名字」：微伴的浮层与控件清单（统一规则）

| 名称 | 用在哪 | 微伴规则 |
|---|---|---|
| **Toast** 轻提示 | 操作后短反馈（已保存、已复制） | 居中黑底小块，1.5 秒自动消失，不挡操作 |
| **Snackbar** 底部提示条 | 可撤销的轻操作（不显示该聊天、取消收藏） | 底部条带「撤销」，5 秒消失；用它代替这类操作的二次确认 |
| **Inline Alert** 行内提示 | 表单校验 | 输入框下红字，改对即消失；不弹窗 |
| **Action Sheet** 底部动作面板 | 一组操作（更多、长按菜单的移动端版、头像来源） | 微信式：白底通栏按钮、无边框、底部独立「取消」；危险操作红字 |
| **Choice Sheet** 底部单选 | 设置里选一个值（深色模式、贴合度、提示音） | 同 Action Sheet 外观，选中项右侧固定列对号（G2 已做对号对齐） |
| **Bottom Sheet** 半页面板 | 评论区、转发选人、表情面板 | 可拖拽、分档吸附（半屏 / 全屏），点蒙层不关闭已填写内容 |
| **Dialog** 普通对话框 | 需要用户明确回答的中等内容 | 公共组件，标题 + 正文 + 两个按钮；按钮写动作（「删除聊天」而不是「是」） |
| **Alert Dialog** 危险确认 | 删除、注销、永久清空 | 主按钮红字；点蒙层不关闭；只在**不可撤销**时用 |
| **二级页面** | 长内容、复杂编辑（资料编辑、自建角色各字段、长文本） | 整页推入，顶栏「取消 / 标题 / 完成」，完成灰→绿（G2 已用于资料） |
| **Lightbox** 看大图 | 图片、卡片、头像大图 | 黑底、双指缩放、下滑关闭 |
| **Tour** 引导 | 新功能首次出现 | 少用，一次一屏 |

**表单选值梯度**：2 个选项用开关；≤5 个用整行单选列表（微信式对号）；5–10 个用 Choice Sheet；>10 个加搜索（地区、模型）；日期 / 时间用微信式滚轮选择器，不用浏览器原生框。

**按钮颜色规则**：主操作绿底白字（灰底灰字为禁用）；危险操作只用红字；普通取消黑字；全站禁止蓝字按钮（目前删除提醒、删除作品、删除全部补充设定、放弃导入是蓝字）。

## 3. 角色广场与自建角色：现状与改法

### 3.1 现状（截图：`screenshots/character-create--top.png`、`--classify.png`、`--filled.png`、`plaza-manage--work.png`）

- **创建角色页**：一屏塞 12 个字段；「进行中的导入」「导入聊天记录」放在最上面抢位置；生日用浏览器原生日期框、音色用原生下拉；角色分类 / 年龄用灰底大圆角单选卡（不像微信）；「名字」的必填星号掉到下一行；所有长文本是带绿色边框的网页文本框；「保存前试聊」是白底细边框按钮，和上面的绿色主按钮像两个产品；到处是「（可选）」字样。
- **作品详情页**：顶部 6 行信息（名字、分类小字、标题、改编自、作者、版本）挤在一起，主次不分；「你将得到的内容」把分类、名字、人设描述、说话方式、口头禅、示例对话、标签按「灰色小标签 + 黑色大字」一路往下堆；分类直接显示「真人 · 公众人物 · 儿童外貌」这种内部标记；底部点赞 / 评论 / 管理是网页式边框按钮；示例对话以纯文本显示。

### 3.2 建议

**创建角色改成「资料卡 + 二级页面」**（像微信个人信息页，不再是一张大表单）：
1. 第一屏只有：头像（大、居中可点）、名字、角色分类（一行，点进二级页选）、年龄设定（一行）。分类说明放进二级页，不在首屏铺大段文字。
2. 下面是分组的白色行：「人设描述 · 已写 75 字 ›」「说话方式 ›」「口头禅 · 3 条 ›」「示例对话 · 2 组 ›」「标签 ›」「生日 ›」「音色 ›」。每行点进**整页编辑器**（大文本区 + 字数，完成灰→绿），口头禅 / 标签用可增删的条目，示例对话用「我说 / TA 说」气泡式编辑。
3. 必填不靠星号：未填完时底部「创建角色」灰色不可点，并在未填的行右侧显示「未填写」。
4. 「试聊」做成和创建同级的次按钮（白底黑字无边框，或顶栏右上角「试聊」）；导入入口收到页面底部一行「从聊天记录导入 ›」。
5. 原生日期 / 下拉全部换成微信式滚轮或 Choice Sheet。

**广场作品详情改用「人设卡」组件**（§4），顶部：大头像 + 名字 + 一句身份（如「原创 · 成年」用小图标灰字，不显示内部标记）+ 作者与版本一行；主操作是底部通栏绿色「添加到通讯录」（已添加则「发消息」）；点赞、评论做成图标 + 数字放在标题区右侧；「管理」收进右上角「…」。

**广场列表**（需在实机补截图核对）：卡片 = 头像、名字、一句话简介、2–3 个标签、热度；不放长描述。

## 4. 「人设卡」组件（全站复用）

一个组件，四处使用：广场作品详情、角色资料页「TA 的人设」、我的补充设定（对照原卡）、后台角色预览。

| 区块 | 内容 | 样式 |
|---|---|---|
| 头部 | 头像、名字、一句身份、标签 chips | 居中或左对齐，标签浅灰底小圆角，不加边框 |
| 关于 TA | 人设描述 | 正文 15px，超过 5 行折叠「展开」 |
| 说话方式 | 风格一句话 + 口头禅 | 口头禅用浅色引用块，每条一行 |
| 示例对话 | 多轮示例 | **渲染成迷你聊天气泡**（左 TA 右我），这是最能体现角色的一块 |
| 背景资料 | 世界书 / 公开资料条目 | 折叠列表，标题一行，点开看内容 |
| 关系 | 认识的其他角色 | 头像 + 名字 + 关系一行，横向滑动 |
| 其他 | 生日、音色（可试听）、来源 / 改编 | 灰字小行 |

规则：区块之间用 8px 灰色间隔（微信分组），区块内无边框；空字段整块不显示，不写「未填写」；真人 / 未成年等分类只在后台显示，用户端只显示「原创 / 作品角色 / 真人」一个词。

## 5. 全站质感细节（按总经理整理的要点逐条对照）

| 要点 | 现状 | 建议 |
|---|---|---|
| 中文输入回车只选字 | 聊天输入已处理（`chat.tsx:1733` 判断 isComposing） | 其他单行输入（搜索、资料编辑）一并检查 |
| 往上翻记录停止跟随 + 「跳至最新」 | 未见「跳至最新」按钮 | 聊天页上翻时右下角显示「↓ N 条新消息」，点击回底 |
| 容器只一层边框、按钮用底色分层 | 20 处 1px 硬边框，多处「框套框」 | 改用 1%–3% 的灰阶分层（白卡 on #EDEDED），去掉内层边框 |
| 内外圆角同心 | 圆角 8 种数值 | 只留 4 / 8 / 12 三档，外圆角 = 内圆角 + 间距 |
| 暗色模式字重降一档 | 未处理 | 暗色下正文 400→350 / 中粗 500→450（可变字体）或降一档 |
| 数字等宽 | 仅 5 处用了等宽数字 | 积分、时间、计数、价格统一 tabular-nums |
| 流式 / 打字效果柔和 | 回复是按气泡整条出现 | 气泡出现用 120ms 淡入 + 轻微上移，「正在输入」三点节奏统一 |
| 长文件名保留后缀 | 待查（导入、文件消息） | 中间截断「很长的文件名…ext」 |
| 动效分性格 | 未统一 | 拖拽吸附（下拉小程序、左滑）瞬间跟手；点赞、拍一拍用有弹性的小动画；页面转场统一 iOS 式推入 |
| 不要点蒙层就关、不做多余确认、按钮写清后果 | 抽屉点蒙层会关（后台已做草稿，用户端未做）；多处「是 / 否」式按钮 | 见 §2 规则 |
