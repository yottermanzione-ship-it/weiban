# 07 总经理 2026-10-14 反馈与裁定（网页试用后）

> 来源：总经理在香港服务器网页版试用后的反馈，附微信登录页与通讯录截图。本文是后续网页改造的需求依据，与 06 旧版 UI 规格、02a 导航树冲突时以本文为准。

## 0. 总体思路（总经理重申）

- **骨架 = 社交应用复刻文档（C:\wb-ref\wechat-docs）的导航树**，完全照它，「微信有啥咱就得有啥」。
- **皮肤 = 旧项目 UI**，填充骨架。
- **内核 = 爱语**（以及 GitHub 上俗称「酒馆」的 SillyTavern）：学习完善的聊天链路——整包请求信息组装、做到缓存命中、维持记忆、更好地保持人设、更贴角色。
- **用户可见功能的原则**：尽可能保持微信生态；能给用户看的必须是真正提供服务、有用的功能。
- 微伴专属内容挂在导航树上补充，风格与旧项目一致。
- 方案对照：设计负责人出「总对照表」（导航树每个页面/入口 → 旧项目组件 → 微伴内容 → 爱语做法），做成网页给总经理圈改，确认后网页一次做完。安卓暂停，先看网页。

## 1. 立即修改（第一批）

1. **启动页**：打开网址先显示启动页（加载进度/品牌），强制停留 1～2 秒，再进登录或主页，显得专业。
2. **登录页改成微信登录样式**（参照截图一）：左上 ×；居中大标题（如「微伴号/邮箱登录」）；「账号 / 密码」两行带分隔线的表单；一行灰色说明；「用手机号登录」类的蓝色文字链接位（我们用不上的入口点击提示「暂未开放」）；底部「登录后同步最近的聊天记录」勾选；绿色「同意并登录」大按钮；最底「找回密码 | 更多」。去掉现在突兀的背景 logo 嵌底。注册入口放在「更多」或对应位置。
3. **通讯录右侧首字母快速导航**：区域控制不好，看起来越界到上方「公众号」等固定行。微信本身也会延伸到上半区，但我们的观感怪；对照截图二调整位置、尺寸、字号、间距，使其与微信一致。
4. **操作手感**：
   - 聊天列表**轻点一下就弹出删除/置顶/免打扰**——错误。轻点应进入会话；只有长按才弹菜单（左滑才出操作按钮）。
   - **下拉出小程序**反馈很奇怪，没有合适的下拉尺度，要向微信学习：阻尼感、触发阈值、松手回弹/展开动画、半拉提示。
5. **「暂未开放」的显示方式**：所有用不上的入口**正常显示，不在后面标「暂未开放」**；点击时弹提示「暂未开放」即可。全局同理。

## 2. 导航与页面

### 2.1 聊天列表右上角 ⊕ 菜单
与微信一致：发起群聊、添加朋友、扫一扫、收付款。后两个点击提示「暂未开放」。

### 2.2 通讯录（截图二）
微信有啥就有啥：新的朋友、仅聊天的朋友、群聊、标签、公众号、服务号、企业微信联系人，「我的企业」分组，然后按首字母分组的角色列表，右侧字母索引，底部「N 个朋友」。用不上的点击提示「暂未开放」。

### 2.3 通讯录右上「添加朋友」（重新设计）
- 进入后与旧版基本一致：顶部搜索框 + 下方角色推荐列表。
- 在列表顶部加两行（同风格的列表行）：**角色广场**、**角色创建**。
- **角色广场**：内有可切换的两个 tab——**自定义角色**（用户分享的）与**微伴角色**（官方制作的）。两边都具备点赞、评论、添加等功能，并能点开查看基本人设，让人了解个大概。**其他所有角色广场入口也统一成这个页面。**
- **角色创建**：三个选项——**自定义人设**、**聊天导入**、**申请制作**。
  - 申请制作 = 旧项目现有的添加方式：用户提交申请，由官方给用户制作角色。**以后要扣积分，扣法未定**（先预留，不扣）。

### 2.4 发现页
同样：用不上的入口不直接显示「暂未开放」，点击才提示。

## 3. 内核（AI）
- 学习爱语与 SillyTavern（酒馆）的聊天链路：请求信息如何整包组装（系统提示、角色卡、世界书/记忆、近期消息、作者注释等的顺序与位置），如何保证前缀稳定以命中缓存，如何维持长期记忆与人设一致性。
- 目标：人设更稳、更贴角色、缓存命中正常。对应 03 方案中尚未做的 #4（稳定开头/动态结尾）、#5（分段稳定窗口+摘要边界）、#7（记忆注入改造）、#8（缓存命中统计）等。
