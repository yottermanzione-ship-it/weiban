# 24 角色搜索与同名消歧（P1，待确认的实施方案）

2026-10-22。依据第四轮批 P-1；本次只写方案，不扩展既有 S 的产品范围。人设定期补全 P2 已取消，不纳入本方案。S 已实现手动公开候选搜索与 20 次/人/日、5000 次/全站/日的默认限额；它还不是下述完整搜索引擎。

## 用户看到的流程

输入「易烊千」时，本地名称 / 别名索引联想「易烊千玺」。错字有候选但不悄悄改搜索词；显示「你是否想找…」，点击才采用。搜索「李晨」分开显示「李晨 · 演员，代表节目…」「李晨 · 服装领域创作者…」；这些注释必须有本站已审核资料或可点击的公开出处，查不到可靠区别时写「暂未核实身份」，不编履历。

先展示本站官方角色、公开广场作品和本人角色。每项明确来源：官方角色可直接添加；广场作品进入详情看作者再添加；已经是好友则打开聊天；本人角色打开自己的角色资料。站内没有对应角色时提供「申请官方制作」和「自行创建」，保留当前申请额度 / 会员规则。本站条目多时可查看全部，不把一个公众人物的不同作者作品合成一张不透明的卡。

站外入口为「查找公开人物或作品」。用户主动点一次才发站外请求，不随每次键入付费搜索，也不把本人导入的朋友姓名自动发送到外网。站外候选仍是线索，点击后先选择身份与出处，再进入现有申请 / 创建页预填；不会一点击就自动收费生成角色。

## 索引和身份

采用现有 PostgreSQL，先不引入独立搜索集群。characters 管官方 / 本人条目的检索投影，plaza 经公开端口提供已发布可见作品的投影；聚合层经公开端口合并，不跨 schema 查询。索引只存角色 ID、可见性、名称、经审核别名、简短身份说明、出处和更新时间。私人卡片与导入资料始终按 owner 查询，不能进入全局推荐、共享别名词库或站外缓存。

匹配分三层：标准化精确名称 / 别名 → 前缀与完整拼音 / 首字母 → 有界错字近似。标准化仅做 Unicode NFKC、大小写、连续空白和固定标点处理；不能通过去掉所有姓氏 / 后缀把不同人合并。中文短名字不用单一 trigram 阈值硬判，2～3 字名字优先精确与审核别名，错字只出建议。若启用 pg_trgm，扩展和索引必须有单独迁移与回退说明；拼音词典需在实施时选择并核许可证，不把用户名字发送给第三方转换。

排序先看文本相关性，再看明确选择的官方 / 广场来源；相同实体内，已添加优先显示「去聊天」。不能因为热度高就用热门同名者覆盖精确匹配。近似建议最多 5 条，展开结果每页 20 条、稳定游标；停用、撤稿、软删、被投诉下架及权限改变必须从投影移除，读取详情时再核资格，旧搜索结果不能绕过添加闸门。

实体键来自经核实的公开资料标识或平台人工关联。不能只用名字、相同头像或模型一句判断合并人物。模型最多归纳已有公开结果中的身份说明，逐项附 source URL；没有足够证据就保留多项候选。站外文本视为不可信资料，不允许网页中的指令改系统提示。URL 校验与抓取继续经过 model-access 的既有出口。

## 与 S 的衔接及费用

保留 `POST /search/character-candidates` 的向后兼容。新增的站内联想 / 聚合结果需另增契约，不能直接改变旧字段含义。拟议结果包含候选 ID、显示名、别名命中、身份说明、来源、可选实体键、作品 / 官方角色 ID、出处、可执行动作和未核实标记；接收端对新增动作容错。点击时只提交候选 ID，服务器重读候选，不信任客户端提交的外部 URL 和名称来授予权限。

站内联想不调用模型、不收费；站外检索由平台付费，沿用 S 的按实际供应商结果计费、公共查询缓存、租约去重和跨 worker 配额。候选页不新增第二套限额。一次主动查询计一次用户申请额度；实际搜索 / 抓取次数与供应商成本单独记，用缓存命中说明区分，不把「缓存免费」理解为可无限刷新。具体缓存与额度口径以 S 实现 / 最终自查为准，P1 实施时不得悄悄改账务含义。

公开缓存只保存已通过公开人物 / 虚构作品过滤的结果，不保存私人原话、手机号、邮箱、健康、住址或实时行踪。不同身份无法确定时不做站外自动扩写。查询空白、一个字和过长输入只在站内搜索；有歧义可提示补作品 / 职业，不弹收费错误。

## 分步实现和验收要求

1. 先做名称 / 别名投影与站内联想，补软删 / 下架 / 私人隔离、前缀、错字和稳定排序；网页与安卓使用同一返回契约。
2. 再做聚合结果的来源、同名注释、已添加状态及动作。复用现有申请 / 创建流程，缺少对应角色时不伪造添加按钮。
3. 最后扩展 S 站外候选的结构化身份和出处，保持手动触发、平台付费；后台可人工修正实体关联、别名和注释，留审计。

统一自审应包含「易烊千」前缀、单处错字、两位李晨、同人不同作者、改名、英文别名、只有一个字、私人朋友同名、已添加 / 撤稿 / 下架、同一词并发缓存、额度耗尽、账号切换的迟到候选、断网、安卓返回与创建预填。用固定语料标注 Top-5 命中率和同名误合并率；目标是主要前缀用例 Top-5 至少 95%、标注的同名反例零误合并。这是拟议目标，不是已验证结果。站内 P95 200 ms 为初始工程目标，须在明确数据量和数据库环境下测量。

需总经理确认的是是否按此范围继续实施 P1；目前交付为可实施方案。S 的基础公开搜索已在本地分支，未因本方案自动升级成完整联想引擎，也未上线。
