# 交接说明：T-026 契约变更申请评审（来自 T-023 计费）

| 项 | 内容 |
|---|---|
| 负责人 | architect |
| 日期 | 2026-10-06 |
| 契约版本 | 1.2 → **1.3**（全部为次版本：只新增、改说明；1.2 的服务器实现不改代码也能编译） |

## 做了什么

**结论**：后端 T-023 的 6 条申请全部有了结论（4 条批准、1 条改方案、偏差 2 处认可），契约升到 1.3。模型接入（D-L0-08 / D-L0-09）不再有接口障碍。主目录 `pnpm check` 带数据库一次通过（20 个测试文件 231 条，format / lint / 依赖检查 / typecheck / tokens 全过）。

| # | 申请 | 结论 | 契约 |
|---|---|---|---|
| 1 | 按用户 ID 批量取用户名 | **批准**。放在新接口 `IdentityDirectoryPort.getUsernames`（一次 ≤ 500 个，不存在的 ID 不返回；调用方不得把用户名存进自己的表）；同一接口另加 `listAdminUserIds()`（给第 6 条用） | `ports/identity.ts` |
| 2 | 按用量记录 ID 查扣费、按日期列出扣费 | **批准**。放在新接口 `BillingChargeQueryPort`：`getChargesByUsageRecordIds`（≤ 1,000）、`listChargesByDay(北京日期, 分页)`；类型 `UsageCharge`（比申请多一个 `chargedAt`）。第 ② 层**由 model-access 比对**，结果用新事件 `model_access.usage_reconciled` 交回 billing，写进当天对账记录（`ReconciliationRun` 新增可选 `usageReconciledAt`、`usageAmountMismatch`） | `ports/billing.ts`、`events.ts`、`http/billing.ts` |
| 3 | 结算 / 解冻带上游 ID | **批准**。`SettleInput.upstreamId?`、`ReleaseInput.upstreamId?`，网关应当传 | `ports/billing.ts` |
| 4a | 流水只增不改用触发器而非撤销权限 | **认可**。触发器对表所有者也生效，比撤销权限可靠；将来拆数据库账号时再加权限锁（TD-027）。`billing.md` 5.2 第 2 条已改 | 无 |
| 4b | 价目表不支持预约生效 | **认可**（首版）。`effectiveFrom` 晚于现在 400，字段保留；登记 TD-026 | `activatePriceVersion` 说明 |
| 5 | 发布价目表时检查缺价 | **改方案**：billing 发布时**不再检查**（看不到模型目录）。改为 ① model-access 启用模型时调 `BillingChargeQueryPort.listActivePricedModelKeys()`，缺价 422 `model_unavailable`；② 管理后台发布前对照模型目录提示；③ 冻结时 `price_missing` 兜底（不会免费调用） | `upsertCatalogEntry`、`activatePriceVersion` 说明 |
| 6 | 统一的「通知管理员」 | **新设计**：事件 `platform.admin_alert_raised`（任何模块可发，种类：平台预算 80%、对账异常、上游余额用完 / 密钥失效 / 不可用 / 恢复），push 订阅后存进 `push.admin_alerts`（同一合并键未处理期间只推一次）、推送到管理员设备；管理后台接口 `GET /admin/alerts`、`POST /admin/alerts/:alertId/acknowledge`；通知种类新增 `admin_alert` | `events.ts`、`http/push.ts` |

新增的端口方法都放在**新接口**里，没有往 `IdentityReadPort` / `BillingReadPort` 加方法：已有实现类 `implements` 旧接口，加方法会让它们编译失败（与 1.2 做法一致）。三项牵涉边界的决定写成 ADR-0017。

## 给其他负责人的交接

- **给后端负责人**：
  - billing：`BillingChargeQueryPort` 直接挂 `ReconciliationService.chargesByUsage`（补 `chargedAt`；按日分页按（写入时间, 流水 ID）升序，游标格式自定）；`listActivePricedModelKeys` 读当前 active 价目表；`settle` / `release` 把 `upstreamId` 写到流水（字段已有）；订阅 `model_access.usage_reconciled` 写当天对账记录（没有就先建、`checkedAt` 新的为准，第 ①③ 层重跑不覆盖第 ② 层字段）；80% 预算、对账异常在原有审计 + 错误日志之外，同事务发 `platform.admin_alert_raised`（合并键见 `billing.md` 8.4 表）；`listAccounts` 用 `IdentityDirectoryPort.getUsernames` 填 `username`，取不到为空字符串。
