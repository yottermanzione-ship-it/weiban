## 做了什么

### 1. 上游账号可删除
- 后台「模型管理 › 上游账号」每行加红色「删除」。
  - 仍被模型线路引用（模型的主上游，或任一路由；**停用的模型也算**）：不删，弹框列出这些模型名，提示先在「模型」里换线路。前端先按列表判断，服务器也会再查一次（409 时同样弹框）。
  - 没被引用：二次确认后删除。
- 后端改为**软删**（`model_access.upstreams.deleted_at`）：删除时清空密钥密文、停用、清掉暂停；行保留，历史调用记录仍能显示「账号名（已删除）」。
  - 已删除的账号：再测试 / 编辑 / 换密钥 / 删除一律 404；不能再被模型或路由指向（422）；网关状态上报忽略；概览的账号计数不算它。
  - 列表接口仍返回它（带 `deletedAt`），后台的账号列表、模型线路选择、工作台、对账登记都已过滤掉；调用记录、对账列表的账号名显示「（已删除）」。
- 契约 3.20：`Upstream.deletedAt`（可选）；`deleteUpstream` 409 的 `error.details = { modelKeys, modelNames }`。安卓生成物已更新。
- 已改原有数据库测试 `apps/server/test/model-access.test.ts` 的删除用例（本机无数据库，未运行，以 CI 为准）。

### 2. 用户端模型列表格式

### 3. 后台抽屉：点蒙层关闭 + 自动草稿
- 公共组件 `apps/admin/src/ui/drawer.tsx`：所有抽屉点遮罩、右上角 ×、Esc、取消都能关闭。
- 编辑抽屉传 `form` + `draftKey`（antd 表单）或 `draft`（自己用 useState 的编辑器）后：关闭时没保存的改动存到 localStorage（键 `wb-admin-draft:<表单类型>:<记录 ID 或 new>`，读写全 try/catch，30 天过期）；下次打开同一条顶部提示「有未保存的草稿 … 恢复 / 丢弃」；保存成功后清除。
  - 「保存成功」的判断：`useFormFeedback().validate()` 全量校验通过且之后没有 `report()` 报错，抽屉收起时清草稿（逻辑在 `apps/admin/src/data/drafts.ts`）。
  - 已接入：上游账号、调度设置、模型、价目表版本、对账登记、每日一问、表情包、音色、卡面模板、作品链接、宠物物种、行为规划、广场停权、关系、公告、版本说明、版本策略、情景模式、角色（自管状态）、节日（自管状态）、公开动态（自管状态）。只读详情抽屉不需要草稿。

## 遗留 / 需要注意
1. 停用的模型也会挡住删除：模型目录的主上游字段不能为空，所以想删一个账号，必须先把用到它的模型（含已停用的）改到别的线路。这符合「仍被引用就拒绝」的要求；如果总经理觉得停用的模型不该挡，需要另加「删除模型」功能。
2. 草稿只存在当前浏览器；换电脑、隐私窗口、清缓存后没有。
3. 「保存成功」按「校验通过且没报错就收起抽屉」判断：如果保存请求还没返回就离开页面，草稿可能被当作已保存而清掉（极少见）。
