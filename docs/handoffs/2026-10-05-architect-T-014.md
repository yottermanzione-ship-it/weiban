## 做了什么

结论：契约包现在能编译、能构建、能导出 JSON Schema 与 OpenAPI，有单元测试，已纳入仓库的格式检查，版本升为 **1.0**；任务卡要求的 5 项规范确认都有结论；总负责人追加的质量问题 Q-001～Q-009 全部按下表处理。

1. **工程化**：契约包改用共享 tsconfig（`src/` 用 `base.json`，不带 Node 类型，保证网页也能用；`scripts/`、`test/` 用 `node.json`）；新增 `build`（编译到 `dist/`）；导出脚本重写为 `scripts/generate.ts` + `scripts/contract-documents.ts`，同时产出 `generated/json-schema.json` 和 `generated/openapi.json`；新增 2 个测试文件 34 条测试；删除 `.prettierignore` 中跳过契约包的一行并格式化。使用方式与取舍写成 **ADR-0014**。
2. **B1 / B2 注释修正**：成人模式模型可以选任何模型，`adult_content` 只是信息标签；没设成人模式模型时不能开启成人模式（`adult_model_missing`），不自动改用聊天模型。
3. **清理 PRD v1.2 已取消的内容**：错误码 `age_not_confirmed`、`group_conversation`；`CurrentUser.ageConfirmed`、年龄确认接口、`identity.age_confirmed` 事件、`IdentityReadPort.isAgeConfirmed`；`setContentScope` 的 `group_conversation` 错误。逐一 grep 确认除文档历史记录外已无引用。
4. **主题偏好（多设备同步）**：新增 `UserPreferences { theme: green | pink }`、`GET/PATCH /api/v1/me/preferences`、事件 `identity.preferences_updated`、同步分块 `settings.updated(section = preferences)`。原「主题只在客户端」的说法实际在 `engineering-standards.md` 10.4（`overview.md` 里没有这句），已改；`overview.md` 的 identity 职责和数据表、`dev-plan.md` D-L0-06 同步更新。
5. **契约 1.0**：`CONTRACT_VERSION = '1.0'`，包版本 1.0.0；README 版本规则重写（新增「接收端容错」清单），变更记录完整列出 1.0 的删除 / 新增 / 修改。

## 遗留问题

1. **Q-002、Q-007、Q-008 是设计修订**，没有实现代码可跑；验证落在 D-L0-16（计费）、D-L1-01（同步）、D-L0-17（协议用例）。

5. 导出的 JSON Schema 里，请求用的定义会出现「原名Input」（例如 `LoginRequestInput`）——主要原因是请求在输入形态下允许多余字段、带默认值字段可省略。这是有意设计，Android 负责人选代码生成工具时请知悉；个别名字较别扭（`CharacterClassificationInputInput`），不影响使用。
