## 2. 真实联调发现并修复的缺陷（会吞钱）

- 现象：供应商已成功（HTTP 200、已产生费用），但网关随后抛 `媒体结算缓存关联不一致`，整次调用被判 `provider_unavailable`，产品侧拿不到语音，费用却已发生。
- 根因：[媒体网关](../../apps/server/src/modules/model-access/application/media-gateway.ts) 的 `run()` 只把 `holdId/usageRecordId` 写进数据库的 `generation_results`，**没有同步更新内存里的 `GenerationRow`**；紧接着 `restoreMediaResult()` 用这份仍是 null 的行做一致性校验，必然不一致。
- 影响面：所有走「幂等缓存 + 结果落盘」的媒体调用（语音合成、识别、图片、搜索）在真实装配下都会失败——这正是此前只用替身端口测试没暴露的原因。
- 修复：写入数据库后同步内存行，保留原校验（跨冻结错配仍拒绝）。
- 回归：`apps/server/src/modules/model-access/application/media-cache-link.test.ts`（2 条：同一次冻结可返回成功结果；错配的缓存结果仍被拒绝）。

## 4. 验收方法（可复现）

1. 独立库 `weiban_voice_probe_20261024`（验收后已删除），独立主密钥，独立媒体目录 `/srv/weiban/voice-probe-20261024`。
2. 只从**生产库只读**解封两家已停用账号的凭据：MiMo、SiliconFlow。百炼**不参与**。凭据只在新容器内存中，未落盘、未打印、未出服务器。
3. 隔离目录里登记**零价测试价目**（明确标注 NOT LIVE PRICING），不修改生产价目与用户默认。
4. 用生产镜像 + 本分支构建的代码启动，`APP_ROLE=web`（不消费后台任务/定时任务）。
5. 浏览器：真实 Chromium 打开验收页，使用生产 `voicePlayer` 模块播放真实 Ogg。
6. 通话：真实 WebSocket `hello` → 接听 → 推送真实 24kHz 短信音（重采样成通话要求的 16kHz PCM）→ 打断 → 静音/恢复 → 两轮 → 挂断。
7. 结束后：删除隔离库、删除隔离目录、关闭隧道，复核生产 `voice_models=0`、`voices=0`、导入的 2 个账号仍 `enabled=false`。

## 5. 明确的限制（不能写成已完成）

- **未部署**：这些结论来自隔离容器里的本分支代码；线上仍是旧镜像，本分支未合并、未发布、未跑发布来源闸门/备份。
- **正式价格未定**：本轮用零价测试价目验证链路，用户侧真实扣费价格、促销有效期与供应商账单对账**仍未验收**；不能把 0 元夹具当成正式定价。
- **百炼仍未跑通**：`qwen-audio-3.0-tts-plus` 合成 HTTP 200 后下载音频仍失败（已确认官方返回 `http:` 签名对象地址、已加安全升级，仍失败），保持未迁/未启用，不再反复付费重试。
- **真机未验**：浏览器播放是桌面 Chromium，不是真机扬声器听感；通话也不是真低延迟流式（当前是把整段音频切块下发）。
- **文字模型**：通话中的文字回复用 MiMo 文字模型，属于测试模型；正式通话场景用户需自选。
- **未覆盖**：Qwen 3.1 token 计费、Omni/实时 WS、声音克隆、跨静音段识别归属（端口无段 ID）等仍未做。
