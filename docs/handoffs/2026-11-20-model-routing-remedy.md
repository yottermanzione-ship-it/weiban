# Weiban OS 模型线路与供应商回执

开发分支 `codex/model-routing-remedy-20261120` 基于 #148 后的 `cf52325b422b052d0882aced9ce76379191adf07`，同时整合了 `2cb18c69f5b0fb38174753d7eb6fde8272669216` 的业务任务键基础。本文是本机开发自测，未触发真实服务商和线上计费。

## 时间、线路和账本

- 普通聊天与允许跨模型的后台任务在原有候选范围内查找备用。预先核对模型、用途、私密边界、识图、核准的计费与上下文限制，再检查账号和模型线路可用性。需要另做上下文压缩的候选不参与抢先留时。没有可用的备用时主路保留已有预算。
- 每一条候选线路按模型、账号和用途记录最近最多 20 次成功适配器耗时。备用可用窗口按中位数计算，限定在 5–30 秒，新线路起始参考为 8 秒。进程重启后从缺少历史样本重新估算。跨模型派发前核对总剩余与候选所需时间，不能把最后 4 秒依次花给多条线路。真实派发的总剩余和为跨模型可能留的时间分别记入 dispatchTiming.overallRemainingMs 和 crossModelReserveMs，备用实际获得时间仍以它自己的 deadlineMs 为准。
- 同模型的有效进度保护继续生效。连接中断、服务商故障等发生后，在已获准选项中优先选择不同网络入口。入口来自真实配置 URL 的 origin；同一入口的不同路径、不同凭据或模型名仍归在一起。后台仅有短哈希用于比对。不同入口是否共用供应商更深层的基础设施，无法从应用配置验证。
- 缓存重放、报价、真实调用前的风险确认、失败解冻和单次成功扣费均经过原网关。跨模型尝试继续归到同一 taskKey。临时上下文压缩另用独立摘要任务键和原截止时间。首选失败后备用遇到余额、预算或内容拒绝时，返回这个最终状态。

## 对照错误类型

| 情形 | 网关与适配器行为 |
| --- | --- |
| timeout_progress、timeout_deadline、timeout_idle、network_error | 两种文字协议共用空闲、有效进度和总截止计时。观察到首个/最近有效文字或思考时记录相对时间；字节与心跳只重置数据空闲。留下连接、响应头、读取、解析或完成阶段及进度保护原因。绝对截止仍终止请求。 |
| provider_error、bad_request、capability_missing | 已知模型专用参数与固定厂商域名匹配，输出字段取线路核准参数。无效温度、最大输出、格式、截止等本地拒绝，返回固定字段名；不记录参数值。记录上游状态、允许的错误码与参数名；200 流内的错误也分类。明确参数错误不原样重试。 |
| rate_limited、concurrency_limited | 429 首次就冷却同模型线路。有 Retry-After 时按秒数或 HTTP 日期计算，无提示时渐增等待。明确声明账号级限流时暂停该账号其他模型的派发。原账户并发/RPM 限制保留；短等待队列优先放行交互请求，重复请求仍共用幂等占位。 |
| content_rejected、invalid_key、quota_exhausted | 明确安全拒绝不重试或换线。401/403 复用缓存的凭证自检。明确模型授权不足且自检成功，隔离该条模型线路；模糊权限和暂时无法自检分别标记，结束该请求，不计作用户违规。已确认的凭证失效、上游额度耗尽继续暂停整个账号，原管理测试与恢复流程保留。 |
| empty_output、truncated_reasoning、truncated | 空白、没有正文与只有思考各有原因；不发送空气泡。普通文本耗尽输出时，保留已经写出的可见正文；符合原有重试次数、同一模型线路且上下文有空间时补一次尾段，消掉重叠，再整体交付。无法取得新增的完整正文则不把原片段标为已完成。只有思考不能续写已有答案。结构化调用继续只在调用方明确要求时回传带截断标志的部分结果，由业务校验。 |
| insufficient_balance、budget_exceeded、request_too_large、provider_unavailable | 发送前拒绝继续不向服务商请求。返回原计费分类和稳定的拒绝原因，能区分并发、额度、估算过大、线路冷却、账号限流或并发满、线路配置不可用或剩余时间不足。余额/预算变动后的业务唤醒、前台引导和最终任务状态由相应业务与 OS 后台消费。 |
| interrupted、cancelled | 实际尝试状态、幂等缓存、已有结果恢复和结算逻辑继续沿用。结果保存后重启可重放；不能把未知是否发出的请求盲目当成未发送。语音取消方与用户消息上的重试入口由各自业务实现。 |

## 诊断和自测

文字适配器白名单元数据在原 attempt 的 bound_snapshot.providerDiagnostic 中，与结束状态原子写入。可用字段包括 HTTP 状态、允许的请求追踪号、字段名、服务商标准错误码、限流等待、阶段、首次/最后有效进度与最后收到数据的时间。没有真实观测的字段留空。没有读取真实聊天、私密预设或访问供应商账单。

针对性验证覆盖两个协议的空输出、流中拒绝、无进展、总时限、原生流提前结束及安全诊断；合成线路限流与优先队列；真实本机 PostgreSQL 与假 HTTP 服务上的备用不足 4 秒跳过、跨模型预留、同任务键、并发重放、单次扣费、双协议授权隔离、普通回复截断补尾与上下文边界。估算等待不是可用性保证，真实上游表现需要独立的发布后观测。
