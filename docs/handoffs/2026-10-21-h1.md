## 做了什么

### 1. 扣费改为「先用后扣、可欠一次」（取代 13 号 §5 / 3.16「先冻结后结算、不透支」）
- **统一入口**：全部改在计费端口 `billing/application/reservations.ts`（模型网关每次付费调用都经过它），所以聊天、角色生态、主动消息、记忆整理、通话（识别 / 合成分段）、导入、玩法等全部覆盖。平台账户（`billingOwner = platform`：安全关怀、小V、搜索候选、管理员工具等）走原逻辑，不受影响。
- **调用前**：用户付费调用只要求可用余额 > 0（≤ 0 拒绝 `insufficient_balance`），不再冻结积分（冻结记录 `postpaid = true`、金额 0，只用于幂等、并发计数、结算关联）。免费模型（售价 0）不受影响。
- **调用后**：按实际用量全额扣（`Ledger.postEntry` 新增 `allowNegative`，只有先用后扣的结算能扣成负数；管理员扣减、服务费照旧不许透支）。迟到 / 过期的结算也照扣。G3「缺用量按估算计费」保留。
- **一旦为负**：可用余额 ≤ 0，之后一切付费调用在入口被拒；扣到负数时原有的 `billing.balance_depleted` 事件照发（生态暂停等原机制照常）；充值使余额 > 0 后恢复（原 `balance_restored`）。
- **防并发叠加**：同一用户同时进行的付费调用上限（数最近 2 分钟内开始、尚未结算的先用后扣调用，进程崩溃留下的记录不会长时间卡人）。满了时前台调用（聊天回复等）排队最多 N 秒，后台任务（生态、记忆整理等，按 `countAsBackground` / `ecologyTask`）直接拒绝 `concurrency_limited`（网关对外报 `provider_unavailable`）。
- **异常巨额拦截**：网关改为按「本平台实际发送的上下文（本地分词估算，含图片）+ 这次最大输出」估算 `estimate`，按价目表（含限时折扣、备用模型取最大）估价；超过拦截线拒绝 `request_too_large`（对外报 `budget_exceeded`），写审计 `postpaid.request_too_large`。后台每日上限也改用这个估算。
- **后台可调**（billing.settings `postpaid_limits`，5 秒缓存）：并发上限默认 **3**、前台排队默认 10 秒、拦截线默认 200 积分。并发默认取 3 而不是卡上例子里的 2：语音通话会同时有识别、回复、合成三路调用，设 2 可能把通话卡住（后台可改）。
- **只看余额 > 0 的配套**：聊天顶部横条（模型状态）不再要求「够一条回复的保守预留」；通话中余额 ≤ 0 才道别（去掉「约 1 分钟」阈值）；导入只要余额 > 0 即可开始（取代 CHR-08 第 7 条）。
- **后台**：对账与平台花费页新增「先用后扣保护」（三项参数，抽屉修改、写审计）和「欠费用户」（欠费人数、合计、每人欠多少与最近一笔扣费）。用户详情 / 用户列表的余额本来就照实显示，负数会显示负号。
- **用户端**：积分页余额显示负数并提示「已欠费 … 充值后积分大于 0 即恢复」；聊天横条文案改为「积分已用完…」；导入估算文案改为先用后扣口径。

### 2. 删除「关系类型」选择
- 接口：`PATCH /contacts/:id` 的 `relationship` 忽略（不写、不报错）；联系人读取不再返回 `relationship`。数据库列 `contacts.relationship_type` 保留以便回滚（新加好友仍写默认值，因为列非空）。

### 3. 拍一拍
- **为什么之前测试无效（查清）**：网页双击头像、服务器写消息、发消息事件都是通的；问题在 AI 这一侧——拍一拍消息在私聊上下文里被当成空消息丢掉（`media-ai.render` / `readableMessageText` 对 nudge 返回空），角色根本看不到被拍，所以没有像样的回应；群聊同理，也不会点名被拍的角色。另外没有长按入口、没有后缀字段和设置页。

- 服务器写拍一拍时盖上被拍方类型 `targetKind` 与后缀快照 `suffix`（目前只有用户有后缀，客户端传的忽略）；角色拍用户（生态 / 主动拍一拍）自动带上用户后缀。
- 资料新增 `nudgeSuffix`（最多 15 字，空 = 不显示，迁移 0127）。网页「个人信息 › 拍一拍」页（G2 的 FormPage，截图 34 样式，前缀「拍了拍我」）。

## 遗留 / 需要注意
1. **欠费上限**：「可欠一次」靠「为负即停 + 并发上限 + 巨额拦截」控制；单用户最坏欠费 ≈ 并发上限 × 拦截线（默认 3 × 200 = 600 积分）。按估算拦截，推理模型的隐藏思考 token 估不到，实际可能略超。
2. **并发计数窗口 2 分钟**：比 2 分钟还长的单次调用（极长的流式语音合成等）在计数里会提前「让位」。
3. **迁移 0126 回滚**：旧代码不允许负余额；已欠费账户余额保持负数（流水不改），旧代码下他们会因余额不足被拒，直到充值。回滚前确认没有进行中的调用。
4. **迁移 0128**：情侣暧昧设置改为自动 / 日常后无法区分还原（down 为空操作）。
5. 服务费（申请制作 200 积分冻结）不是模型调用，仍按原「冻结、不透支」，欠费用户不能提交收费申请。
6. 安卓原生端只重新生成了契约；网页壳内的拍一拍、拍一拍设置直接生效。
7. 关系类型的策略端口 `PolicyPort.checkRelationshipType` 与 `contacts.contact_updated` 里 `relationshipType` 字段名的订阅保留未删，只是不再触发。
