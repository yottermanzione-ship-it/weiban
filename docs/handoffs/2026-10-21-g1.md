## 做了什么（按 7 条）

1. **私密模式去掉检查模型与 OpenRouter 限制**
   - `ai-runtime/application/adult-boundary.ts` 改为直通：私聊、群聊、主动消息、通话都不再在回复前后请「成人内容检查」模型；`reply-engine.ts` 去掉前后两次检查。
   - `model-access`：去掉「检查模型必须走 OpenRouter」的判断（resolver）；平台内部模型 `adult_check` 不再使用（读取时去掉、写入时忽略，不再发 `adult_checker_configured`）；后台「平台内部模型」里这一行去掉。
   - 迁移 0123：清掉已配置的 `adult_check`，删除旧检查留下的加密证据（`ai_runtime.adult_boundary_states`，表保留）。
   - **保留**：违禁词规则（`reply-rules.ts outputAllowed`）、角色资格（policy）、仅单角色、私密内容不外流、私密模型需「允许成人内容」标记、安全关怀优先；私密模式提示词里「不涉及未成年人或真实存在的人」两条（`domain/persona.ts` MODES.adult，未动）。
   - 删除了只测旧检查流程的 `apps/server/test/adult-input-boundaries.test.ts`（整份都是「检查模型判分 / 不可用 / 恢复 / OpenRouter 路由」用例）。
2. **后台人工标注角色资格**
   - 新 `characters.eligibility_override`（全量事实）+ `characters.eligibility_changes`（谁、何时、原因、改前改后）。`CharacterService.classify()` 有人工标注时按人工标注（优先于资料分类、AI 检出、用户套用的预设改版检出），没有时按原自动结果；**分类触发器没改**（自动列照常维护，清除人工标注即恢复）。
   - 新 `CharacterEligibilityService` 与 GET / PUT `/admin/characters/:id/eligibility`：预设和用户自建角色都能改，两个方向都能改，原因必填；写审计；生效分类变化时发 `characters.character_classification_changed`（ai-runtime 照原逻辑立刻收紧 / 放开私密模式、恋爱模式）。
   - 后台：角色编辑抽屉里新增「资格标注（人工）」卡片（自动结果 / 人工标注 / 实际生效 / 修改记录）；角色库右上角「按角色 ID 标注资格」用于用户自建角色。
3. **会话列表私密消息预览「[私密消息]」**：服务端 `chat/store.ts`（用户自己的会话列表）和内部读取 `read.ts` 都改；网页 `conversation-list.tsx listPreview` 对本机私密消息同样显示。
4. **私密内容的后台任务只用私密模型**：记忆抽取 / 摘要（`memory.ts`，同一次调用产出两套摘要）在这段是私密模式时用 `modelRole: 'adult'`（= 该用户的私密模式场景模型）；私密模式通话的通话摘要同样。生态读取对话本来只读日常范围（未动）。
5. **「模型暂时无法使用」原因只给后台看**：用户端接口（场景配置、角色场景、模型列表、旧选择接口、`/model/status`）统一去掉 `unavailableDetail` / `detail`（`model-access.controller.ts withoutUnavailableDetail`）；网页横条统一「TA 暂时没法回复，请稍后再试」，模型行只写「暂不可用」。后台 `AdminModel.availability` 不变。
6. **好感度改回旧版六阶段**
   - 粉丝 → 朋友 → 亲密好友 → 暧昧 → 恋人 → 伴侣（名称在契约 `FAMILIARITY_STAGE_NAMES`，一处定义）。点数规则不变；默认阈值 **0 / 100 / 400 / 500 / 600 / 700**（满级仍是 700，约 100 条有效消息到「亲密好友」），后台 系统设置 › 好感度阶段 可调（`growth.settings`，写审计；已达到的阶段不因调高阈值回落）。
   - 旧版各阶段语气提示与「暂停亲密表达」移植到 `ai-runtime/domain/relationship-stage.ts`，放进私聊提示词的「关系与设置」；用户说「别叫我宝贝 / 先当朋友」等记为暂停，说「可以叫我老婆 / 继续」恢复并记下称呼（`familiarity.romance_paused / preferred_title`，迁移 0122）。
   - 违禁词第 3 类（「我是你男朋友 / 爱上你 / 跟你结婚」）改为按阶段放开：私聊回复的输出检查用「这一轮的恋爱放开情况」——恋人阶段起（或用户明确选了恋人关系 / 恋爱模式 / 私密模式）且未暂停才允许；暧昧阶段的提示词允许表达想念、偏爱、吃醋。未成年设定角色：任何阶段都不涉及恋爱，且最高停在「亲密好友」。
   - 生态、群聊、朋友圈评论、主动消息里原来的「熟悉度 L3」等说法改为阶段名；好感度卡标题 / 文案、成就（亲密好友、恋人）改为新说法。
7. **权益层卡死（方案 A）**：从未付过费、当前也不是 PRO+ 的账号最高停在「亲密好友」；点数照常累计，付费后按点数直接显示对应阶段（下次加分时写回并发升级提示）。「付过费」= 管理员代充值过积分（不含注册赠送、开会员赠送）或开通过会员（新端口 `BillingPaidHistoryPort`）。网页好感度弹层写明「充值或开通 PRO+ 后可以继续升级 · 去看看」，会员权益对照表加一行「好感度最高阶段：亲密好友（充值后解除）/ 伴侣」。

## 遗留 / 需要注意

1. **用户明确选「恋人」关系 / 恋爱模式 / 私密模式时，按恋人阶段的口吻**（即可以用恋爱说法，不受阶段卡），沿用原产品里「关系由用户自己选」的做法。若总经理希望恋爱表达**只**随好感度阶段解锁（选了恋人关系也要到阶段），改 `relationship-stage.ts toneStage` 一处即可。
2. **违禁词第 3 类按阶段收紧后**：低阶段角色若说出「爱上你 / 我是你男朋友」会被拦下重写一次，仍不行转开话题（原有流程）。恋爱称呼（宝贝 / 老公）低阶段只靠提示词约束，没加进违禁词（避免误伤「我的宝贝相机」这类说法）。
3. **已有好感度数据**（迁移 0122）：按累计点数换算到新阶段，存库值先按「未付费」最高到亲密好友；付费 / 会员用户读取时按点数直接显示更高阶段，下次加分时补发升级提示和卡。以前拿过旧 L4「老友」/ L5「知己」卡的，新阶段 4、5 的卡因幂等键相同不会再发（旧卡标题保留旧说法）。
4. **「付过费」口径**：现阶段没有真实支付，管理员给用户加积分（除注册赠送、开会员赠送外）都算充值；如果以后用加积分做补偿，也会解除卡死。会员到期后不会重新卡住（付过费永久算）。
5. 平台内部模型的数据库约束 `not adult_content or defaultFor <@ ARRAY['adult_check']` 和事件 `model_access.adult_checker_configured`（及 ai-runtime 的订阅）保留未删，只是不会再触发；`packages/ai-evals` 里成人边界评测的「检查模型路由已验证」项目前已无意义，留待 ai-lead 清理。
6. 后台按 ID 标注只能填角色 ID；后台目前没有「用户自建角色列表」，需要从反馈 / 记录里复制 ID。
7. 删除的 `adult-input-boundaries.test.ts` 里有几条群聊「检查恢复 / 租约」用例，它们测的是检查模型等待后的恢复路径，随功能一起去掉。
