## 做了什么

### 1. 去掉面向用户的「平台默认模型」，改为按场景配置
- 七个场景：文本聊天、图片识别、语音消息（角色发语音的合成）、语音识别（用户语音转文字，含通话）、语音通话（通话里对话用的文本模型）、发照片（图片生成）、私密模式。每个场景用户单独选一个模型，**没有平台兜底**：没配置的场景就不可用。
- 解析只有一处：`model-access/application/scenarios.ts` 的 `ScenarioService.pick()`（角色单独设置 > 用户场景配置 > 未配置）。网关执行、报价（`ModelQuoteService`）、模型状态（`ModelStatusService`）、媒体网关（语音合成 / 识别 / 图片）全部经它。
  - `chat` 角色 → 文本聊天（`purpose = vision` → 图片识别；调用方传 `scenario` 时按它，目前通话传 `voice_call`）；`adult` 角色 → 私密模式；`background` 角色（记忆整理、生态发文字等后台文字任务）→ 同一角色的文本聊天。
  - 带图而模型不能识图 → 改用同一角色「图片识别」场景的模型；没配置 → `capability_missing`。图片识别没单独配置、而文本聊天模型自己能识图时直接用文本聊天模型。
  - 语音消息：角色音色绑定了具体语音模型且该模型可用时以音色为准（音色代号只在它自己的模型上有效），但用户必须已配置「语音消息」场景。
  - 只有管理员自己的 `admin_*` 调用在没配置时用场景推荐模型。
- 角色生态不单独选：生态发文字走文本聊天、发语音走语音消息、发照片走发照片（都按该角色的设置）。
- 旧接口兼容：`/model/selection` 的 `chat` = 文本聊天、`adult` = 私密模式、`background` 恒为 null（写入忽略）；`/model/character-overrides` = 该角色文本聊天的单独设置。未升级的安卓照常可用。

### 2. 用户端「模型配置」
- 「我 › 服务 › 我的模型」改名「模型配置」（未配置文本聊天时有红点），「设置 › 通用」里也加了入口。两个视图：
  - **按场景**：七行，显示所选模型或「未配置」；进入某场景只列后台标注能用于该场景的模型，行内「消耗倍率 ×… · 约每条 / 约每次 … 积分」，后台推荐的模型带「推荐」标记；文本聊天页保留排行榜 / 热门榜；有未配置场景时显示「一键选推荐（只填未配置的场景）」。
  - **按角色**：通讯录角色列表 → 进入某角色逐场景指定，未指定显示「跟随（当前模型）」。聊天信息页「TA 用的模型」进入的就是这一页。
- 私密模式开启前检查「私密模式」场景（该角色单独指定优先），没配置时弹框可直接「去选模型」。
- AI 模型价格页同一格式；语音 / 图片模型显示「约每次」。

### 3. 首次引导
- 文本聊天还没配置时（`GET /model/scenarios` 的 `needsSetup = true`）：进入聊天自动弹「先选好模型」，列出一键推荐会填入的模型，按钮「稍后 / 自己选 / 一键选推荐」；聊天页顶部常驻提示「还没选文本聊天模型，选好后才能发消息 · 去配置」。配置好之前发文字、发图、发语音都会被拦下并重新弹出引导（输入框里的字保留）。
- 老用户迁移（0115）：所有 active 账号写入场景配置——文本聊天、语音通话 = 原全局聊天模型，没选过 = 原平台默认聊天模型；私密模式 = 原成人模式模型；图片识别 / 语音消息 / 语音识别 / 发照片 = 原平台默认；原角色单独聊天模型 → 该角色的文本聊天与语音通话。所以老号不会被引导拦住。原「后台模型」不再单独存在。

### 4. 后台
- 模型编辑抽屉：「默认给谁用」换成「可用于哪些场景」（勾选图片识别需先有识图能力）；列表加「可用场景」列，按场景筛选。
- 模型管理页顶部新卡片「场景推荐模型 · 平台内部模型」：
  - 推荐模型（每场景一个，只用于一键推荐，不是兜底）；
  - 平台内部模型：安全检查、小V 答疑、**角色生态决策**、平台内容生成（官方角色公共朋友圈、搜索候选）、行为规划、成人内容检查、联网搜索。「角色生态决策」存的仍是生态配置里的决策模型（与「模型与计费 › 角色生态」同一个设置），这里改了就是那里改了。
- 原 `defaultFor` 由 0114 迁到这两类（`model_access.settings` 的 `model_uses`），列保留只为回滚，服务器不再读写（返回空数组）。
- 导入配置导入的文字模型默认勾「文本聊天、语音通话、私密模式」（能识图再加图片识别）。

### 5. 限时折扣
- 模型编辑抽屉 ④：开关 + 折扣（0.01～0.99）+ 起止时间；列表「限时折扣」列显示「5 折 · 进行中 / 未开始 / 已结束」与截止时间。
- 存在 billing（`billing.model_discounts`）。**报价、冻结、结算只用一个算式** `applyDiscount`（`billing/domain/rules.ts`）：报价按此刻折扣；冻结时把折扣锁进 `billing.holds.discount_bp`，结算按冻结时的折扣算售价，避免折扣在调用中途到期造成前后不一致。只打售价，成本不变；到期自动恢复。
- 用户端：`ModelInfo.discount` + 折后的「约每条 / 约每次」；显示「消耗倍率 ~~×1.0~~ ×0.50 · 限时 5 折」（划线）。折扣期间不用最近 7 天平均（里面混有折后数），改按默认用量 × 折后售价估算。
- Bai 的 MiMo：总经理在后台自己添加上游账号、填密钥，再在模型抽屉里设折扣即可。

### 6. 封禁账号跳过后台任务（批 E2 遗留）
- 网关文本调用与媒体调用在解析模型、冻结之前判断：用户付费调用且账号已封禁 → 直接拒绝，不冻结、不扣积分（覆盖生态、主动消息、记忆整理等所有后台任务）。生态调度入口 `EcologySettingsService.isActive` 也先判断，封禁账号不入队。
- 契约 `IdentityAccountStatusPort.isBanned?`（可选），identity `SettingsService` 实现。

## 遗留 / 需要注意
1. **行为变化**：后台文字任务（记忆整理、通话摘要、生态发文字等）从「平台默认后台模型」改为跟随该角色的文本聊天模型，选了贵模型的用户后台花费会变高（任务卡「按动作所属场景自动走」的直接结果）。发布说明里要写明。
2. 语音消息以角色音色绑定的模型为准（音色代号跨模型无效），用户在「语音消息」里选的模型只在音色模型不可用、或音色没绑定可用模型时生效；用户看到的「约每次」按所选模型估算。要彻底按用户选择，需要「音色按模型分组 / 换模型时换同款音色」，另开任务。
3. 新注册用户没有任何场景配置：后台必须先在模型管理页设好推荐模型，否则一键推荐填不进去（引导会提示「自己选」）。上线前请总经理在后台核对推荐模型与平台内部模型（0114 已从原 defaultFor 迁过来）。
4. 网页同步层（`sync-http.ts`）仍按旧口径缓存 `/model/selection`；新页面都直接请求新接口（`networkOnly`），不受影响。安卓还没有场景配置界面，旧接口可用。
5. 空输出降级的备用模型改为「文本聊天」场景的推荐模型（原来是平台默认后台 / 聊天模型）。
6. 后台「角色生态」页仍可改决策模型，与模型页那一栏是同一个设置。
7. 迁移 0115 只给 `status = 'active'` 的账号写配置；注销中账号不写。原 `selections` / `character_overrides` 表保留（只读不写），回滚 0115 即恢复原表的作用。
8. 数据库测试按新口径改写但本机没跑，CI 若有失败多半是测试夹具里还假设有平台默认模型，按本交接的口径补场景配置即可。
