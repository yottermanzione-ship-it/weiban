# 收款监控简化交接

经理要求参考旧收款监听，不再反复配对、启用；实际旧1.0.6安装包已静态核对。实现、失败证据与检查见[开发自测](../quality/2026-11-08-payment-monitor-simple-setup.md)。本次正式监控包1.0.3/4，沿用原监控包名和签名。微伴主应用3.0.0无需为此更换。

经理的现有监控手机已经设置过，后台已恢复唯一已配对设备。新包直接桌面根目录，覆盖安装后打开点“开始监控”；不要卸载，不必新增连接码。通知权限未授权才引导系统设置。正常状态为通知监听已连接、服务器连接正常、待补报0；真实收款目前仍关闭。

经理已确认1.0.2在重新关闭/打开系统通知权限后连接恢复。1.0.3补齐断开重绑及旧实例回调保护，按钮反馈、权限直达与八秒超时提示；主页可截屏，首次设置含连接码时仍不可截屏。不把这次连接恢复当作真实到账完成。

首次新手机在后台“用户→扫码收款→设置收款手机”复制连接码，在手机保存一次，第一台自动启用。已有手机场景显示“连接另一台手机”；换机先补报旧手机，再启用新手机。未配对申请不再当作实际设备显示，旧申请仍保留。

到账类型由服务端订单确定，手机及后台展示积分充值/会员购买。手机显示最近十条；后台完整分页分别显示通知时间、服务器收到时间与订单入账时间。未匹配金额、过迟通知等仍在待核对，不凭通知猜用途。

旧站暂停订单及停止旧自动入账已授权，尚未执行。不得在新监控未确认在线时先切换；保留两站聊天、用户、密码、历史收款。开通后的微信、支付宝小额真实收款及锁屏/断网仍需要经理在实际收款手机验证。

发布前完整检查和 `Assert-ReleaseSource.ps1` 必须通过；契约7.7兼容追加，无迁移。部署、APK摘要、签名及固定提交以PR114追加回执为准。若远端仍遇编译依赖下载故障，不绕过门禁、不宣称已发布。
