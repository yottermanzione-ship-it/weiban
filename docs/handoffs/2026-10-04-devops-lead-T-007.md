## 做了什么

- 编写面向零基础的 Windows 11 开发环境安装说明 `docs/ops/dev-env-setup.md`，覆盖：
  - 通俗解释 Node.js、pnpm、npm、Docker、WSL 2；列出现在不用装的软件（Android Studio/JDK 留到 L5，本机 PostgreSQL 永远不装等）。
  - 开工前检查：Windows 版本（`winver`）、内存与硬盘、任务管理器看虚拟化、BIOS 开启虚拟化的通用步骤。
  - Node.js 24 LTS：官网与 npmmirror 镜像下载地址、安装向导每一屏怎么选（「Tools for Native Modules」不勾）、验证命令；PowerShell「禁止运行脚本」的处理（当前用户设为 RemoteSigned）。
  - pnpm：推荐 `npm install -g pnpm@10`（与 ADR-0003 版本基线一致），说明为何不用 Corepack；npmmirror 镜像配置为可选项，列出利弊和回退方法。
  - WSL 2：`wsl --install --no-distribution`（不装 Ubuntu，免设 Linux 账号）、更新与排错。
  - Docker Desktop：系统要求、许可（个人免费）、下载渠道（官网 / Microsoft Store）、安装每一屏（Per-user 默认、必须勾 WSL 2）、首次启动（接受协议、不需要登录可 Skip）、推荐设置、验证命令（`docker --version`、`docker compose version`、`docker run --rm hello-world`）、Docker Hub 国内连不上时的镜像加速配置。
  - 资源占用提醒与可选的 `.wslconfig` 内存上限；常见报错 Q&A；结尾一段可整体粘贴的自查命令和合格对照表。
- 联网核实（2026-10-04）：Node.js 当前 LTS 为 v24.21.0（文件 `node-v24.21.0-x64.msi`）；Docker Desktop 最新 4.93.0（2026-09-28），Windows 11 要求 23H2（build 22631）及以上、WSL ≥ 2.1.5、8 GB 内存、BIOS 虚拟化，默认 Per-user 安装；Node.js 25 起不再自带 Corepack；pnpm 最新为 12.9.1，10.x 仍在发布（10.34.6，2026-09-29）。

## 遗留问题

- **pnpm 版本基线可能过时**：ADR-0003 写 pnpm 10，而 pnpm 已出到 12（11 起要求 Node 22+、配置从 `.npmrc` 迁到 `pnpm-workspace.yaml`、`packageManager` 字段被 `devEngines.packageManager` 取代）。本文按 ADR 写 `pnpm@10`；若架构改基线，只需把第五节命令和自查表里的「10」改掉。已上报，不自行选边。
- **总经理电脑的 Windows 是 23H2（build 22631）**：刚好满足 Docker 最低要求，但该版本 2025-11-11 已停止安全更新。文档里建议先升级到 24H2 及以上，不是强制。
- Docker Hub 国内镜像加速（`docker.m.daocloud.io`）是第三方服务，可用性会变；文档已写明失败时找运维，不让总经理自己换。
- 未在真实机器上演练（任务要求不替总经理安装），安装向导截图式描述依据官方文档与常见版本，个别屏幕文字可能与实际略有出入，已在文中提示「按内容对照」。

## 需要总经理决定的事

无。（升级 Windows 到 24H2 是建议，不是选择题；按文档做即可。）

## 给其他负责人的交接

- 给项目总负责人：请把 `docs/ops/dev-env-setup.md` 交给总经理执行；收到他贴回的「自查清单」输出后转给运维，由运维判断是否合格并开始 D-L0-01。请把上面「pnpm 版本基线」问题转给架构负责人。
- 给架构负责人：ADR-0003「版本基线」中 pnpm 10 是否升级到 11 或 12，请评估后更新 ADR。注意 11+ 的配置迁移（`.npmrc` 只保留认证与源地址，其余设置写进 `pnpm-workspace.yaml`）会影响 D-L0-01 骨架写法。
- 给运维（自己，D-L0-01 / D-L0-02）：
  - 在根 `package.json` 写 `packageManager`（或 11+ 的 `devEngines.packageManager`）锁定 pnpm 版本，`.nvmrc` 写 `24`；`engines.node` 设 `>=24 <25`。
  - D-L0-02 的 Postgres 数据用 Docker 命名卷，不要绑定 Windows 目录（WSL 2 跨文件系统读写慢）；镜像拉取要考虑国内网络（文档第七节第 6 步的镜像加速）。
  - 本机不装 PostgreSQL，Compose 默认映射 5432；如总经理机器上 5432 被占用再改端口。
- 给 AI / 后端 / Web 负责人：总经理电脑的 PowerShell 执行策略将是 RemoteSigned，pnpm 可直接调用；依赖尽量选有预编译包的库，**不要依赖本机 C++ 编译工具链**（安装时没装 Tools for Native Modules）。
