## 做了什么

1. **GitHub Actions**（`.github/workflows/ci.yml`）：推送任何分支、向 main 发 PR、网页手动触发时运行；步骤 `pnpm install --frozen-lockfile` → `format:check` → `lint` → `typecheck` → `test` → `tokens --check`。Node 读 `.nvmrc`，pnpm 读 `package.json` 的 `devEngines`（版本号不在 CI 里重复写）；`pnpm/action-setup` 缓存 pnpm 依赖；三个第三方 action 钉到 40 位提交哈希；权限只读；同分支新推送会取消旧运行。安卓 Gradle 部分在文件末尾留了注释占位（D-L0-18 接入）。检查任务名固定为 `check`，供保护规则引用。
2. **R7 加固**（QA 建议 1）：`no-raw-time.js` 识别 `globalThis.Date` / `global.Date` / `window.Date` / `self.Date` / `globalThis['Date']`，另补 `Date()`（不带 new）、`Date.now` 引用（不调用也报）；范围从「modules/」扩到 `apps/server/src` 下除 `platform/` 和测试以外的全部文件（含 `main.ts`、`app.module.ts`、其他目录）。
3. **禁止路径别名**（QA 建议 6）：新规则 `weiban/no-path-alias`，`apps/server/` 下（含测试）出现 `@/…`、`~…`、`#…`、`src/ modules/ platform/ apps/…` 开头的导入直接报错；`@nestjs/common`、`@weiban/contracts` 等正常包不受影响。
4. **同层循环依赖**（T-011 遗留问题 4）：选用 **dependency-cruiser**（不是 `import-x/no-cycle`），规则 `no-cross-module-cycle`：`modules/A` 的文件沿引用绕一圈回到自己、且途经别的模块即报错；`import type` 也算；同模块内部循环、测试文件不算。根目录 `.dependency-cruiser.js` 引用 `@weiban/eslint-config/dependency-cruiser`，新脚本 `pnpm lint:deps`，并入 `pnpm lint`。
   - 选型理由：循环要看整张引用图，dependency-cruiser 能精确表达「跨模块的循环」；纯 JavaScript、无原生二进制（`import-x` 要配 TS 解析器，后者依赖原生二进制 `unrs-resolver`，与 T-011 的「零原生依赖」做法不一致）；已在 `engineering-standards.md` 第 3 节列为可选工具。
5. **Q-009（总负责人补充）**：R9 的两种绕过（类型是 `BillingPort` 但变量名叫 `port`；`billingPort['estimateAndReserve']` 方括号写法）写成 `it.skip` 用例并注明 Q-009。我临时去掉 skip 实测过：两个用例都失败（`expected [] to have a length of 2 but got +0`），证明漏检确实存在；加固时改回 `it` 即可直接用。R9 规则本身未改。
6. **设计令牌脚本**：`docs/design/tools/build-tokens.mjs` 移到 `scripts/build-tokens.mjs`（原文件已删）；`--check` 增强为「同时给 `--css` / `--kotlin` 时比对生成物与重新生成结果，不一致退出码 1」，比较前统一换行符；根脚本 `pnpm tokens`（生成 `docs/design/tokens.css`），`pnpm check` 和 CI 末尾跑 `pnpm tokens --check`。生成物表头的脚本路径改为新路径，所以 `tokens.css` 重新生成（只有表头一行变化）。生成逻辑未改。
7. **文档**：新增 `docs/ops/ci.md`（CI 说明、看结果的方法、main 保护规则一步一步操作、gh 命令行安装登录）；`dev-env-setup.md` 末段措辞修正（QA 建议 7）；`local-dev.md` 第四节检查表更新；`packages/eslint-config/README.md`、`scripts/README.md` 同步。

## 遗留问题

1. **CI 实际运行结果需要有 GitHub 登录的人查看**（原因见上表）。若是红叉，请把失败步骤截图转运维。
2. **私有仓库 + 免费账号无法真正启用 main 保护规则**，见「需要总经理决定的事」。在此之前「必须通过 CI 才能合并」只能靠总负责人合并前核对。
3. **启用保护规则后合并流程要变**：本机 `git merge --no-ff` 生成的新合并提交没有跑过 CI，推送 main 会被拒绝，需改为 GitHub 上开 PR、绿勾后点「Merge」（见 `ci.md` 第四节）。`git-workflow.md` 等决定后再正式修订。
4. R7 仍识别不了「先把 Date 赋给别的变量再用」（`const D = Date; new D()`），由评审兜底，已写入 eslint-config README。
5. 循环检查只管跨模块；同模块内部文件循环未检查（ADR-0004 没要求）。如架构希望一并禁止，改一行规则即可。
6. R9（含 Q-009）未加固，等 T-014 架构方案后另开小任务。
7. CI 中 `pnpm tokens --check` 目前只比对 `tokens.css`；安卓 `WbTokens.kt` 的比对等 D-L0-18 接入。

## 需要总经理决定的事

1. **main 保护规则要不要真正启用（涉及每月约 4 美元）**。仓库是私有的，GitHub 免费账号对私有仓库的保护规则不生效。可选：升级 GitHub Pro（约 4 美元 / 月）；或把仓库改公开（不推荐，仓库里有 AI 提示词和测试样本）。

2. **（可选，推荐）装 gh 命令行并登录一次**（`docs/ops/ci.md` 第五节，约 5 分钟），之后总负责人能在命令行直接看 CI 结果、开 PR，不用每次请总经理看网页。
