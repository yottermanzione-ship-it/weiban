## 做了什么

1. **GitHub Actions**（`.github/workflows/ci.yml`）：推送任何分支、向 main 发 PR、网页手动触发时运行；步骤 `pnpm install --frozen-lockfile` → `format:check` → `lint` → `typecheck` → `test` → `tokens --check`。Node 读 `.nvmrc`，pnpm 读 `package.json` 的 `devEngines`（版本号不在 CI 里重复写）；`pnpm/action-setup` 缓存 pnpm 依赖；三个第三方 action 钉到 40 位提交哈希；权限只读；同分支新推送会取消旧运行。安卓 Gradle 部分在文件末尾留了注释占位（D-L0-18 接入）。检查任务名固定为 `check`，供保护规则引用。
2. **R7 加固**（QA 建议 1）：`no-raw-time.js` 识别 `globalThis.Date` / `global.Date` / `window.Date` / `self.Date` / `globalThis['Date']`，另补 `Date()`（不带 new）、`Date.now` 引用（不调用也报）；范围从「modules/」扩到 `apps/server/src` 下除 `platform/` 和测试以外的全部文件（含 `main.ts`、`app.module.ts`、其他目录）。
3. **禁止路径别名**（QA 建议 6）：新规则 `weiban/no-path-alias`，`apps/server/` 下（含测试）出现 `@/…`、`~…`、`#…`、`src/ modules/ platform/ apps/…` 开头的导入直接报错；`@nestjs/common`、`@weiban/contracts` 等正常包不受影响。
4. **同层循环依赖**（T-011 遗留问题 4）：选用 **dependency-cruiser**（不是 `import-x/no-cycle`），规则 `no-cross-module-cycle`：`modules/A` 的文件沿引用绕一圈回到自己、且途经别的模块即报错；`import type` 也算；同模块内部循环、测试文件不算。根目录 `.dependency-cruiser.js` 引用 `@weiban/eslint-config/dependency-cruiser`，新脚本 `pnpm lint:deps`，并入 `pnpm lint`。
   - 选型理由：循环要看整张引用图，dependency-cruiser 能精确表达「跨模块的循环」；纯 JavaScript、无原生二进制（`import-x` 要配 TS 解析器，后者依赖原生二进制 `unrs-resolver`，与 T-011 的「零原生依赖」做法不一致）；已在 `engineering-standards.md` 第 3 节列为可选工具。
5. **R9 加固（第二轮，按 `engineering-standards.md` 3.1）**：`billing-port-exit.js` 重写，删除旧的「看变量名里有没有 billing」判断，改为只看名字本身：
   - 规则 A：`BillingReservationPort`、`BILLING_RESERVATION_PORT` 这两个名字以任何形式出现都报错——import / import type / `as` 别名（按原名）、`export … from`、命名空间 `c.X`（值和类型位置，含 `TSQualifiedName`）、`import('…').X` 类型、动态导入后解构、方括号 `c['X']`、字符串形式的导入名。
   - 规则 B：`estimateAndReserve` 以任何形式出现都报错——`.x`、`['x']`、无插值模板字符串键、解构、字符串常量。
   - 规则 C：`ModuleRef`（含别名导入、`core.ModuleRef`）报错。
   - Q-009 两条用例已从 `it.skip` 改为必须报错的正式用例（第一轮曾临时去掉 skip，确认旧规则下两条都失败）。
6. **R10（第二轮，3.2）**：`module-boundaries.js` 扩展到 `apps/server/test/`：集成测试只能引用 `modules/<模块>/index.ts`、`modules/<模块>/testing.ts`、`platform/**`；生产代码 import 任何模块的 `testing.ts`（含本模块）报错；测试文件（含模块目录内单元测试）可以引用其他模块的 `testing.ts`。
7. **R4 扩展（第二轮，3.3）**：`exclusive-sdk.js` 的检查范围加上 `packages/ai-evals/`（R5 推送 SDK 名单同一规则，一并生效）。
8. **按「最严格理解」处理的歧义**（总负责人要求，请架构确认）：
   - R10 允许名单：**总负责人已裁定**加入装配入口——集成测试可以 import `src/app.module.ts` 和 `src/main.ts`（只此两个，理由：集成测试需要启动整个应用）；`src/` 下其他目录（如 `config/`、`cli/`）仍报错。**待架构在 `engineering-standards.md` 第 3 节 R10 / 3.2 同步措辞。** 实现时顺带修正：识别装配入口时扩展名可省略（`../src/app.module` 也算），因此业务模块 import 不带扩展名的 `app.module` 现在会被 R2 拦下（以前漏检）。用例：「集成测试引用 app.module.ts、main.ts → 通过」「集成测试引用 src/config、src/cli → 仍报错」。
   - R9 规则 A、B 的范围是 `apps/server/src` 全部（不只 `modules/**`），含 `platform/`、`src` 其他目录、模块目录里的单元测试；豁免只有 model-access、billing、装配入口、`apps/server/test/`。
   - R9 规则 C 对 model-access、billing 也生效（规范 3.1 第 5 条只豁免 platform 与装配入口），`apps/server/test/` 豁免（按第 6 条）。不限定来源包：任何名为 `ModuleRef` 的标识符都报错。
   - 只按名字判断：自己声明一个同名的变量 / 接口（如 `estimateAndReserve`）也会报错。
9. **设计令牌脚本**：`docs/design/tools/build-tokens.mjs` 移到 `scripts/build-tokens.mjs`（原文件已删）；`--check` 增强为「同时给 `--css` / `--kotlin` 时比对生成物与重新生成结果，不一致退出码 1」，比较前统一换行符；根脚本 `pnpm tokens`（生成 `docs/design/tokens.css`），`pnpm check` 和 CI 末尾跑 `pnpm tokens --check`。生成物表头的脚本路径改为新路径，所以 `tokens.css` 重新生成（只有表头一行变化）。生成逻辑未改。
10. **文档**：新增 `docs/ops/ci.md`（CI 说明、看结果的方法、main 保护规则一步一步操作、gh 命令行安装登录）；`dev-env-setup.md` 末段措辞修正（QA 建议 7）；`local-dev.md` 第四节检查表更新；`packages/eslint-config/README.md`、`scripts/README.md` 同步。
