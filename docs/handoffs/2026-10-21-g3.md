## 做了什么

### 1. models.dev 自动预填（G3-1）
- 数据源实测（10-21）：`https://models.dev/api.json`（开源项目 sst/models.dev），约 5.9MB、232 个服务商、9090 个模型。结构 `{服务商ID: {id, name, models: {模型ID: {name, cost:{input, output, cache_read, cache_write}, limit:{context, output}, modalities:{input:[…'image']}}}}}`，价格单位「美元 / 百万 token」。
- 服务端 `model-access/domain/models-dev.ts`（解析、压缩、按名匹配，纯函数）+ `application/models-dev.ts`（缓存、定时、接口）：
  - 只保留预填字段压缩后存表 `model_access.models_dev_snapshot`（一行，约 1.2MB）；每天 04:10（北京）自动抓，后台「立即刷新」；第一次检索时还没缓存会先抓一次。失败保留上次数据、记下失败时间与原因。
  - 汇率存 `model_access.settings` 键 `models_dev_settings`，默认 7.2，后台可改（写审计）。
  - 匹配：模型名小写、去掉「服务商/」前缀与「:free」后缀、点号空格下划线统一成连字符（`anthropic/claude-opus-4.6` = `claude-opus-4-6`）；完全对不上再去掉日期 / latest 后缀做近似匹配（标「近似匹配，请核对」）。同名条目多时优先「出品方」对应的官方服务商，其次首发服务商、有价格的条目。
  - 实测：claude-opus-4-6、gpt-5.5-pro、deepseek-v4-pro、gemini-3.1-pro-preview、mimo-v2.6-pro、kimi-k3、glm-5.3、qwen3.6-max-preview、grok-4.7 都命中官方服务商；`gemini-4-argon-max`（中转别名）匹配不到。
- 接口（管理员）：GET `/admin/model/models-dev`、POST `…/refresh`、PUT `…/settings`、POST `…/lookup`（一次最多 200 个名字）。
- 后台：
  - 模型页顶部一行「官方价格数据（models.dev）」：模型数、更新时间、汇率（可改）、立即刷新；自动更新失败黄条写原因。
  - 添加模型：填上游模型名后 0.6 秒自动检索，匹配到就预填**售价**输入 / 输出 / 缓存命中 / 缓存写入 5 分钟、线路计费上限的上下文长度 / 最大输出（超过 32000 按平台上限 32000）/ 最多图片数、识图能力，空着时顺带填显示名、出品方（模型键随之重算）。只填空着、还是默认值或上次自动填的格子，不覆盖手改的。抽屉里「models.dev 参考」块列出官方人民币价、美元原价、上下文 / 最大输出、识图。
  - 编辑模型：不自动改，点「用这些数据填入」才覆盖。
  - 匹配不到 / 没有数据 / 查询失败：黄条提示手动填写（建议改成官方叫法再试）。
  - 导入配置：读入文件后批量检索；上下文、最大输出、识图按官方数据预填；文件没写缓存价 / 缓存写入价时按官方「缓存价 ÷ 输入价」比例 × 文件输入价预填（蓝色格子），查不到才按输入价 10%（黄色格子）；新增「models.dev」列显示已匹配 / 近似 / 没找到。**文件里的售价、成本不被覆盖。**
  - 预填的是官方价，写进「售价」；成本价不预填（应按中转实际进价）。

### 2. 缺用量按估算计费，不再暂停线路（G3-2）
- 原因回顾：截图 37 的「系统没法确认这条线路的实际用量，已暂停」来自 3.16 预冻结设计——上游没报 token 数（或请求失败没有用量）时记「成本待核」，并把线路停用、同一路由有待核调用时拒绝新调用。注意：原来连 429 / 401 等**明确报错**的失败也会走到这一步。
- 现在（网关 `gateway.ts`、`media-gateway.ts`，计费 `reservations.ts`）：
  - 成功但上游没报用量：按本地分词估算（中文字 ×0.7、英文词 ×1.3 等原规则；新增每张图 1000 token、每条消息 4 token）计费，`SettleInput.actualEstimated`。仍受冻结上限保护（只扣冻结范围内、不透支、差额不向用户补扣），结算快照标 `usageEstimated`，用量记录标「估算」。
  - 失败：上游报了用量照旧；只有估算（正文为空 / 截断）用估算；什么都没报时，明确拒绝类（密钥、余额、限流、请求错误、服务商报错）按 0 计，网络中断 / 超时按估算输入 token 由平台吸收（用户不付钱），标估算。
  - 媒体调用：本地有数量（例 决策调用估算的输入 token）同样按估算结算；连数量都没有的保持「成本待核」，但不再暂停。
  - `beginCall` 不再因同路由有待核调用而拒绝新调用；`billing.call_cost_unknown` 事件不再暂停线路，只计入连续缺用量。缺用量也不再触发「换线路」（只按错误类别决定）。
  - 冻结、结算、失败吸收、待核核实（cost-resolution）其余逻辑不变；进程中断造成的「成本待核」仍按 `docs/ops/unknown-cost-resolution.md` 核实（文档已加更新说明）。
- 连续缺用量提示：`model_routes` 新增计数（0124）。上游报了用量清零；缺一次 +1；连续 5 次（`USAGE_MISSING_ALERT_STREAK`）写审计 + 发一条管理员提醒（`upstream_usage_missing`，info 级，只进后台提醒列表、不推送），本轮不再重复。后台模型列表「状态」列显示「连续 N 次没返回用量 · 按估算计费」（悬停看线路与起始时间），线路照常使用。
- 对账：「对账与平台花费」每日对账新增「估算计费」列（当天条数 + 记账金额），上游账单比对里也带估算条数；估算不算异常、不标红。调用记录列表 token 列加「估算」标签。
- 0124 迁移：把以前因「用量未知」被暂停的线路恢复启用并去掉暂停标记。

## 遗留 / 需要注意
1. **估算会有偏差**：本地分词是近似值，推理模型隐藏的思考 token 估不到（可能少收）；图片按每张 1000 token 估。估算条数多的线路建议检查中转是否返回 usage。
2. 网络中断 / 超时（含连接都没建立的情况）按估算输入 token 记平台吸收成本，可能略高于实际；明确报错的失败按 0 计（假设供应商不收费）。
3. 进程崩溃后恢复的调用仍是「成本待核」（没有正文可估），不再暂停线路，但需按 `docs/ops/unknown-cost-resolution.md` 核实。
4. 0124 会把所有带「用量未知」暂停标记的线路重新启用；如果某条是暂停后管理员又故意停用的，也会被启用（没法区分）。回滚 0124 不会恢复暂停。
5. models.dev 价格是官方价，中转站实际价不同；「售价」预填官方价、「成本」不预填。上下文按官方真实值预填（很多模型 100 万），每条回复预冻结会变大（回复后按实际退回）；如果用户余额少常被拦，可在抽屉里把上下文改小。
6. models.dev 的显示名可能带「(latest)」之类后缀，预填后可改。
7. 服务器需能访问 `https://models.dev`（公开、无需密钥）；访问不了时后台会提示，手填照常可用。
