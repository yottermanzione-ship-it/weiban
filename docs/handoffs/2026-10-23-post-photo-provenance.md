# 普通图片的出处核验规则（2026-10-23，未接线）

> 这批只做**判断规则**，不做抓取、不接线、不在线上生效：普通图片目前仍然是不发送的状态。目的很明确——先把「什么才算可以发的真实照片」写死成代码，避免再出现拿网页封面凑图。

## 规则：五项同时成立才放行

1. **页面就是那条原帖**：页面里的规范地址必须和期望的原帖地址完全一致（新闻页、转载页一律不认）。
2. **人物对得上**：页面标注的作者必须包含已核实的人物账号 ID；**账号 ID 为空直接拒绝**，不允许凭昵称猜人。
3. **图片是原帖自己的图**：只接受微博/新浪图片 CDN 的 https 地址；其它站点一律视为「网页封面」，直接拒绝；`data:`、http 也拒绝。
4. **时间可核验且新鲜**：必须是可解析的 ISO 时间，不能是「昨天」这种自然语言；默认只认 7 天内，未来时间（超过 5 分钟时钟偏差）同样拒绝。返回的是**原帖发布时间，不是拍摄时间**。
5. **有原帖配文**：文案少于 4 个字符视为没有配文，拒绝——没有配文就没法保证「图文对应」。

另外提供一个对外说明函数，固定输出「配图来自公开原帖（某日发布），非实时拍摄」，防止把旧图说成刚拍的自拍。

## 一次修复、一次复测

- 首轮 9 条测试有 1 条失败：**账号 ID 为空时，`includes('')` 恒真，身份核验被绕过**。这是测试真正抓到的漏洞，不是测试写错。
- 修正为「ID 为空直接拒绝」后只复测一次，9/9 通过，类型检查同时通过；测试到此停止。

## 现在还不能做什么

- **没有接线**：没有新增抓取、没有调用任何网络、没有接进朋友圈或聊天发送链路，因此线上行为完全不变，普通图片仍然不发。
- 真实微博页面是否稳定提供这些元数据、图片 CDN 是否覆盖全部图片，都**没有实测**；如果实际页面缺字段，规则会直接拒绝（宁可没有图，也不发错图）。
- 下一步才是接线：用既有安全出站链路抓原帖页面 → 本规则判断 → 通过后落库为媒体 → 发送时附出处说明。真正启用前需要用真实页面样本核对，再决定是否打开开关。
