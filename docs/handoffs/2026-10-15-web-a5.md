## 核查与改动

总经理 T1.16.11 与 11 号 A5 要求删除手填称呼、初始使用昵称、后续在长期聊天自然形成。现有问题不只是入口：普通回复使用 contact.addressAs 覆盖 profile.nickname，通话也读旧值且无值时直接叫“你”，玩法/主动/关怀/提醒另有同样读取。

- `chat-settings.tsx` 删除「TA 怎么叫我」、addressAs sheet 状态和分支；关系类型沿用原 FieldSheet、30 字、必填与既有后台关系政策。保存仅 PATCH relationship，不再附带备注或历史 addressAs。源码核实联系人更新采用字段 patch，省略字段不会被清空。A1 已删小程序行，本批没有重做或恢复。
- 普通/试聊回复从用户当前昵称取初始资料，称呼提示统一为“初识时以此称呼；后续自然延续真实对话与记忆形成的称呼”，不要求永远照昵称叫；{{user}} 宏与安全兜底也不再由 contact.addressAs 覆盖。
- 通话通过已有 IdentityReadPort 读取昵称；AiRuntimeModule 本已导入 IdentityModule，没有新模块依赖或新 API。通话未配置、语音模型和真实 ASR/TTS 均未实测。
- 主动、玩法、经期关怀复用现成昵称与同一提示辅助函数；群聊安全关怀兜底以最小资料读取获取昵称，读取失败回退“你”，不额外阻断关怀；提醒直接用现有 ctx.nickname，删除只为旧称呼发起的联系人查询，发送前的联系人资格检查保留。
- 历史字段、存储、契约与更新 API 保留，不批量清理数据。广场隐私检查继续把历史 addressAs 视为隐私词。真实聊天/记忆中已有称呼自然保留，不抹除用户原对话；没有新建称呼写回系统、关系等级或确认流程。

`user-naming.ts` 只提供昵称与提示文字辅助，没有模型调用。`offline-naming-context.json` 为该实际函数的离线输出；不是模型或整条回复链执行证明。
