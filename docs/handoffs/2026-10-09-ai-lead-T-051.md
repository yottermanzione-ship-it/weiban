## 做了什么

实现了推演引擎第一版（D-L3-01）：

1. 数据库迁移 0019：新增 `ai_runtime.simulation_states`、`ai_runtime.daily_events`、`ai_runtime.mood_states` 三张表（含 up/down）。
2. Drizzle 表定义写入 `infra/db/schema.ts`。
3. 推演引擎服务 `application/simulation.ts`：
   - 每天凌晨 2:00（北京时间）扫描活跃角色对，每角色入队一个推演 job。
   - 单角色推演：purpose=simulation、modelRole=background、countAsBackground=true，走后台网关，计入用量记录与计费。
   - 每日至多 1 次调用（幂等键）；每次至多 8 条事件（SIM-12 规模控制）。
   - 余额/预算不足时静默暂停（pausedReason），不影响聊天（SIM-12 降级）。
   - 长期不活跃（>=14 天无消息）时推演暂停（SIM-13）。
   - 暴露 `SimulationReadPort`（getDailyEvents / getCurrentMood），供 T-052 读取。
4. `application/lifecycle.ts` 注册推演 job worker 和每日 cron（`RUN_DAILY_SIMULATIONS_JOB`）。
5. `ai-runtime.module.ts` 注册 `SimulationService` 并 exports `SIMULATION_READ_PORT`。
6. 评测用例 `packages/ai-evals/cases/l3.ts`：14 道，覆盖 SIM-01（10 道，通过线 90%）、SIM-02（4 道）。
7. 实现说明 `docs/ai/simulation-engine.md`。

## 遗留问题

1. **markActive 调用缺失**：`SimulationService.markActive()` 已实现，但 `lifecycle.ts` 的 `chat.message_created` 订阅目前未调用它（原有逻辑只处理回复计划和记忆）。`simulation_states` 依靠第一次推演 job 运行时初始化，活跃更新需要 T-052 或后续版本补充。如果活跃时间不更新，角色会在 14 天后因「inactive」暂停。建议在 T-052 任务中或另开一个小 commit 调用 `markActive`。

2. **角色人设上下文**：当前推演提示词是通用模板，没有传入角色的人设、情景模式、关系网。等 T-052 主动消息调度成熟后，可以把 `CharacterReadPort.getCard(characterId)` 的人设片段加入推演提示，让事件内容更贴合角色。这不影响当前验收标准。

3. **EvalCase 类型**：`packages/ai-evals/cases/l3.ts` 中的 `category: 'simulation'` 和 `severity: 'soft'` 需要 `EvalCase` 类型支持；如果 `EvalCase` 目前只有 `'memory'` 等类别，需要架构/质量负责人在契约中补充这两个枚举值。

4. **数据库连接 API**：`simulation.ts` 中直接使用 `this.db.db`（两级 db），与 memory.ts 等现有代码一致；若 Database 包装层接口有变动，需同步修改。

## 给其他负责人的交接

**给主动消息调度 T-052（ai-lead 自己或后续迭代）：**

T-052 可以通过注入 `SIMULATION_READ_PORT`（从 `AiRuntimeModule` exports）读取推演数据：

```typescript
// 在 T-052 的 module 中 import AiRuntimeModule
// 然后注入：
@Inject(SIMULATION_READ_PORT) private readonly sim: SimulationReadPort

// 读取今天的日常事件（date 格式 YYYY-MM-DD）：
const events = await this.sim.getDailyEvents(userId, characterId, '2026-10-09');

// 读取当前心情：
const mood = await this.sim.getCurrentMood(userId, characterId);
```

类型定义在 `apps/server/src/modules/ai-runtime/application/simulation.ts` 中导出：`DailyEventEntry`、`MoodEntry`、`SimulationMood`、`EventKind`。

**给 Codex 质量验收：**

验收标准对照 T-051 任务卡，关键检查点：
- 迁移 0019 的 up/down 都已提供；可用 `pnpm db:migrate` + 手动回滚验证。
- 推演调用走后台网关（purpose=simulation，countAsBackground=true）：集成测试应断言 `usage_records` 中有对应记录。
- 余额耗尽时推演暂停：可用 `BillingTestQueries` 置零余额后触发推演 job 验证。
- 长期不活跃暂停：将 `lastActiveAt` 改为 15 天前再触发推演 job 验证。
- 每角色每天事件数 <= 8：模型输出超过 8 条时 Zod 校验会拒绝，静默跳过。
