用户列表（`/accounts`）· 会员订阅记录（`/membership-records`）· 充值记录（`/recharge-records`）· 套餐与价格（`/plans`）。

### 2. 用户列表（参考旧版 UsersPage「搜用户 → 开会员」）
- 顶部：总用户数、PRO+ 会员数（点了筛选列表）、7 天内到期名单（点名字直接打开该用户的「会员」页，超过 12 人有「全部 N 人」切到筛选）。
- 搜索：账号 / 昵称 / 用户 ID；快捷筛选：全部 / PRO+ / 7 天内到期 / 已封禁。
- 列表：昵称 + 登录名、会员（7 天内到期标橙）、余额（含赠送）、近 30 天消耗、注册 / 活跃、状态（正常 / 已封禁 / 注销中）。
- 点一行打开**用户详情抽屉**，5 个标签：
  - **基本资料**：登录名、昵称、ID、身份、注册、最近活跃、状态、会员、封禁信息。
  - **会员**：当前档位、到期、剩余天数、首次价是否用过；按钮「开通 / 续期」「调整到期日」「取消会员」（确认框）；下方是该用户的订阅记录，点一行开详情抽屉。
    - 开通 / 续期（子抽屉）：三档卡片，系统按该用户是否用过首次价自动显示首次价或原价（可手动关掉首次价），预览「本次收多少、会员到哪天、送多少积分」，确认框后提交；幂等键一次打开一个，重复点不会重复开通。
    - 调整到期日（子抽屉）：日期 + 快捷 +7 / +30 / +90 天 + 必填原因；明确提示「不记订单、不收钱、不发积分」。
  - **积分**：余额 / 赠送积分 / 充值积分（= 余额 − 赠送）/ 冻结中；「加 / 扣积分」子抽屉（扣积分有确认框）；流水表（可加载更早）。
  - **用量**：近 30 天消耗、调用次数（含失败）、平台成本；常用模型前 10（按消耗排序、占比）。
  - **封禁与删除**：封禁（必填原因 + 确认框；已封禁显示时间 / 原因 / 操作人，可解封）；删除账号（必须输入登录名 + 原因，确认框；走和用户自助注销同一套删除流程）。管理员账号两项都不可用；注销中的账号只显示说明。
- 所有子抽屉都是右侧抽屉（叠在详情抽屉上），点遮罩只关最上面那层；编辑类子抽屉接了 E1 的草稿（关闭留草稿、再开提示恢复 / 丢弃）。

### 3. 会员订阅记录
只列会员相关：开通、续期（订单）+ 手动调整到期日、取消会员（新的调整记录表）。筛选：时间范围、类型（月 / 季 / 年卡、手动调整 / 取消）、首次价（不限 / 只看首次价 / 只看原价）、账号 / 昵称 / ID。点一行开详情抽屉；点用户名打开用户详情抽屉。每类每次 100 条，可「加载更早的记录」。

### 4. 充值记录
只列积分充值：管理员加积分、扣积分、注册赠送（开通会员送的积分不在这里，在订阅记录里）。筛选：时间、类型、用户；显示当前列表加积分合计。点一行开详情抽屉，点用户名打开用户详情（积分页）。

### 5. 套餐与价格
一页三块：PRO+ 档位（原价 / 首次价 / 折扣 / 开通赠送 + 用户端联系说明）、充值档位（价格 / 到账积分 + 联系说明）、注册赠送积分。页面只展示，点「编辑」在右侧抽屉里改（价格改为按「元」填写，自动换算成分；首次价高于原价会定位到该格报错）。

### 6. 后端补的接口（契约 3.21）
- `AdminUsersEndpoints`（identity）：`GET /admin/users`（资料 + 会员 + 封禁）、`GET /admin/users/overview`（总数、PRO+ 数、7 天内到期名单）、`POST /admin/users/:id/ban`、`POST /admin/users/:id/unban`、`POST /admin/users/:id/deletion`（管理员替用户注销，需登录名确认 + 原因）。
- 封禁：`identity.users` 新增 `banned_at / ban_reason / banned_by`。封禁即作废全部会话（发 `session_revoked`，实时连接会断）；`SessionService.create` 拒绝给封禁账号发新会话（登录、注册重试都走这里，提示「该账号已被封禁」，403 forbidden，密码校验通过之后才提示）；`verify`、`isActiveAppSession` 也拒绝封禁账号。管理员账号不能封禁 / 删除。
- 会员调整记录：新表 `identity.membership_changes`；`PUT /admin/users/:id/membership`（`SetMembership`）加可选 `reason`，每次真正改动都记一行；新接口 `GET /admin/membership/changes`（按用户、时间筛选）。注销删除时随账号级联删除，并加进了 identity 的残留计数。
- 订单：`listOrders` 加 `from / to / planId / firstPurchase` 筛选；`MembershipOrder` 加可选 `renewal`（生效开始晚于下单时间 = 续期）。
- 计费：`AdminAccountSummary` 加可选 `bonusBalanceMicros / bonusBalancePoints`；新接口 `GET /admin/billing/topups`（管理员加扣 + 注册赠送，排除 `membership_bonus`），返回带 `userId / username / kind`。
- 安卓生成物已更新（3.21，1469 个定义）。

## 遗留 / 需要注意
1. **封禁只挡登录和会话**：封禁期间角色的主动消息、角色生态等后台活动不会因此停止（仍按积分扣费）。如需「封禁即暂停所有后台活动」，要各模块接入，另开任务。
2. 封禁沿用通用错误码 `forbidden`（没新增错误码，避免客户端改动）；客户端显示服务器给的中文提示。
3. 用户列表一次拉全部账号（上限 5000）在前端搜索，内测规模够用；用户多了要改成服务端分页搜索。
4. 会员订阅记录由「订单」和「调整记录」两个接口在前端合并排序；点「加载更早」时两边各翻一页，跨页边界的先后顺序可能有一两条不严格。
5. `renewal`（续期）按「生效开始晚于下单 1 秒以上」推断，没有新存字段；历史订单同样适用。
6. 「充值记录」的「加积分」包含所有管理员手动加积分（补偿也算），原因写在备注里区分；`kind` 只分加 / 扣 / 注册赠送。
7. 开通会员的确认框按钮是红色（公共 `useDangerConfirm` 的样式），与旧页面一致，未改公共组件。
8. 管理员替用户删除后，审计里保留管理员填写的原因，账号删除完成时随审计匿名化流程处理（只记用户 ID 哈希）。
