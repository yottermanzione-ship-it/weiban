## 做了什么

1. **记忆分档**（后台可调，默认按 16 号 §5.3）：常驻 免费 3 / PRO+ 16；记忆库 免费每角色最早 30 条参与（其余不删，开通即恢复）/ PRO+ 不限；摘要 免费最近 7 天 / PRO+ 全部（年度回忆在 `renderStableMemory` 留了 `annual` 口子，暂无数据）；每次回想 免费 3 / PRO+ 8。用户删除记忆仍立即删除（原逻辑不变）。
2. **新用户前 7 天按 PRO+ 记忆**（从注册时间算，天数后台可调）。只送记忆，不含长上下文。
3. **翻聊天记录**（照旧版）：本轮出现回忆意图词时，在「原文窗口之前、删除屏障之后」的聊天里两字片段打分取最相关 3 条原话，放动态结尾，格式「用户：… / 角色：…」。复用 chat 端口的服务器内存解密读取（ADR-0027 补记方案 A），不建明文索引。免费只翻最近 7 天，PRO+ 全部；每次最多扫 2000 条。
4. **长上下文模式**：聊天信息页 › 高级，PRO+ 才显示开关；打开前弹窗说明「每条约 X 积分（是平时的 N 倍左右）」（按所选模型当前售价经报价端口估算，估不出就如实说）。原文窗口从约 1.6 万字放到约 14.5 万字（约 10 万 token），分段稳定窗口参数同步放大。非 PRO+ 调接口打开返回 403；会员到期自动按关闭处理。
5. **留住人**：平台守则加「不主动结束对话 / 挽留一次 / 坚持放行留期待 / 不内疚不纠缠 / 考试上班身体不适深夜犯困关怀中不挽留」；冷场（嗯、哈哈、好…或只发表情）或告别时，在写作提示后追加一句本轮提示（首次告别撒娇留一次、30 分钟内第二次告别放行、有正事或凌晨 1–5 点说困改为关心）。安全关怀中不加。
6. **记忆页**显示「TA 能记住的范围」（档位 + 各项实际范围），没有任何开通引导文案。
7. **后台**新增「系统 › 记忆分档」页（Ant Design）：两档参数、新用户天数、翻聊天记录条数、长上下文窗口。
8. **评测集**补 20 题（只登记材料，未跑模型）：`KEEP-001~013` 留住人、`RECALL-001~005` 翻聊天记录与档位、`TIER-001~002` 不诱导 / 不越过删除屏障。版本 `2026-10-20.1`。

- 改动位置：守则加一段（开头，只在上线那一次让所有会话开头缓存失效一次）；本轮提示在深度 4 的写作提示里（本来就每轮变）；翻到的旧聊天在动态结尾（只在用户提旧事时出现）。

## 遗留问题

- **批 A 合并时改接**：`MemoryTierService.membershipSnapshot()` 一处改为批 A 的统一「是否 PRO+」查询即可（注册时间已走 identity 新端口，若批 A 也提供可一并替换）。批 A 若新增专门的「需要会员」错误码，`settings.ts` 里长上下文的 403 `forbidden` 可换成它。
- 契约版本：本批 3.17，与 A / C 并行，合并时版本号冲突由总负责人处理。后台菜单 `menu.tsx` / `app.tsx` 各加一行，可能与批 A 新页面行冲突，按两边都保留合即可。
- 翻聊天记录不越过「删除屏障」：用户在记忆页改 / 删过任何一条记忆后，屏障之前的旧聊天不能再翻（这是原有删除语义——删掉的事不能从原话里回来）。代价是改过记忆的用户能翻的范围变小。如要放宽，需要按「被删记忆的来源消息」精确排除，属于后续改进。
- 记忆库容量按「最早记下的 30 条」参与；免费用户若想让新事参与，需删旧的。记忆页只写了范围，没有逐条标注「暂不参与」（避免像诱导文案）；要不要逐条标，产品可再定。
- 年度回忆只留了口子，没有生成逻辑。
- 「约每条积分」用固定口径估算（平时按 1.2 万 token 输入 80% 命中、长上下文按 10 万 token 90% 命中、输出 300），实际以扣费为准；批 A 的「最近 7 天平均消耗」上线后可改用同一数据源。
- 评测集只登记了材料，没有真实执行器，需在真实模型上跑一轮前后对比（重点 KEEP-001 不主动赶人、KEEP-005 坚持放行、TIER-001 不诱导）。
- 18 号提到的国内拟人化陪伴监管要求（防沉迷、不诱导情感依赖），正式上线前需核实；本批守则已写明不内疚、不纠缠、不拿离开做筹码。
