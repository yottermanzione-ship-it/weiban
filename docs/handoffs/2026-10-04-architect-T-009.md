## 做了什么

1. **安卓客户端选型（ADR-0011）**：对比了 Kotlin + Jetpack Compose、React Native、Flutter，比较维度是原生体验、能和网页复用多少、AI 写代码是否熟练、推送 / 保活 / 来电 / 通话、国内厂商推送、调试和打包。**结论：Kotlin + Jetpack Compose。** 本地数据库用 Room，网络用 OkHttp，后台任务用 WorkManager；契约先导出 JSON Schema，再自动生成 Kotlin 代码；原生桥 `bridge.ts` 删除。代价是两端各写一套界面和同步引擎，用协议一致性测试用例来控制风险。
2. **计费（ADR-0012 + `billing.md`）**：新增 `billing` 模块，`model-access` 改为管上游（平台密钥）、模型目录和模型网关。
   - 钱一律用整数「微元」记，流水只增不改。
   - 扣费方式是预授权：调用前先冻结一笔估算金额，调用完按实际用量结算，失败就全额解冻。
   - 余额不足时不调上游；加余额后补一次合并回复。
   - 后台每日上限、平台每日总上限、管理员加扣余额（要填原因、带幂等键）都已设计。
   - 对账分三层；价目表按版本发布，同时记成本价和售价。
   - 聚合服务的建议：国内模型走官方（百炼 / DeepSeek）；国内没有的模型（如无审查模型）再走境外聚合服务（如 OpenRouter）；不用非官方中转站。
3. **成人模式（ADR-0007 修订、`hard-boundaries.md` v1.1）**：
   - 资格只看两条底线：非儿童、非真人。
   - 年龄确认、群聊禁用、需配置成人模型、内容隔离、法律禁止清单都移出 policy。「需配置成人模型」保留为功能前提；其余按 PRD v1.2 执行。
   - 新增「无审查模型闸门」：无审查模型只能给有成人资格的角色用。
   - 已并入总负责人的补充决定：
     - 「真人」的定义收窄：以真实人物本人身份呈现。以真人为灵感、换了新名字的角色算原创。系统只看分类字段。
     - 古人 / 虚构角色的形象图裁定已删除，`portraitPolicy` 简化为 forbidden / allowed。
     - 主题切换只在客户端，不影响契约。
4. **消息链路对比（ADR-0013）**：把现方案和 OpenIM、Matrix/Synapse、Tinode 做了对比。**结论：维持自建方案。** 三家用的可靠机制和我们是同一类；把它们搬进来会让消息和业务数据分在两个系统里，资源占用也大。从它们那里借鉴了两项：会话级缺口自检、协议一致性用例；另外给 L1 验收补了两个破坏性用例。
5. **同步更新**：
   - 架构文档：overview、dev-plan（新增 D-L0-16～19、D-L1-09，以及各层安卓任务；删除 BYOK / Capacitor 任务）、message-reliability、security-and-privacy、repo-structure、engineering-standards（新增 R9、金额规则、安卓规则）、prd-answers、tech-debt。
   - ADR：0003、0004、0005、0006 的状态行；0007 的修订记录。
   - 契约升到 v0.2，变更清单见 `packages/contracts/README.md`「变更记录」。
6. **顺带处理**：
   - pnpm 基线定为 **11**（理由写在 ADR-0003）。
   - 批准设计负责人申请的角色展示字段：应援色、头像字、图案、主题色。
   - 头像上传接口：管理员上传 `character_avatar`；用户上传通讯录头像的接口原来就有。

## 遗留问题

- 契约 v0.2 仍然**没有编译验证**（TD-011），需要 D-L0-04 跑通 typecheck。
- `packages/contracts/test-vectors/` 还没建，列为 D-L0-17。
- **与 PRD v1.2（T-010）需要对齐的地方**：年龄确认、群聊情景模式限制、成人范围的推送隐藏 / 记忆隔离 / 分享图排除，这些现在都写成「以 PRD v1.2 为准」。契约里暂时保留了 `age_not_confirmed`、`group_conversation` 两个错误码和 `ageConfirmed` 字段；如果 PRD 取消，在契约 1.0 时删除。余额不足提示、微伴服务入口的界面归产品 / 设计。
- 余额提醒线的默认值没有定，需要产品给出一个 PRD 参数。后台每日上限沿用 cost-estimate 里的 3 元。
- 历史人物（如李白）属于真人分类，原「古风插画」例外随裁定删除后，按推论变成「不生成本人形象」，需要总负责人确认（见下文）。
- AI 文档（`docs/ai/runtime-overview.md` 第 2.3、2.4 节，`model-catalog.md`，`cost-estimate.md`）还保留着 BYOK 的表述和旧的 portraitPolicy 枚举，需要 AI 负责人更新（我没有越界修改）。
- `docs/design/default-avatar.md` 第 2 节「管理员不能为真人配图」已经和第二轮意见冲突，归设计负责人更新。
- ADR-0009（角色卡）还是「提议」状态，在 D-L0-10 评审。

## 需要总经理决定的事

无。以下两件需要**总负责人**确认，不需要总经理拍板：
1. 历史人物在删除古风插画例外后，按真人规则「不生成本人形象」——这个推论是否成立。
2. 成人模式下，「真人角色、儿童角色的输出守卫要检查性内容」这一条保留为底线在生成层的执行（我认为是两条底线的必然要求）——请确认不属于被取消的限制。
