## 做了什么

### 1. 计费上限去掉「资料来源链接」「核对日期」（F2-1）
- 契约 `RouteBillingBounds.sourceUrl` / `checkedAt` 改为可选。后台表单只剩上下文长度 / 最大输出 / 输出参数名 / 最多图片数。
- 核对时间改由服务器在保存时记下（`CatalogService.stampBounds`）：「用量未知暂停」仍按它判断先后，不会误停刚重新保存的线路。
- 数字没改时原样提交原来的计费上限（保留核对时间和暂停标记）；改了数字或勾选新加的「已重新核对，保存后恢复这条线路」= 重新核对，暂停解除（线路上的「启用这条线路」也要勾）。
- 导入配置不再要求 `price_source`，也不再有资料链接列。

### 2. Anthropic（Claude 原生）协议（F2-2）
- 上游账号新增协议「Anthropic · Claude 原生（/v1/messages）」（`UpstreamKind = anthropic`），添加 / 编辑账号可选、可改（改协议与改地址一样清空暂停，需重新测试）。地址填中转给的 Claude 地址，带不带 `/v1` 都行。
- 新适配器 `model-access/infra/anthropic-adapter.ts`，网关按线路所在账号的协议选用（`RoutingTextAdapter`，同一模型的多条线路可以一条 OpenAI 兼容、一条 Anthropic）：
  - 开头连续的系统消息 → 顶层 `system`；中间 / 结尾的系统消息改成用户消息并注明「系统提示，不是用户说的话」（不是所有 Claude 都支持对话中插 system）；不合并相邻消息，保证每轮开头逐字节相同；
  - 缓存断点（与 09 号 §6 稳定开头一致）：开头系统消息末尾 + `meta.stablePrefixChars` 覆盖的最后一条整消息（断点随原文追加后移，上游往回找到上一轮写入的缓存）。默认 5 分钟缓存；
  - 图片：data URL → base64 图片块（jpeg/png/gif/webp），放在文字前；
  - `max_tokens` 必填；**不发 temperature**（新一代 Claude 不接受非默认采样参数）；思考关 = 对支持的新模型发 `output_config.effort = low`，不发 thinking 字段；
  - 流式（SSE）读取，累积文字、记首字耗时（写入调用记录 `ttftMs`）；中转忽略 stream 直接回 JSON 也能解析；要求 JSON 时去掉 ```json 围栏；
  - 读回 `input_tokens` / `output_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` 及 `cache_creation.ephemeral_5m/1h_input_tokens` 分项（没有分项时全部按 5 分钟）；
  - 错误归类：401/403 密钥无效、402 / billing_error / 「credit balance」等余额不足、429 限流、5xx / overloaded 上游错误、refusal → 内容被拒。
- 连通测试与「拉模型列表」：`GET {base}/v1/models`（x-api-key）；中转没有模型列表（404/405）时发一个故意不完整的 Messages 请求只校验密钥（不生成、不扣费）。每分钟的恢复探测也按账号协议走（原来写死 OpenAI 兼容）。

### 3. 缓存写入计价（F2-3、F2-7）
- 模型价格新增「缓存写入 · 5 分钟」「缓存写入 · 1 小时」（可选，售价与成本都有）；价目表单位 `cache_write_5m/1h_tokens_per_million`，只在填了时写入；没填 → 按普通输入价计。
- 计费：`UsageQuantities.cacheWrite5mTokens / cacheWrite1hTokens`；`priceUsage` 计价（缺价回落输入价）；冻结上限 `priceUsageCeiling` 按「输入 / 缓存读取 / 缓存写入」里最高单价覆盖全部输入，冻结不会少冻；结算、失败吸收、对账都走同一算式。
- 用量记录新增两列（0118），后台调用记录详情与导出 CSV 显示缓存写入；看板缓存命中率分母含缓存写入。
- OpenAI 兼容通道只报告缓存读取，缓存写入看不到，按输入价计（任务卡口径）。
- 导入配置认 `cache_write_5m` / `cache_write_1h`（也认 `cache_write` = 5 分钟档）；中转「分档价格」只取基础档（文件里的 input/output/cache），其余字段忽略——后台没加分档字段（需要时另开任务）。
- 顺手修了一个已有问题：调用失败但上游报告了用量时，网关把 `estimated` / `reported` 等说明字段一起交给计费，会被用量校验拒绝；现在只交计价字段（`billableUsage`）。

### 4. 去掉「图片识别」场景（F2-4）
- 用户端模型配置只剩 6 个场景；图片随「文本聊天」模型（私密模式下随「私密模式」模型，`media-ai` 的看图 / 表情包识别按会话 contentScope 选模型角色）。模型不能识图时 `capability_missing`，不再改用别的模型。
- 契约 `ModelScenario.vision` 保留只为旧客户端能解析，服务器不再返回、忽略写入；`listModels?scenario=vision` 返回能识图的文本聊天模型。
- 0119 迁移：用户 / 角色的图片识别配置删除（用户只配了图片识别、没配文本聊天且该模型可用于文本聊天时转成文本聊天）；模型的「可用于图片识别」勾选、推荐模型里的 vision 去掉；三张表的场景约束不再允许 vision。
- 后台：场景勾选去掉图片识别；勾了文本聊天 / 私密模式但没勾「识图」能力 → 抽屉里即时黄条提示，保存时再确认一次（可「仍然保存」），列表状态列显示「缺识图能力」。导入配置的新模型默认勾识图（总经理的聊天模型都是多模态）。

### 5. 「暂时无法使用」写清原因（F2-5）
- 新契约 `ModelUnavailableDetail`：已下架 / 没有启用的线路 / 上游账号已停用 / 上游密钥无效 / 上游余额不足 / 连接异常被健康检查暂停 / 连续失败短暂暂停 / 缺计费上限 / 用量核对未通过已暂停 / 价目表没有价格 / 最大输出不够一条回复。
- 服务器 `CatalogService.availabilityDetails` 逐条线路判断（多条都不行时报「离可用最近」的原因），用于：用户端模型列表（`unavailableDetail`）、场景配置（`ModelRefState.unavailableDetail`）、聊天横条（`ModelStatus.detail`；原来报价失败会误报「还没给 TA 选可用的模型」，现在写明最大输出太小 / 缺计费上限 / 没价格）、后台模型列表（`availability`）。线路层面的问题（缺计费上限、暂停）现在也算不可用，和网关实际能否调用一致。
- 后台：模型表「状态」列挪到第二列，写出原因（计费上限类可点开直接定位），悬停有处理办法；上游账号表新增「协议」、异常原因（密钥无效 / 余额不足 / 连接异常被暂停及最近错误 / 连续失败暂停到几点）；手动测试结果写清是密钥、余额还是网络。
- 用户端：模型名后红框短标签（余额不足、计费未配置…），页面下方与聊天横条给完整一句话。
- **Bai 的 MiMo**：线上为何不可用我没法查（不碰服务器）。上线后在后台模型列表「状态」列直接能看到原因；按任务卡排查方向，最可能是计费上限缺失 / 最大输出小于 600，或上游测试没通过被标异常。

### 6. 排行榜自动获取（补充 F2-6）
- 模型新增「榜单对应名称」（`arenaModelName`，0120；导入配置取文件 `arena_model`，后台抽屉可编辑）。
- 服务器每天 04:20（北京）抓后台填的来源链接，后台「立即刷新」；解析页面内嵌 JSON / HTML 表格；按名称（不区分大小写）完全匹配原榜名次。抓取失败保留上次结果，后台卡片写明失败时间与原因。
- **arena.ai 实测（10-21）**：对服务器请求返回 Cloudflare 人机验证页（403「Just a moment...」），没有公开数据接口；平台不绕过人机验证，所以**自动抓取目前会失败**，已实现兜底：后台「粘贴导入」——浏览器里整表复制粘贴（制表符 / 一格一行都认）或上传 CSV（表头 rank、model）。网站以后放开时自动抓取即可生效。
- 用户端名次：本次返回的列表里有名次的模型按原榜名次重新编号 1、2、3…N（原榜 1、3、4、9 → 1、2、3、4），不显示原始名次；匹配不到的用手填名次（原榜名次口径），都没有就不上榜。来源日期显示榜单快照日期。后台卡片列出匹配 / 没匹配的模型。
