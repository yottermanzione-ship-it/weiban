# 2026-11-08 扫码付款与到账监控交接

范围由经理明确确认：积分＋会员，微信/支付宝两个旧收款码，另做收款到账监控。实现和开发自测见[专项报告](../quality/2026-11-08-scan-payment-monitor.md)。当前候选默认关闭支付，不能说已经正式收款。

## 后台与用户入口

- 后台：**用户 → 扫码收款**。配置收款码与开关、一次性监控配对、唯一设备启用、订单与到账分页、待核对关联、漏报账单登记。
- 用户：**我 → 服务 → 积分 → 充值**、**PRO+会员**。网页和安卓共用。**积分 → 扫码付款记录**可以查看最近10单，即使收款后来关闭也可查看。
- 手机软件只给收款管理员安装，普通用户无需安装；正式独立包 `微伴收款监控-1.0.0.apk`，直接桌面根目录，微伴主应用3.0.0/127不更换。

## 正式收款交接（需要经理批准旧站例外）

旧服务器原授权仅只读，当前未修改。旧代码以 `POST /api/pay/orders` 建立订单，扫码通知有独立入口；最终操作前还需核对线上正在使用的入口与配置。建议：暂停旧站新增扫码订单，已有订单至少等待15分钟并核对未付/迟到记录；旧监控最后补报、确认队列清空，再停止旧站独立认单；新监控接管后启用新站。

新旧金额池不能直接重叠。切换时需避免近期旧订单金额被新单立即复用，检查汇总金额占用或安排排空时间；已有截图迟到付款仍须人工核对。任何无法唯一归属的到账不自动开会员或加分。整个过程保留旧聊天、密码、用户和旧账目，不借机执行用户迁移。

## 经理最后要点的操作

以下要等后台正式发布、旧收款交接完成再付款；权限和配对可以先准备。

1. 在**实际登录收款微信、支付宝的安卓手机**安装桌面监控包。后台“用户 → 扫码收款”填设备名称，点“新增监控配对”，十分钟内把一次性信息粘到手机并点“配对这台手机”。后台再点“设为唯一监控”。配对信息不要发进对话或文档。
2. 手机点“开启通知使用权”，允许微伴收款监控；点“开始监控与补报”，按系统提示允许运行状态通知。收款应用保持登录且开启到账通知，手机允许后台运行并联网。后台“刷新”后应显示“正在监听”。
3. 开通后用测试账号创建一笔小额积分订单，按页面**精确金额**微信付款。正常：付款页显示“已到账”，积分增加恰好等于实际付款金额乘100，后台只有一次入账。
4. 用支付宝完成另一笔小额订单；会员可选实际需要的档位，核对有效期与赠分。无法用最低费用验证真实会员时，不要替用户做无需求的付费；自动化已经覆盖会员履约，但真实支付仍写未验证。
5. 支付通知到来时离开监控界面、锁屏，确认可以到账；断网后恢复应补报，迟到单进入“待核对”，不会自动认给新买家。不需要发送付款人姓名、完整账单、聊天或密码。
6. 如显示“未能识别”，先对照真实账单，在后台相应订单点“核实漏报到账”，填写实收金额、支付机构交易编号和依据；已存在到账记录时优先用已有记录核对，避免重复登记。本软件不退款。
