   - `importer` → `ai-runtime`
   - 其余上层模块（`proactive`、`moments`、`growth`、`library`、`play`）不能 import 任何其他上层模块。反方向改用事件。

   - `calls` 是中层，原有 R2 已经禁止它 import `ai-runtime`（`CallAgentPort` 按约定由装配入口注入）。

3. **顺带登记 ai-runtime → proactive**：T-053 / T-060 已在用（`proactive-scheduler.ts`、`health-care.ts` import `../../proactive/index.js`），已写进白名单，注释写明「待架构在 ADR-0024 补记」。

## 遗留问题

- **契约对照表和 ADR 不一致（上报，未选边）**：`contracts-3.0-map.md` 第 4 节写 T-078（library）「使用 `MomentsReadPort`」，但 ADR-0024 和同一份对照表第 3 节的上层白名单里**没有 library → moments**。lint 按 ADR 执行，所以 library 直接 import `../moments` 会报错。不卡开发的做法：library 在**自己的**模块里定义一个注入令牌（类型用契约的 `MomentsReadPort`），由 `app.module.ts` 把 moments 的实现绑上去，这和 `calls` / `CallAgentPort` 的做法一样，不需要改 lint。如果架构决定直接把 library → moments 加进白名单，改 `UPPER_LAYER_ALLOWED_DEPS` 一行即可。
- 「plaza 只能经 `CharacterPlazaPort` 访问 characters」：架构文档写的是设计约定，没要求 lint 强制，按任务卡「不自行新增限制」没加规则。plaza 仍然只能 import characters 的 `index.ts`（R1）。
- 新规则没有补单元测试（本轮约定），留给 Codex 整体验收时补，或下一轮运维补到 `packages/eslint-config/test/module-boundaries.test.ts`。
- `engineering-standards.md` 第 3 节 R2 一行还写的是「上层 → 中层 → 底层」，没有提上层之间的白名单（文档归架构，运维不改）。
