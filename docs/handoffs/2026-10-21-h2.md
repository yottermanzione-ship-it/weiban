## 做了什么（按 6 条）

### 1. 私密模式只开放文字与图片
- **语音通话**：`calls` 模块按私聊会话的内容范围判断——私密模式下入口状态返回 `private_mode`（契约新增），拨打返回 `private_mode_unsupported`（422，新错误码），角色来电也不发起。
- **语音输入**（按住说话 = 发语音消息、服务器转文字）：`chat/write.ts` 在私密范围会话里拒绝语音消息（含带语音的转发记录），提示「私密模式只支持文字和图片，暂时不能发语音」；`media-ai.render` 在私密范围不做语音识别（兜底）。
- **角色发语音**：私聊回复本来就只在日常范围配语音（未动）；生态 / 主动消息在私密范围不发语音（生态不再提供「语音」动作，主动消息执行时再拦一次）。
- **网页**：私密模式下「按住说话」切换按钮、＋面板「语音通话」、通话记录回拨、角色资料页「语音通话」置灰，点了提示原因；从日常切到私密时自动回到键盘输入。开启私密模式的说明补了一段（只支持文字和图片；切回时整理一份不含露骨描写的简短记忆，消耗少量积分）。

### 2. 私密模式期间记忆抽取、摘要用私密模型
G1 已做（私密那段的抽取 / 摘要用 `modelRole: 'adult'`），本批确认未改动。

### 3. 切出私密模式时的「干净整理」
- **触发**：切出私密模式（切到自动 / 日常 / 任何非私密模式）时，在切换的同一事务里登记一行任务（新表 `ai_runtime.private_digests`，`(会话, event_key)` 唯一）。`event_key` 以这次切换为准：手动切换用切换 ID（同系统提示的幂等键），私密模型不可用导致的自动切回用该次回落的键 → **同一次切出只生成一次**。切换本身不等它（异步任务 `ai.private_digest`）。
- **生成**：读「上一次切出之后到这次切出」的私密消息（最近最多 200 条 / 1.6 万字，去掉经期、撤回草稿、拍一拍），交给**该用户的私密模型**（`purpose: memory`、`modelRole: adult`、`billingOwner: user` → **按用户积分扣**，计入后台功能），要求写不超过 200 字的第三人称摘要，露骨内容只概括为「亲密行为」等。
- **把关**：输出必须能解析、不含露骨字眼（比聊天违禁词更严的词表，含身体部位与动作细节）、不含经期信息、过违禁词规则，否则算一次失败重试。
- **写入**：一条**日常（normal）范围**记忆「（私密模式期间的经历整理）……」，类别「共同经历」，重要度 8（进稳定记忆块，日常聊天一定带上），只这个角色知道、不跨角色转述；之前的整理降到重要度 6，只留最新一条常驻。用户在「我们的记忆」里可见、可改、可删。日常聊天、群聊、生态读日常范围记忆时都能用到。
- **失败可重试**：普通失败按 5 分钟 → 30 分钟 → 2 / 6 / 12 小时重试，最多 6 次；余额不足 / 预算 / 并发上限不计次数，6 小时后再试，14 天后放弃；角色已没有私密资格或模型被禁止 → 跳过（不再把私密内容交给任何模型）。每分钟的 `ai.reconcile` 负责重投到点的任务；意外异常也记一次失败，不会每分钟空转。
- **原私密记忆**、原文仍是 adult 范围，只在私密模式可见，没有改动。

### 4. 角色处于私密模式时，生态动作强制私密模型
- 判断：该角色私聊会话内容范围为 adult 且角色有私密资格。
- 决策调用改用私密模型（`modelRole: adult`；行为规划用途不允许私密模型，所以改用 `proactive` 用途，不再用后台配置的决策模型）；发私人朋友圈、点赞评论朋友圈也走私密模型；发私聊消息本来就随会话走私密模型（未动）。
- 期间不提供「发语音」「去群里说话」两个动作（只开放文字图片、仅单角色）。快照仍只读日常范围，私密内容不进生态、不出私密范围；朋友圈输出仍按日常范围检查。
- 「发照片」用的是图片生成模型，不是文字模型，照常。

### 5. 私密模式的安全关怀由私密模型生成
- 私聊：疑似风险的判断原来交给平台安全检查模型（会把私密原话发出去），现在私密范围改交该用户的私密模型；关怀回合本来就走私密模型，动态结尾新增「这一轮的关怀要求」（停下亲密成人内容、确认安全、12356 / 110 / 120、不提供方法）。
- 次日关怀跟进（主动消息）：私密范围改由私密模型生成并加关怀要求（原来是平台模型却带着私密原文）；私密模型调不通时退回平台关怀模型，但只给日常范围的聊天。关怀输出一律按日常范围检查。
- 通话的关怀回合同样改为私密模型（遗留自 call-scope-fix 的问题），虽然私密模式已不能通话。

### 6. 「私密通话」相关修复保留
`call-scope-fix` 的私密通话摘要写 adult 保留；入口关闭后不再发生。

## 遗留 / 需要注意
1. **已有数据**：上线前已经切出过的私密时段不补整理；上线后第一次切出会把「上次切出之后」（没有记录则从会话开头）的私密消息一起整理（最多最近 200 条）。
2. **资格被收紧导致的切回**（`onClassificationChanged`）不登记整理：此时角色已无私密资格，按规则不再把私密内容交给任何模型。
3. **生态在私密模式期间不用后台配置的决策模型**，改用该用户的私密模型（行为规划用途不允许私密模型）。私密模型输出生态决策 JSON 的稳定性没实测，运行记录里看 `bad_output` 比例。
4. **安全关怀的判断与跟进改为用户付费**（私密范围）：余额 ≤ 0 时疑似风险判断调不通，按原逻辑视为不高危（高危关键词规则仍生效）；跟进会退回平台模型（只带日常聊天）。
5. 整理摘要的干净检查是词表，可能误拦（算一次失败重试，6 次后放弃）或漏过隐晦说法；记忆页用户可删。
6. 安卓原生端只重新生成了契约：原生聊天如有按住说话 / 通话入口，需按 `private_mode` 置灰（网页壳内已生效；服务器两头都会拒绝）。
