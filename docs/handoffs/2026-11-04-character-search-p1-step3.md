## 结论

1. 「联网查找」的每个候选现在带**一句身份说明、逐项出处、未核实标记**。身份说明只按固定规则从公开结果里摘（百科标题括注「李晨（中国内地男演员）」、摘要首句里以这个名字开头、带职业 / 作品词的那一段），摘不出就写「暂未核实身份」，**不调用模型、不编**。
2. **同名不误合并**：只有同一个公开资料条目（同一个百科 / 维基 / 豆瓣 / Bangumi / 萌娘条目的不同网址）才并成一项；两位李晨是两个百科条目，永远分开。名字、头像、网页里的一句话都不算证据。固定语料（30 组同名、90 人、320 个网页）误合并 **0**。
3. **后台人工修正**（新页面「角色 → 搜索身份修正」）：把公开资料条目和本站官方角色登记成一个「实体」、填写核实过的身份说明和出处，可以合并 / 拆分；官方角色的搜索别名先「添加（待审核）」，通过后才进站内搜索，人设里的别名可以从搜索里去掉 / 恢复。**每次修改必须写原因**，记审计（谁、何时、改了什么、原因），页面能看到修正历史；改完后对应角色的站内搜索几秒内自动刷新。
4. 后台关联过的站外候选显示「**添加 / 去聊天**」（直接到本站官方角色）；没关联的只能「自行创建 / 申请官方制作」。**点击只提交候选 ID**，服务器重读保存的候选和当前关联再决定，客户端改网址、改名字都拿不到添加按钮；添加仍走原来的添加闸门。
5. 费用不变：S 的每人每日 20 次 / 全站 5000 次 / 每分钟 5 次额度、公共查询缓存、按实际供应商结果计费都没改。**同一个词并发查询只打一次供应商**（后到的等先到的那次结果落进缓存，命中不计费）。空白、一个字、超过 64 字、像私人信息的词都不发站外请求。

## 1. 服务端

### 站外候选结构化（model-access）

- `domain/web-candidates.ts`（纯函数）：供应商结果 → 候选（最多 5 个，每个最多 5 条出处）。
  - 公开资料标识（`platform/search/public-identity.ts`，model-access 和 characters 共用所以放平台内核）：只从网址结构取「一页一个条目」的编号 / 条目标题——`baike:<百度百科义项编号>`、`sogou:`、`baikecom:`、`wiki:<zh|en|ja>:<条目>`、`wikidata:Q…`、`douban:celebrity|personage:`、`bangumi:character|person|subject:`、`moegirl:<条目>`。只有名字没有义项编号的百度百科页（可能是多义词页）、消歧义页、分类 / 搜索 / 特殊页都不算。**不看网页正文**。
  - 合并键 = 标识（没有标识时 = 规范化网址）。候选 ID = `web_` + 合并键的 SHA-256 前 22 位（base64url），同一条目每次都一样，不含查询和用户。
  - 身份说明：标题括注或摘要首句（必须以候选名字开头），带职业 / 作品 / 所属词、不超过 40 字；像指令的文字（忽略、系统、管理员、已核实、你现在是、prompt、ignore…）一律不要。每条身份都记 `identitySourceUrl`。
  - 公开人物 / 虚构作品过滤：网页是认识的百科条目，或标题 / 摘要里有公开身份、作品类词；隐私词、电话、邮箱、内网地址在此之前已被 S 的规则丢掉。
- `application/web-candidates.ts`（`WebCandidateSearch`，实现契约端口 `WebCandidateSearchPort`，令牌 `MODEL_WEB_CANDIDATES`）：顺序与 S 原来完全一样——隐私词 → 联网搜索是否开通 → `consumeCandidate` 额度 → 网关 `webSearch`（`search_candidates` 用途、平台付费、查询格式不变）→ 结构化 → 保存候选快照。**供应商调用不在任何事务里**；不调用文本模型。
- `media-gateway.ts` 两处改动（只对 `search_candidates` 用途）：
  1. 租约被占用（同一个词正在查）时，后到的每 200ms 领一次租约（每次一个短事务，等待期间不占连接），最多 15 秒；先到的结果落进公共缓存后直接读缓存（命中不计费）。原来是立刻返回「暂时不可用」。
  2. 写进公共缓存的结果只留通过公开人物 / 作品过滤的网页；**计费仍按供应商原始结果**（有结果计 1 次、空结果 0 次），不变。
- `web-tools-store.ts`：`saveCandidates`（单条语句 upsert，按候选 ID 排序写入）、`readCandidate`（未过期才读）；维护任务顺带清理过期快照。
- 原 `http/search.controller.ts` 删除，同一路径、同一契约搬到 plaza（见下）。

### 实体关联与后台修正（characters）

| 表（迁移 0158） | 内容 |
|---|---|
| `model_access.web_candidates` | 候选快照（显示名、标题、摘要、身份、出处、标识），24 小时过期；不存查询原文、不存用户 ID |
| `characters.search_entities` | 实体：实体键、显示名、核实的身份说明、出处（≤5） |
| `characters.search_entity_identifiers` | 公开资料标识 → 实体（主键 = 标识，一个标识只属于一个实体） |
| `characters.search_entity_characters` | 官方角色 → 实体（主键 = 角色，一个角色只属于一个实体；角色硬删级联） |
| `characters.search_aliases` | 后台搜索别名（pending / approved）与从搜索里去掉的人设别名（blocked） |
| `characters.search_terms` 加列 | `entity_key`、`source_url` |

- 新表都**不存操作人 ID**；谁、何时、改了什么、原因写 `platform.audit_log`（`module = characters`，动作 `search.*`，注销时随审计一起匿名化）。平台内核 `AuditLog` 新增只读的 `list()`，后台按对象读修正历史用。
- 实体键 = 第一个可识别的公开资料标识；都没有时为平台人工关联的 `manual:<uuid>`。标识或角色已属于别的实体时，「关联」返回 409，必须显式「合并」或先取消。
- 投影刷新复用第 1、2 步的待刷新机制：三张新表的写入由触发器在同一事务里登记 `characters.search_dirty`，服务端照旧分批刷新（刷新者只用 SKIP LOCKED）。官方角色投影现在叠加：后台实体的身份说明优先、被去掉的人设别名不进、通过的后台别名进，并写入实体键与第一条出处。站内聚合结果的 `entityKey` / `sourceUrl` 从此有值。
- `SearchEntityService`：所有后台写操作一个事务（锁实体行、锁别名行，按键排序加锁），事务内不调用其他模块端口；读人设别名（同模块 `CharacterService`）和查管理员用户名（identity 端口）都在事务外。
- 后台接口 `SearchAdminController`（`/api/v1/admin/search/*`，管理员）：实体列表 / 详情 / 新建 / 修改身份与出处 / 关联 / 合并 / 拆分，官方角色别名查看与修改。

### 聚合与点击（plaza）

- `SiteSearchController` 新增 `POST /search/character-candidates`（原路径原契约）和 `POST /search/character-candidates/resolve`。
- `SiteSearchService.webCandidates`：model-access 出候选 → characters 给实体关联（`CharacterSearchPort.resolveEntities`）→ `mergeWebCandidates`（只按登记的实体合并，实体的显示名和核实身份优先）→ 重新核对关联的官方角色是否仍上架（`searchCards`）、是否已是好友 → 动作 add / chat / create。
- `resolveWebCandidate`：只收候选 ID，重读快照与**当前**关联；关联还在且角色仍上架 → add / chat；否则 → create，并给出服务器保存的公开资料作预填。过期 / 不存在 → 404。

## 4. 与方案不一致或需决定的地方

1. **身份说明不调用模型**：方案允许「模型最多归纳已有公开结果中的身份说明」，这里一律按固定规则摘取，没有模型调用、没有新增费用，也就不存在提示词注入面；代价是摘不出时只能写「暂未核实身份」。如以后要用模型归纳，需要另开任务并核算费用。
2. **`POST /search/character-candidates` 的实现从 model-access 搬到 plaza**（路径、契约、额度、计费都不变）。原因：要组合 characters 的实体关联和 contacts 的好友状态，model-access 是被 characters 依赖的中层，不能反过来引用它们；plaza 是上层，第 1、2 步的聚合层也在这里。model-access 仍是唯一的站外出口（经 `WebCandidateSearchPort`）。
3. **并发同词的行为变化**（只对联网查找）：原来同一个词正在查时，后到的请求直接返回「联网查找暂时不可用」；现在等最多 15 秒读先到的那次结果（缓存命中，不计费、不再打供应商）。额度照旧每次主动查询计一次。这是任务卡「同一个词并发只打一次供应商」的落实方式。
4. **公共缓存多一道公开过滤**：S 原来缓存所有非隐私结果；现在联网查找只缓存通过公开人物 / 虚构作品过滤的网页（方案原文要求），所以少数普通网页不再出现在候选里。计费仍按供应商原始结果。
5. **「未核实」的口径**：只有后台填写过身份说明的实体才算「已核实」；从百科标题摘出的身份也标「未核实」（但附出处）。如果希望百科条目标题里的身份直接算已核实，请总负责人定。
6. 站内结果不为空时也显示联网查找入口（第 2 步只在为空时显示），否则搜不到同名的另一位；入口文案按方案改为「查找公开人物或作品」。
7. 新增字段在契约里都是可选的（次版本规则：只加可选字段），5.6 服务器总是给出。
8. 平台内核 `AuditLog` 新增只读 `list()`（后台修正历史用），属于平台改动。
