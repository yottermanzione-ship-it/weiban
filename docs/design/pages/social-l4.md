> 已有说明（本次不改，只引用）：群聊页、选择角色页、群聊信息页 `group-chat.md`；朋友圈主页、发朋友圈页 `moments.md`；通讯录、角色广场、添加流程 `contacts-add.md`；名片消息气泡 `ContactCard`（C 4.2）；资料页未添加态 `character-profile.md` 第 7 节。本文补齐这些页面里「点进去之后」的子页面和状态。

## 1. 结论

- 所有新增页面都对齐参照产品的同名页面：群聊列表、修改群名、@ 选人、朋友圈个人相册页、动态详情、朋友圈消息列表、新的朋友。
- 名片的全流程是：**聊天里的名片 → 资料页（未添加态，底部「添加到通讯录」「不感兴趣」）→ 打招呼弹层 → 等待通过**，与 `contacts-add.md` 第 3 节的添加流程完全一样，只多一个「不感兴趣」。
- 新增一页「TA 认识的人」：只给自定义角色用，让用户手动设定自定义角色之间的关系（SOC-01 第 3 条）。这是 PRD 有要求、此前没有画的页面。

## 2. 群聊

### 2.1 群聊列表（通讯录 › 群聊）

```
┌────────────────────────────────┐
│ ‹             群聊              │
├────────────────────────────────┤
│ [群头像] 火锅小分队（4）           │  ContactItem（C 3.3）变体：GroupAvatar（C 2.2）+ 群名 +（人数）
│ [群头像] 杨幂、王一博、肖战（4）     │  群名未改时显示成员名拼接
├────────────────────────────────┤
│             2 个群聊              │  底部计数（footnote、text.tertiary）
└────────────────────────────────┘
```

- 列出用户当前所在的全部群（参照产品只列「保存到通讯录」的群；微伴群数量少，全部列出更简单）。按最近消息时间倒序。
- 点行 → 群聊页。左滑无操作（删除并退出只在群聊信息页做，避免误触解散）。
- 空：EmptyState「还没有群聊 · 在会话列表右上角 ⊕ 可以发起群聊」。

### 2.2 @ 选人弹层（SOC-04、C 4.6）

- 触发：输入框输入「@」，或长按群里某个角色的头像（直接插入，不弹层）。
- 底部弹层（高度 = 屏高 × 0.6）：标题「选择提醒的人」；SearchBar；成员行（头像 40 + 名字，有备注显示备注）；不含用户自己。
- 点一行 → 关闭弹层，输入框插入「@名字 」并保持键盘弹出。关闭弹层不插入时，已输入的「@」保留为普通文字。
- 群里只有 1 个角色时（其余都被移出）：直接插入，不弹层。

### 2.3 修改群名

- 群聊信息页「群聊名称 ›」→ 推入页：TextField（单行，≤ 16 字，占位为当前默认名），右上「完成」（无变化时禁用）。
- 保存后群里出现会话内提示「你修改群名为『火锅小分队』」；角色在群里提议改群名（SOC-03 第 2 条）时，提示为「杨幂 修改群名为『XX』」。
- 清空后保存 = 恢复默认名（成员名拼接）。

### 2.4 加人与移出（群聊信息页 MemberGrid）

| 操作 | 表现 |
|---|---|
| 点「+」 | 推入选择角色页（`group-chat.md` 第 3 节），已在群里的成员显示为已选且锁定（实心灰勾）；可选人数 = P-21 − 当前人数 |
| 加入不具备当前情景模式资格的角色 | 完成前不提醒；加入后群聊回到日常，会话内提示（`group-chat.md` 第 4 节，不变） |
| 点「−」 | 进入删除态：每个成员头像左上角出现 20 的红色减号（`status.danger`），「−」变为「完成」；点减号 → 立即移出，群里提示「你将 XX 移出了群聊」 |
| 移到只剩 1 个角色 | 允许（群仍存在）；移出最后一个时「−」禁用，说明「群里至少要有 1 个角色，不想要这个群可以『删除并退出』」 |
| 群成员超过 10 人 | 不会发生（P-21 上限 9 个角色 + 用户） |

### 2.5 群里的未添加角色（SOC-06 第 3 条）

- 群聊里点未添加角色的头像或名字 → 资料页未添加态（`character-profile.md` 第 7 节），底部「添加到通讯录」→ 打招呼弹层，打招呼默认文字「我们在『火锅小分队』群里见过」（可改）。
- 通讯录已满（P-26）→ Dialog「通讯录已满 50 个角色，先删除一些再添加吧」。
- 在群里该角色的名字与已添加角色无差别显示（不加「未添加」标记，参照产品群里也不区分好友与非好友）。

### 2.6 群聊状态补充

| 状态 | 表现 |
|---|---|
| 群聊信息页加载中 | MemberGrid 位置 5 个 48 圆角灰块；列表行骨架 |
| 群聊信息页加载失败 | EmptyState「加载失败」+「重试」 |
| 删除并退出后 | 会话列表移除该群；从通知点进来：EmptyState「这个群聊已解散」 |
| 群被系统自动解散（例如最后一个成员角色被彻底删除） | 群里最后一条提示「群聊已解散」；输入栏替换为灰字「你已不在该群聊中」（C 5.1） |
| 消息免打扰开启 | 会话列表该群显示灰点而不是数字（C 6.3），被 @ 时仍显示「[有人@我]」并推送 |
| 角色自己聊天中（SOC-05） | 不推送；会话列表只显示未读数 |

## 3. 朋友圈子页面

### 3.1 某个角色的朋友圈（资料页 › 朋友圈）

对齐参照产品的个人朋友圈页：封面 + 按日期的相册式列表。

```
┌────────────────────────────────┐
│ ‹                               │  NavBar 透明，下滑后实色（同 moments.md）
│ ┌────────────────────────────┐ │
│ │        封面（屏宽 × 0.75）      │ │  MomentsCover（C 10.3）：该角色的封面
│ │                  杨幂 [头像]  │ │
│ └────────────────────────────┘ │
│ 今天    [图72] 上海站，谢谢大家～    │  左列日期：「今天 / 昨天」或「5」(title1) +「10月」(caption1)
│                                │  右列：有图 = 第一张 72 方图 + 文字两行；纯文字 = bg.page 底的文字块
│ 3 10月  ┌────────────┐            │
│         │ 收工！        │           │  纯文字动态：bg.page 底、radius.sm、内边距 space.3，最多 3 行
│         └────────────┘            │
│ …                              │
└────────────────────────────────┘
```

- 同一天多条动态共用一个日期，竖向排列。日期列宽 56，`fontFamily.numeric`。
- 点某条 → 动态详情页（3.2）。
- 显示哪些动态（例如是否包含添加之前发的）以服务器返回为准，界面不做额外过滤。
- 用户自己的朋友圈（我 › 朋友圈）用同一版式，右上角多一个相机按钮（发朋友圈）；封面可点 → ActionSheet「更换封面」→ 选图（裁剪为 4:3）。
- 状态：加载 = 3 行骨架（日期块 + 72 方块 + 两行文字）；空 =「TA 还没有发过朋友圈」/「你还没有发过朋友圈」；加载更多失败 = 底部「加载失败，点击重试」。
- 该角色在资料页里关闭了「TA 的日常」（SIM-13）：已有动态照常显示，不加说明。

### 3.2 动态详情页

- 推入页，标题「详情」；内容为一张完整的 MomentCard（C 10.1）：正文不折叠、图片网格、点赞行、**全部评论**；底部固定评论输入栏（同朋友圈主页的评论输入栏）。
- 入口：个人朋友圈页点条目、朋友圈消息列表点条目、推送「杨幂 回复了你的评论」。
- 动态已被删除（用户删了自己的动态）：EmptyState「该动态已删除」。
- 右上角「…」：角色动态 → 收藏、生成分享图；自己的动态 → 删除（Dialog「删除这条朋友圈？」）。

### 3.3 朋友圈消息列表（「1 条新消息」胶囊进入）

```
┌────────────────────────────────┐
│ ‹            消息            清空 │  「清空」→ ActionSheet「清空所有消息」（只清这个列表，不删评论）
├────────────────────────────────┤
│ [头像40] 杨幂            [图56]   │  右侧：动态第一张图 56 方块；纯文字动态显示前 12 字的 bg.page 块
│          哈哈哈你也去了！           │  评论内容（subhead）；点赞显示 16 大拇指图标（不用爱心，D-18）
│          10:24                  │  时间（caption1、text.tertiary）
├────────────────────────────────┤
│        查看更早的消息               │  文字按钮
└────────────────────────────────┘
```

- 进入后先只显示未读的消息，底部「查看更早的消息」加载已读的。
- 点一行 → 动态详情页并滚动到该条评论（评论行闪一下，同 QuoteBlock 定位）。
- 空：「暂无消息」。

> 点赞图标：用户端朋友圈的点赞沿用 C 10.1 的现状（参照产品是爱心）。人设广场的点赞用大拇指（D-18）。消息列表跟随朋友圈本身的点赞图标，不单独换。

### 3.4 谁可以看（发朋友圈页 › 谁可以看）

```
┌────────────────────────────────┐
│ 取消          谁可以看          完成 │
├────────────────────────────────┤
│ 全部角色                        ✓ │  ListCell 选择型
│ 部分角色可见                    › │  选中后下方显示已选角色名（footnote，最多 2 行省略）
└────────────────────────────────┘
```

- 「部分角色可见」→ 通讯录多选页（同选择角色页的列表样式，无数量上限，至少选 1 个才能完成）。
- 发表后在自己的动态时间行右侧显示 16 的「部分可见」小人图标（`text.tertiary`），点击 Toast「仅 3 个角色可见」。
- 说明行（footnote）：「看不到的角色不会点赞评论，也不会在聊天里提起这条动态」（SOC-09 验收）。

### 3.5 发朋友圈补充

- 图片区使用 ImagePickerGrid（C 21.4），上限 9。
- 发表中、失败的表现见 `moments.md` 第 5 节（不变）；断网时「发表」照常可点，动态以「发送中」状态排在顶部，联网后自动发出。
- 离开时有内容：ActionSheet「保留此次编辑 / 不保留」（参照产品同款）。

## 4. 新的朋友（CHR-04、CHR-05）

替换 `contacts-add.md` 1.2 的简述。

```
┌────────────────────────────────┐
│ ‹           新的朋友              │
├────────────────────────────────┤
│ 🔍 搜索角色                       │  点击 → 角色广场（预设角色分页）并聚焦搜索框
├─ 近三天 ───────────────────────┤
│ [头像48] 王一博           [ 添加 ] │  名片推荐：第二行「杨幂 推荐」
│          杨幂 推荐                │
│ [头像48] 肖战               等待中 │  已发打招呼、等待通过
│          来自 角色广场             │
├─ 更早 ─────────────────────────┤
│ [头像48] 罗小黑              已添加 │  text.tertiary
│ [头像48] 张三               已忽略 │  点过「不感兴趣」的名片
└────────────────────────────────┘
```

- 行结构：头像 48 + 名字（`fontSize.body`）+ 第二行来源（`fontSize.subhead`、`text.secondary`）；右侧：Button sm primary「添加」或状态文字（`fontSize.subhead`、`text.tertiary`）。
- 来源：「XX 推荐」（名片）、「来自 角色广场」、「来自 人设广场」、「来自 群聊『XX』」。
- 点行（按钮以外）→ 资料页（未添加 / 等待 / 已添加态）。
- 左滑 → 删除（只删这条记录）。
- 红点规则：有新的名片推荐时，通讯录「新的朋友」行右侧红点 + 底部「通讯录」标签红点；进入本页后消失。添加记录本身不产生红点。
- 状态：加载 = 行骨架 × 4；空 = EmptyState「还没有新朋友 · TA 的朋友们会通过名片介绍给你」（不变）。

## 5. 名片（CHR-04）

| 步骤 | 表现 |
|---|---|
| 收到名片 | 私聊里出现 ContactCard（C 4.2）；同时「新的朋友」出现一条「杨幂 推荐」记录并亮红点 |
| 点名片 | 资料页未添加态，底部两行：「添加到通讯录」（`text.link`）、「不感兴趣」（`text.secondary`） |
| 添加到通讯录 | 打招呼弹层，默认文字「是 杨幂 推荐我来的」（可改，`contacts-add.md` 第 3 节）→ 等待通过 → 通过后会话列表出现新角色，TA 的第一条消息会提到推荐人（由 AI 保证） |
| 不感兴趣 | 直接生效，不二次确认；Toast 文字型「好的，不会再推荐 TA」；「新的朋友」里该记录变「已忽略」；名片本身外观不变（消息已发出、高度不变），再点仍可进资料页并添加 |
| 已经添加过 | 名片照常显示；点开是资料页已添加态 |
| 通讯录已满 | Dialog「通讯录已满 50 个角色，先删除一些再添加吧」 |
| 被推荐的角色已下架（ADM-01 第 5 条） | 资料页未添加态底部只有灰字「TA 暂时不能添加」（`text.tertiary`），没有按钮 |
| 名片出现在群聊里 | 规则相同 |

- 长按名片：收藏、删除（无复制、无引用）。

## 6. TA 认识的人（自定义角色之间的关系，SOC-01 第 3 条、CHR-07 第 5 条）

入口：**自定义角色**的资料页列表，在「关系类型」行下方增加一行「TA 认识的人　2 个 ›」。只有用户拥有 2 个及以上自定义角色时才显示；预设角色的资料页没有这一行（预设角色的关系由管理员维护，用户看不到关系表）。

```
┌────────────────────────────────┐
│ ‹          TA 认识的人         ＋ │  ＋ 添加关系
├────────────────────────────────┤
│ [头像40] 阿青              朋友 › │  ListCell：头像 + 名字，右侧关系类型 + 亲疏（如「朋友 · 亲密」）
│ [头像40] 小白        同事 · 熟悉 › │
├────────────────────────────────┤
│ 只有你创建的角色之间可以设置关系。设置后  │  说明（footnote、text.secondary）
│ TA 们会在群聊、朋友圈里互相认识。       │
└────────────────────────────────┘
```

- 「＋」→ 推入表单页：
  - 对方 *：选择页，只列用户的其他自定义角色（已有关系的不列）；没有可选时「＋」禁用。
  - 关系类型 *：ChoiceChip 单选：朋友 / 家人 / 同学 / 同事 / 搭档 / 其他（选「其他」时出现 TextField，≤ 8 字）。
  - 亲疏 *：ChoiceChip：点头之交 / 熟悉 / 亲密。
  - 右上「完成」。
- 关系是双向的：在 A 这里添加，B 的「TA 认识的人」里也出现 A。
- 点一行 → 同一表单（编辑），底部危险按钮「删除关系」→ Dialog「删除后，TA 们不会再在群聊、朋友圈互动，也不会再互相提起；以前的聊天记录会保留」。
- 涉及儿童角色（年龄设定「未满 18 岁」）时，关系类型里没有任何恋爱向选项（本表本来就没有恋爱向选项，无需额外处理）。
- 状态：加载 = 行骨架；空 = 一行说明「还没有设置关系」+ 文字按钮「添加」。

> 这一页需要接口支持「自定义角色之间的关系」的增删改查。架构 D-L4-01 写了「自定义角色之间的关系」，但契约里是否已有对应接口未确认，已在索引第 4 节上报。

## 7. 平台差异

- 两端相同。安卓：@ 选人弹层打开时系统返回 = 关闭弹层；朋友圈个人页封面下拉没有回弹放大效果（两端都不做，避免大图缩放重绘）。
- ≥ 900px 宽屏网页：群聊列表、新的朋友在左栏，点进的资料页 / 群聊在右栏打开（`02-interaction-flows.md` 第 6 节）。
