# 首次使用引导

## 1. 目的与入口

新账号几分钟内和第一个角色聊上天；从登录到发出第一条消息不超过 5 次页面跳转（ACC-04）。界面走法见 `../02-interaction-flows.md` 5.1。

## 2. 页面序列

| 步骤 | 页面 | 结构 | 组件 |
|---|---|---|---|
| ① | 登录 / 注册 | 品牌插画（星星 + 对话气泡）+ 「微伴」字标 + 一句话「像加上了自己爱豆的微信」+ 登录表单（方式由架构定）+ 主按钮 | EmptyState 式插画、TextField、Button lg |
| ② | 你的昵称（1/2） | 顶部步骤点（2 个，当前为品牌色）；标题「TA 该怎么称呼你？」（`fontSize.title2`）；昵称 TextField（必填）；可选：头像、生日、城市（折叠在「补充更多资料（可选）」下）；底部主按钮「下一步」 | TextField、ListCell、Button lg |
| ③ | 配置模型（2/2） | 标题「给 TA 接上大脑」；说明「微伴使用你自己的模型密钥，费用由你直接付给供应商」；PromoBanner「不知道选哪个？看排行榜」；主按钮「填写密钥」；文字按钮「稍后再说」 | PromoBanner、Button、ListCell |
| ④ | 角色广场（引导模式） | 同 `contacts-add.md` 第 2 节，顶部不可关闭的 InlineTip「先加一个你喜欢的 TA 吧」；左上角无返回按钮 | 同角色广场 |
| ⑤ | 私聊 | 添加后直接进入私聊，显示「已发送好友申请」，等待通过 | 同私聊 |

- 引导页（②③）不显示 NavBar 返回，左上角为「‹」仅返回上一步；不显示标签栏。
- 页面切换用 M-01 推入动效。
- 跳过模型配置：私聊顶部显示「还没有配置模型」系统横条（C 7.1）。

## 3. iPhone 添加到主屏幕引导（ACC-05）

- 时机：iPhone Safari 中、未添加到主屏幕、收到第一个角色的第一条消息之后（不在登录前打断）。只自动出现一次。
- 形式：底部弹层（C 6.9 的容器样式），内容：
  1. 标题「添加到主屏幕，才能收到 TA 的消息提醒」；
  2. 三步图文（每步一行：序号圆点 + 图标 + 文字）：点底部「分享」按钮 → 选「添加到主屏幕」→ 从主屏幕打开微伴；
  3. 一张示意插画（Safari 分享按钮位置，画界面不画人）；
  4. 底部「知道了」主按钮。
- iOS 低于 16.4：弹层改为说明「当前系统版本收不到推送，消息会在打开微伴时显示」+「知道了」。
- 从主屏幕图标打开时不再出现；设置页可再次查看（`settings.md` 第 2 节）。
