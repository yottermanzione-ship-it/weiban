> 本文**替代** `contacts-add.md` 4.2 的六步简表（那一节改为引用本文）。角色编辑器仍以 `contacts-add.md` 4.3 为准。人设更新提示（CHR-10）已在 `character-profile.md` 第 2 节「资料已更新」，本文不重复。

## 1. 结论

- **一条主线、三种来源**：说明 → 放入内容（粘贴 / 上传文件 / 上传截图）→ 选「哪一方是 TA」→ 确认选项和花费 → 生成（可以离开）→ 编辑草稿并保存。截图多一步「确认识别出的对话」（CHR-08 第 1 条）。
- **花费在开始前说清楚**：开始按钮上方显示「预计花费 约 ¥0.70」（按价目表估算，CHR-08 第 7 条）；余额不够时不能开始。
- **原文默认删除**：选项默认关「保留原文」，生成完成后在编辑器顶部告诉用户「原始聊天记录已删除」。
- **生成中可以离开**：进度保存在服务器；「创建自己的角色」页有「进行中的导入」入口，完成时推送通知。

## 2. 导入聊天记录生成新角色（CHR-08）

入口：通讯录右上角 → 角色广场 → 底部「创建自己的角色」→ EntryCard「导入聊天记录」（`contacts-add.md` 4.1）。

### 2.1 第 1 步：说明与选择来源

```
┌────────────────────────────────┐
│ ‹          导入聊天记录             │
├────────────────────────────────┤
│ 从聊天记录里读懂 TA 的说话方式，      │  说明（callout）
│ 生成一个像 TA 的角色草稿。           │
│                                │
│ ┌ 粘贴文字 ─────────────────── ›┐ │  三张 EntryCard（C 15.7）纵向排列
│ ┌ 上传文件  .txt / .csv ────── ›┐ │
│ ┌ 上传聊天截图  最多 30 张 ──── ›┐ │  次要入口：放在最后
│                                │
│ ⓘ 微伴不直接读取微信数据。可以先用第三  │  InlineTip 中性（C 7.2 v2.2）
│   方工具把聊天记录导出成文字或 csv。   │
│ ⓘ 聊天记录里有其他人的信息，请只导入   │
│   你有权使用的内容。                  │
└────────────────────────────────┘
```

- 所选聊天模型不能识图、平台也没设默认识图模型：「上传聊天截图」卡片禁用，卡片内说明「当前模型不能识别图片，请先在 我 › 服务 › 模型 更换」（CHR-08 第 1 条）。

### 2.2 第 2 步：放入内容

**粘贴文字**

- 满屏多行 TextField（`fontSize.subhead`），占位「把聊天记录粘贴到这里」；右下字数「12,340 字」。
- 下方文字按钮「查看格式示例」→ 底部弹层：三种常见格式各举 3 行（`姓名 时间` 换行内容、`姓名：内容`、`[时间] 姓名: 内容`）。
- 超过单次上限（20 万字）：输入框上方 InlineTip 警告变体「超过 20 万字，只会取最近的 20 万字；也可以分批导入，分批的内容会合并进同一份草稿」。不阻止继续。
- 底部主按钮「下一步」（空时禁用）。

**上传文件**

- UploadArea（C 21.5）：「点击选择文件 · 支持 .txt、.csv」。
- 选好后显示文件行 + 下方预览前 10 行（等宽小字 `fontSize.caption1`，`bg.page` 底）+ 识别结果一行：「识别为：CSV（时间, 发言人, 内容）」或「识别为：文字聊天记录」。
- 编码无法识别 / 文件不是文字：文件行下红字「这个文件读不出来，请另存为 UTF-8 编码的 .txt」。

**上传聊天截图**

- ImagePickerGrid（C 21.4），上限 30；说明「请按聊天顺序排列，可以长按拖动调整」。
- 超过 30 张：选图后只保留前 30 张，Toast「一次最多 30 张，剩下的可以分批上传」（CHR-08 边界）。

### 2.3 第 3 步：识别

| 来源 | 表现 |
|---|---|
| 文字 / 文件 | 「正在识别发言人…」页内转圈（通常 1～3 秒）→ 直接进入 2.4 |
| 截图 | ProgressBar（C 21.3，确定进度）+「正在识别第 3 / 12 张」→ 进入 2.3.1 确认对话 |
| 识别不出两个以上发言人 | 错误页：EmptyState「没认出是谁在说话」+ 说明「每行需要带上说话人的名字」+ 按钮「查看格式示例」「返回修改」 |

#### 2.3.1 截图：确认识别出的对话

```
┌────────────────────────────────┐
│ ‹       确认识别结果           下一步 │
├────────────────────────────────┤
│ ⓘ 截图识别可能会认错说话的人，请检查一遍。 │  InlineTip 中性
│   点一条消息可以改成对方说的或删掉。     │
├────────────────────────────────┤
│ [灰头像]◀ 你今天几点下班      │       │  MessageRow（C 4.1）预览：左 = 对方，右 = 我
│          │ 六点吧 ▶[灰头像]           │  头像统一用中性默认头像，不显示真实头像
│ ── 第 2 张 ──                      │  每张截图之间一条 SystemTip「第 2 张」
│ …                              │
└────────────────────────────────┘
```

- 点一条 → ActionSheet：「改成对方说的 / 改成我说的」「删除这条」。
- 相邻截图重叠的部分已由识别去重；用户看到的就是去重后的结果。

### 2.4 第 4 步：哪一方是 TA

```
┌────────────────────────────────┐
│ ‹        选择要生成的角色            │
├────────────────────────────────┤
│ ○ 小王                  1,203 条  │  ListCell 选择型；右侧发言条数
│   「明天早点来」「哈哈你又迟到」      │  前 2 句示例（footnote、text.secondary，单行）
│ ● 阿青                   987 条   │
│   「那我先去占座」「好呀」           │
└────────────────────────────────┘
```

- 截图来源：只有「对方」和「我」两项，默认选中「对方」。

### 2.5 第 5 步：选项与花费

```
┌────────────────────────────────┐
│ ‹            开始生成              │
├────────────────────────────────┤
│ 保留原文以便以后补充        ( ○ ) │  默认关（CHR-08 第 6 条）
│ 默认生成后删除原文，只保留角色草稿和     │  说明（footnote）
│ 摘取的示例对话。                    │
├────────────────────────────────┤
│ 预计花费               约 ¥0.70   │  ListCell 只读；数字为价目表估算
│ 按当前模型和价目表估算，实际以余额明细为准 │  说明（footnote、text.tertiary）
│ 预计用时               3 分钟以内   │
├────────────────────────────────┤
│ [            开始生成            ]  │  主按钮
└────────────────────────────────┘
```

- 预计花费：接口给金额时显示「约 ¥X」；只给档位时显示「较少（约 1 元以内）/ 中等 / 较多」Tag（cost-estimate 第 5 节）。
- 余额不足以完成（CHR-08 第 7 条）：按钮禁用，按钮上方一行「余额不足，暂时不能生成」（`text.secondary`）+ 文字按钮「查看余额」。

### 2.6 第 6 步：生成中

```
┌────────────────────────────────┐
│ ‹                               │
│          [插画占位：书页]           │  EmptyState 尺寸的静态插画（素材待制作，占位用 Phosphor book-open 64）
│     正在读懂 TA 的说话方式…           │  callout
│  ━━━━━━━━━━░░░░░░░                │  ProgressBar（C 21.3）：知道进度用确定式，否则不确定式
│     大约还需要 2 分钟                 │  caption1、text.secondary；超时后改为「快好了」
│                                │
│   可以先离开，完成后会通知你            │  footnote
│ [            先离开             ]   │  secondary lg
└────────────────────────────────┘
```

- 「先离开」或返回 → 回到「创建自己的角色」页，页面顶部多一行 ListCell「进行中的导入 · 正在生成 ›」（有多个时显示数量），点进回到本页。
- 完成：推送「阿青 的角色草稿生成好了」→ 点击直接进入编辑器；若用户停在本页，自动进入编辑器。
- 超过 3 分钟：进度照常走，文字改「快好了」，**不显示失败**（CHR-08 第 5 条）。
- **失败**（模型出错、余额中途用完）：插画位置换成感叹号图标；文字「没能生成草稿：原因」；按钮「重试」（primary）、「放弃这次导入」（text）。余额用完的原因写「余额不足」+「查看余额」。放弃 = 删除原文和进度（Dialog 确认「放弃后已上传的内容会被删除」）。

### 2.7 第 7 步：编辑草稿

- 进入角色编辑器（`contacts-add.md` 4.3）：角色分类默认「真人」、改选需勾选声明、真名高亮提示等规则不变（CHR-08 第 4 条）。
- 编辑器顶部 InlineTip 中性（不可关闭，只显示在第一次打开时）：
  - 未保留原文：「原始聊天记录已删除，只保留了草稿和示例对话」；
  - 保留了原文：「原始聊天记录已保存，可以在 TA 的『我的补充设定』里继续补充」。
- 由导入生成的字段，标签后加 Tag 中性型「来自导入」，用户改过后 Tag 消失。
- 编辑器底部除「保存」外多一个文字按钮「继续导入下一批」（分批导入，内容合并进同一份草稿，CHR-08 边界）。
- 未保存就离开：ActionSheet「保存草稿 / 放弃」。保存的草稿出现在「进行中的导入」里（状态「待保存」）。

## 3. 我的补充设定（CHR-09）

入口：私聊 › 聊天信息 › 高级 › 我的补充设定。

### 3.1 补充设定页

```
┌────────────────────────────────┐
│ ‹          我的补充设定             │
│              杨幂                 │  副标题
├────────────────────────────────┤
│ 只对你这里的 TA 生效，不会改变其他人   │  说明（预设角色时显示）
│ 看到的 TA。                         │
├─ 已添加的设定 ──────────────────┤
│ 喜欢吃辣，最爱火锅              ›  │  ListCell，每条一行，点 → 编辑 / 删除
│ 说话爱用「嘿嘿」                 ›  │
│ 生日 3 月 1 日   与公开资料冲突，不生效 › │  冲突项：第二行 text.tertiary 说明（CHR-09 第 2 条）
├────────────────────────────────┤
│ [ 导入资料 ]        [ 手写一条 ]     │  两个 Button md：tonal + secondary
├────────────────────────────────┤
│ 发布为改版                      ›  │  预设角色才有（PLZ-02，persona-plaza.md 4.1）
│ 删除全部补充设定                    │  危险型行
└────────────────────────────────┘
```

- **手写一条**：推入 TextField 页（≤ 200 字），保存后加入列表。
- **导入资料**：与第 2 节同一套第 1、2、5、6 步（来源只有粘贴文字和上传 .txt；不需要选发言人），完成后进入 3.2 确认页。
- **删除全部**：Dialog「删除后，TA 会回到原本的设定」（CHR-09 第 4 条）。
- 空：列表区一行说明「可以把你收集的采访、语录导入进来，让这里的 TA 更像 TA」。

### 3.2 确认导入结果

- 列出生成的设定条目，每条前面一个勾选框（默认全选）；冲突项不勾选且不可勾选，后面写「与公开资料冲突：以公开资料为准」。
- 试图改变分类、年龄、成人模式资格的条目（例如「TA 是成年虚构角色」）：直接不出现在列表里，列表底部一行说明「有 1 条涉及角色分类或年龄的内容不会生效」（CHR-09 第 5 条）。
- **自定义角色**：标题改为「合并进 TA 的人设」，每条显示合并后的位置（「加入：口头禅」）；确认后直接写进人设（CHR-09 第 3 条）。
- 底部主按钮「添加 3 条」。

## 4. 状态汇总

| 状态 | 表现 |
|---|---|
| 页面加载 | 列表骨架 |
| 上传中 | 文件行 / 图片格内转圈（C 21.4、21.5） |
| 上传失败 | 文件行红字原因；图片格感叹号点重试 |
| 识别失败 | 2.3 错误页 |
| 余额不足 | 2.5 按钮禁用 + 说明；生成中用完见 2.6 失败 |
| 生成失败 | 2.6 失败态 |
| 断网 | 当前步骤保留已填内容；按钮点击 Toast「网络不可用」 |

## 5. 平台差异

- 安卓：上传文件用系统文件选择器；截图用系统照片选择器；生成完成通知走原生推送。
- 网页：电脑上 UploadArea 支持拖入；iPhone 网页只能从「文件」选 .txt / .csv。完成通知走 Web Push（iPhone 需已添加到主屏幕）。
