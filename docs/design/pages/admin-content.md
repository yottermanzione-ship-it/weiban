### 1.1 列表

```
┌────────────────────────────────────────────────────────────────────┐

├────────────────────────────────────────────────────────────────────┤
│ 待审核 12 │ 全部                                                    │  TabSwitch（C 1.5）
├────────────────────────────────────────────────────────────────────┤
│ 角色 [多选]  状态 [全部 ▾]  来源 (手动)(系统候选)  生效日期 [起 → 止]  [重置][查询] │
├────────────────────────────────────────────────────────────────────┤
│ 角色  │ 内容（单行省略）        │ 日期范围     │ 来源   │ 状态    │ 生效日期 │ › │
│ 杨幂  │ 11 月上海站演唱会        │ 11-02～11-03 │ 候选 🔗 │ 待审核  │ —       │ › │
│ 杨幂  │ 新剧《XX》定档            │ 10-20～      │ 手动 🔗 │ 已生效  │ 10-09   │ › │
└────────────────────────────────────────────────────────────────────┘
```

- 「待审核」分页只列系统候选中未处理的，按发现时间从早到晚（先处理积压的）；「全部」按生效日期倒序。
- 来源列：「手动」/「候选」+ 链接图标，点链接在新标签页打开来源。
- **状态**（界面名称；与后端枚举的对应以 T-052 的契约为准，后端没有的状态不显示）：

| 状态 | Tag | 角色是否知道 | 说明 |
|---|---|---|---|
| 草稿 | 中性 | 否 | 手动录入后选「存为草稿」 |
| 待审核 | 注意 | 否 | 系统候选，或手动录入后选「提交审核」 |
| 待生效 | 中性 | 否 | 已通过，生效日期在未来 |
| 已生效 | 成功 | **是** | 只有这一种状态角色会知道（ADM-03 第 3 条） |
| 已驳回 | 危险 | 否 | 候选被驳回 |
| 已撤回 | 危险 | 否（之后不再提起） | 生效后撤回（ADM-03 第 4 条） |

### 1.2 新建 / 编辑（DetailDrawer 编辑变体）

| 字段 | 控件 | 规则 |
|---|---|---|
| 所属角色 * | 可搜索单选 | 只列预设的**真人**角色（公开动态只针对真人，SIM-03 第 1 条） |
| 内容 * | TextField 多行，≤ 200 字 | 下方说明「角色只会说这里写明的内容，不会补充细节」（SIM-03 第 4 条） |
| 日期范围 * | 起止日期；止可空（「长期」） | 活动结束后自动转为「经历」，界面不需要操作 |
| 来源链接 * | TextField（网址） | 必填；保存时校验是网址格式 |
| 生效日期 * | 日期，默认今天 | |
| 底部操作 | 「存为草稿」（secondary）、「保存并生效」（primary） | 手动录入由管理员本人负责，可直接生效；任务卡要求的「提交审核」作为第三个按钮「提交审核」（secondary），进入待审核 |

### 1.3 审核候选

点「待审核」行 → DetailDrawer：上半只读（角色、内容、日期范围、来源链接、发现时间、搜索关键词）；下半三个操作：

- 「通过」（primary）→ 直接按候选内容生效（生效日期默认今天）。
- 「修改后通过」（secondary）→ 抽屉切换为编辑变体，内容预填，保存即生效。
- 「驳回」（danger）→ Dialog：原因（选填，ChoiceChip「不实 / 重复 / 不相关 / 其他」+ 补充）→「驳回」。

处理完自动打开下一条待审核（抽屉不关闭，内容交叉淡入），最后一条处理完关闭抽屉并 Toast「待审核已全部处理」。

### 1.4 撤回

「已生效」「待生效」的抽屉底部危险按钮「撤回」→ Dialog 标题「撤回这条动态？」正文「撤回后角色不会再提起这件事；已经发出的消息不会删除」→ 原因必填 →「撤回」。撤回不可恢复，要恢复请新建一条。

### 1.5 手动触发候选搜索

右上「手动触发搜索 ▾」→ 下拉：搜索角色（可搜索单选，只列已上架、被用户添加过的真人角色，ADM-03 第 2 条）→「开始搜索」。按钮变加载中；完成后 Toast「找到 3 条候选，已放入待审核」或「没有找到新的候选」。搜索服务关闭时按钮禁用，悬停说明「自动候选搜索已关闭，只能手动录入」。

## 3. 关系网（ADM-02、SOC-01；L4）

菜单「关系网」。只做表格，不做关系图（关系图大面积重绘、对 60 帧不友好，管理员按角色查就够）。

```
┌───────────────────────────────────────────────────────────────────┐
│ 关系网                                             [新建关系]       │
├───────────────────────────────────────────────────────────────────┤
│ 角色 [搜索单选：选一个角色只看 TA 的关系]  关系类型 [全部 ▾]  亲疏 [全部 ▾] │
├───────────────────────────────────────────────────────────────────┤
│ 角色 A │ 角色 B │ 关系类型  │ 亲疏    │ 公开依据（单行，🔗）  │ 更新时间 │ › │
│ 杨幂   │ 王一博 │ 合作演员  │ 熟悉    │ 《XX》剧组 🔗          │ 10-02   │ › │
└───────────────────────────────────────────────────────────────────┘
```

- 一条关系只显示一行（双向生效，ADM-02 第 2 条）；按角色筛选时，该角色固定显示在「角色 A」列。
- 新建 / 编辑字段：角色 A *、角色 B *（可搜索单选，**只列预设角色**；选 A 后 B 的候选里去掉 A 本人和已有关系的角色）；关系类型 *（下拉：同团成员、合作演员、朋友、师徒、家人、同事、作品中的关系、其他）；亲疏 *（ChoiceChip：点头之交 / 熟悉 / 亲密）；**公开依据 ***（TextField 多行 + 链接，必填，ADM-02 第 1 条）。
- 校验：真人角色和虚构角色之间不能建立关系（SOC-01 第 2 条）——选完 A、B 后若一真一虚，B 下方红字「真人和虚构角色之间不能建立关系」，保存禁用。
- 删除：Dialog「删除后，两人不会再在群聊、朋友圈互动，也不会再互相提起；已有的聊天记录会保留」（ADM-02 第 3 条）。
- 空（按角色筛选时）：「TA 还没有关系 · 没有关系的两个角色相遇时会像陌生人一样」。

## 4. 素材库（ADM-04；L5、L6、L7）

菜单「素材库」，页面顶部 TabSwitch：表情包 | 音色 | 卡面模板 | 宠物图鉴 | 经期症状标签 | 每日一问题库。各分页随对应功能所在开发层出现。

### 4.1 表情包（ADM-04 第 1 条、MED-01；L5）

- 视图：左侧分类列表（可新建、改名、排序），右侧 6 列图片网格（每格 96，下方名称）；网格超过 200 个用虚拟滚动。
- 上传：右上「上传表情包」→ DetailDrawer 编辑变体：UploadArea（C 21.5，支持多选；格式 PNG / GIF / WebP，单个大小以媒体接口为准）、分类、含义说明（给角色理解用，如「得意」「委屈」）、**指定给哪些角色**（可搜索多选；默认「全部角色」）、**确认勾选**「这张表情包不含任何真人的本人照片」（ADM-04 第 1 条，必勾才能保存）。
- 点某格 → 抽屉：大图预览 + 字段编辑 + 「停用」（停用后角色不再发，已发出的不受影响）。
- 空：「还没有表情包 · 上传后，角色会按偏好使用」。

### 4.2 音色（ADM-04 第 2 条、MED-03；L5）

- DataTable：试听（32 圆形播放按钮，同 C 21.6）· 音色名 · 气质标签 · 使用中的角色数 · 状态 · ›。
- 新建 / 编辑：音色名 *（保存时校验：名字里出现已录入真人角色姓名 → 字段下红字「音色名不能使用真人姓名」，ADM-04 验收）、供应商音色编号 *、气质标签（Tag 可增删）、试听文本（默认「你好呀，今天过得怎么样」）+「生成试听」按钮。
- 为预设角色指定音色在「角色库」的角色编辑里做；本页抽屉只读显示「使用中的角色」列表。
- 停用一个仍有角色在用的音色：Dialog「有 N 个角色在用这个音色，停用后它们会改用默认音色」。

### 4.3 卡面模板（ADM-04 第 3 条、GRW-05；L6）

- 4 列卡片网格（每张按 C 9.5 网格尺寸的 1.5 倍预览），按类型分组：纪念卡、熟悉度卡、节日卡、瞬间卡（含宠物、心愿、慢信子类）。
- 新建 / 编辑：类型 *、子类（瞬间卡）、画面图 *（UploadArea，3:2.2、WebP、≤ 80KB，规格见 `cards-familiarity.md` 3.4）、可替换主题色区域（上传一张同尺寸的单色蒙版图；没有则整张不换色）、适用角色分类（全部 / 只给虚构与原创——用于有角色形象的卡面，真人角色永远不会选到带人物的卡面）。
- 预览区同时显示浅色、深色两种卡片背景下的效果（`cards-familiarity.md` 3.4 要求的可读性检查），管理员目视确认。

### 4.4 宠物图鉴（ADM-04 第 5 条、PLAY-02；L6）

- 左列物种列表（名称 + 状态 Tag + 外观数）；右侧选中物种的外观表：外观名 · 幼年图 · 少年图 · 成年图（三列 64 缩略图）· 状态 · ›。
- 新建物种：名称 *、简介（≤ 50 字）；新建外观：外观名 *、三个阶段图片 *（UploadArea × 3，规格见 `pet.md` 第 7 节）。三张没传齐时「上架」按钮禁用。
- 上架 / 下架：物种和外观都可单独下架；Dialog「下架后不能再被选择领养，已经领养的不受影响」（ADM-04 验收）。

### 4.5 经期症状标签（ADM-04 第 5 条、PLAY-01；L3 起可用）

- 简单列表：标签名 · 排序（拖动手柄）· 状态 · 操作。新建：标签名 *（≤ 6 字）。
- 页面顶部固定说明（InlineTip 中性、不可关闭）：「这里只能维护标签。任何用户的经期记录在后台都看不到。」（ADM-04 第 5 条、`health-data.md` 第 6 节）
- 下架的标签：已记录过的用户仍能看到自己的历史记录里有它，新记录不能再选。

### 4.6 每日一问题库（ADM-04 第 5 条、PLAY-03；L7）

- DataTable：题目 · 标签（Tag 中性，多个）· 状态 · 被分到的次数 · ›。FilterPanel：标签（多选）、状态、关键词。
- 新建 / 编辑：题目 *（≤ 40 字）；标签（多选 ChoiceChip，至少提供「恋爱」「适合儿童」「涉及工作」三个，可自定义新增）；下方说明根据所选标签实时显示分配规则：选了「恋爱」→「只有关系类型为恋人的角色会被分到」；没选「适合儿童」→「儿童角色不会被分到」（规则原文见 PLAY-03 第 3 条）。
- 上架 / 下架（下架的题目不再出现，已答过的历史保留）。

## 5. 行为规划（ADM-05 第 10 条、PLAN-03；L7）

菜单「行为规划」，页面顶部 TabSwitch：「决策实现 | 决策记录」。

### 5.1 决策实现

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 决策类型      │ 当前实现        │ 模型               │ 置信度门槛 │ 最近评测   │ 状态      │ › │

│ …（回复时机、小巧思、来电时机、朋友圈、玩法时机）                                    │
└──────────────────────────────────────────────────────────────────────────┘
```

- 7 行固定（PRD ADM-05 第 10 条列出的决策类型），不能新建或删除。
- 状态：「正常」（成功 Tag）/「熔断中 7′」（注意 Tag，剩余分钟数；`behavior-planning.md` 7.3）。
- 点行 → DetailDrawer 编辑变体：实现（SegmentedControl：纯规则 / 规则 + 便宜模型 / Jev；Jev 未配置时该段禁用并悬停说明「Jev 账号未配置」）、模型（下拉，只列「可作规划模型」的已上架模型；纯规则时隐藏）、置信度门槛（0.00～1.00，步长 0.05）、**评测报告编号 ***（下拉，只列该决策类型 + 该实现的报告；没有可选报告时「保存」禁用，下方说明「需要先有这类决策、这个实现的评测报告才能切换」，`behavior-planning.md` 7.2）。
- 保存 → Dialog「把『主动消息时机』切换为『规则 + 便宜模型』？切换前请确认已通过人设稳定检查（PLAN-02 第 3 条）」→「切换」。
- 页面顶部固定说明：「决策层出错时会自动退回纯规则，用户无感；这里的切换不影响任何频率上限和用户开关。」

### 5.2 决策记录（供质量抽查，CR-19）

- FilterPanel：用户（ID 或用户名搜索）、角色、决策类型、时间、退回原因（无 / 超时 / 出错 / 预算 / 无效选择 / 熔断）。
- DataTable：时间 · 用户 · 角色 · 决策类型 · 选择 · 置信度 · 理由（单行省略，悬停看全文）· 实现 · 退回原因 · 耗时 ms。
- **不显示消息原文**（`behavior-planning.md` 7.1），理由列是决策层输出的一句话说明。
- 点行 → DetailDrawer 只读：全部字段 + 可选项列表。

## 6. 注销未完成（ADM-10；L6）

菜单「注销未完成」，右侧 Badge = 列表条数（0 时不显示）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 注销未完成                                                            │
│ ⓘ 这里只显示删除进度，不显示账号的任何内容。注销不能撤销。                    │  InlineTip 中性、不可关闭
├──────────────────────────────────────────────────────────────────────┤
│ 用户名    │ 申请注销时间      │ 最近手动重新触发 │ 模块进度          │ 操作          │
│ xiaoyu   │ 10-08 21:14     │ —              │ 9 / 11 已完成 ⚠   │ [重新触发删除] │
└──────────────────────────────────────────────────────────────────────┘
```

- 按申请时间从早到晚。模块进度列：「已完成数 / 模块总数」，有未完成时后面跟注意 Tag「未完成」。
- 点行（操作按钮以外）→ DetailDrawer 只读：每个模块一行「模块名 · 状态 Tag（已完成 / 未完成）· 删除条数 · 完成时间」；后台不认识的模块显示为「其他模块」（ADM-10 第 2 条）。
- 「重新触发删除」（secondary sm）→ Dialog「只会对还没完成的模块再执行一次删除；如果其实都已完成，会直接完成账号删除」→「重新触发」。按钮进入加载中，完成后该行刷新；全部完成的行淡出（opacity，`duration.base`）并从列表移除，Toast「xiaoyu 的数据已全部删除」。
- **没有**「取消注销」「恢复账号」按钮（ADM-10 第 6 条），设计上也不给这类操作留位置。
- 空：EmptyState「没有未完成的注销」。

## 7. 人设广场管理（ADM-09；L7）的补充状态

结构见 `admin.md` 第 3 节，补充：

| 状态 | 表现 |
|---|---|
| 作品列表空 | 「广场还没有作品」 |
| 举报列表空 | 「没有待处理的举报」（举报 Tab 的 Badge 不显示） |
| 下架后 | 行状态 Tag 变「管理员下架」（危险），抽屉底部按钮变「恢复上架」 |

| 操作失败 | Dialog 不关闭，正文下方 `status.dangerSoft` 横条显示原因 |

## 8. 平台差异
