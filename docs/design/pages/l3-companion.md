| 对应开发项 | D-L3-07（网页）、D-L3-09（安卓）；任务卡 T-056、T-057 |

## 1. 结论

- **摘要卡按接口现有字段先做一个「简版」**：卡片标题 + 一句摘要（`summary`）+ 最多 5 条事件；事件没有日期和来源时就不显示这两项。接口以后补上日期、朋友圈、公开动态时，卡片按 `while-away-timeline.md` 的完整版显示，不用改版式。
- **心情不在界面上显示**：接口给了 `currentMood`，但界面不出现「TA 现在很开心」之类的心情标签。心情只通过 TA 说话的语气体现（SIM-12）。理由：贴心情标签像「看仪表盘」，不像朋友。
- **熟悉度和认识天数放在资料页头部，不放在聊天信息页**（与 v2.0 起的设计一致，对齐参照产品）。聊天信息页只放「设置」，展示类信息去资料页。这一点与任务卡 T-056 的写法不同，已在索引 `../pages-l3-l7-index.md` 第 4 节请总负责人对齐任务卡。
- **主动消息的「关闭 / 少 / 适中 / 多」= 一个开关 + 三档频率**（CHAT-13 第 2 条）。任务卡写的「关闭 / 低 / 中 / 高」四档，界面上按「开关 + 三档」实现，数据上一一对应。

## 2. 「你不在时」摘要卡：接口字段怎么显示（SIM-11）

### 2.1 什么时候显示

| 条件 | 表现 |
|---|---|
| 进入私聊时调用摘要接口，`summary` 不为空 | 展开摘要卡（M-11） |
| `summary` 为空 | 不显示卡片，也不显示右上角「TA 的近况」胶囊；不提示任何原因（不论是离开时间太短、没有事件还是后台预算用完） |
| 接口失败或超时（2 秒） | 不显示卡片，不重试，不弹错误；消息列表照常 |
| 同一段缺席期间已经展开过 | 不再自动展开（SIM-11 第 2 条），只保留胶囊；「同一段缺席」以客户端记录的本次 `lastActiveAt` 为准 |

> 显示门槛以 PRD P-18 为准：**距上次进入该私聊 ≥ 12 小时且期间有日常事件**。T-054 交接写的服务器门槛是「离线 ≥ 1 小时」，两者不一致，已在索引第 4 节上报；客户端不自己加判断，以服务器是否返回 `summary` 为准。

### 2.2 卡片内容

```
┌────────────────────────────┐
│ 你不在的这 2 天，TA……      ⌃ │  标题：天数由 offlineSeconds 换算（规则见 while-away-timeline.md 2.3）
│ 上午开了个很长的会，下午终于去   │  summary：fontSize.subhead、text.primary，最多 2 行省略
│ 喝了杯咖啡。                   │
│ ☀ 开项目汇报会                 │  events：每条一行，最多 5 条（P-18），按 seq 顺序
│ ☕ 下午去咖啡馆休息              │
│                  问问 TA ›   │
└────────────────────────────┘
```

| 字段 | 显示 |
|---|---|
| `summary` | 标题下第一段，最多 2 行；超出省略，不提供展开（完整内容在时间线） |
| `events[].summary` | 条目文字，单行省略 |
| `events[].kind` | 条目图标（下表）。颜色统一 `text.secondary`，线性图标 |
| `events[].detail` | 卡片里不显示；时间线条目展开时显示 |
| `events[].moodAfter`、`currentMood` | **不显示** |
| 条目日期 | 接口暂无日期：不显示日期列，图标后直接接文字 |

`kind` 与图标（Phosphor）：

| kind | 含义 | 图标 |
|---|---|---|
| work | 工作 | briefcase |
| social | 和别人相处 | chat-circle |
| leisure | 休闲 | coffee |
| errand | 办事 | shopping-bag |
| rest | 休息 | moon |
| unexpected | 意外小插曲 | sparkle |
| （以后）朋友圈 / 与其他角色互动 / 公开动态 | 见 `while-away-timeline.md` 2.1 | camera / chat-circle / megaphone |

- 未知的新 `kind`：用太阳图标（sun）兜底，不报错。
- 「问问 TA」：预填「（第一条事件的文字）是怎么回事？」，不自动发送（不变）。

### 2.3 状态

| 状态 | 表现 |
|---|---|
| 请求中 | 什么都不显示（不放骨架屏：卡片本来就是「有才出现」的东西，骨架屏会让人以为一定有内容） |
| 成功且有内容 | 卡片展开 |
| 成功但无内容 / 失败 | 无卡片 |
| 卡片展开时又来了新消息 | 卡片不动；新消息照常出现在列表底部 |

## 3. 时间线页「TA 的近况」（SIM-11 第 3、4 条）

版式不变（`while-away-timeline.md` 第 3 节）。补充实现要点：

- **数据来源**：时间线需要「按时间倒序、分页、带时间和来源」的列表接口；目前契约只有摘要接口，**还没有时间线列表接口**（已在索引第 4 节上报）。接口到位前，资料页「TA 的近况」行的右侧值显示最近一条事件文字（来自摘要接口的 `events` 最后一条，没有就不显示），点进时间线页显示 EmptyState「TA 的近况会出现在这里」——**不要**用摘要接口拼一个假的时间线。
- **分页**：向下滚动到底自动加载更早一天；底部转圈（16）；全部加载完显示「只保留最近 90 天」。
- **加载失败**：首屏失败 EmptyState「加载失败」+ 按钮「重试」；加载更多失败时底部一行「加载失败，点击重试」（`text.link`）。
- 时间线条目展开（「展开」）时显示 `detail`。

## 4. 熟悉度与认识天数（GRW-03、GRW-04）

### 4.1 显示位置（汇总，不新增位置）

| 位置 | 显示 | 说明在 |
|---|---|---|
| 角色资料页头部副信息行 | 「认识第 128 天 · ◐ L3 熟络 ›」 | `character-profile.md` 第 2 节 |
| 点副信息行的底部弹层 | DaysCounter 大号 + 纪念日入口 + FamiliarityMeter 圆环 + 5 级月相说明 | 同上、`cards-familiarity.md` 第 2 节 |
| 服务 › 熟悉度 | 每个角色一行进度条 | `me-and-services.md` 3.2 |
| 聊天中升级 / 纪念日当天 | 会话内提示（C 4.4） | `cards-familiarity.md` 第 2、4 节 |
| 分享图角标 | 「认识第 N 天」 | `../share-templates.md` |

聊天信息页**不显示**熟悉度和认识天数（`private-chat.md` 6.1）。

### 4.2 状态

| 状态 | 表现 |
|---|---|
| 加载中 | 副信息行文字位置显示 `bg.skeleton` 色块（宽 160 高 16）；弹层中圆环位置显示同尺寸灰环 |
| 加载失败 | 副信息行只显示「认识第 — 天」并且不可点；不弹错误（资料页其他部分照常） |
| 刚添加（第 1 天） | 「认识第 1 天 · ◔ L1 初识」 |
| 关系类型为恋人且选择显示「在一起第 N 天」 | 按 C 9.3 改写 |
| 角色已删除、30 天内恢复 | 天数和熟悉度接着原来的（CHR-06）；选「重新认识」则从第 1 天、L1 开始 |

- 「认识第 N 天」按**用户时区**的自然日计算，第一天是添加通过当天（GRW-04）；客户端只显示服务器给的数，不自己算。
- 熟悉度点数只显示「距下一级还差 N 点」，不显示每天获得多少、上限多少（`cards-familiarity.md` 第 2 节）。

## 5. 纪念日列表页（GRW-04、SIM-09）

入口：资料页副信息弹层 →「纪念日 3 个 ›」。

```
┌────────────────────────────────┐
│ ‹            纪念日            ＋ │  ＋ 新建自定义纪念日（最多 10 个，满了 ＋ 禁用）
├─ 认识的日子 ─────────────────────┤
│ 认识那天            2026-06-04    │  ListCell 只读
│ 下一个：第 200 天     还有 72 天    │  只显示下一个系统纪念日
├─ 我们的纪念日 ───────────────────┤
│ 第一次通话          2026-07-12  › │  自定义纪念日：名称 + 日期；每年提醒的右侧加 Tag 中性型「每年」
│ TA 的生日            03-18 每年  › │
├────────────────────────────────┤
│ 纪念日当天，TA 会记得给你发消息。     │  说明（footnote、text.secondary）
└────────────────────────────────┘
```

- 新建 / 编辑：推入表单页：名称（TextField，≤ 20 字）、日期（TimePickerSheet 的日期变体，C 15.4）、「每年提醒」Switch；右上「完成」。编辑页底部危险按钮「删除纪念日」→ Dialog「删除后 TA 不会再在这天特别找你」。
- 空的「我们的纪念日」分组：一行说明「可以把你们的重要日子记下来」+ 文字按钮「添加」。
- 加载：ListCell 骨架 × 4；失败：EmptyState「加载失败」+「重试」。
- **不**推送「纪念日快到了」，不做倒计时动画（`cards-familiarity.md` 第 4 节）。

## 6. 主动消息设置（SIM-10、CHAT-13、ACC-03、MED-07、SOC-06）

页面结构已有：单个角色 `private-chat.md` 6.2；全局 `me-and-services.md` 3.4。补充：

### 6.1 和接口值的对应

| 界面 | 数据含义 |
|---|---|
| 「TA 主动找我」关 | 该角色主动消息关闭（对应任务卡的「关闭」） |
| 开 + 少 / 适中 / 多 | 三档频率（CHAT-13 第 2 条：少 = 每天最多 1 次；适中 = P-03；多 = P-03 + 2）；默认「适中」 |
| 「TA 给我打电话」 | 该角色主动来电开关（MED-07），**L5 来电功能上线前这一行不显示** |

### 6.2 保存与状态

- 每次切换立即保存，**乐观更新**：开关先变，接口失败时退回原状态 + Toast 文字型「没保存成功，请重试」。
- 频率切换成功后 Toast「下一次主动消息开始生效」（与聊天信息页其他设置一致）。
- 全局总开关关闭时，单角色页的开关显示为关且禁用，下方说明「已在 服务 › 主动消息与免打扰 中关闭」+ 文字按钮跳转（不变）。
- 页面加载中：开关位置显示 `bg.skeleton` 色块（51×31）；加载失败：EmptyState「加载失败」+「重试」。
- 「允许角色拉我进群」：L4 拉群功能上线前这一行不显示。

### 6.3 免打扰时段

- 开始与结束相同：保存时 Toast「开始和结束时间不能相同」，不保存。
- 跨过午夜（如 23:00–08:00）是正常设置，不提示。
- 时段只影响主动消息和来电；用户自己发消息时角色照常回复（说明文字已写在页面上）。

## 7. 平台差异

- 两端相同。安卓的时区以系统时区为准，网页以浏览器时区为准；两者都只把时区传给服务器，天数由服务器算。
- 安卓：摘要卡展开时按系统返回键先收起卡片（不变）。
