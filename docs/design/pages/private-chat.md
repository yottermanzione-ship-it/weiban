# 私聊与私聊设置

## 1. 目的与入口

和一个角色一对一聊天，是微伴最核心的页面。入口：会话列表、角色资料页「发消息」、推送通知。

## 3. 使用的组件

NavBar、TypingIndicator、ModeIndicator、SystemBanner、InlineTip、WhileAwayCard、MessageRow 及全部消息类型（C 4.1–4.2）、SystemTip、发送状态（C 4.3）、InputBar、EmojiPanel、PlusPanel、VoiceRecordOverlay、QuotePreview、MultiSelectBar、LongPressMenu、ActionSheet、Toast。

## 4. 消息区规则

- 背景 `bg.chat`；虚拟滚动；进入时定位到最新消息（有「你不在时」摘要卡也一样）。
- 有未读消息且超过一屏时：右上角出现 JumpPill「↑ 12 条新消息」（C 15.3），点击跳到第一条未读。
- 不在底部时收到新消息：右下角出现 JumpPill「↓」+ 红点，点击滚到底部；在底部时自动滚动显示新消息。
- 下拉加载更早消息：顶部 16px 转圈，加载完成后保持当前阅读位置不跳动。
- 拆条：每条气泡前副标题先显示「对方正在输入…」，气泡依次出现（M-07）。
- 人设小巧思的界面表现：已读不回 = 「已读」出现后一段时间才出现正在输入；撤回重发 = 系统提示「XX 撤回了一条消息」后紧接新气泡；打错字 = 一条以「*」开头的普通气泡。都**不加任何特殊标记**（像真人）。

## 5. 状态

| 状态 | 表现 |
|---|---|
| 首次进入（刚添加） | 系统提示「XX 通过了你的好友申请，现在可以开始聊天了」→ 角色第一条消息；顶部一次性提示条「想和 TA 是什么关系？ 去设置 ×」（C 7.2，GRW-02） |
| 等待通过好友申请 | 消息区只有系统提示「已发送好友申请」，输入栏可用但发出的消息会在通过后显示已读 |
| 未配置模型 | 系统横条「还没有配置模型，TA 暂时无法回复」+「去配置」（ACC-04） |
| 模型故障 | 系统横条（模型故障变体）；用户消息照常「已送达」；**不显示**正在输入（MDL-04） |
| 断网 | 网络横条；新发消息显示转圈待发送，联网后按顺序发出 |
| 成人模式 | 副标题「成人模式」+ 锁形图标；本模式下的消息在多选时不可勾选；其余界面与日常相同 |
| 角色已删除（30 天内） | 从会话列表移除，无法进入；如从收藏等位置跳转，显示 EmptyState「TA 已被删除，30 天内重新添加可恢复」 |
| 安全关怀触发 | **界面无任何变化**（不弹窗、不插官方文案，SAFE-06）；只是回复节奏变快 |

- 每个设置修改后立即生效，无「保存」按钮；改回复节奏、贴合度、模式后底部 Toast「下一条回复开始生效」。
- 全局开关为「关」时，对应的会话开关显示为关且不可开，下方说明「已在 设置 › 通知 中关闭」（ACC-03 第 3 条）。

## 7. 平台差异

- 安卓：系统返回键在面板（表情 / +）打开时先收起面板，再按一次才返回会话列表。
- iPhone：输入框聚焦时页面不能整体被键盘顶上去导致导航栏消失——输入栏固定在可视区域底部（Web 负责人用 visualViewport 处理）。
- iPhone 网页版不支持语音通话时：「+」面板中语音通话点击弹出说明（C 5.3）。
