## 1. 目的与入口

和一个角色一对一聊天，是微伴最核心的页面。入口：会话列表、角色资料页「发消息」、推送通知。

## 2. 页面结构


## 3. 使用的组件

NavBar、TypingIndicator、ModeIndicator、SystemBanner、InlineTip、WhileAwayCard、MessageRow 及全部消息类型（C 4.1–4.2）、SystemTip、发送状态（C 4.3）、InputBar、EmojiPanel、PlusPanel、VoiceRecordOverlay、QuotePreview、MultiSelectBar、LongPressMenu、ActionSheet、Toast、JumpPill。

## 4. 消息区规则

- 背景 `bg.chat`；虚拟滚动（网页）/ LazyColumn（安卓）；进入时定位到最新消息。
- 有未读且超过一屏：右上角 JumpPill「↑ 12 条新消息」。
- 不在底部时收到新消息：右下角 JumpPill「↓」+ 红点。
- 下拉加载更早消息：顶部转圈，加载后保持阅读位置不跳。
- 拆条：每条气泡前副标题先显示「对方正在输入…」，气泡依次出现（M-07）。
- 人设小巧思（已读不回、撤回重发、打错字）都**不加特殊标记**。

## 5. 状态

| 状态 | 表现 |
|---|---|
| 首次进入（刚添加） | 会话内提示「XX 通过了你的好友申请，现在可以开始聊天了」→ 角色第一条消息；一次性提示条「想和 TA 是什么关系？ 去设置 ×」（C 7.2，GRW-02） |
| 等待通过好友申请 | 会话内提示「已发送好友申请」；输入栏可用 |
| 模型服务不可用 | 系统横条「模型服务暂时不可用，角色暂时无法回复」（该角色单独模型出问题时多一个「临时改用默认模型」）；消息照常「已送达」；**不显示**正在输入（MDL-04） |
| 模型被下架 | 会话内提示一次「原模型已停止提供，已改用 XX，TA 的说话风格可能有变化」（MDL-04） |
| 余额不足 | 系统横条「余额不足，角色暂时无法回复」+「查看余额」（MDL-10，`billing.md` 第 9 节） |
| 断网 | 网络横条；新消息转圈待发送，联网后按顺序发出 |
| 成人模式 | 副标题「成人模式」+ 锁形图标；多选、收藏照常；**不能生成分享图**（v2.1，EXP-01 第 6 条，C 5.6）；推送不显示内容（CHAT-10 第 7 条） |
| 成人模式模型被下架 / 清除 | 会话内提示「成人模式模型已不可用，已回到日常模式」，副标题消失（MODE-03 第 6 条） |
| 「健康」标记的消息（v2.1） | 气泡无任何标记；分享图、推送、收藏的规则见 `period-diary.md` 第 7 节 |
| 专注中（v2.1） | 顶部 FocusCapsule（C 19.9）；聊天照常 |
| 角色已删除（30 天内） | 从会话列表移除；从收藏等处跳转时 EmptyState「TA 已被删除，30 天内重新添加可恢复」 |
| 安全关怀触发 | **界面无任何变化**（SAFE-06） |

## 6. 聊天信息页（CHAT-13，对齐参照产品私聊的「聊天信息」）

```
┌────────────────────────────────┐
│ ‹            聊天信息             │
├────────────────────────────────┤
│ [头像48]  ┌┄┄┐                   │  MemberGrid（C 17.1）：角色 + 「+」
│  杨幂     ┆ + ┆                   │  点头像 → 资料页；点 + → 选角色发起群聊
├────────────────────────────────┤
│ 查找聊天记录                   › │
├────────────────────────────────┤
│ 消息免打扰                 ( ○ ) │
│ 置顶聊天                   ( ○ ) │
├─ 和 TA 的相处 ──────────────────┤  微伴专属分组（有标题）
│ 情景模式                 傲娇   › │  → ModePicker 页面（C 8.2）
│ 人设贴合度               平衡   › │  → settings.md 第 7 节
│ 秒回                       ( ○ ) │  CHAT-04
│ 拆条                       ( ● ) │  CHAT-05
│ 主动消息                 适中   › │  → 6.2
│ TA 怎么叫我              小鱼   › │  GRW-01

│ 我们的宠物               团子   › │  v2.1 PLAY-02 → pet.md；没有宠物时值为「一起领养」
│ 心愿清单                 12 件  › │  v2.1 PLAY-04 → play.md 第 2 节
├─ 高级 ─────────────────────────┤
│ 使用的模型        跟随全局默认   › │  MDL-02 → billing.md 6.1（单个角色）
│ 我的补充设定                   ›  │  CHR-09；页内底部有「发布为改版」（persona-plaza.md 4.1）
│ 发布到人设广场                 ›  │  v2.1 仅自定义角色（PLZ-02 第 1 条）；已发布时值为「已发布 · 版本 3」
├────────────────────────────────┤
│              清空聊天记录          │  危险型行（居中，text.danger）
└────────────────────────────────┘
```

- 参照产品原有的项（查找聊天记录、免打扰、置顶、清空）位置和分组照搬，不加分组标题；微伴专属的放在中间两个带标题的分组（CHAT-13 第 1 条）。
- 每个设置修改后立即生效，无「保存」按钮；改回复节奏、贴合度、模式后 Toast「下一条回复开始生效」。
- 清空聊天记录：ActionSheet 标题「只清空聊天记录显示，TA 的记忆和你们的养成数据会保留」+ 红色「清空聊天记录」。
- 「+」发起群聊：推入选择角色页（`group-chat.md` 第 3 节），当前角色已预选且不可取消；至少再选 1 个（CHAT-13 验收）。
- v2.1：「我们的宠物」「心愿清单」放在「和 TA 的相处」组末尾（CHAT-13 v1.3）；「发布到人设广场」放在「高级」组末尾，不能发布时的禁用态和说明见 `persona-plaza.md` 4.1。这些功能所在开发层未上线时对应行不显示。
- v2.1：经期日记的授权**不**放在聊天信息页（统一在经期日记「让谁知道」里管理，避免在聊天页面出现经期字样）。

### 6.1 认识天数和熟悉度去哪了

v1.0 的设置页顶部有「认识第 N 天 · 熟悉度」。v2.0 为了和参照产品一致移到了角色资料页头部（`character-profile.md`）。

## 7. 平台差异

- 安卓：系统返回在面板（表情 / +）打开时先收起面板；键盘弹出用 `WindowInsets.ime` 让输入栏跟随，消息列表底部同步留出空间。
- iPhone 网页：输入框聚焦时输入栏固定在可视区底部（visualViewport）。
- iPhone 网页版不支持语音通话时：「+」面板中语音通话点击弹出说明（C 5.3）。
