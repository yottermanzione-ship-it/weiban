# 好感度方案 v1（2026-10-19）

> 背景：旧版微伴有「好感度」，用户已经养成过一轮；新版叫「熟悉度」，迁移后显示为空，用户会觉得白养了。
> 本文给出一套**一条线、不可被话术绕过、旧数据能接上**的方案，供总经理确认后实施。
> 现状字段：`familiarity`（1–5 级）+ `contacts.relationship_type`（朋友/恋人…），两套并存，这是要解决的核心问题。

## 一、结论先说

1. **只留一条线**：好感度 0–100，分 5 段；原来的「关系类型」不再独立存在，改为好感度段位达标后解锁的**标签**。
2. **改名不改数据**：界面叫「好感度」，字段仍是 `familiarity`，迁移零风险。
3. **AI 不能改关系**：AI 只能"提议"，改关系必须走系统事件 + 用户确认。旧版能被一句"我们在一起吧"骗成情侣，这条路堵死。
4. **旧数据直接映射**：旧版好感度数值按比例搬过来，用户看到的是"接着之前的进度"。

## 二、数值

| 段位 | 好感度 | 旧版对应 | 解锁 |
|---|---|---|---|
| 初识 | 0–19 | 旧版 0–20% | 基础聊天 |
| 眼熟 | 20–39 | 20–40% | 可以主动找你（每天 1 次） |
| 熟络 | 40–59 | 40–60% | 解锁「朋友」标签、纪念日 |
| 老友 | 60–79 | 60–80% | 解锁「暧昧」标签、共同记忆 |
| 知己 | 80–100 | 80–100% | 解锁「恋人」**邀请**资格 |

## 三、怎么涨（每天上限 +6，PRO+ +8）

| 行为 | 好感度 |
|---|---|
| 当天第一次对话 | +1 |
| 连续 3 天有对话 | +2（第 3 天当天） |
| 一次深度对话（≥20 条来回） | +2，每天最多 1 次 |
| 共同经历：通话 / 陪我专注 / 心愿达成 | +2，每类每天 1 次 |
| 纪念日当天 | +3 |
| 完成 TA 的心愿 | +3 |

**防刷**：同一类行为每天只算一次；用户连发 100 条不加分；不因"说了什么"加分，只看行为。

## 四、怎么掉

- 连续 **14 天**没有任何互动：−1，**最低降到当前段位下限**，不会掉段。
- 不因一句话、不因拒绝某个请求掉分。
- 删除角色 = 关系清零，不可恢复（已有二次确认）。

## 五、关系标签怎么来

```
好感度到 40 → 系统提示「你们已经是朋友了」（自动，无需确认）
好感度到 60 → 可以出现「暧昧」邀请，用户接受才生效
好感度到 80 → 角色可以在聊天里"提议"成为恋人
             → 用户点「好」→ 关系变为恋人（双方确认）
             → 用户不回应 → 不变，角色不再重复提议（7 天内）
```

- 标签只能由系统写，AI 回复文本里说"我们是情侣了"**不改变任何状态**，下一轮上下文仍按实际关系注入。
- 反向降级：用户可以在角色资料页手动解除关系标签，好感度不掉。

## 六、旧数据迁移

| 旧版状态 | 新版 |
|---|---|
| 好感度数值 | 按百分比线性映射到 0–100 |
| 旧版「朋友」 | 直接给「朋友」标签 |
| 旧版「恋人」 | 给「恋人」标签，但标 `legacy=true`，首次进入资料页提示"这是旧版留下的关系，还作数吗？"，用户点确认后转正 |
| 旧版无记录 | 从 0 开始 |

这样老用户打开就看到"好感度 72 · 老友"，不会觉得清零。

## 七、UI 落点

| 位置 | 显示 |
|---|---|
| 角色资料页 | 昵称下方：好感度进度条 + `L3 熟络` + 关系标签 |
| 聊天页标题下方 | 只在升级时短暂出现，不常驻 |
| 服务 › 好感度总览 | 所有角色的好感度排序、距离下一段还差多少 |
| 聊天系统消息 | 「你和 XX 的好感度升到了 L3 熟络」 |

## 八、需要总经理确认的三点

1. 段位名字用「初识/眼熟/熟络/老友/知己」，还是直接用「好感度 Lv1–5」？
2. 旧版恋人标签的"转正确认"要不要做（不做就直接认，风险是旧版被骗出来的关系也被承认）。
3. PRO+ 的每日上限加成 +2 是否保留。
