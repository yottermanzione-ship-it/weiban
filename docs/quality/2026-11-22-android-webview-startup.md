# 安卓旧网页组件卡在启动页

2026-11-22，开发自测。分支 `codex/android-webview-startup-20261122`，线上复现基线 `a6664a8b727c7df0742ca97ac13df1584be90503`，修复提交 `622fe791b5d7f6841d2202e6828680779bb1a5f8`。

## 现象与原因

用户截图显示 vivo S1 使用 Android 10 和 OriginOS 1.0。另有华为同样停在绿色启动页的反馈。两台报障设备的网页组件版本均未知。

取正式站点当时提供的 HTML、入口 `index-C8cj5IwM.js` 和两份 CSS，在隔离的本地 HTTP 服务上打开。Chromium 72、74、79 解析到 `??` 时报错，83 也在解析入口时报错。在 360 × 780 的视口中，72 和 79 的启动层只有 246 × 188，提示与品牌名重叠。提示由 CSS 定时显示，无需发生网络错误。实际手机各自是否还有网络问题待现场复核。

## 修复

网页、预缓存和通知使用的 Service Worker 统一编译到 Chromium 67，并各自在业务模块之前装载所用的标准 API。该内核已有金额处理和 Zod 契约使用的原生 BigInt。core-js 依赖锁定具体版本，其安装提示脚本无需执行。

启动层通过四边定位铺满窗口，提示在进度条下方换行。入口无法下载或解析时，十秒后出现普通 HTML 重试链接。程序已经接管、十二秒后首页仍为空时，也会保留重试入口。登录欢迎页、主导航和聊天页增加旧视口高度写法。更新由正式网页分发，重试保留本机数据。

## 正式站点复测与已安装用户的恢复

PR #152 的网页修复于北京时间 05:27 上线，提交 `33d1dc605ca7850ea22b849f1634941934b14fcb`。Android 10 模拟器自带系统 WebView 74.0.3729.185。上线前它直连正式站点复现了截图中的绿屏。上线后，全新访问能进入登录页，已打开过旧首页的同一测试程序仍加载 `index-C8cj5IwM.js`。等待 45 秒后根节点仍空，页面没有受 Service Worker 控制，从网络传输的旧脚本字节数为 0。当时正式站点的根路径响应缺少缓存复核指令。

在同一 WebView、同一正式网址、同一份本机数据上，只让首页请求带上 `Cache-Control: no-cache`，即进入欢迎页、打开登录表单，网页缓存接管后刷新成功。另在 Chromium 74 的独立配置目录预置可工作的旧缓存组件及旧正式入口，确认绿屏后准备新组件。关闭旧页再打开，原路径、查询参数和本机标记均保留。

后续修复分支 `codex/android-entry-refresh-20261122`，源码 `b508a5c18997235243ab3436c3abccbc28f6a5a5`。正式站点的首页和网页路由要求浏览器复核 HTML；带版本名称的静态文件继续长期缓存。正式安卓 3.0.0 构建 129 在冷启动、升级后恢复旧页面以及手动重连时复核入口。用户可直接覆盖安装以接续新版首页。

正式签名构建大小为 5,539,606 字节，SHA-256 为 `b7a6d96ac4d4ab52c62ca34f389569bddf02a681883614048b2e69e79b64a916`。应用身份、证书与已分发的构建 128 匹配。安卓壳 25 项测试全部执行通过，静态检查、正式签名打包和 16 项发布工具用例通过。在独立的 Android 10 模拟器先安装公开的 128，再原位升级到 129。系统记录的首次安装时间一致，冷启动正式包后能看到欢迎页，点“登录”进入账号密码表单。测试未输入真实账号。生产容器演练增加了首页、深链、静态文件及构建号的缓存响应断言。
