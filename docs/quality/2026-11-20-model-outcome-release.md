# 模型调用与任务交付核对

运营可在 Weiban OS 的「模型用量 → 任务结果」打开一件任务，从首选线路看到最后一次尝试。「角色消息已入库」「主动消息已送入会话」「碎碎念可展示」和「摘要已落库」分别要求对应业务有采用证据。同一条消息即使产生多个气泡，仍算一次交付。用户是否实际读到消息由聊天的已读状态表示。

| 调用记录中的原因 | 怎么理解和处理 | 可核对的证据 |
| --- | --- | --- |
| insufficient_balance | 用户可用积分不足。原私聊消息显示积分入口。记忆待办合并，恢复资金时重新检查。 | 上游派发、冻结、用户实际扣款，以及待办下次检查时间。 |
| timeout_progress | 线路收到的数据长时间没有新增有效正文或思考，且当时有可用备用。 | 首次及最后有效进度、切换条件、下一条线路和任务结果。 |
| timeout_deadline | 整条请求或当前分得的窗口用尽。按线路历史耗时给合格备用预留时间。 | 各次获配时限、实际耗时，以及线路耗尽后原消息上的状态。 |
| provider_error | 供应商服务出错。临时错误可以转往其他获准入口。 | 有回执时显示 HTTP 状态、允许记录的供应商错误码及追踪号。 |
| network_error | 连接建立或读取过程中断。优先尝试仍适用的独立入口。 | 最后到达的阶段、上游入口标识、最后数据时间。 |
| timeout_idle | 指定时段内没有收到数据。心跳算收到数据，正文或思考才算生成进度。 | 空闲时限、最后收到数据和有效进度分别显示。 |
| empty_output | 供应商没有提供可交付正文。聊天有限补救，全部失败则保留缺失回复的状态。 | 区分正文缺失、只有空白和只有思考。 |
| truncated_reasoning | 生成达到输出限制，返回了思考内容。任务按已核准线路能力分配额度。 | 输出上限与思考用量；结构化业务仅采纳通过验证的部分。 |
| rate_limited | 供应商限流。按 Retry-After 或退避时间冷却，明确账号级的限流也约束该账号的其他模型。 | 供应商等待提示、限流范围和后续调度。 |
| concurrency_limited | 同时付费调用达到上限。短暂等待时先释放给交互请求。 | 发送前拦截、后续是否取得名额以及用户账本。 |
| content_rejected | 供应商明确拒绝此次内容。停止相同请求，保留现有业务提示。 | 尝试终态、实际交付与费用。模糊权限错误单独标识。 |
| cancelled | 调用已取消。语音按是否已经派发记录，重复取消沿用同一释放结果。 | 取消方、派发证据、冻结释放和扣款。 |
| bad_request | 参数或能力组合不合要求。能在本地识别的先拦截，供应商明确拒绝后结束相同请求。 | 允许记录的字段名和错误码。 |
| budget_exceeded | 计费预检发现平台预算不足，后台待办按预算日和业务时效复查。 | 平台预算和用户余额分别显示，核对发送前状态及恢复时间。 |
| interrupted | 执行被打断。复用已经保存的结果。已经派发且结果无法确定的原请求保留防重依据。 | 派发、已有结算、业务回执，以及「派发结果待核」状态。 |
| provider_unavailable | 路由器没有可供本次请求使用的线路，或网关只取得通用失败。 | 核对账号、线路健康、名额、费率边界和剩余时间，旧数据保留不确定性。 |
| truncated | 正文被截断。普通文字在同一条线路上可以补一次尾段并消除重叠。 | 完整文本只交付一次。结构化任务核验每条来源后推进游标。 |
| request_too_large | 这次预计售价超过单次保护上限。保留原保护，适合拆分的摘要有界缩小后重试。 | 新记录包含预计售价、上限及价格版本，超限发生在实际派发前。 |
| invalid_key | 上游凭据失效，或需要进一步查明账号对模型的权限。 | 账号自检与模型授权分开，确认异常后隔离相应账号或模型线路。 |
| quota_exhausted | 供应商账号额度耗尽。暂停该账号，有合格备用才换路。 | 供应商额度、账号告警、恢复验证，与用户钱包余额分别显示。 |

## 业务验收

- 同一用户消息的并发重试共用一个轮次和一份角色回复。原消息已隐藏、撤回、清空或不属于当前用户时，无法从该入口再发起生成。
- 代码围栏只在完整包住单一 JSON 时剥除。摘要来源必须属于本次授权批次。旧摘要、写入游标与退款记录分别核对；重复对账只退款一次。
- 业务幂等键或外键可以证实的历史记录才归组。供应商返回成功、用户扣款、后台采纳、用户已读分别核对。缺少原始凭据的旧结果标记证据不足。
- 旧普通私聊的收费编号只能关联用量和角色消息。即使另一线路成功，旧版也可能发本地兜底。此类记录单列「备用返回成功且消息已入库」，不计入「备用救回」。新版只用实际采用结果的编号认定救回。
- 用户实际扣退来自积分账本。供应商用量、自行计量和待核成本分别展示。输入按缓存与未缓存拆分，可核对当时价格版本和长历史输入对费用的影响。
