# 授权后的只读自动核对与旧设定修复候选

日期：2026-11-09。开发自测及只读核对，未执行真实迁移、删除或上线变更。经理在本轮明确允许：程序只读处理本次迁移相关旧人设、消息关联和附件，在内存中比对，仅输出类别和数量，不向模型展示正文、不保存明文、不修改线上。这是对最初仅看结构/数量范围的明确扩展，后续在相同范围内不重复索要授权；不是正式迁移或切站授权。指定新版账号先按固定身份摘要排除。

## 运行方式与隐私边界

`legacy-persona-readonly-review.mjs` 仅在显式只读及私人内存授权参数同时出现时读取两站。旧站使用SQLite readonly、query_only、BEGIN/ROLLBACK；新版使用只读可重复读事务和五秒语句上限。原始字段仅在确定性进程内，查询/异常正文不回显；程序没有导出、保存私人明文、模型调用、应用启动或迁移入口。需要检查新站占位记录时，临时只读程序通过标准输入在现有应用容器的独立进程运行，不上传文件、不修改容器、配置或服务；数据库连接强制默认只读，使用现有加密实现解密后立即清除缓冲区，仅返回固定类别。主密钥只在服务器该进程内读取和清除，不传输、不打印、不另存。

`legacy-persona-private-audit.mjs` 复用实际人设投影规则，只返回预定义计数，输出明确 `importApproved:false`；检查用的目标摘要故意不是可执行导入摘要。转换规则单独检查可以证明结构能处理，不能绕过新版编辑、删除/关系或来源证明来激活内容。

## 针对旧占位记录的候选修复

内部导入格式新增可选 `importedSupplementPlaceholder` 证明，要求具体密文SHA256和更新时间。没有此证明继续保护既有新版记录，不自动把所有补充设定当旧内容。

执行时在同一事务锁住对应行，逐项检查：当前密文摘要和时间等于已审核证明、时间不晚于首次迁入截止、无冲突和广场来源、实际解密字节完全等于旧导入器的固定无效占位值。任何不一致拒绝；真正文字、较新记录、带额外内容的字符串不能走此修复。完整来源检查通过并取得active或原reset状态后，才用对应专属设定替换该占位行；被阻断的来源保留原行。替换与新设定、来源回执同一事务，后续批次失败全部回滚；重复导入不会再删除用户后来写的新设定。此候选没有在生产执行，具体受保护替换清单应作为正式迁移包的一部分。
