# 电话记忆取消：根因、修复与收尾

## 真实根因证据

经理明确授权仅在服务器内存中检查原两条历史整理结果，正文不输出、不落盘、不交模型、不产生费用。复现工具严格限定取消时间、用量窗口、任务请求哈希、成功备用结果且必须恰好2行；只读事务，10秒超时，输出固定类别和数量。先以4组虚构加密结果验证不暴露正文；SSH一次连接关闭后重试不改变范围。

| 类别 | 数量 | 可支持的结论 |
| --- | ---: | --- |
| inspected | 2 | 两条目标结果均已检查 |
| invalid_result_schema | 2 | 原整份严格格式校验均会失败 |
| operations.action.invalid_value | 1 | 一条含不支持的操作名；并非大小写/空格或常见无操作别名 |
| operations.unrecognized_keys | 1 | 另一条有额外字段；核心字段符合旧结构 |
| repair_all_valid | 1 | 新输入解析可保留1条合法操作和1条共同经历，仅内存验证，未写生产 |
| repair_invalid_source_reference | 1 | 另一条还存在来源编号不符；即便解决操作格式，也不应强行写入 |

没有读取或输出用户正文、操作的原始值、额外字段名字、私有ID、异常原文或密钥。根因不是“备用模型没有调用”：前轮精确关联已证明两个备用成功返回，失败发生在后续格式校验。原提示词仅列操作枚举和不完整顶层示意，未清晰展示action字段结构；工作器一处不符即取消并清空临时结果，造成多余字段连带丢弃有效记忆。

## 修复行为

- 通话专用提示词升级，明确JSON对象、完整字段示例、允许操作名、无事实空数组、更新必须有已有记忆ID及唯一真实来源ID。群聊和普通文字抽取不顺带改动。
- 仅输入边界剔除无关字段；逐条校验事实，已知操作允许大小写/两端空格规范化。无操作不要求模型编造content。未知操作不映射成新增/删除，更新缺ID不猜测目标。
- 一条普通格式坏项不会取消其他合法事实及共同经历；审计区分完整保存、保存有效部分及没有有效部分，并仅记忽略数量。没有有效部分不是“记忆保存成功”。
- 来源不符、健康内容仍整批拒绝，且不能借坏操作绕过。联系人、遗忘修订号、用户手改保护、范围隔离、来源存在、事务与幂等继续执行。
- 保存前缓存的是规范化且加密的结果。事务/审计中断重试复用该结果，不额外请求模型，不重复写记忆。
- 两条历史取消记录不自动恢复；本次例外只授权检查。原通话气泡和已存双方文字未删除；不重生成、不追扣、不退款。不将这次源头修复写成“两个历史任务已恢复”。
