## 结论与修复

1. 更新入口统一在“我 → 设置”，保留“检查更新 / 更新版本”，移除关于页重复入口；操作结果使用全局 Dialog。确认后等下载、消息保存、新工作线程实际激活，再加载页面；激活失败恢复聊天。兼容旧客户端的显式更新请求：新工作线程仅重新导航发起请求的页面，不主动刷新其他页面。
2. 较长网络挂起的受控浏览器测试失败，定位到聊天驱动每20秒替换挂起的状态请求，旧轮次的异常被当成过期回调忽略，在线状态没有及时失效。新增明确离线与发件队列暂停，恢复对账后用原消息编号重试。保留草稿、登录和本机消息，不清库。
3. 普通聊天、记忆/日常推演/动态等既有后台兜底用途，在供应商失败或模型不可用后，从当前价目选择输入和输出单价均不高于原模型、至少一项更低的上架普通模型，按估价升序最多三项。先排除无可用线路、无价、私密/实时模型；同一中转站不同模型可尝试。每次仍走完整权限、上下文容量、余额、预留与结算，保留消息、范围和返回格式。未指定整体截止时间时给主模型和备用合计两分钟，调用方的明确截止时间优先；安全拒绝、额度/权限拒绝不换模型，不把私密内容转给普通模型。
4. 百炼实时通话实际报告的字段为 `input_tokens_details / output_tokens_details`，原代码只读单数拼法，误认用量缺失。现兼容两种字段；后台详情和导出可见文本/音频用量，缺失仍记待核，不把未知当免费。Omni 3.5 / Audio 3.1 的伴随输出文本按官方规则免收，Omni 3.8 分别计费；保留原始报告用量，不改写供应商数字。
5. 三款北京实时通话的17项售价仍沿用早期加三成，和经理后续“官方售价”不一致。准备版本化修正脚本：只修指定17项，保留100项中的其他83项、采购成本、折扣和历史流水；预览、过期条件拒绝与重复执行均有检查。后续目录配置工具也改用官方价，防止重新带回加价。
6. 后台已有情景预设提示词编辑页，现菜单明确改名“情景模式与提示词”，并在系统设置顶部提供直达入口。保存后作用于后续回复，无需发布；不替经理改写现有生产提示词。
7. 经理追加用户端和后台均不显示中文模型/厂商名。改用英文目录名称、默认配置及供应商选项；新增/编辑/导入对名称作英文校验。生产明确更名清单为10条（含1条已删除历史条目），仅更名和更新时间，键、型号、路由、价格及启用状态不变。预览确认10条；真实数据库验证预览、过期旧值拒绝、只改名称和幂等执行通过。
