> 供项目总负责人生成任务卡。层次来自 PRD 第 7 节，调整建议见 `prd-answers.md` 第 8 节（本清单已按建议编排）。
> 编号 `D-层-序号` 只是本清单内的临时编号，总负责人派发时换成正式的 `T-xxx`。

## 0. 使用说明

- **负责人**：后端 = backend-lead，AI = ai-lead，Web = web-lead，安卓 = android-lead，运维 = devops-lead，质量 = qa-lead，架构 = architect，设计 = design-lead，产品 = product-lead。
- **依赖**：必须先完成（或至少契约已定稿）的任务。「契约」指 `packages/contracts` 中对应部分已由架构批准。
- **每层收尾**都有一个质量验收任务，验收通过才进入下一层（下一层的契约和设计可以提前做）。
- **并行**：同一层中依赖已满足、且改不同目录的任务可以并行，各用独立工作副本（`docs/ops/git-workflow.md` 第六节）。
- **跨层前置**：T-005（AI 方案与角色卡）、T-006（设计体系）是 L0 网页和 AI 任务的输入。

```
D-L0-01 → D-L0-05 → D-L0-06 / D-L0-08 → D-L0-09 → D-L1-01 → D-L1-02 → D-L1-04 → D-L2-02 → D-L3-01 → D-L3-03 → D-L4-03 → D-L4-04 → D-L5… → D-L6…
```

AI 运行时（D-L1-04、D-L2-02/03、D-L3-01/03、D-L4-04）是关键路径上的主力，AI 负责人的任务应优先排期；后端、网页、安卓任务尽量与之并行。
