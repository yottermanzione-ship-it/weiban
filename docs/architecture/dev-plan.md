## 0. 使用说明

- **负责人**：后端 = backend-lead，AI = ai-lead，Web = web-lead，安卓 = android-lead，运维 = devops-lead，质量 = qa-lead，架构 = architect，设计 = design-lead，产品 = product-lead。
- **依赖**：必须先完成（或至少契约已定稿）的任务。「契约」指 `packages/contracts` 中对应部分已由架构批准。
- **每层收尾**都有一个质量验收任务，验收通过才进入下一层（下一层的契约和设计可以提前做）。
- **并行**：同一层中依赖已满足、且改不同目录的任务可以并行，各用独立工作副本（`docs/ops/git-workflow.md` 第六节）。
- **跨层前置**：T-005（AI 方案与角色卡）、T-006（设计体系）、T-010（PRD v1.2）是 L0 网页、安卓和 AI 任务的输入。
- **网页与安卓**：同一功能的网页任务和安卓任务依赖相同的契约，可以同时开工；两端的同步引擎都必须通过协议用例（D-L0-17）。

## 关键路径（最短完成路线）

```
D-L0-01 → D-L0-05 → D-L0-16（计费）/ D-L0-06 / D-L0-08 → D-L0-09 → D-L1-01 → D-L1-02 → D-L1-04 → D-L2-02 → D-L3-01 → D-L3-03 → D-L4-03 → D-L4-04 → D-L5… → D-L6…
```

- AI 运行时（D-L1-04、D-L2-02/03、D-L3-01/03、D-L4-04）是关键路径上的主力，AI 负责人的任务应优先排期。
- 计费（D-L0-16）挡在模型网关前面，必须在 D-L0-09 之前完成核心部分（冻结、结算、价目表）；管理端对账可以稍后补。
- 安卓任务（D-L0-18、D-L1-06、D-L1-09 及各层安卓任务）不在服务器关键路径上，但工作量与网页相当，建议 Android 负责人从 L0 末起持续并行；安卓推送与保活（D-L1-09）受厂商差异影响大，应尽早开始。
