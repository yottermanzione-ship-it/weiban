# 电话上下文契约变更：7.2

经理明确要求电话只改变输入输出形式，沿用聊天上下文与记忆；通话双方文字必须可以接续。本次由已接管架构和开发职责的 Codex 评估并实施，开发自测不替代独立验收。

## 变更与兼容

- `CallRecordContent` 新增可选 `transcript`，每项保留 user/assistant 与文字。与现有聊天消息同一加密正文存储；没有录制或保存通话音频。总文字在写入端限定 200,000 字符，最多 10,000 项，单项不能因旧 1,000 字上限静默截断。
- `ChatParticipantPort.attachCallTranscript(tx, input)` 仅服务器调用，更新同一通话的既有记录。验证用户、角色、会话、通话编号、当前消息状态和范围，并遵守清空/隐藏状态；已经有转写不覆盖。只发 `message.updated`，不再发布创建消息事件、排普通回复或新增通知。健康提示参与过的通话加已有 health 标签，不进入长期提炼和共享。
- 旧客户端忽略可选字段，原通话气泡、现有接口、最低客户端版本和 WebSocket 帧保持兼容；安卓生成代码同步 7.2。无需数据库迁移，线上迁移仍为 0160。
- 原文存档复用消息的归属、范围与加密；记忆来源用实际消息编号。用户编辑/删除记忆、联系人重新认识和账号注销沿用同一屏障。隐藏气泡与“遗忘记忆”仍是现有产品里的不同操作，没有扩大成自动忘掉所有普通聊天的语义。

## 处理与限制

复用 `ReplyContext`，仅改声音输出要求，保留人设、情景、关系阶段、世界书、聊天、图片已有描述、语音转写、记忆、健康和社会背景。长历史使用普通聊天相同的摘要窗口和模型容量；不承诺无限上下文。

级联电话每轮重建；实时供应商会自行维护本通电话的声音历史，平台以同一组装器初始化并在回合间更新动态材料，不重复塞入当前电话的全部文字。供应商自动开始的当前回应不取消重发，动态更新不能追溯改变已经生成的回应。开场、提醒与道别的局部要求必须连同完整指令发送，不能覆盖掉人设。

删除网关和传输层 20,000 / 4,000 / 2,000 字的静默截断，改用明确容量检查；超出模型可用输入容量拒绝开始，不能擅自削掉边界指令。已存电话原文按 12,000 字符分批提炼，保留分段发言角色与来源；每批应用后继承新的记忆版本，防止首批提炼让后续批次误判为外部修改。

当前文字在通话正常收尾时附入消息；短暂写入故障幂等重试三次并仅记错误分类。进程突然终止前尚未收尾的内存轮次仍可能丢失，不能声称做到了逐个声音帧的持久化。被打断的输出没有手机逐字播放确认，存为不完整提示，不把未说完内容当作已告知。旧版本已经丢弃的原文不能恢复。
