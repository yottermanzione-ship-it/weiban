# 角色管理与微博资料窄接口申请（实施前登记）

依据：[用户明确的角色系统任务](../tasks/T-20261026-character-system.md)。负责人在用户开发接管授权内登记本轮窄变更，不代称独立架构复核已通过。

## 需要的增量

- 管理端AdminLegacyFields增加可选weibo资料块，含enabled、nickname、可选HTTPS头像及数字账号ID。字段省略=不改；关闭标记不是删除角色，也不更改生态用户设置。旧详情/恢复读取缺字段兼容。
- AdminCharacter追加可选微博资料概要，供列表显示有微博/缺账号信息，不加N+1客户端请求。现有客户端忽略新增字段。
- 新卡既有profileExtra.weibo接口保持原样；迁入卡从明确的weibo_nickname等来源读标记，不从角色名、别名或平台头像推断微博身份。昵称已存在且没有显式关闭时认作已有标记，不必批量覆盖677个角色。
- 运行时微博视图可表示“有昵称但无头像/账号ID”。文字同步沿用候选帖核验；图片仍要求账号ID并核对原帖作者，不为通过校验伪造头像或账号。WeiboPublication在同一事务中兼容迁入卡资料核验，不能仍依赖新格式publishedCiphertext。
- 声音、头像与有效人物文字优先复用既有接口，不增加克隆接口、音频供应商绑定明文字段、模型调用或费用路径。人物文字分段编辑保持有效文本逐字往返，不引入另一套角色格式。

## 兼容及数据

全部是可选管理端响应/请求增量；不删除原字段、不改角色ID、无DDL，不改变用户聊天请求。若契约工具要求版本/生成产物，同步按项目规则更新，不能只改前端类型。角色快照会保留新的旧字段，恢复只还原角色资料，不还原资格、用户数据或生态开关。

待实现后由直接相关契约/服务端/后台用例验证；未宣称独立复核完成。
