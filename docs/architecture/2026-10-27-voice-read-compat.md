# 音色目录历史名称读取兼容：窄契约修补

## 原因与依据

用户线上截图：角色页“声音与微博”报“第376项·名称：最多20个字”。当前Voice.name读取校验max(20)，导入服务原样保存历史音色名称；后台新面板又用Promise.all合并音色库与默认绑定，导致音色库一条失败时默认绑定的成功响应也未显示。

只读生产统计（2026-10-27 +08:00）：501音色中3条名称超过20字符，最长25；供应商代号最长63、无超过64；677默认角色绑定仍在。只输出计数和长度，不输出代号/样本/秘密，不调模型、不改数据。

## 申请并实施的最小修补

- Voice/AdminVoice响应名称容纳既存历史值，上限80；不截断、不重命名、不删除历史目录。
- AdminVoiceWrite显式保留新建/编辑名称1～20字符约束，其余请求约束、供应商代号64、角色绑定接口均不动；不因继承读取schema而放宽写入。
- 面板两份读取结果分开处理，目录失败仍显示已读到的绑定名称；读取失败禁用危险保存/清除，提供重试，不能把失败当“未指定”。
- 不增加接口、字段、枚举或更改字段含义，仅修补已有4.3读取校验与既存数据不一致；沿用4.3，不新增数据库迁移或发APK。生成定义与Kotlin数据类型不变，但重新导出校验约束。
- 一次直接相关回归：长名完整读取/新写入仍20；目录失败保留绑定、绑定失败不当未设置。相关contracts/admin类型一次；生产只读完整目录按新schema解析一次，无模型调用/绑定写入。按既有源闸门、备份回退发布app+edge。
