# 硬性边界的系统级执行

> 负责人：架构负责人 · v1.1 · 2026-10-04 · 来源任务：T-004，T-009 修订
> 回答 PRD 8.1 第 9 问；规则来源是 PRD 第 10 章、`docs/product/input/2026-10-04-pm-rulings.md`、`docs/product/input/2026-10-04-manager-feedback-2.md`（第二轮意见，与前者冲突时以它为准），本文只讲**怎么在系统里执行**，不改规则本身。决策记录见 `docs/decisions/ADR-0007-hard-boundary-enforcement.md`（含 T-009 修订记录）。
> AI 层的执行方式（提示词、输出检查、评测集）由 AI 负责人在 `docs/ai/` 设计；本文规定 AI 层必须遵守的系统约束。

## 0. v1.1 改了什么（T-009）

- 成人模式只保留**两条底线**：**儿童角色不开、真人角色不开**（总经理第二轮意见第 1 条）。资格公式不变（原公式本来就等价于「非真人且非儿童」）。
- 从硬性边界中**移除**：年龄确认、群聊禁用、需配置成人模型、内容隔离、成人模式法律禁止内容清单。它们是否作为体验设计保留，由 PRD v1.2 决定；即使保留，也由相应业务模块执行，不进 `policy`。
- **新增模型层闸门**：无审查模型（能力 `adult_content`）只能用于有成人资格的角色。
- 分享图标注文案改由 PRD 定义（第二轮意见第 3 条），`policy` 只给出「要不要标」。
- **「真人」分类定义收窄**（总负责人 2026-10-04 补充决定第 1 条）：见第 2 节 `basis` 的定义。系统只按分类字段执行，不检测人设的灵感来源。
- **古人 / 虚构角色形象图裁定已删除**（同上第 2 条）：`portraitPolicy` 简化为「真人 → 不生成本人形象；其他 → 允许」。历史人物属于真人分类，回到 SAFE-01 的一般规则（不生成本人形象）——这是删除例外后的推论，已在 T-009 交接中请总负责人确认。虚构角色不再要求「分享图加注」。

## 1. 结论

**硬性边界不靠「提示词里写一句请不要」，而是靠四道闸**：

| 闸 | 做什么 | 例子 |
|---|---|---|
| ① 能力缺席 | 系统里**根本不接入**越界能力 | 不接任何声音克隆服务；不提供通用「这是谁」人脸搜索 |
| ② 数据闸 | 决定边界的字段由服务器推导，客户端和管理员**写不进去**；某些字段只能单向修改 | 「成人模式资格」不是一个可以设置的字段，而是每次由角色分类算出来的结果 |
| ③ 服务闸 | 所有可能越界的操作都必须经过 `policy` 模块判定，判定失败直接拒绝（HTTP 403） | 直接调接口把真人角色设为成人模式 → 403 |
| ④ 生成闸 | 模型网关和 AI 运行时在**每次生成前再查一次**（纵深防御），并在生成后做输出检查 | 即使数据库里的模式值被篡改，网关也拒绝为该角色使用成人模式模型或无审查模型 |

一句话：**用户能看到、能点到、能调用的一切，都在服务器端被同一个 `policy` 模块重新判定一遍。**

## 2. 角色分类：系统层面的最小字段

角色卡的完整字段由 AI 负责人设计（`docs/ai/character-card-spec.md`）。以下字段是硬性边界的**判定依据**，必须作为结构化字段存在 `characters` 模块中（不能只写在人设文本里），契约见 `packages/contracts/src/http/characters.ts` 的 `CharacterClassification`：

| 字段 | 取值 | 谁能设置 | 修改规则 |
|---|---|---|---|
| `basis` 原型 | `real_person` 真人 / `fictional` 虚构作品角色 / `original` 原创 | 预设：管理员；自定义：用户创建时 | 自定义角色：`real_person` **不能改为其他**；导入生成的角色默认 `real_person`，只有创建时勾选「虚构声明」才能选其他（CHR-08） |

**`real_person` 的定义**（总负责人 2026-10-04 补充决定）：**以真实人物本人身份呈现的角色**——使用其真名，或包含其可识别的真实身份事实（真实作品、真实人际关系、真实经历等）。以某位真人的性格、说话风格为灵感，但用新名字、不带上述真实身份事实的角色，归为 `original`（原创）。系统**只按这个字段执行**，不检测人设的灵感来源；字段由创建者（管理员或用户）按定义选择，界面在选择处展示这条定义（文案归产品 / 设计）。自定义角色一旦选了 `real_person` 仍不能改回（单向规则不变）。
| `realPersonKind` 真人子类 | `celebrity` 公众人物 / `historical` 历史人物 / `private_person` 基于身边真人 | 同上 | 历史人物由管理员按裁定标准标注（去世超过 100 年、无照片录音） |
| `ageSetting` 年龄设定 | `minor` 未满 18 / `adult` 已满 18 | 同上 | 自定义角色：`minor` **不能改为** `adult` |
| `childAppearance` 外表为儿童 | 是 / 否 | 预设：管理员；自定义：用户创建时 | 自定义角色：「是」**不能改为**「否」 |
| `childFeaturesDetected` 人设文本含儿童特征 | 是 / 否 | **只能由系统检测写入**（SAFE-03 第 4 条，检测方法归 AI） | 用户不能修改 |

**推导结果**（只读，每次实时计算，不存为可写字段）：

| 推导值 | 公式 | 用于 |
|---|---|---|
| `isMinor` 儿童角色 | `ageSetting = minor` 或 `childAppearance` 或 `childFeaturesDetected` | SAFE-03、SAFE-05 |
| `adultModeEligible` 成人模式资格 | **非真人**（`basis ≠ real_person`，含历史人物）**且 非 `isMinor`** | SAFE-03（两条底线） |
| `adultContentModelAllowed` 可用无审查模型 | = `adultModeEligible` | 模型层闸门（第 4 节） |
| `romanceAllowed` 可恋爱 | 非 `isMinor` | SAFE-05、GRW-02、MODE-01（儿童保护是否调整等总经理确认，确认前不变，见 T-010 任务卡第 9 点） |
| `portraitPolicy` 形象图策略 | 真人（含公众人物、身边真人、历史人物）→ `forbidden`；虚构、原创 → `allowed` | SAFE-01、MED-02（原裁定 9.2 第 1、3 条已删除） |
| `publicStatementGuard` 公开言论检查 | `basis = real_person` | SAFE-02（AI 输出守卫据此开启，不自行判断分类） |
| `shareImageLabel` 分享图标注 | 真人 → `not_real_person`；其他 → 无 | EXP-01；**标注文案以 PRD 为准**（第二轮意见第 3 条），本文不重复 |
| `voiceCloneAllowed` | 恒为「否」 | SAFE-01 |
| `recognitionAllowlist` 识图可认的人 | 角色本人 + 关系网中与其有关系、且为真人或有公开形象的角色 | SAFE-04 |

「我的补充设定」、人设描述、聊天内容都是**自由文本**，系统**永远不从自由文本里读取分类**。所以在补充设定里写「TA 是成年虚构角色」不会改变任何判定（CHR-09 验收第 2 条）。

## 3. `policy` 模块

- 位置：`apps/server/src/modules/policy/`。规则由架构负责人定义（本文），后端实现。
- 形态：**纯函数**（输入角色分类，输出允许 / 拒绝 + 原因码），没有自己的业务表；每次拒绝写一条审计日志（不含聊天内容）。
- **只管硬性边界**：产品体验规则（例如 PRD 若保留「群聊只用日常模式」）不放进 `policy`，由对应业务模块执行，避免把可调的体验规则误当成不可绕过的底线。
- 对外端口：`PolicyPort`（契约 `packages/contracts/src/ports/policy.ts`），主要方法：
  - `getCharacterPolicy(userId, characterId)` → 上表全部推导值；
  - `listAllowedScenarioModes(...)` → 可显示的情景模式（不具备资格的**不返回**，界面自然不显示）；
  - `checkScenarioMode(...)`、`checkRelationshipType(...)`、`checkAdultGeneration(...)`、`checkModelForCharacter(...)`、`checkImageGeneration(...)` → 允许 / 拒绝 + 原因码。
- 测试要求：每条规则正反两面的表驱动单元测试，覆盖 PRD 第 10 章所有验收中列出的角色（杨幂、李白、江流儿、罗小黑、导入角色、「8 岁但选了已满 18 岁」的自定义角色），以及 AI 负责人的成年虚构测试样本角色（如「林夏予」）。

## 4. 每条硬性边界的执行点

### SAFE-03 成人模式：两条底线（不可被接口绕过）

| 位置 | 执行方式 |
|---|---|
| 角色数据 | `adultModeEligible` 是推导值，**没有任何接口可以写它**；管理员后台也只能改分类字段 |
| 情景模式列表接口 | 只返回 `listAllowedScenarioModes` 的结果；资格为「否」的角色列表里没有成人模式（不是灰色） |
| 切换情景模式接口 | 服务器调用 `checkScenarioMode`：角色无资格 → 403 `adult_mode_not_eligible`。另有一个**功能前提**（不属于 policy）：用户没有可用的成人模式模型 → 422 `adult_model_missing`，提示去选模型 |
| 资格变化 | `characters.character_classification_changed` 事件 → AI 运行时把所有该角色处于成人模式的私聊强制切回日常并发系统提示（SAFE-03 第 5 条）；`childFeaturesDetected` 由检测写入时同样触发 |
| 生成前再查（成人模式） | 模型网关收到 `modelRole = adult` 的请求时，自己调用 `checkAdultGeneration`；不通过直接拒绝，**不会因为上游代码出错或数据被改而用成人模式模型生成** |
| **模型层闸门（新增）** | ① 写入时：全局聊天 / 后台模型不能选 `adult_content` 模型（422 `model_not_allowed`）；为角色单独设置 `adult_content` 模型时调用 `checkModelForCharacter`，无资格 → 403 `model_not_allowed`。② 调用时：网关解析出的模型带 `adult_content`，必须带 `characterId` 且 `checkModelForCharacter` 通过，否则拒绝。详见 `billing.md` 第 9 节 |
| 输出检查（生成层） | AI 输出守卫对**真人角色和儿童角色**检查性内容，命中即重生成 / 兜底（方法归 AI）。这是两条底线在生成层的执行，**不随其他成人模式限制取消** |
| 自定义角色单向字段 | `characters` 模块在更新时校验：`real_person → 其他`、`minor → adult`、`childAppearance 是 → 否` 一律 422 拒绝；数据库触发器再拦一次 |

### 内容范围标签（数据能力，原 SAFE-07）

v1.1 起「内容隔离」不再是硬性边界，但**数据能力保留**，原因：标签从第一天起盖在每条消息上几乎零成本，事后补加则要迁移全部历史消息。

1. 会话有通用属性 `contentScope`（`normal` / `adult`），AI 运行时在进入 / 退出成人模式时通过 `ChatAdminPort.setContentScope` 设置。`chat` 只知道「范围标签」，不知道「成人模式」是什么。
2. 消息写入时由服务器按会话当时的 `contentScope` 盖章 `scope`，客户端发送的数据里**没有**这个字段，无法伪造。
3. `ChatReadPort` 读消息时仍要求声明 `scopes`（显式声明比隐式默认更不容易出错）。
4. **哪些地方按标签过滤**（记忆是否跨模式、推送是否隐藏正文、分享图 / 收藏是否排除、成人模式下是否发主动消息等）**以 PRD v1.2 为准**，由 ai-runtime、push、library 各自执行，本文不再规定。

### SAFE-01 真人：不生成肖像、不克隆声音

| 位置 | 执行方式 |
|---|---|
| 声音 | **能力缺席**：系统只接入「从音色库选音色」的语音合成，不接入任何声音克隆接口；语音合成请求只接受音色库里的音色 ID。音色库保存时校验名称不含真人角色姓名（ADM-04 验收第 2 条） |
| 图片生成 | 所有图片生成经模型网关，请求必须带 `characterId`；网关查 `portraitPolicy`：为 `forbidden` 时只允许 AI 负责人定义的「场景 / 物品」模板，并强制执行生成后检查（是否出现人脸，检查方法归 AI）；检查不通过则丢弃，改用无图回复 |
| 头像 | 真人角色默认头像为非肖像设计（设计负责人方案）。**管理员上传的头像不属于「生成」**，按第二轮意见第 2 条允许（管理员为预设角色上传、用户为自己的通讯录上传），接口见契约 `http/media.ts` |
| 卡面、表情包 | 表情包、卡面模板上传时管理员勾选确认「不含真人肖像」，记审计日志 |
| 历史人物 | 属于真人分类，`portraitPolicy = forbidden`（原「古风插画」例外随裁定 9.2 删除而取消，待总负责人确认） |

### SAFE-02 真人：不冒充本人发表公开言论

主要在 AI 层（提示词约束 + 输出检查 + 评测集，归 AI 负责人）。系统层保证：
- 公开动态只有管理员审核通过（`effective` 状态）后，`CharacterReadPort` 才会返回给 AI 运行时；候选动态对 AI 不可见（SIM-03、ADM-03）。
- 分享图数据中，凡含真人角色内容，`library` 模块标记 `requiresAiLabel = true`，客户端模板必须渲染 PRD 规定的标注，没有关闭选项（标注文案与样式以 PRD / 设计为准）。

### SAFE-04 识图认人只限两类对象

- **能力缺席**：不提供通用人脸搜索接口，也不维护角色以外的人脸库。
- 识图请求由 AI 运行时组装，参考信息只能来自 `policy.recognitionAllowlist`；关系网变化（ADM-02 删除关系）后下一次识图立即生效。
- 准确率和「范围外不识别」的保障由 AI 负责人设计并用评测集验证。

### SAFE-05 儿童角色额外保护

（总经理是否保留此条正在确认中，确认前保持不变，见 T-010 任务卡第 9 点。）
- 关系类型接口：`checkRelationshipType` 对 `isMinor` 角色拒绝「恋人」（403）；自定义关系描述中的恋爱含义检测归 AI，检测为是则拒绝保存。
- 情景模式：管理员标记「含恋爱内容」的模式对 `isMinor` 角色不返回；标记「含成人内容」的模式只对 `adultModeEligible` 角色返回（MODE-01 第 3 条）。

### SAFE-06 安全关怀 / SAFE-08 不操纵

- 识别和回应方式归 AI 负责人。系统约束：识别结果写入 AI 运行时的会话安全状态，**由代码开关**（不是提示词）关闭已读不回、撤回、打错字、负面心情、人为延迟（SAFE-06 第 4 条）。
- 所有频率上限（P-03、P-04、P-10、P-11 等）由代码中的配额账本执行，不交给模型判断。
