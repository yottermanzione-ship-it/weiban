# 消息转发（契约 3.10，A4 第二批）

任务卡 `docs/tasks/2026-10-15-chat-forward.md` 已批准本常规契约变更。

`POST /api/v1/conversations/:conversationId/forward` 接收源消息 UUID（1～50）、目标会话 UUID（1～10）、`individual/merged` 和 `clientRequestId`。不接收正文或原发言人。通讯录 active 联系人已有持久私聊 ID，即使没有历史也可作为目标；pending 联系人不能收信。不新增一条绕过添加资格的创建链。

服务器按本人可见源记录、seq 顺序读取；撤回/隐藏/清空、过期试聊、归属不符拒绝。单条强制逐条；合并新增 `forwarded_record`，含会话标题、原发言人名、时间和非递归内容快照。动作卡、拍一拍、通话记录转换为静态文字，不执行旧业务对象。已合并记录暂不再次转发，明确提示。合计最多 20,000 正文字、512 KiB 结构数据；超限明确失败，不截断保存。快照随正常消息加密持久，不用原会话链接读取。

每目标独立事务，锁定源/目标会话后构造快照并走既有 writer、sync、outbox；结果逐目标成功/失败。新增转发收据表，用用户+请求 UUID+目标会话唯一键及请求摘要防止重复/不同内容复用键；消息 UUID 从请求和目标及序号确定性派生。成功收据与消息同事务，重试只返回编号，不暴露已隐藏正文。媒体先通过 `MediaReadPort.getMedia` 查真实归属/ready 状态；内部受限转发能力再次校验整个快照媒体读权限，普通发送仍执行用途校验。adult 源不能盖 normal 标签，目标须为 adult 并通过 writer 当前所有角色政策检查；health 等标签保留，不进入记忆/通知正文。

私聊共用 MediaAi 渲染合并卡原发言人与真实内容；群聊及记忆共用离线内容渲染。转发文本明确为引用资料，不将其中原发言人冒充当前用户事实。新增类型仍走既有接收端未知类型降级。没有新增模型调用管线。

迁移序号实施时避开尚未合入的 q-features WIP；不改会员、支付或部署。
