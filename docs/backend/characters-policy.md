# 角色库与统一 policy（T-030）

WB-Card 1.0 的完整卡与草稿卡分别由 contracts 校验。管理员可保存未完成的草稿；发布要求完整资料、备用问候，以及同一修订号上的人设稳定/边界检查。客户端提交的检查结果被忽略。评测通过真实 ModelGatewayPort，走平台预算和账本；损坏的评分、未知儿童特征及基础设施失败都不能自动放行。模型评分不是独立质量验收，真实供应商和人工样本质量仍需配置后复核。

角色草稿和每个发布版本使用平台数据密钥加密，只有分类/搜索/版本元数据可直接查询。编辑保留活跃版本，发布锁定修订号，并发/重复请求只产生一个版本。旧修订的评测结果不能覆盖新修订。管理备注不进入提示词或用户资料；公开资料只有卡片知识条目这一份权威来源。

policy 调用时从可访问的角色事实重新派生资格，不采信卡片里的自由声明。儿童年龄/外观/系统检测任一命中即限制浪漫和成人内容；真人不允许成人生成，无审查模型同样受闸门控制。历史人物古风插画例外仅对管理员预设有效，语音克隆始终禁止。生成缓存重放也重新检查模型标签，不能借旧缓存绕过分类收紧。拒绝只记录代码和脱敏ID，不记录正文。

## 装配

组合根注入公开端口，业务模块不使用 ModuleRef。CharacterService 负责读取/更新和检查结果持久化；CharacterCheckWorker 持有评测器，避免 gateway → policy → characters → evaluator → gateway 的构造循环。管理接口触发队列评测，未通过时返回422，不假装已上架。

characters 数据库触发器再次阻止自定义真人/儿童事实放宽和归属变更，everPrivatePerson 只能增加。系统检测儿童后，发布禁止爱心图案；活跃头像在分类未知或收紧时回退为星星。预设下架后仅已添加用户可继续读取；L0 默认关系端口拒绝访问，L1接入真实通讯录。注销仅删除用户自定义数据，平台预设不因某个管理员注销而消失。
