# 好友申请与通讯录

T-038，contacts自己的schema；公开CONTACTS_READ_PORT。HTTP使用既有contracts ContactsEndpoints。字符资料的added和已有好友看下架角色，通过组合根将CharacterContactAccess装配到仅依赖平台/identity的ContactsReadService，characters不导入contacts实现，contacts写端才调用characters与chat，避免构造循环。

申请和接受都在用户咨询锁/账号共享行锁内处理；pending与active共同计入P26的50角色上限。CharacterReadPort.canAdd在同事务锁自己角色，确认上架及自定义角色归属，不通过公开profile绕过下架资格。认识日期按用户资料时区，默认关系为明星「粉丝与偶像」、其他「朋友」；恢复沿用日期、备注、头像和称呼，重新认识重置。

申请立即返回pending、conversationId=null。实际选择P30允许区间内的3～28秒，留出调度余量；接受队列单独采用0.5秒轮询、4个本机消费者，避免50个并发申请在串行2秒轮询下排到30秒之后；持久任务只存用户/角色/请求ID，原事务未提交就不存在任务。独立worker事务中接受申请、创建/恢复私聊、写通过系统提示、发布完整contact.upserted和contacts.contact_accepted。请求ID阻止重复任务及前一轮迟到任务改变新关系；每分钟对账补处理已到期申请/清理记录，防止时钟回拨或曾暂不可用后悬挂。下架发生在待接受期间时取消申请；若是历史恢复，原会话仍软删除保留，不默默丢失历史。

打招呼正文按用户DEK加密，AAD绑定contact记录ID；事件、任务和日志不带正文。第一条角色消息提交并投递后清空问候密文，仅处理当前已接受且事件发生时间不早于本次申请接受时间的关系，防止迟到旧消息擦掉新的问候。资料备注只影响本人显示；头像必须是本人拥有的contact_avatar，不能用其他用途或其他用户媒体。

软删除立即从通讯录/会话列表消失并归档停止发送，保留30天；重复软删除不重置期限。恢复选项必填，恢复沿用原会话，重新认识或立即删除物理清除旧私聊及contacts记录。恢复将当前会话范围回到normal，既有adult历史仍在原私聊，避免重加时未经确认重启成人情景。30天到期再次添加不要求恢复选项，得到新关系。清理任务比较本轮请求ID和期限，不能清掉已恢复关系。purged事件带原conversationId，后续记忆/养成等订阅者应据此清理旧关系数据。

账号进入deleting后读端返回空，所有写与迟到接受/清理任务拒绝；注销删除清单物理清除自己的记录，chat由其独立清单负责自己的全部子表。迁移0011_contacts由Drizzle生成且有down回滚。AI问候由下一任务订阅accepted生成，好友服务不伪装模型回复；群成员移除/推演/朋友圈等在相应后续层订阅removed/purged。
