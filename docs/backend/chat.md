# 聊天存储与收发

T-037；模块 apps/server/src/modules/chat。只操作自己的chat schema；公开ChatReadPort、ChatParticipantPort、ChatAdminPort和ChatUserPort。realtime底层只依赖契约，组合根把消息发送令牌绑定到ChatUserPort，HTTP与WS共用处理器。

私聊及后续角色群属于单一用户，角色参与者与用户参与者隔离。会话行锁分配连续seq；同会话、发送者与clientMsgId唯一索引保证重试只返回原消息，不再产生同步更新或领域事件。消息正文按用户DEK加密，AAD绑定消息ID；撤回物理清除密文。消息、会话预览/未读、更新日志与chat.message_created发件箱记录同事务提交；回滚不消耗序号、不返回成功ACK。事件不携带正文。

用户历史分页在会话锁内扫描连续seq窗口，返回coverage及hidden/cleared排除区间；内部缺失报错，不擅自跳过。本人隐藏和清空仅影响用户视图，记忆读取仍须明确scopes。引用预览按当前源消息状态计算；源消息撤回、本人隐藏或清空不再显示引用正文。normal范围消息不能借引用带出adult内容，内部会话预览也屏蔽adult正文。旧幂等键重试不会取回本人隐藏/清空的正文。

用户撤回受P23两分钟上限限制，重复撤回不再更新。用户已读只前进，手工未读可清除；角色已读游标独立推送，typing不落库。状态更新携带完整个人状态和未读数，新消息恢复用户隐藏的会话。归档与隐藏不同：contacts归档后停止角色/用户新消息并从列表排除；恢复沿用原会话与历史，重新认识/立即删除物理删除旧会话及本schema子表，然后创建新会话。

adult范围切换与每一条新消息重新检查真实policy。CharacterReadPort.getClassification及PolicyPort.checkAdultGeneration支持调用方事务，角色分类行共享锁一直保留到消息提交，阻止分类改变与写入交错。用户发送和范围切换的资格拒绝先提交审计，再由外层报告失败。chat不直接查询characters表，也不依赖AI运行时。网络请求不能指定消息scope。

账号删除清单物理删除所属会话、参与者、消息、个人状态和隐藏记录；账号状态共享行锁阻止删除期间迟到发送重建数据。迁移0010_chat同时提供回滚脚本。当前检查属于开发自测，独立验收由其他审查者完成；客户端聊天驱动、好友流程、AI回复与推送仍待后续任务。
