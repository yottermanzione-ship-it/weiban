写出微伴完整产品的需求文档（PRD v1.0），覆盖全部功能。架构、AI 系统、设计负责人能据此开工，质量负责人能据此验收。

## 需要产品负责人重点设计的地方

总经理明确说「不知道怎么做」、交给团队的部分：
1. **加角色的流程**：预设角色怎么上架、用户怎么发现和添加（像加好友？），自定义角色怎么创建（导入聊天记录生成）。
2. **推演 → 互动的产品形态**：人设推演日常 → 主动消息 / 朋友圈 / 「你不在时」时间线 → 与用户互动。说清楚用户看到什么、多久一次、怎么避免重复和打扰。
3. **角色之间的关系网**：关系来自公开资料中的真实关系；在群聊、朋友圈、私聊中如何体现；D5 角色主动拉群的触发条件和体验。
4. **养成系统**：熟悉度（不是恋爱向好感度）、卡片收集、成就、纪念日（「认识第 N 天」）如何融成一套，避免强制恋爱化。
5. **情景模式**：傲娇 / 恋爱 / 成人等模式的入口、切换规则，以及与硬性边界的关系。
6. **人设小巧思**：已读不回、撤回、打错字更正、有事件原因的心情，触发规则和频率上限，以及用户可调的「贴合人设 ↔ 顺从」设置。
7. **模型选择体验**（BYOK）：用户怎么填密钥、怎么选模型、排行榜怎么呈现、密钥无效或额度用完时的体验。
8. **C7 明星真实动态、C8 长期剧情线**：给出产品建议（做 / 不做 / 怎么融合），可行性标注「待架构 / AI 评估」。
9. **G10 导入导出**：导入聊天记录生成角色的流程；导出为分享图片的样式要求。
