## 契约变更申请（先于实现）

申请日期：2026-10-08。依据：MEM-01/02/03/05/06/07、CHAT-09/14、MODE-01～05、GRW-02；架构设计见 ADR-0018。

1. 新增 `MemoryEndpoints`：每个角色独立的记忆列表、新增、修改、删除。对象含分类、内容、状态、重要性、来源消息、创建方式、时间、内容范围和共享可见性；服务端盖章用户与角色、来源和范围。客户端只能通过受限请求修改，不能伪造抽取来源或跨角色写入。列表设有上限与游标，不暴露密文、密钥和隐藏的删除屏障。
2. `Contact` 新增可选 `relationship`（最长30字）；更新请求新增同名可选字段。沿用已有 contacts.relationship_type 存储，只有用户主动修改；调用统一 policy。存量响应/客户端仍可解析，运行时读缺省采用现有关系值。儿童和不具恋爱资格的角色不能用自定义描述绕过边界。
3. `CompanionSettings` 新增可选字段：`personaFit`（1～5，默认3）、`scenarioMode`（daily/tsundere/romance/adult，默认daily）、主动消息开关/频率、主动来电、日常开关。请求全部可选，旧客户端更新两项设置时保留新字段。模式列表另设只返回 policy 允许候选的接口；全局默认不允许 adult，角色成人模式必须先选成人模型，禁止回落到聊天模型。L3 调度消费者尚未实现的设置只存储，不声称已有主动行为。
4. 为设置模式提供 model-access 只读成人模型可用性端口，复用现有 resolver，不引入模块内部跨边界引用；不得暴露模型密钥。`ChatAdminPort.setContentScope` 增加可选Tx参数，让模式设置、范围盖章和系统通知同事务提交。`ChatParticipantPort.postMessage` 同样增加可选Tx与可选expectedScope，使记忆版本检查/发送/计划推进原子化，关闭删除与实际发消息之间的竞态。原有调用不变。所有模型调用继续走 `ModelGatewayPort`。
5. HTTP 文档、JSON Schema、安卓 Kotlin 生成物由源 schema 生成；Web 与 Android 现有设置请求兼容。新增端点与可选字段升级次版本 `2.2 → 2.3`；若实现中需要必填字段或改变既有枚举含义，先修订申请并升主版本，不偷改兼容约定。

影响方：ai-runtime（加密存储、后台抽取、上下文与生命周期）、contacts（关系）、model-access（只读模型检查）、Web/Android（设置及记忆管理）、契约生成与数据库迁移/注销清单。数据库新增迁移0014及手写回滚，不修改已有迁移。不引入供应商 SDK 或新的明文个人数据日志。

追加申请：`ChatReadPort.getConversation` 增加可选Tx，手动记忆的scope与删除屏障必须读取同事务锁定的会话，避免先读后写时模式改变；`PolicyPort.checkRelationshipType` 增加可选Tx，关系写入在事务中重新检查当前分类，避免资格变化与写入竞态。均为兼容旧调用的可选参数。
