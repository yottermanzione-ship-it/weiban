## 2. 所有卡共用的约定（每张卡只引用，不重复）

1. **契约**：接口、端口、事件、消息类型一律以 `docs/architecture/contracts-3.0-map.md` 为准（架构 T-062 正在写）。开发负责人**不改** `packages/contracts/**`；发现缺字段、缺接口，写进交接说明的「契约变更申请」，由总负责人转架构，不自行添加。
2. **迁移号段**：每张卡在卡内写明自己的迁移编号，只能用这几个号。文件放 `apps/server/drizzle/00xx_名称.sql` 和对应 `.down.sql`。层号段：L4 0030–0039，L5 0040–0049，L6 0050–0059，L7 0060–0069。号不够用时向总负责人申请，不占别人的号。
3. **本轮完成标准**：**本轮不写额外测试、不做评审，只保证可编译**。服务器和网页：`typecheck` 与 `build` 通过；安卓：`assembleDebug` 通过。已有测试不删、不改宽。交付前在本机只跑一次，之后以 CI 为准（`CLAUDE.md`「节省额度」）。卡里的「验收标准」是留给 Codex 整体验收用的，开发时照着实现，不需要为它写测试。
4. **参数**：卡中引用的 P-xx 均抄自 `docs/product/prd-v1.md` 5.1 节原文；如与 PRD 不一致，以 PRD 为准并上报。
5. **真实账号与密钥**：一律用假上游（测试替身）开发；需要真实供应商账号、Jev 账号、真机才能验证的部分，在交接说明中列为「待配置后验证」（总经理 2026-10-05 答复第 3 条）。
6. **工作副本**：从 `main` 新建分支 `T-0xx-简称`，worktree 放 `C:\wb-dev\wb-t0xx`；共享文件夹 `C:\Users\lomjy3\Desktop\weiban` 始终停在 `main`，不在里面切分支。PR 指向 `main`，描述末尾加 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`；**不要合并，不要动 main**。本机环境先读 `docs/team/dev-environment-notes.md`。
7. **交接说明**：按 `docs/handoffs/_template.md` 写 `docs/handoffs/2026-10-09-负责人-T-0xx.md`，必须写「给其他负责人的接口说明」和「待配置后验证」。
8. **不能放宽的底线**：硬性边界（PRD 第 10 章）、成人模式内容去向（MODE-05）、「健康」标记（PLAY-01 第 7 条）、不操纵（SAFE-08）在每张卡里都适用；涉及的地方卡内已点名。
