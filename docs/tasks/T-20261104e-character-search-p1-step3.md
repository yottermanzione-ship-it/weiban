「联网查找」（`POST /search/character-candidates`，S 的站外检索）返回的候选带上结构化身份说明和逐项出处，同名的不同人物分开列出；后台可以人工修正实体关联、别名和身份说明，并留审计。第 1、2 步的站内聚合结果能显示这些经核实的身份说明。

## 要做的事

1. **站外候选结构化**：联网查找的每个候选给出显示名、身份说明（职业 / 作品 / 所属，模型只能根据已有公开结果归纳，不能编）、逐项 `sourceUrl`、可选 `entityKey`、未核实标记。没有足够证据就保留多个候选，不合并；只凭名字、相同头像或模型一句判断不算证据。站外文本按不可信资料处理（防提示词注入）；URL 校验和抓取继续走 model-access 现有的出口。
2. **实体关联**：`entityKey` 只来自经核实的公开资料标识或平台人工关联。已有站内角色和站外候选指向同一实体时，聚合结果里合并成一项并显示「去聊天 / 添加」；证据不够就分开显示。
3. **后台人工修正**：管理员可以修正实体关联（合并 / 拆分）、别名（增删，审核后才进投影）、身份说明，每次修改写审计（谁、何时、改了什么、原因）。修改后对应投影要刷新（复用第 1、2 步的 dirty 刷新机制）。
4. **缓存与费用**：沿用 S 的公共查询缓存、租约去重、跨 worker 配额和按实际供应商结果计费；同一个词并发查询只打一次供应商。公共缓存只存通过公开人物 / 虚构作品过滤的结果，不存私人原话、手机号、邮箱、健康、住址、实时行踪。空白、一个字、超长输入仍只在站内搜，不弹收费提示。
5. **点击只提交候选 ID**：服务器重读候选，不信任客户端提交的外部 URL 和名称来授予添加权限（第 1、2 步交接里说这一步留到第 3 步补，请补上）。
6. **网页**：联网查找结果展示身份说明、出处链接（外链安全属性）、未核实标记；同名分开，可以按作品或职业补充关键词再查。
7. **测试**：方案「统一自审」里站外相关的用例都要覆盖，包括同一词并发缓存、额度耗尽、两位同名人物不误合并、提示词注入文本不影响系统提示、点击伪造 URL 不授予权限、后台修正留审计并刷新投影。测试数据全部自造，站外供应商用假服务。

## 验收标准

- [ ] 联网查找候选有身份说明、逐项出处和未核实标记；证据不足时不合并。
- [ ] 实体关联只来自核实标识或人工关联；同名反例零误合并（固定语料，结果写进交接）。
- [ ] 后台修正实体、别名、身份说明可用，有审计，投影会刷新。
- [ ] S 的计费、缓存、额度含义不变；并发同词只打一次供应商。
- [ ] 点击候选只提交 ID，服务器重读后再走添加闸门。
- [ ] 本机只运行一次相关检查；推分支、开 PR，以 CI 为准。
