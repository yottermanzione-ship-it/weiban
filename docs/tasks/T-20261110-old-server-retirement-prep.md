## 执行顺序

1. 复制官网现用静态文件及已验证正式 APK，准备旧 `/api/app/config`、`/api/download-config`、旧网页跳转与历史下载别名。
2. 在线备份旧 SQLite 至独立历史副本；复用旧后台路由与密码体系，只恢复管理登录/退出及查看，关闭生成/收款/渠道/后台任务。凭据不输出或以明文写入新文件。
3. 新机以独立容器承载上述入口，不替换新站数据库。服务只接内部网络与本机准备端口；为官网域名配置新机入口和证书获取流程，解析由经理最终修改。
4. 原微信授权仅在内存中读取并加密暂存，固定原归属/角色/代次。在新机复用已经运行的兼容收发代码，独立容器待命，避免另写原生渠道导入和改变消息去重语义。准备停旧后启新顺序与回退；已失效一条不伪造可用、不自动重新授权。
5. 一次集中验证本轮入口、历史库/鉴权、下载校验、旧更新响应及微信导入边界。没有实际切换或真实手机验证的项目明确标记未验证。
6. 回执必须列明已准备内容、仍需经理修改的解析记录、正式切换步骤及旧机尚保留的依赖，不提前宣布可以销毁旧服务器。
