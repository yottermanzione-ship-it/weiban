## 背景：线上和 v3 的差别

#41（契约 5.0）只删除、合并了 10 个开关，还没有按 v3 收拢展示层级。线上现在仍有 17 个开关：基础层的动作还列在开关里，没有「私人朋友圈」一个开关，「很久没说话时问候」和「跟进你说过的事」也还单独列着。v3 的口径是：

- **基础层**：所有人默认都有，不展示，也不需要开生态。包括语音、图片、表情包、拍一拍、熬夜催睡、朋友圈的三种互动（给你的朋友圈点赞评论、回复 TA 朋友圈下的评论、去其他角色朋友圈互动）。
- **生态层**：只展示下面 6 个开关。碎碎念没有开关，只有展示入口。

| 展示的开关 | 内部覆盖的动作 |
|---|---|
| 主动消息（`message`） | message，另含早安晚安、生日纪念日、经期关心、很久没说话时问候（care_absence）、跟进你说过的事（care_follow_up） |
| 私人朋友圈（新 key `private_moments`） | weibo_sync、moment_post（转发微博到私人朋友圈） |
| 更新状态（`status`） | status |
| 改个性签名（`signature`） | signature |
| 照顾宠物（`play_pet`） | play_pet（仍置灰「即将上线」） |
| 群聊主动话题（`group_talk`） | group_talk |

## 1. 开关清单收拢（契约 + 服务端 + 网页）

- `getEcology` 响应里的 `actions` 只返回上面 6 个开关，分组和顺序沿用现有分组（private_moments 归 `moments` 组）。
- 新增 key `private_moments`，标签「私人朋友圈」。关掉它等于同时关 weibo_sync 和 moment_post，打开就两个都开。推荐做法：沿用现有 `disabled_actions` 存储，由服务端映射，这样不用迁移数据。显示状态以「两个都没被关」为开；如果旧数据只关了其中一个，显示为开，并在用户下次切换时统一写成两个都开或都关。
- care_absence、care_follow_up 改由 `message` 开关管。旧数据里单独关掉的这两项，读取时忽略（视为跟随主动消息）。早安晚安和跟进不计入「3 次无回复」，这条已有逻辑不能被改坏。
- **兼容旧客户端**：旧 key 继续留在枚举里，客户端发来更新时接受，但对已收进别的开关或已归基础层的 key 不起作用。只新增字段或枚举值，不删除，所以是**次版本**升级。T-20261103（网页批次）会先合入 5.1，本任务在它之后升 **5.2**：开工前先合并最新 origin/main，`version.ts`、README 变更记录、`service-unit-pricing.test.ts` 版本断言、Android 生成产物（`pnpm android:generate`）都要同步。WebSocket 已放行 5.x，不用改。
- 网页 `ecology.tsx`「按动作」页签只渲染服务端返回的开关。检查有没有按旧 key 写死的文案或图标，有的话更新。

## 2. 基础层不再受生态开关控制

- `moments-ai.ts` 里三处 `ecology.isActive(..., 'moment_interact' | 'moment_peer' | 'moment_reply')` 闸门改成基础层判断：账号正常、角色是好友且在通讯录里、可见范围对得上就排。不再要求 PRO+、生态开关、角色生态开关或动作开关。旧版机制（点赞评论分开排、延迟 1–15 分钟、各自去重、人数和概率）已经照抄过，保持不变。
- 这些互动的模型费用按现有「后台消耗由用户承担」规则计费，和聊天里的后台消耗一样，不再标成生态任务。积分不足时跳过，不报错。具体计费入口读 `docs/` 里积分相关文档和现有 `countAsBackground` 用法后决定，交接里写明选择。
- 聊天里的语音、图片、表情包、拍一拍、熬夜催睡如果有地方受生态开关控制，一并去掉（`suppressedForms`，即用户说过不要某种形式就不发，必须保留）。生态的「主动消息」本身可以继续用这些形式送达，但它们不再作为独立的生态候选动作。
- 官方角色公共朋友圈（`postPublic`）不变。共同事件 `coordinateDay` 仍只给开着生态的用户安排。

## 3. 碎碎念修正（宁静那条像提示词）

- **根因**：`generateMurmurInner` 把 `jevSummary` 的运营摘要原样喂给模型（「对方上次发消息在…；角色发了还没被回的消息 N 条」「角色今天已经做过…」），而且 `maxOutputTokens: 80` 太小，11-02 那次输出正好 80 token 被截断。
- **要求**：
  1. 碎碎念单独组装素材：当前时段、角色自己的生活或今天发生的事（状态、签名、最近自己发的动态、共同事件里与角色自己有关的部分）、这次做了什么（用自然语言描述）。素材里不出现聊天计数、未回条数这类运营指标，也不出现「对方 / 用户 / 角色」这类第三人称称呼。
  2. `maxOutputTokens` 提到 200 左右，在服务端截到 60 字以内，截断点落在句末标点。
  3. 输出过滤：出现「角色、对方、用户、碎碎念、日记、人设、提示词、以下、好的、作为」等明显元话语，或像在复述指令的，丢弃这次碎碎念，不重试，也不写库。
  4. 单测覆盖三点：素材里不含运营摘要字段、截断规则、元话语过滤。
