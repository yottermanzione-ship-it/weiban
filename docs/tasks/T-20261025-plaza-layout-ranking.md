# T-20261025：角色广场布局与添加热度排名

## 用户要求

1. 顶部“自定义角色 / 微伴角色”两个TAB等宽填满可用顶栏，选中下划线更靠近文字；保留返回与个人入口。
2. 删除热门、类型、分类等全部筛选控件。搜索框保留（主代理已明示），两个TAB及搜索结果只按被用户添加的次数排热度，不按点赞/评论或综合热度。
3. 角色列表自然填满下方剩余空间，不再是中间短列表、底下大块空白。列表末尾加入一行“加载更多”，用户主动点才取下一批；转圈、重复点击保护、失败重试与无更多状态明确，不自动触底连拉。
4. 整体排版清爽，不横向溢出；不擅自删除点赞/评论等已有业务能力，它们只是不参与排名。

## 排名与分页原则

- 先查现有真实添加/采用统计，不把下载、点赞、评论改个名字当添加数。
- 同一请求重试、重复点击不能刷添加次数。沿用已有合理真实口径；若需基于用户实际添加关系统计，明确是当前关系还是累计添加，不编造旧历史。
- 排序在后端分页前完成，添加数降序，相同计数使用稳定次序；不能只把当前一页在前端重排。
- 搜索、切TAB、翻页时口径一致，不重复或漏项。
- 不跨模块直接读表；必要契约字段先向主代理说明，不擅自改版本或生成产物。大迁移/大范围模块改造先报告，不自行扩张。
