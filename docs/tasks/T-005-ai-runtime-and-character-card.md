## 目标

设计微伴的「灵魂」：全新的角色卡框架，以及 AI 运行时的整体方案（模型接入与选择、上下文构建、记忆、推演、群聊调度、安全边界执行、评测）。

## 背景

- 总经理不提供旧角色包，希望团队**全新设计角色卡**，参照成熟产品（如 SillyTavern 的角色卡 V2/V3、世界书），做得更适合「明星 / 公众人物 / 虚构角色 + 微信式陪伴」。调研整理见 `docs/product/research/competitive-analysis.md` 第 4 节。
- 预设角色通过蒸馏网络公开资料制作（如杨幂、李白、罗小黑、江流儿），人设需要能持续更新（PRD CHR、ADM-06）。
- BYOK：用户自带密钥、自选模型，需要角色扮演模型排行榜（ADR-0002）。
- 与本任务并行的 **T-004（架构负责人）** 负责系统模块边界和接口契约。AI 运行时对外的接口由架构定，你负责内部方案；角色卡结构由你设计，架构之后会把它并入契约。

## 验收标准

- [ ] `docs/ai/character-card-spec.md`：角色卡规范 v1
  - 字段清单（含义、类型、必填与否、示例），覆盖 CHR-11 的全部产品信息
  - 角色分类字段（真人 / 历史人物 / 儿童 / 虚构成年 / 原创成年）及其对硬性边界的约束
  - 粉丝名、关系网、公开资料库（世界书式按需调出）、说话风格样例、情景模式适配、版本与更新机制
  - 与 SillyTavern 卡片的对照：借鉴了什么、改了什么、为什么；能否导入酒馆卡片
  - 附 2 个完整示例卡：一个真人明星（可用虚构的示例明星，避免编造真人隐私）、一个虚构角色（如罗小黑，只用公开设定）
- [ ] `docs/ai/character-distillation.md`：从网络公开资料制作预设角色的流程（资料来源、整理步骤、质量检查、更新流程）
- [ ] `docs/ai/runtime-overview.md`：AI 运行时方案，至少包括：
  - 模型接入：支持的供应商、统一接口、BYOK 密钥使用、排行榜数据来源与维护
  - 上下文构建（各部分的组装顺序和 token 预算）
  - 记忆体系（近期、关于用户、共同经历、长对话摘要、跨角色共享规则）
  - 推演 → 主动消息 / 朋友圈 / 时间线的流程与成本估算（回答 P-15、P-16 是否需要调整）
  - 群聊发言调度、角色之间接话、主动拉群
  - 识图 + 联网搜索的认人方案（SAFE-04 范围限制）
  - 硬性边界在 AI 层如何执行（不只靠提示词）
  - 人设小巧思（已读不回、撤回、打错字、心情）的生成方式
- [ ] **平台侧模型调用的费用方案**（推演、朋友圈、记忆整理、导入分析）：记在用户密钥还是平台，给出推荐和理由，写成 ADR 草案（状态「提议」）
- [ ] 评测集方案：覆盖 PRD 中所有标注「评测集覆盖」的验收项，列出类别和样例
- [ ] 回答 PRD 8.2 的全部 15 个问题（做不到的明确说做不到，并提出替代方案）
