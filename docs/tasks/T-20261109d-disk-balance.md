# 两盘容量利用与打包缓存上限

- 负责人：Codex；开发自测，不冒充独立验收。
- 基线：1c77a04b92e4003d5f275f3b48bc6d62c2a9d5c7；线上应用 fe356c1d2113802b593ca154d68c4e9027905412。
- 总经理授权：限制打包缓存，合理利用两块盘，尽量不影响正常使用。
- 边界：本任务不执行旧站迁移、不改 DNS/下载入口、不搬动生产数据库或媒体、不重启 Docker 或聊天容器。

## 验收

1. 新打包缓存实际落在剩余空间较多的 50G 文件系统，不只是换目录名称；保留上限4GiB，旧默认缓存上限1GiB。
2. BuildKit 自动回收、每30分钟补充回收和每次发版后回收均有配置；正在构建的缓存不强删，完成后回到保留预算，不能宣称硬磁盘配额。
3. 新打包环境只有2核、4GiB内存额度，预留12GiB磁盘空间；容量不足时拒绝新构建，运行中的服务不停止。
4. 发布显式选择已检查的独立打包环境，同时检查其实际存储盘。发布和定时维护互斥。
5. 现有应用/数据库容器身份、当前和两次回退镜像、卷挂载保留；实际微型构建/加载及公开健康采样通过。
6. 提交、检查、来源门禁和运维单独安装证据齐全；不为只改运维工具而重发应用。
