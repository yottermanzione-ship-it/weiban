# 收款监控启动闪退修复

经理在安装 1.0.0 后反馈，点击“开始监控与补报”应用闪退。基线为已发布主线 `dfd078812fb0b92a5eb71f085723c76884086961`，独立分支 `codex/payment-monitor-startup-fix-20261108`。

## 范围与证据

- 修复独立收款监控启动与补报调度；沿用包名、签名、设备绑定、私钥及未确认到账队列，覆盖安装为正式 1.0.1/2。
- 现有网络约束的 JobScheduler 未声明 ACCESS_NETWORK_STATE，Android 14 及以上对 target 34 及以上应用会抛 SecurityException；异常发生在 Delivery 的 finally 内，没有保护，会逃出后台线程。
- [Android 官方要求](https://developer.android.com/about/versions/14/behavior-changes-14#jobscheduler)：网络约束需要上述普通安装权限。此项不是要求经理手动再授权。
- 目前未连接实际手机，没有获取用户崩溃日志。代码中的确定缺陷与用户症状吻合，但不能据此声称已排除该手机的所有其他原因。
- 旧版测试只覆盖解析、协议与队列，未覆盖权限和调度拒绝；补齐有意义的回归检查，保留修复前失败证据。

## 验收标准

1. 安装包实际包含所需权限，正常补报任务仍有网络约束、60 秒延迟和重启持久化。
2. 系统拒绝调度或返回失败时不闪退，显示单独警告；后续调度成功可清除警告，不把失败冒充已启用。
3. 调度失败不改变设备绑定、不删除或确认待补报到账，重试及通知解析继续执行原协议。
4. 自动检查、正式签名与覆盖升级标识通过；安装包直接放桌面根目录，经理覆盖安装后复测启动。
5. 收款切换已经取得旧服务器例外授权，但须监控手机真正上线后再执行。修复期间不开放新站收款，不修改旧站，不伪造到账，不自动付款。
