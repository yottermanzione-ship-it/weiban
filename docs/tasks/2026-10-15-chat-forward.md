# A4 第二批：完整消息转发（2026-10-15）

目标：把暂未开放转发接通，实际可用。长按转发进入多选，选中当前条；多选底栏增加转发；多条提供逐条/合并，单条强制逐条；接收目标最近聊天优先，另可从通讯录角色选择（未聊角色也可选，不做仅最近的假功能）。取消退回原选择，不循环路由。逐条以用户身份原样发，合并聊天记录卡保留原发言人/时间/内容、显示谁与谁聊天，点击展开对照截图。多个目标可靠去重，不因重试重复发；普通发送后接收角色会实际获得上下文。

契约变更申请由总负责人在此批准：可以新增源消息ID转发端点和服务端生成的聊天记录快照消息类型，以及对应客户端/AI渲染配套。先在docs/backend/或交接记录接口方案，再写packages/contracts。建议次版本3.10（q-features WIP已预留3.9且未合入）；与生成物必要一致，但安卓仍不编译/重做UI。重大架构选择有必要才ADR，不为常规端点造复杂体系。

实现约束：
- 客户端只提交源会话/选中消息ID、目标/模式、幂等键；服务端按当前用户真实可见性读取并构造快照，不接受客户端伪造原发言人或正文。源与目标归属/成员、隐藏清空撤回、媒体权限都核查，使用现有写入事务/同步/模型触发链。不硬编码假成功；一次结果明确各目标成功/失败，重试复用幂等。
- 单条即使请求合并也按逐条处理；按原seq顺序，数量/总字数/大小上限有清晰提示。逐条文本/图片/表情/链接等保持原语义；动作卡快照不能在目标处误执行原会话动作，不支持的内容明确说明，不静默丢失。
- 合并记录为加密持久快照，不通过未经鉴权原会话链接给目标取内容；不无限递归嵌套合并记录。媒体经当前权限读取，不把未授权media直接透传绕过权限。转发不同scope与目标资格沿既有政策检查，不得绕过真人/未成年性内容边界。
- AI上下文必须包含合并卡里的原说话人和实际内容，不是只送「聊天记录」占位；接入私聊及群聊/记忆通用内容渲染处的必要支持，未知新类型老客户端仍容错。保持现有稳定前缀组装，不另开模型调用或另写一套聊天管线。可用离线真实组装器检查实际输入片段，不调用收费模型；不是写测试套件。
- A4-ui六格菜单/引用/头像/情景等继承，不能因新转发退回深色菜单或多出第7项。图片/旧表情导入继续现有配套，不执行线上导入。
