## 排查与修复范围

- 检查已浏览页面的重新挂载、角色资料/姓名读取、媒体元数据/签名链接、图片显示与加载状态。
- 检查通讯录全量数据、姓名分组和头像请求链；必要时调整已存在的共享状态和缓存，不另造一套互不一致的页面缓存。
- 检查会话列表、通讯录、资料页及其他使用同一读取/媒体组件的页面，修复有证据的同类问题；不借此重写全站或优化无关功能。
- 优先复用既有 [api-client.ts](<C:/wb-dev/wb-client-logs/packages/client-core/src/api-client.ts>)、[local-store.ts](<C:/wb-dev/wb-client-logs/packages/client-core/src/local-store.ts>) 的缓存/所有者隔离机制。

## 必须满足的缓存语义

- 首次读取完成后，再切回页面时已有内容立即可见，不先清空成占位、空列表或整页加载状态。
- 有效缓存期内复用稳定的媒体链接，避免每次取角色资料都生成全新图片 URL，导致浏览器无法复用已加载的图片。
- 同一身份、同一资源的并发请求合并；不能因为一个组件卸载就取消其他组件仍需要的共享请求。
- 签名链接必须按有效期刷新，失效时有有界恢复，不能靠无限延长授权链接或全局公开缓存私有图片解决。
- 好友添加/删除、备注与头像修改、角色更新后及时使相关缓存失效；手动刷新仍有效。
- 缓存必须隔离账号/会话，并处理退出登录、401、切换账号，以及旧请求延迟返回后的写入保护，禁止串数据。
- 尊重显式 networkOnly、写请求和强实时业务要求，不能把余额/权限/可用性等决策永久缓存。
- 缓存容量和过期清理有界，不使用无上限 Map/图片集合无限增长。

## 验收场景

1. 按用户截图尺寸 349 × 756，以及底部安全区场景检查；先浏览一批头像，再在“微伴 → 通讯录 → 发现 → 微伴 → 通讯录”间切换。
2. 记录首次与后续切换的请求差异；有效期内不得重复对整批角色资料/头像做无意义完整请求，必要的后台增量校验不应阻塞显示。
3. 通讯录已加载的好友、姓名与分组立即显示，避免先全部归到空名字/# 分组，再整页跳动重排。
4. 修改头像、添加/删除好友、手动刷新后看到正确新结果；签名链接失效后能恢复。
5. 切换到另一个账号，不能出现上一个账号的好友、私有头像或迟到响应。
6. 只执行一次直接相关的回归检查；失败只修相关错误并至多复测一次，不跑无关全量测试。
