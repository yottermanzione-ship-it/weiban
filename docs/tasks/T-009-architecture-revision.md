## 目标

按总经理第二轮决定修订技术架构，开发计划和契约同步更新，开发启动前底座稳定下来。

## 背景

总经理三项改动：① 安卓不要 WebView 套壳，做原生客户端；② 不是 BYOK，改为平台中转、用户余额扣费；③ 成人模式只保留「儿童角色不开、真人角色不开」两条底线，其他限制取消。另外，总经理非常在意消息不丢不重，问能否直接用成熟开源通讯产品的消息链路。总经理表示信任团队判断，但需要一份对比作为记录。

## 工作内容

1. **安卓客户端选型 ADR**：至少对比 Kotlin + Jetpack Compose、React Native、Flutter。评估：原生体验（总经理的核心诉求）、和网页端能复用多少（契约、业务逻辑、UI）、AI 写代码的熟练度、推送 / 保活 / 全屏来电 / 语音通话等原生能力、国内厂商推送接入、调试和打包对零基础总经理的友好程度。给出结论。
2. **计费模块设计**（取代 BYOK）：
   - 平台密钥管理（替代用户密钥模块）
   - 模型价目表（按模型、输入 / 输出 token、图片、语音分别定价）
   - 用户余额、流水、扣费时机（预扣还是后扣）、调用失败退还、余额不足时的行为
   - 后台预算、管理员手动加余额、对账
   - 是否接入模型聚合服务作为上游（例如一个密钥覆盖多家模型），给出建议
   - 新增 ADR
3. **成人模式资格规则修订**：资格 =「非儿童」且「非真人」，其余条件取消；同步更新 `hard-boundaries.md` 和 policy 推导规则。
4. **消息链路对比**：把现有方案与主流开源方案对比（至少 OpenIM、Matrix/Synapse、Tinode，可自行补充），维度包括：消息可靠性机制、能否接入 AI 角色作为参与者、单台服务器的资源占用、二次开发难度、和我们模块化单体的契合度。结论写进 ADR-0005 的补充或新 ADR，用通俗语言向总经理解释为什么选现在这条路（或建议换）。
5. **同步更新**：`overview.md` 模块清单、`dev-plan.md`（新增安卓原生和计费相关任务，删除或修改 BYOK 与 Capacitor 相关任务）、契约（BYOK 接口改为余额 / 价目表 / 模型目录接口；原生桥 `bridge.ts` 按选型决定是否保留）、`tech-debt.md`。
6. 顺带处理：pnpm 版本基线（T-007 交接：10 / 11 / 12，影响 D-L0-01）；设计负责人申请的角色显示字段（应援色、头像字、头像小图案、主题色）；头像上传接口（管理员为预设角色上传、用户为自己的通讯录上传）。
