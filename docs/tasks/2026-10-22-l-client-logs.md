# L 客户端运行记录实施

依据：第四轮第五轮确认的 23 号方案。2026-10-22 总经理要求不需本人参与的任务连续完成，配置 / 方案确认后才统一自审。本任务不逐阶段运行完整测试或要求继续，不把必要编译当作验收。

活动副本 `C:\wb-dev\wb-client-logs`，分支 `codex/client-logs-l`，基于 M `dc8f6153398e999dfd3207da6074ae6b4fe051ec`。契约 3.33，迁移 0135。共享 main、生产配置与 `docs/quality/` 不写；不 push、合并、部署或真实供应商调用。

实施范围：网页全局异常 / 未处理异常 / 渲染崩溃 / 脚本资源失败 / 请求失败 / 实时异常；安卓崩溃保存后补发、请求和推送注册异常；本人 / 匿名两条接收路由、固定技术分类、归组、去重、配额、清理、注销删除和告警；后台问题详情、用户近期记录、工单技术快照；隐私说明。

隐私收紧：不收任何异常原文，不依赖正则把聊天内容「猜成」技术信息。代码文件和组件只保留短指纹及数字坐标，路由未知片段统一 `:id`。没有原始 URL、HTTP 正文、输入值、令牌、设备永久编号或持久化 IP。匿名配额只在进程内的有界 IP 表计算；全平台和已登录额度用 DB 串行计数跨 worker 生效。

验收清单（统一自审时执行）：

- 固定字段契约拒绝正文 / 自由异常、双端路由归一化、跨账号离线队列清除与迟到返回。
- 同一事件累加按差值入账；重试不重复增加；单次 20、队列 200、设备 50/小时、用户 300/日、匿名 IP 100/小时、全局 6000/分、32KB 超出成功丢弃。
- 30 天明细 / 会话 / 用户关联 / 工单快照清理，180 天纯分组 / 版本元数据；注销后本人数据为零且旧请求不能复活。
- 已解决问题在不同版本重现重新打开；20 名登录用户/小时单次告警；新版本头一小时两版本各至少 20 会话且当前至少 5 次受影响、比例大于三倍时单次告警。
- 后台筛选、趋势、请求编号复制、用户跳转、标记备注与审计、反馈附带技术记录；安卓崩溃不吞异常、无异常原文落盘、下次启动补发。
- 真实 PG 迁移 up/down、并发配额、注销竞态、浏览器真实网络和 Android 真机行为尚待检查。必要编译与生成只记实现证据。

统计边界：后台比例仅针对成功上报的会话，不能称全站真实报错率；影响登录人数仅近 30 天。匿名不能跨进程共享 IP 表，此限制不影响 DB 全局总量闸门。第一期不还原 source map，不新增外部遥测供应商。

计数口径：事件按累计次数差值计入接收量；新打开会话的一条基线也计一单位，已有会话的同一回执重发不重复增加用户日额度。全局还按请求至少一单位控量，匿名另外限制每 IP 每小时最多 100 次请求。版本激增是客户端首次被观察到的一小时内的采样比较，不是已核实的全量发布质量报告；离线旧版补发不按新版本自动重开问题。
