## 批 H1：去关系选择 + 欠费扣费机制 + 拍一拍（已确认）

1. **删除「关系类型」选择**（总经理：有好感度机制就不要关系选择）：用户端聊天信息页 / 资料页的关系类型入口、二级页面、接口写入一律去掉；恋爱表达只随好感度阶段解锁（暧昧起想念偏爱，恋人起恋爱称呼）；「恋爱模式」等手选恋爱入口如存在也去掉或改为跟随阶段。旧数据中的关系类型字段不再读取（保留列以便回滚）。注意 G1 里「用户选了恋人关系直接用恋人口吻」的特例一并删除。
2. **扣费改为「先用后扣、可欠一次」**（取代 13 号 §5 的「先冻结后结算、不透支」）：
   - 调用前不再按「最大可能花费」冻结大额积分；只检查余额 > 0（余额 ≤ 0 直接拒绝，提示充值）。
   - 调用后按实际用量扣，余额可以变成负数；**一旦为负，立即停止该用户的一切付费调用**（聊天、生态、主动消息、记忆整理等后台任务都停），直到充值使余额 > 0。
   - 防止并发叠加欠费：同一用户同时进行的付费调用设上限（如 2 个），超出排队或拒绝；单次请求按模型最大输出与本平台实际发送的上下文封顶估算，异常巨额请求（预估超过 N 积分，后台可调，默认 200）先拦截。
   - 后台对账能看到欠费用户与欠费金额；用户端积分显示负数并提示充值。
   - 保留 G3 的「用量未知按估算计费」。
3. **拍一拍做完整**：聊天页双击（及长按菜单）对方头像 → 发出「我拍了拍 X（后缀）」系统提示，角色可按人设回应；「我」页 / 个人信息里增加「拍一拍」设置（G2 已做好的二级页面，截图 34），服务器保存用户的拍一拍后缀；角色拍用户时显示用户后缀。查清现有实现为何测试无效并修好；群聊里拍成员同样可用。

## 批 H2：私密模式重整（已确认）

1. 私密模式下**只开放文本与图片**（模型自带能力）：不能语音通话、不能语音输入、角色不发语音消息；入口隐藏或置灰并说明。
2. 私密模式期间：记忆抽取、摘要等全部交给私密模型，正常使用。
3. **切出私密模式时（切到自动或任何非私密模式）**：由私密模型做一次「干净整理」——生成一份不含露骨描写的摘要（露骨内容概括为「亲密行为」等），写入日常范围，供日常聊天、群聊、生态使用；原私密记忆仍只在私密模式可见。
4. 该角色处于私密模式时，其角色生态的动作也强制使用私密模型（避免上下文互相干扰导致摘要出不来）。
5. 私密模式中的安全关怀回合仍由私密模型生成（加关怀要求），私密内容不出私密范围。
6. 之前「私密通话」相关修复保留，但入口关闭后不再发生。

## 批 H3：图片描述存档（已确认部分）

1. 用户发图时，聊天模型直接看图回复（所有模型都是多模态），**同一次调用顺带输出一段简短图片描述**（不额外调用），描述存档，后续上下文、记忆、群聊、生态都用这段描述，不再只记「发过一张图片」。
2. 角色相关图片识别（例如用户发了这个明星本人的照片、海报、作品截图）：方案待写（见批 P 第 3 条），本批不做。

## 批 H4：微博同步（已确认，需总经理在后台配置 DeepSeek 搜索密钥后才能真实运行）

1. **只对有微博标记的角色**（角色卡上有微博昵称与微博头像这两个属性）同步。
2. **只在有人真正在用时同步**：至少有一个用户加了这个角色且为它开启了角色生态。
3. **频率**：每天一次（后台可调）。
4. **费用由这些用户平摊**：每次同步的搜索费用，平均分摊给当时「加了该角色且开了角色生态」的所有用户（按积分扣，四舍五入到 0.01 积分；不足 0.01 记累计）。
5. **结果去向**：同步到的新微博，写成该角色的私人朋友圈内容，推给所有开了角色生态并加了该角色的用户（与公共朋友圈区分）。同时写入该角色的「近期公开动态」，供聊天上下文使用。只用公开内容，不编造私生活。
6. 接入 DeepSeek 搜索：作为「联网搜索」平台内部能力的一种上游（`POST https://api.deepseek.com/v1/tools/search`、`/v1/tools/fetch`），详见 21 号文档。

## 批 P：只出方案（写文档，等总经理定）

1. **角色搜索引擎**（`docs/refactor/24-character-search.md`）：像微博搜索那样支持错字、前缀联想（「易烊千」→ 易烊千玺）给候选词；同名消歧（「李晨 · 演员，《奔跑吧》大黑牛」「李晨 · 服装博主」），每个候选带一句注释说明是谁、特征是什么；候选结合本站情况：已有（官方角色或角色广场用户作品）→ 直接添加；没有 → 去申请制作 / 创建。站外候选用联网搜索（平台出钱、限频）。
2. **人设补全机制**：角色由「女娲技能」从网络公开资料蒸馏总结而来；出方案：例如定期（如每月）联网检索新公开信息 → AI 生成「人设更新建议」差异 → 后台审核后应用，不自动改卡。
3. **角色相关图片识别**：用户发的图片可能就是这个角色本人 / 海报 / 作品，角色要认得自己；结合角色外貌特征、代表作、头像，必要时联网检索，出方案（更新 22 号文档）。
