# 后台用户详情重置密码

总经理 2026-11-10 明确要求将密码重置入口放在后台用户详情，方便自行操作；沿用开发接管及发布授权。本任务不重置任何生产账号。

## 契约变更申请与接管评估

- 新增 `POST /api/v1/admin/users/:userId/password`，管理员管理会话鉴权，正文仅为密码，响应仅为 `revokedSessions`。契约 7.10，最低客户端协议不变。
- 用户详情“基本资料”显示“重置密码”；弹窗绑定用户编号并展示昵称及登录名，两次输入确认，不使用可持久化的表单草稿。
- 服务端复用密码强度、散列及会话吊销能力；在事务内复核管理员身份和目标账号，仅处理正常状态的普通账号。重置退出全部旧会话、解除全部关联登录名锁定，保留已有封禁。
- 审计只记录操作者、目标用户和退出会话数，不保存密码。无数据库迁移，不改积分、会员、聊天、用户自助找回流程或安卓安装包。
- 影响范围：后台页面、身份模块和新增管理接口；安卓只同步生成契约。旧网页和客户端保持兼容。

## 验证与发布

使用独立数据库和虚构账号验证成功路径、旧登录退出、权限拒绝、密码规则、封禁保留、审计和日志保密；后台浏览器检查入口、确认、关闭后清空。仅在相关检查通过并执行发布来源校验后上线。结果见本轮交接；属于开发自测，不代替独立验收。
