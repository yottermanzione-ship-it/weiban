# 旧版两种扫码付款与新监控软件

经理2026-11-08新增：付款只接旧版扫描两个二维码的方式，另做新的监控软件。经理已确认：积分＋会员，做收款到账监控。实现两个扫码渠道、积分和会员订单、后台对账、独立安卓监控软件。

基线：`2780ae0783039298d56785be56ca523825ecfabe`（已合并的情景配置 PR #111）。此任务独立分支 `codex/scan-payment-monitor-20261108`，已快进对齐主线，保留既有修复。

## 已核实的旧版机制

- 微信和支付宝个人收款码，不是本次接入官方钱包跳转。收款码由服务器配置，图片换内容就换地址。
- 服务端下单时分配带零头的唯一待付金额，15分钟有效；手机监听到账通知后签名上报金额、事件标识、通知时间与请求时间。
- 原协议分开到账观察时间和补报请求时间，断网后仍可补报；重复通知去重，金额冲突不自动开通，未匹配进入后台人工核查。
- 本地旧工程 `C:/wb-ref/old-weiban/tools/wechat-pay-watch` 当前快照1.0.4，仅监听微信；旧服公开交付包1.0.6。不能拿本地旧快照当全部线上功能。两个付款渠道必须分别验收。
- 新版充值与会员目前均关闭真实支付，使用管理员加积分/开通。新功能需要订单与可信到账入账链路，不能仅替换按钮和二维码。

## 实施约束

1. 金额、购买内容与积分由服务端快照确定；积分按实际支付金额1元=100积分，不凭客户端“已付款”入账。
2. 订单和到账事件分离，接收、匹配、履约同事务且幂等；重复、过期、延迟、金额矛盾、签名失败与并发分配均需用合成测试覆盖。
3. 退款不自动执行；人工处理必须看明确的金额、订单和原因，并有审计。
4. 原二维码若同时用于旧站，两个独立金额池会有重叠风险。正式开通前需确定旧站收款切换安排，不能把同一到账通知直接交给两个站各自猜单。旧站仍只读，不修改其入口或配置。
5. 监控若为安卓到账监听器，只解析支付应用通知，排除普通聊天、退款、付款、汇总及多笔含糊通知；不记录原文。待发事件先持久化后发送，服务器明确持久接收才出队；重启、断网、权限关闭都有可见状态。
6. 专用认证不进入代码仓库、安装包、日志或回复。优先设备生成且不可导出的签名私钥、服务端只保存公钥的配对方案；不复用旧站秘密，也不把秘密写普通配置文件。
7. 包放桌面根目录，不创建交付文件夹。新收款监控使用独立包名，不覆盖微伴主应用或旧监控。
8. 真正到账与手机通知识别需经理最后用小额真实付款验证；开发不擅自付款、伪造正式到账或给正式用户加钱。

## 官方依据

- [安卓通知监听](https://developer.android.com/reference/android/service/notification/NotificationListenerService)：用户须授予通知访问；监听连接后方可取活动通知，断连需重绑。不能把通知权限等同所有机型后台收款可靠性已验收。
- [安卓密钥存储](https://developer.android.com/privacy-and-security/keystore)：使用应用专有系统密钥存储，避免私钥作为普通文件导出。

## 验收矩阵（实际执行结果见专项报告）

| 场景 | 必须达到的结果 |
| --- | --- |
| 用户在网页与安卓进入付款 | 共用服务端订单、价格与到账记录；只显示微信/支付宝两个扫码入口 |
| 同渠道、同金额的多个同时下单 | 服务端串行分配可识别金额；没有空位就明确稍后重试，不能重复分配并猜测买家 |
| 用户重复点击“已付款” | 仅触发查单，不以客户端状态加积分或开会员 |
| 相同到账事件反复上报、响应丢失重试 | 返回既有处理结果，订单只履约一次，钱包流水只有一笔 |
| 相同事件标识却金额或渠道不同 | 拒绝自动入账、保留冲突类别供核对，不覆盖首条事实 |
| 金额不符、多个候选、订单取消或过期 | 进入待核对状态，不自动认领最近订单，不自动退款 |
| 手机断网后补报 | 保留首次观察时间，以新请求时间签名重发；重连和重启不丢队列 |
| 缺少通知权限或监听断连 | 软件明确显示未监听和恢复步骤，不能用“已启动”冒充实际接收中 |
| 普通聊天伪装收款、转出、退款、汇总通知 | 不自动报成到账；不保存通知正文，不读取其他应用通知 |
| 账号注销、订单并发结算 | 按既有用户/钱包锁顺序处理；不复活已注销账户，不制造悬空入账 |
| 余额入账中数据库失败 | 订单状态、到账匹配和流水一起回滚，可安全重试 |
| 新旧站共用收款码 | 正式开放前必须明确单一认单归属或相互隔离的收款码，不能同时独立匹配 |

旧充值报价与会员权益接口的固定关闭值继续保留，避免旧客户端被新字段值阻断；新扫码能力使用独立接口，契约升至 7.6 并生成安卓配套。订单记录保留服务端购买快照，价格后续变动不改变已下订单。

## 旧监控源代码额外核查

本地快照的金额解析采用首个匹配值，只检查是否含支付/收款文字；同包通知仍可能是普通聊天或多笔聚合。新实现不能照抄后宣称可靠。需按渠道保守匹配明确单笔通知，无法安全识别时提示人工核对，并分别用真实微信、支付宝到账通知做最终验收；合成样例通过只能登记为开发自测。

通知派生的事件标识不是支付机构的真实交易号。新软件重复识别、通知更新时间变动、金额复用与迟到上报必须一起核验；不能仅靠“事件标识唯一”声称绝无重复认单。自动化能安全处理的范围之外，保留人工对账入口。
