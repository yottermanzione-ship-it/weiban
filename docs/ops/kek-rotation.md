# 主密钥轮换（TD-022 / T-033）

运行工具：开发`pnpm --filter @weiban/server crypto:rotate`；生产`node dist/rotate-kek.js`。默认仅验证现有数据密钥能解包、报告版本与数量，不修改数据库；`--help`显示用法。输出不含KEK、DEK、用户编号或业务数据。每次事务最多100条，整个批次失败会回滚；已提交批次保留，重复执行只处理旧版本，拒绝退到比数据库旧的版本。版本只能加一，不复用旧密钥内容。

维护流程：

1. 在维护窗口停止全部app/web/worker及运维写入工具；备份数据库与媒体并单独备份旧KEK。当前实现不宣称在线无停机轮换。
2. 将新随机32字节KEK存入新的秘密文件，不覆盖旧文件。部署节点和恢复节点都保留旧版直到验证完成。
3. 创建密钥集合JSON，例如`{"currentVersion":2,"files":{"1":"/run/secrets/kek-v1","2":"/run/secrets/kek-v2"}}`，设置`PLATFORM_KEK_RING_FILE`为该文件路径（优先于旧单文件配置）。版本文件值只能是路径，不能直接放原始密钥。
4. 先执行默认只读检查，全部DEK可解包后执行`node dist/rotate-kek.js --apply --maintenance`。发生错误保持新/旧集合；检查损坏记录或缺失密钥并重试，不能改回仅旧KEK启动。
5. 再执行只读检查，版本计数只能包含当前版本；恢复进程，用旧业务密文验证上游和用户数据可读。
6. 运行进程改成只保留当前版本秘密文件后，另跑只读验证。新备份可以使用新KEK恢复；旧备份仍需要旧KEK，旧离线密钥不可提前销毁。密钥备份始终与数据库备份分开保存。

Compose单文件秘密挂载适用于平时运行；轮换时用额外覆盖文件把集合及两份KEK只读挂入临时维护容器，同时将`PLATFORM_KEK_RING_FILE`传入。完成后将正式`kek`秘密指向新文件、`PLATFORM_KEK_VERSION`升到当前版本，重新创建容器。

开发验证：真实PostgreSQL覆盖分批中断/恢复/重入、业务密文不变、只保留新KEK可解包、损坏DEK整批回滚、缺旧版拒绝、并发批次与版本倒退；配置覆盖版本文件格式、缺当前版本、重复KEK和不泄露文件内容。独立验收仍待交付。
