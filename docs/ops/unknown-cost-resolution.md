# 未知供应商费用核实（3.16）

> **3.27（2026-10-21，批 H1）更新**：用户付费调用改为「先用后扣、可欠一次」——不再冻结积分，结算按实际用量全额扣、余额可变负（为负后一切付费调用被拒，直到充值）。本文「用户余额及原扣费不得改变」「不向用户补扣」照旧：核实只调平台成本，不追扣用户。见 `docs/handoffs/2026-10-21-h1.md`。

> **3.26（2026-10-21，批 G3）更新**：上游没返回用量时，网关改为按本地分词估算 token 计费并标记「估算」（对账页「估算计费」列条数），**不再暂停线路**，同一路由有待核调用也不再拒绝新调用。只有进程中断等连估算都没有的情况才会产生「成本待核」，仍按本文核实；第 6 条「再由管理员单独启用路由」不再需要（线路不会被停用）。说明见 `docs/handoffs/2026-10-21-g3.md`。

此入口只供有后台管理员权限的人在核对单次调用凭证后使用；本轮未在真实服务器执行。HTTP接口上线依赖整批0101/0102迁移及正常outbox，不新增迁移。不是财务系统自动推定成本。

1. 从后台待核记录的调用ID，在受控数据库只读查询 `billing.holds` 中 `risk_snapshot->>'usageRecordId'` 对应hold，核对具体上游、模型、发送时间和供应商单次账单/追踪ID。不得把整月账单或经验估算当作单次成本。
2. 若hold仍active/expired，先检查网关恢复任务；只有settled/released且有待核快照，接口才允许核实。旧无完整调用关联的记录需单独审查，不强行清风险。
3. 使用现有后台管理员会话，POST `/api/v1/admin/billing/holds/{holdId}/cost-resolution`。body：`{"costMicros":12345,"evidenceUrl":"https://供应商凭证链接","reason":"核对的单次账单及追踪编号说明"}`。金额为整数微元（1元=1000000微元），允许核实为0；原因至少5字。示例不是可实际提交的数据。本入口仅保存链接，不访问凭证网站。
4. 同hold同成本/链接/原因重试返回原resolvedAt；更换参数拒绝，不能覆盖原记录。返回成功后查审计 `prehold.cost_resolved`、原流水及新增差额、权威快照、原预算日风险占用与实际成本。用户余额及原扣费不得改变。
5. outbox `billing.call_cost_resolved` 将金额与已核状态同步用量副本；pending记录会重试，已注销记录不重建。核对后台待核笔数及风险上限。原估算token不会冒充供应商精确token。
6. 核实仅解除该hold的unknown锁。它不自动重启目录，也不清除同一具体路由其他未知调用。逐笔核实后，确认供应商计费上限/参数有效，再由管理员单独启用路由。

账务：用户任务及失败平台任务只在平台追加吸收成本差额；成功平台任务保持原售价/余额，在平台追加零金额`adjustment`成本修正（固定`cost_resolution:`幂等键）。不修改原流水、用户不补扣。负成本差额合法，不能取绝对值再相加。供应商账单对账纳入成本修正，关联hold的成本按原hold创建日期归期，旧无hold的流水保持记账日期；近30天流水看板仍按入账日，原预算按原预算日。跨午夜延迟发送及供应商账期口径需在真实账单核验时确认。

上线前必须以备份后的真实PG开发/验证环境手工核验：同hold并发相同/不同凭证、0及正负差额、用户/平台成功/失败、过期恢复、跨日账单、事件延迟与旧快照迟到。类型/构建通过不能代替这些验证。当前没有真实PG/供应商证据，不可据此宣布财务验收或直接部署。
