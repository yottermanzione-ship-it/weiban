## 0. 先看结论（给总经理）

| 场景（一个「典型用户」一天） | 便宜模型 | 中档模型 |
|---|---|---|
| 后台全部（推演、朋友圈、记忆整理、主动消息、群聊自发、检查） | **约 0.55 元** | 约 2.3 元 |
| 其中推演本身（日常事件 + 协调 + 检查） | 约 0.15 元 | 约 0.6 元 |
| 聊天回复（80 次回复） | 约 0.9 元 | 约 4 元 |
| **合计 / 天** | **约 1.5 元** | 约 6.3 元 |
| **合计 / 月** | **约 45 元** | 约 190 元 |

- 推荐搭配：聊天用中档模型、后台用便宜模型 → 约 **4.5 元 / 天**。
- **P-15（每天 3–6 件日常事件）、P-16（朋友圈每周 2–4 条）不需要调整**：日常事件是一次调用一次性生成的，多几件只多几百个字的输出；推演只占后台费用的约四分之一，真正的大头是聊天本身和记忆整理。
- **后台预算默认值建议：每天 3 元**（MDL-05）。理由：PRD 规定「不选后台模型就沿用聊天模型」，很多用户会让后台也用中档模型（约 2.3 元 / 天），3 元能覆盖且有余量；用便宜后台模型时只会用到约五分之一。
- 以上按**高峰价**计算（偏保守）；DeepSeek 等夜间和周末半价，实际会更低。

## 1. 价格假设

来源：DeepSeek 官方价格页 https://api-docs.deepseek.com/zh-cn/quick_start/pricing （2026-10-04 抓取，经工具摘要，**接入开发时请以官方页面为准再核对一次**）。用 DeepSeek 作基准，是因为它价格公开、有缓存和分时价，且在 RP-Bench 多轮人类投票中排名靠前；其他供应商的价格见 `model-catalog.md`。

| 档位 | 代表模型 | 输入（缓存未命中）元/百万 token | 输入（缓存命中） | 输出 |
|---|---|---|---|---|
| 便宜 | deepseek-flash（高峰价） | 2.00 | 0.04 | 8.00 |
| 中档 | deepseek-v4-pro（高峰价） | 9.00 | 0.30 | 27.00 |

高峰时段：工作日 9:00–12:00、14:00–18:00（北京时间）；其余时段半价。

token 与字数：中文约 1 个汉字 ≈ 0.6–0.8 个 token（因模型分词而异），本文统一按 1 字 ≈ 0.7 token 粗算。

## 2. 「典型用户」假设

| 项 | 假设 |
|---|---|
| 已添加角色 | 10 个，全部开启「TA 的日常」，其中 6 个是真人角色 |
| 私聊 | 每天约 100 条用户消息，合并后角色回复约 80 次 |
| 群聊 | 2 个开启「角色自己聊天」的群，每群每天自发 10 条（P-20 上限） |
| 主动消息 | 每天约 5 次（P-04 上限 8） |
| 朋友圈 | 每角色每周约 3 条 → 每天约 4.3 条 |
| 日常事件 | 每角色每天 6 件（按上限算） |

## 3. 后台调用明细（每天）

| 任务 | 次数 | 单次输入 token（未命中 / 命中） | 单次输出 | 便宜 | 中档 |
|---|---|---|---|---|---|
| 日常事件生成 | 10 | 3,000 / 0 | 900 | 0.132 | 0.513 |
| 社交协调 | 1 | 2,500 / 0 | 500 | 0.009 | 0.036 |
| 真人事件批量检查 | 1 | 3,000 / 0 | 300 | 0.008 | 0.035 |
| 朋友圈正文 + 角色互评 | 4.3 | 3,000 / 0 | 500 | 0.043 | 0.174 |
| 记忆提取 | 15 | 2,500 / 0 | 300 | 0.111 | 0.459 |
| 摘要整理（分段 6 次 + 日摘要 3 次） | 9 | 约 2,500 / 0 | 300 | 0.066 | 0.276 |
| 边界检查（约 5% 回复命中预筛） | 4 | 1,000 / 0 | 50 | 0.010 | 0.041 |
| 群聊自发（用聊天模型） | 20 | 3,000 / 2,000 | 80 | 0.134 | 0.596 |
| 主动消息（用聊天模型） | 5 | 3,500 / 2,500 | 100 | 0.040 | 0.175 |
| **合计** | | 输入约 19 万 + 缓存 5 万 | 输出约 2.1 万 | **≈0.55 元** | **≈2.3 元** |

说明：「群聊自发」和「主动消息」由角色在用户不在场时发起，**计入后台预算**；用户在场时的群聊回复算聊天费用。

## 4. 聊天费用（每天）

每次回复上下文约 8,000 token（`runtime-overview.md` 4.1），其中约 3,000 token 是稳定前缀（平台守则 + 角色核心 + 示例对话），可命中缓存；输出约 150 token。

| | 便宜 | 中档 |
|---|---|---|
| 80 次回复 | 未命中 40 万 × 2 + 命中 24 万 × 0.04 + 输出 1.2 万 × 8 ≈ **0.9 元** | 未命中 40 万 × 9 + 命中 24 万 × 0.3 + 输出 1.2 万 × 27 ≈ **4.0 元** |

## 6. 默认后台预算与执行规则

| 项 | 默认值 / 规则 |
|---|---|
| 后台每天预算 | **3 元**（用户可改；按用户时区自然日） |
| 计入后台预算的用途 | `simulation`、`moments`、`memory`、`guard`、群聊自发、`proactive` |
| 不计入 | 聊天回复（含成人模式）、识图、语音、导入（用户主动发起的） |
| 达到预算后 | 当天停止：推演、朋友圈、群聊自发、主动消息；**记忆整理延后到第二天优先执行，不丢**；边界检查**不停**（安全优先，费用极小） |
| 用量页标注 | 「估算值，以供应商账单为准」；后台费用单独一栏（ADR-0008） |

## 7. 估算方法（用量页怎么算）

1. 每次调用：费用 = 未命中输入 token × 输入价 + 命中输入 token × 缓存价 + 输出 token × 输出价，价格取调用时刻（区分高峰 / 低谷）对应的价格表版本。
2. token 数优先用供应商响应中的用量字段；没有时按「中文字符 × 0.7 + 英文单词 × 1.3」估算并标记。
3. 价格表维护在 `model-catalog.md`，后台存一份带版本号的副本；调价时新增版本，不改旧记录。
4. 本文第 3、4 节的估算在首个开发版本跑通后，用**真实调用记录**重算一次，写入 `docs/ai/cost-report-YYYY-MM.md`（成本报告，按月）。
