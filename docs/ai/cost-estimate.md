## 0. 先看结论（给总经理）

所有费用都**从用户余额里扣**，个人测试阶段售价 = 成本价，所以下面的数字既是用户看到的扣费，也是总经理实际垫付的成本。

| 场景（一个「典型用户」一天） | 便宜模型 | 中档模型 |
|---|---|---|
| 后台全部（推演、朋友圈、记忆整理、主动消息、群聊自发） | **约 0.55 元** | 约 2.3 元 |
| 其中推演本身（日常事件 + 协调 + 检查） | 约 0.15 元 | 约 0.6 元 |
| 聊天回复（80 次回复） | 约 0.9 元 | 约 4 元 |
| **合计 / 天** | **约 1.5 元** | 约 6.3 元 |
| **合计 / 月** | **约 45 元** | 约 190 元 |

- 推荐搭配：聊天用中档模型、后台用便宜模型 → 约 **4.5 元 / 天**（PRD P-32 低余额提醒线 5 元即按此设定）。
- **P-15、P-16 不需要调整**（理由不变：日常事件一次调用生成，多几件只多几百字输出）。
- **后台预算默认值：每天 3 元**（第 6 节），从余额扣。
- **安全关怀的次日跟进不受后台预算和 P-33 限制**（第 6.3 节，回答 PRD 9.3 第 1 条）。
- 以上按 DeepSeek **高峰价**计算（偏保守），夜间和周末半价。
- 「大约每条回复 X 元」的算法和首批模型的数值见第 7 节。
- **v1.3 新功能（第 5.1、5.2 节）**：行为规划每天约 **0.03 元**，是聊天回复费用的约 1%～6%，低于产品要求的 10%，代码另有「当天超过 10% 就改用纯规则」的闸；5 个玩法和宠物多数是「一次普通回复」的量级（约 0.01～0.05 元 / 次），慢信一封约 0.02～0.09 元，「TA 的提醒」到点发送不花钱；广场发布前检测一次约 0.01～0.08 元；安全兜底消息不花钱。
- **安全关怀**：余额不足时高危消息可透支到 −2 元（`billing.md` 6.6，契约 1.1 已支持），透支也用完时发不花钱的兜底消息（`runtime-overview.md` 9.1）。

## 6. 后台预算与执行规则（余额模式）

### 6.1 默认值与范围

| 项 | 默认值 / 规则 |
|---|---|
| 后台每天预算 | **3 元**（用户可改；按用户时区自然日；从余额中扣，不是另一笔钱） |
| 计入后台预算的用途 | 与契约 `BACKGROUND_PURPOSES` 一致：`memory`、`simulation`、`proactive`（含群聊自发、来电开场、v1.3 的经期关心、宠物分享、心愿提议、主动寄信）、`moments`。另：调用时传 `countAsBackground: true` 的也计入（契约 1.1）：**朋友圈配图、宠物分享配图**（`image_generation`）、**为主动行为做的行为规划**（`behavior_planning`，5.1 节） |
| 不计入、也不受限 | `chat_reply`（含成人模式回复、恢复后的合并回复、v1.3 回应用户操作的玩法消息，5.2 节）、`safety_check` 与 `safety_followup`（契约 `BUDGET_EXEMPT_PURPOSES`）、`vision`、`voice`、聊天中触发的 `image_generation` 与 `web_search`、`import_analysis`（用户主动发起，含广场发布前检测）、为聊天回复做的 `behavior_planning` |
| 达到预算后 | 网关在冻结步骤返回 `budget_exceeded`（`billing.md` 第 7 节）。ai-runtime 当天停止：推演、朋友圈、群聊自发、主动消息（含经期关心、宠物分享、心愿提议）；主动行为的决策退回规则版（不产生行为规划费用）；**记忆整理延后到第二天优先执行，不丢**；安全检查、安全关怀次日跟进**不停**；「TA 的提醒」到点发送不调用模型，**不受影响** |
| 花费统计页 | 数字是**实际扣费**（与余额明细一致），后台费用单独一栏；不再写「估算值，以供应商账单为准」 |

### 6.2 两道闸：后台预算 + 余额保留线 P-33

PRD MDL-05 第 3 条、MDL-10 第 3 条要求两道闸同时生效：

1. **后台预算**：由 billing 在冻结时执行（6.1）。
2. **余额保留线 P-33**（1 元）：由 ai-runtime 执行——每次安排后台任务前读 `BillingReadPort.getSpendStatus` 的 `availableMicros`（契约 1.0 起原 `BillingPort` 拆为只读的 `BillingReadPort` 与只有 model-access 能用的 `BillingReservationPort`），低于 P-33 时与「达到预算」同样处理（停止 / 延后，不丢记忆整理）；回到 P-33 以上后恢复。P-33 是体验规则，不是钱的安全规则，所以放在 ai-runtime，不进 billing。
3. 余额耗尽（`billing.balance_depleted`）：全部后台任务暂停；`balance_restored` 后恢复并对等待中的会话补一次合并回复（`billing.md` 6.4）。

### 6.3 安全关怀相关调用（回答 PRD 9.3 第 1 条：确认「不受限」）

| 调用 | 后台预算 | P-33 | 余额为零 |
|---|---|---|---|
| 关怀识别与输出检查（`safety_check`） | 不受限（契约已支持） | 不受限 | 可透支到 −2 元（`billing.md` 6.6，带 `safetyPriority`）；透支也用完 → 不花钱的兜底消息（`runtime-overview.md` 9.1） |
| 关怀状态下的聊天回复（`chat_reply`） | 不受限（聊天本来就不受限） | 不受限 | 同上 |
| **次日跟进关心消息**（`safety_followup`） | **不受限** | **不受限** | 同上（透支用完时发模板跟进） |

- 理由：单条约 0.005–0.02 元，费用可以忽略；而「出事后第二天没人问一句」的代价很大。
- 次日跟进仍计入主动消息次数上限 P-03（PRD SAFE-06 第 6 条），不受「用户未回复不再发」限制。
- 原「实现上的缺口」已关闭：契约 1.1 新增用途 `safety_followup`，在 `BUDGET_EXEMPT_PURPOSES` 中（T-020 批准）；安全优先透支上限 2 元（`billing.md` 6.6 是该数字的唯一定义处）。
- 透支也用完、平台每日总上限触发或上游故障时，高危消息由 ai-runtime 发不调用模型的兜底消息，费用为 0（`runtime-overview.md` 9.1.2）。

## 7. 估算方法

### 7.1 每次调用实际扣多少（以 billing 为准）

计算公式、取整、分时价、缓存价的执行都在 billing（`billing.md` 4.2），本文不重复。token 数优先用上游返回值；没有返回时按「中文字符数 × 0.7 + 英文单词数 × 1.3」估算并标 `estimated = true`（`runtime-overview.md` 2.5）。

### 7.2 「大约每条回复 X 元」怎么算（MDL-02 第 5 条、MDL-09 第 3 条）

用一条「标准回复」的用量乘以该模型的价目表单价：

| 项 | 标准用量 | 说明 |
|---|---|---|
| 未命中输入 | 5,000 token | 默认 8K 上下文中每轮变化的部分 |
| 命中输入 | 3,000 token | 稳定前缀（平台守则 + 角色核心 + 示例对话）。**模型没有缓存价时，这 3,000 按未命中价算** |
| 输出 | 150 token | 一次回复 1–4 个气泡 |
| 时段 | 取**高峰价** | 偏保守；页面注明「夜间和周末可能更便宜，实际以余额明细为准」 |

```
约每条回复 = (5000 × 未命中价 + 3000 × 命中价 + 150 × 输出价) / 1,000,000   （元，价格单位为元/百万 token）
约每次后台推演 = (3000 × 未命中价 + 900 × 输出价) / 1,000,000
```

显示时保留 2 位有效数字（「约 0.05 元」）；小于 0.001 元显示「< 0.001 元」。价格档位按 `model-catalog.md` 第 2 节阈值由这个数推出。价目表发布新版本时由系统自动重算，不需要人工改数字。

### 7.3 首批模型的估算值（价目表初稿对应的结果）

| 模型 | 约每条回复 | 约每次后台推演 | 价格档位 |
|---|---|---|---|
| `deepseek/deepseek-v4-pro` | 0.050 元 | 0.051 元 | 中等 |
