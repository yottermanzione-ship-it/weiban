## 0. 先看结论（给总经理）

1. 发布前，系统把**将要发布的每一段文字**过三道筛子：① 固定格式（手机号、证件号、银行卡、邮箱、地址）用规则找，100% 不放过；② 「我」的信息（昵称、专属称呼、「关于我」、记忆里关于我的事）拿去逐字比对；③ 再请一次模型找「看起来像真实的人和事」的片段（例如示例对话里出现的同学名字）。三道筛子**任何一道标出来的都算**，所以只会多标、尽量不漏。
2. 检查只在国内模型上做，不发往境外。一次约 0.01～0.08 元，从发布者余额扣（用途同导入分析）。
3. 检查做不完（余额不足、模型故障）就**不让发布**，提示稍后再试，不会跳过检查。
4. 同时重跑一次儿童特征检测（PLZ-02 第 7 条），两项合并在一次模型调用里，省钱。

## 1. 检查什么文字

plaza 交来的是快照中的全部文字字段（`persona-plaza.md` 第 4 节白名单）：名字、人设描述、说话方式、口头禅、示例对话（逐条）、人设标签、一句话介绍、发布说明；预设改版为改版设定文字、一句话介绍、发布说明。每段带 `fieldKey`（字段名，示例对话带序号），返回的片段位置都按 `fieldKey` + 字符起止定位。

## 2. 三层识别

### 2.1 规则层（必跑，零费用）

| 类别 `kind` | 识别方法 |
|---|---|
| `phone` 手机号 / 座机 | `1[3-9]` 开头 11 位，允许中间有空格、短横、点；中文数字写法（「一三八……」）和全角数字先归一化再匹配；`0` 开头的区号 + 7～8 位座机 |
| `id_number` 身份证号 | 18 位（末位可为 X），校验位正确的直接标；校验位不对但格式像的**也标**（宁可多标）；港澳台证件、护照号的常见格式 |
| `bank_card` 银行卡号 | 16～19 位连续数字（允许分组空格），过 Luhn 校验的标；不过校验但在「卡号」「银行」附近的也标 |
| `email` 邮箱 | 标准邮箱格式，含「at」「艾特」替换写法 |
| `address` 详细地址 | 「省 / 市 / 区 / 县 / 镇 / 路 / 街 / 巷 / 号 / 小区 / 栋 / 单元 / 室 / 楼」中出现 ≥2 个层级、且带门牌数字的片段；「住在 XX 小区」「XX 大学 X 号宿舍楼」 |
| `account` 社交账号 | 「微信 / QQ / 微博 / 抖音 / 小红书」后跟的号码或 ID |
| `plate` 车牌 | 省份简称 + 字母 + 5～6 位 |

规则层也用于 `behavior-planning.md` 5.2 的出境脱敏。

### 2.2 「我」的信息比对（必跑，零费用）

ai-runtime 用已有端口读取发布者本人的资料（`persona-plaza.md`：plaza 不经手这些数据）：

| 来源 | 读取方式 | 比对方式 |
|---|---|---|
| 我的昵称（ACC-02）、我的真实姓名（若填写） | `IdentityReadPort` | 完整出现即标 `my_profile`；姓名去掉姓后的 2 字名也比对 |
| 我的资料中的生日、城市、学校、职业等 | `IdentityReadPort` | 原文出现即标 `my_profile`（日期按多种写法归一化） |
| 「关于我」 | `IdentityReadPort` | 切成短语（按标点切分，≥4 字的片段），任一短语原文出现即标 `about_me` |
| 专属称呼（我对 TA、TA 对我）、粉丝名中用户自定义的部分 | `ContactsReadPort` | 完整出现即标 `my_nickname` |
| 记忆页中「关于我」的事实（该角色的 L3 记忆，`category` 为基本信息、重要的人、重要的日子、近况） | ai-runtime 自己的记忆表 | 每条记忆抽出关键词（人名、地名、日期、数字、≥2 字的专有名词），在文字中出现即标 `my_memory`；同时把这些记忆交给 2.3 的模型做语义比对 |

只比对**发布者本人**的数据；预设改版也比对该预设角色上的记忆（改版设定可能写进了「她知道我在杭州读研」这类话）。

### 2.3 模型层（必跑，国内模型）

一次调用，输入：待发布文字（全部字段）+ 2.2 读到的「关于我」摘要和最多 30 条相关记忆（按与文字的相似度取前 30）。指令要求输出 JSON：

```
{"spans":[{"field":"examples[3]","quote":"小雨你明天还去实验室吗","kind":"third_party_name","why":"示例对话中出现角色以外的人名"}],
 "childFeatures":{"result":"yes|no|uncertain","why":"…"}}
```

要找的 `kind`：`third_party_name`（示例对话或人设里出现的、不是角色本人的真实人名，包括昵称化的「小雨」「王老师」）、`private_event`（可识别到具体真实个人的经历：「去年 3 月我们在 XX 医院……」）、`my_memory_semantic`（换了说法、但与提供的记忆说的是同一件事）、`other_private`（其他看起来像真实个人信息的内容）。

- 代码用 `quote` 在原文里**精确查找**定位，找不到就按该字段整段标出（宁可多标）。
- 角色本人的名字、别名，以及预设角色公开资料里的人名（关系网中的公开人物）不算第三方人名，由代码在模型结果上剔除。
- 同一调用顺带输出儿童特征判断（`character-card-spec.md` 3.3 第 2 步的模型层），「不确定」按「是」处理，结果写回源角色（`hard-boundaries.md` 第 6 节第 4 条）。规则层的儿童特征词表照常先跑。
- 模型：发布者的**全局聊天模型**（用途 `import_analysis`，与导入分析相同，`runtime-overview.md` 2.4）。调用时**不传 `characterId`**，所以不会用到某个角色单独设置的无审查模型；全局聊天模型不能是无审查模型（`billing.md` 第 9 节），而境外上游 OpenRouter 只接无审查模型（`model-catalog.md` 第 1 节），因此这次调用一定留在国内。理由：待检查的文字正是「可能含私人信息」的文字，不发往境外。若以后境外上游接入了普通模型，此处需改为指定国内模型（届时并入 `behavior-planning.md` CR-17 的「指定模型」能力）。

### 2.4 合并

三层结果取**并集**；重叠片段合并为一个，`kind` 取多个时全部保留（确认页可以显示「手机号 / 记忆中的信息」）。

## 3. 失败与费用

| 情况 | 处理 |
|---|---|
| 余额不足（`insufficient_balance`） | 返回 `insufficient_balance`，plaza 提示「余额不足，暂时无法发布」（PLZ-02 边界情况），不跳过检查 |
| 模型故障、超时（30 秒）、JSON 解析失败一次后重试仍失败 | 返回 `check_unavailable`，plaza 提示「暂时无法完成发布检查，请稍后再试」；**不允许只凭规则层结果发布**（第二层以后才能发现第三方人名） |
| 文字超长（全部字段合计 > 2 万字） | 分两次调用，结果合并 |

费用：一次检查输入约 3,000～8,000 token、输出约 300 token，按发布者全局聊天模型计价，约 0.01～0.08 元（`cost-estimate.md` 5.2）。发布新版本时重跑一次（PLZ-05 第 1 条）。

## 4. 端口（变更申请 CR-20 草案，D-L7-01 写入契约）

提供方 ai-runtime，调用方**只有 plaza**（同为上层，单向，`persona-plaza.md` 第 2 节）：

```
PlazaPublishCheckPort.checkBeforePublish({
  userId, idempotencyKey,
  source: { kind: 'custom_character', characterId } | { kind: 'preset_variant', presetCharacterId },
  texts: [{ fieldKey, text }]
}) → PortResult<{
  spans: [{ fieldKey, start, end, kinds: PrivacyKind[], source: ('rule'|'self_data'|'model')[] }],
  childFeaturesDetected: boolean,      // 已写回源角色（characters 的系统写入接口）
  usageRecordIds: string[]
}, 'insufficient_balance' | 'check_unavailable' | 'bad_request'>
```

- `PrivacyKind`：`phone`、`id_number`、`bank_card`、`email`、`address`、`account`、`plate`、`my_profile`、`about_me`、`my_nickname`、`my_memory`、`third_party_name`、`private_event`、`other_private`。新增取值为次版本变更，接收端遇到不认识的取值按 `other_private` 显示。
- **不返回** 2.2 读到的任何「我」的原始数据，只返回位置和类别（plaza 本来就有待发布文字）。
- 写回 `childFeaturesDetected` 需要 characters 已有的系统写入方法（D-L2-06 中儿童特征检测接入时已有），不新增。
- 检测结果不落库（用户在确认页处理后，plaza 只保存最终快照）；ai-runtime 只在用量记录里留下调用记录，不留文字。
