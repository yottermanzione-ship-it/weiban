## 3. 原创性约束（每张卡都已自查）

依据：PRD 10.0「真人」定义、总经理第二轮意见第 1 条补充、`hard-boundaries.md` 第 2 节。

| 约束 | 做法 |
|---|---|
| 新名字 | 名字、别名都是新取的，不使用任何真实人物的真名或艺名 |
| 不含真实作品 | 卡中出现的作品名（剧、电影、歌、建筑项目、游戏）全部虚构；上架前管理员用搜索引擎再查一次，有同名知名作品就改名（`admin.creatorNotes` 已注明） |
| 不含真实人际关系 | 卡中出现的朋友、同事、家人都是虚构人物，不提任何真实团体、公司、节目、经纪公司 |
| 不含真实经历 | 经历全部编写；虚构明星「陆遥川」只借用「清冷、慢热的顶流演员」这一类气质，不对应任何具体的人 |
| 成年且无儿童特征 | 年龄全部 27 岁以上；人设文字中不出现小于 18 的年龄数字、学龄身份词、儿童外貌描写，避免触发儿童特征检测（`character-card-spec.md` 3.3）误判 |
| 分类字段 | `basis = original`、`realPersonKind = null`、`ageSetting = adult`、`childAppearance = false` |

## 4. 怎么用

1. **总经理手动测试**：管理员把卡录入为预设角色（测试环境），或由总经理以自定义角色创建（分类选「原创」「已满 18 岁」）。在「服务 → 模型」设置成人模式模型（建议先用 `model-catalog.md` 3.2 的无审查模型），然后按每张卡末尾的「跨模式测试清单」逐项聊。
2. **评测集**：`eval-plan.md` 3.12 的成人模式用例以这 6 张卡为角色（每张卡都跑两条底线用例）；3.5 人设一致性探针题对这 6 张卡分别建基线。
3. **policy 测试**：6 张卡都应得到 `adultModeEligible = true`、`adultContentModelAllowed = true`。对照组：把任一张卡的 `basis` 改为 `real_person` 或 `ageSetting` 改为 `minor`，资格立即变为「否」。

## 5. 成人模式通用要点（6 张卡共用，单卡只写差异）

1. **人设优先于模式**：成人模式只是叠加一层「允许成人内容」，不改变角色是谁（PRD 第 11 章开头）。说话方式（自称、句长、口头禅、emoji、标点）、性格、价值观必须和日常模式一致。
2. **两条底线由系统执行，角色只负责「怎么拒绝」**：用户要求扮演未成年人或某位真实存在的人时，角色用自己的口吻拒绝或转开（例如高冷角色冷淡地拒绝，温柔角色温和地拒绝），不出戏、不说「系统不允许」。
3. **安全关怀优先**：用户出现高危信号，成人内容立即停止，角色以本人口吻关心（SAFE-06）；这在每张卡的 `careVoice` 中都有对应口吻。
4. **记忆共享、内容不外传**：同一角色在各模式之间共享记忆；成人模式的内容不会被其他角色、朋友圈、非成人群聊提起（总负责人第二轮裁定第 2 条）。
5. **熟悉度仍然起作用**：L1 的角色即使在成人模式中也保留初识的分寸，随熟悉度升高逐步放开（`persona.growthByFamiliarity`）。
6. **小巧思照常受规则约束**：撤回、打错字在成人模式下关闭（`runtime-overview.md` 10.1），已读不回按人设标签和上限照常。
