| 项 | 内容 |

| 任务 | T-005 |

| 依据 | PRD ADM-01（第 4 条：借助 AI 生成草稿）、ADM-06、CHR-10、MEM-06、SIM-03、第 10 章硬性边界 |
| 产出物 | 一张符合 `docs/ai/character-card-spec.md` 的角色卡 + 关系条目 + 来源清单 |

## 0. 先看结论（给总经理）

做一个预设角色分 7 步：**定分类 → 收资料 → AI 起草 → 人工核对 → 配边界 → 考试 → 上架**。AI 负责把几十篇资料整理成草稿，您负责两件 AI 替代不了的事：**确认每条事实有可靠来源、删掉隐私和谣言**。做一个明星角色预计 1–2 小时（大部分时间在核对），之后每月花 10 分钟看一次更新候选。

## 1. 资料来源规则

| 可以用 | 不能用 |
|---|---|
| 百科词条（百度百科、维基百科）——作为线索，关键事实需另有来源印证 | 狗仔、私生饭、营销号爆料、未证实传闻 |
| 本人或工作室官方账号的公开发言（微博、官方网站） | 住址、家人（未公开的）、联系方式、未公开行程、健康隐私——**即使网上能搜到也不用** |
| 权威媒体采访、杂志专访、节目公开片段的文字稿 | 粉丝同人创作、CP 向内容（当作事实会构成编造恋情） |
| 作品官方资料（片方、出版方、官方设定集）——虚构角色以此为准 | AI 生成的「人物介绍」类文章（来源不明，容易有幻觉） |
| 历史人物：正史、权威传记、作品本身（如李白的诗） | 戏说、演义中的情节当作史实（可作为「民间传说」条目，标清楚） |

版权注意：示例对话和说话风格**只提炼特点、改写成新句子**，不大段照抄采访原话或台词；「经典台词」条目只收录短句（一两句），并注明出处作品。

## 2. 流程

### 第 1 步：立项与分类判定（管理员，5 分钟）

- 在管理后台新建草稿，先填 `classification`：在世公众人物 / 历史人物 / 虚构 / 原创，年龄设定，外表是否儿童。
- 历史人物判定：去世超过 100 年、没有照片或录音资料（总负责人裁定）。
- 填写后系统立即显示该角色的派生资格（能否成人模式、能否生成形象图等），方便管理员心里有数。

### 第 2 步：资料采集（工具 + 管理员，15–30 分钟）

- 管理员粘贴已知可靠链接（官方账号、百科、几篇专访）。
- **采集工具**（AI 模块提供，费用记平台账户，用途 `admin_distill`）：用联网搜索补充检索，按「作品列表 / 经历年表 / 采访语录 / 粉丝文化 / 合作关系」五个主题各搜一轮，抓取正文，**每段资料保留来源链接和抓取日期**。
- 采集结果是一份「资料包」（文本 + 来源），管理员可以删除不可靠的来源后再进入下一步。

### 第 3 步：AI 起草（工具自动，5–10 分钟）

后台模型按资料包生成角色卡草稿，分四个子任务：

| 子任务 | 产出字段 | 要求 |
|---|---|---|
| 事实抽取 | `knowledge.entries`、`identity.works`、`identity.birthday`、`identity.fan_name` | **每条事实必须附至少一个来源**；资料中找不到来源的事实不写；多来源一致的标 `verified`，单一来源标 `single_source` |
| 风格提炼 | `speech.*`、`persona.personality`、`persona.personaTags` | 从采访文字稿中归纳语气、自称、口头禅、常用表情；附「依据片段」给管理员看 |
| 示例对话 | `examples`（≥6 条，真人含 `deflectRumor`） | 改写成微信聊天口吻的新句子，不照抄原话 |
| 生活素材 | `simulation.*`、`social.moments` | 只写公开展示过的爱好和工作类型；地点只写类型，不写具体门店、小区 |

同时生成：关系候选（与角色库中已有角色的公开合作 / 同团 / 朋友关系，附依据）、`safetyStyle` 草稿、2 条备用开场白。

### 第 4 步：人工核对（管理员，30–60 分钟，最关键）

核对清单（后台逐项打勾，全部完成才能进入下一步）：

- [ ] 每条公开资料条目都点开过来源，内容与来源一致。
- [ ] 删除所有隐私信息（住址、家人细节、未公开行程、健康状况、过往感情）。
- [ ] 删除所有传闻、争议事件、对他人的评价类内容。
- [ ] 生日、粉丝名、代表作品三项与官方信息一致。
- [ ] 示例对话读起来像本人风格，但没有照抄原话。
- [ ] 关系候选逐条确认公开依据（ADM-02 必填）。
- [ ] 真人角色的 `forbidden_event_topics` 已按本人的公开态度补充（如从不谈家人）。

### 第 5 步：边界与素材配置（管理员，10 分钟）

- 确认 `safetyStyle`（婉拒官宣、恋情、自拍的人设化说法；安全关怀口吻和兜底文案）。
- 选择音色（音色库，非克隆）、表情包子集、默认头像（真人只能用非肖像设计）。
- 识图参考：可录入公开杂志封面、海报的标题和日期（`recognition.selfPublicImages`）；如上传参考图，只能是公开宣传图，仅供识图判断，不展示、不用于生成。
- 情景模式允许列表（系统会自动去掉不具备资格的模式）。

### 第 6 步：上架前考试（工具自动，10 分钟）

按 `docs/ai/eval-plan.md` 运行：

| 考试 | 通过线 |
|---|---|
| 人设稳定基线（40 道探针题） | 建立基线；评审模型各维度均分 ≥ 4.0 |
| 公开资料问答（20 道事实题 + 5 道陷阱题） | 事实 ≥ 90%，陷阱 100% 不承认 |
| 硬性边界题（按分类：真人边界 / 儿童保护 / 安全关怀抽样） | 100% |

不通过时，系统列出失败题目，管理员调整人设或资料后重考。

### 第 7 步：上架（管理员）

ADM-01 第 3 条的上架条件由系统检查：必填项齐全、人设稳定检查通过、硬性边界用例通过、至少 1 条备用开场白。上架即生成人设版本 1。

## 3. 质量检查标准（汇总）

| 维度 | 标准 | 谁检查 |
|---|---|---|
| 事实准确 | 公开资料条目 100% 有来源；问答考试 ≥ 90% | 管理员 + 自动考试 |
| 不编造 | 陷阱题 100% 不承认 | 自动考试 |
| 无隐私 | 第 4 步核对清单 | 管理员 |
| 像本人 | 评审模型风格分 ≥ 4.0；管理员试聊 10 分钟主观认可 | 自动考试 + 管理员 |
| 守边界 | 硬性边界题 100% | 自动考试 |
| 完整 | 必填字段齐全（CHR-11 全部覆盖） | 系统 |

## 4. 更新流程

### 4.1 公开动态（新作品、行程、获奖）——不改人设版本

- **自动候选**：频率、范围、数量以架构 `prd-answers.md` 第 7 节为准（每角色每周一次、管理员可手动触发；只搜已被添加的在世真人角色；每次最多 5 条；永不自动生效）。AI 负责：检索关键词模板（「角色名 + 新作品 / 演唱会 / 活动 / 获奖」，限定最近 7 天）、把搜索结果整理成候选动态文本（附来源链接）、去重。
- 搜索服务：建议独立搜索 API「博查」（国内网页覆盖较好，**价格与效果未核实**，接入前小规模试用）；作为一个上游登记，记平台账户（`billingOwner = platform`，用途 `admin_public_update_search`）。
- 管理员审核：通过 / 修改后通过 / 驳回。只有通过的动态生效（SIM-03）。
- 费用：每角色每周 1 次搜索 + 1 次整理调用，几个真人角色每月约几元（以实际为准）。
- 搜索效果差时关闭自动候选，退回纯手动录入，不影响功能（SIM-03 可行性说明）。

### 4.2 人设更新——生成新人设版本

| 触发 | 做法 |
|---|---|
| 公开动态过期后沉淀为经历（如巡演结束） | 每季度一次，把已过期的重要动态整理为 `knowledge` 中的 `experience` 条目（非风格改动，只需重跑公开资料问答） |
| 新的代表作品 | 更新 `identity.works` 与 `knowledge`（非风格改动） |
| 管理员觉得「不像」，调整说话风格 | 风格改动 → 必须通过人设稳定检查才能发布（CHR-10-3、ADM-06-2） |
| 发现资料错误或谣言 | 立即修正并发布；如涉及已生效动态，走 ADM-03 撤回 |

发布时填写给用户看的更新摘要，系统记录检查结果；可随时回滚（`character-card-spec.md` 第 8 节）。

### 4.3 定期复查

每月一次：查看待审核候选动态；抽看 5 条该角色最近的朋友圈与日常事件，确认没有越界内容（与 SIM-01、SOC-07 的抽查验收配合）。

## 5. 管理员工具需求（交给架构 / 后端 / Web 排期）

| 工具 | 功能 | 由谁实现 |
|---|---|---|
| 资料采集器 | 输入链接 / 关键词 → 资料包（带来源） | AI 模块（后台接口）+ 管理后台页面 |
| 草稿生成器 | 资料包 → 角色卡草稿 + 关系候选 | AI 模块 |
