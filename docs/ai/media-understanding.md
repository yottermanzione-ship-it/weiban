## 1. 一句话结论

所有多媒体能力都经模型网关（`ModelGatewayMediaPort`，model-access 实现）调用并计费；ai-runtime 的
`MediaAiService` 负责「什么时候用、用多少、哪些不能说」。平台没在模型目录里把某个模型设为对应默认
（`speech_synthesis` / `speech_recognition` / `image_generation` / `web_search` / `vision`）就等于「未开通」，相关功能安静消失。

## 2. 模型网关多媒体扩展（model-access）

| 方法 | 计价单位 | 说明 |
|---|---|---|
| `synthesizeSpeech` | `ttsChars`（tts_10k_chars） | 音色取自音色库（非克隆）；优先用音色登记的模型，否则用默认语音合成模型；结果存为 `generated_voice` |

| `openRealtimeAsr` | `asrSeconds` 每分钟一段 | 通话用（T-072）。每分钟冻结、结算；冻结不到下一分钟时结束结果流；能量断句后逐句识别 |
| `streamSpeech` | `ttsChars` | 通话用。`abort()` 打断后按已收到的音频折算字数结算 |

| `decide` | — | T-090 实现前一律 `not_configured` |

- 非流式调用 24 小时幂等（复用文本网关结果缓存，键前缀 `media:`）。
- 用量记录新增 `media_units`（迁移 0047），记下字数 / 秒数 / 张数 / 次数；金额、耗时、模型照常记。

- 装配入口把 calls 的 `CALL_SERVICE_STATUS` 绑定为「语音识别与语音合成都开通」。

## 3. ai-runtime 行为

### 3.1 理解用户发来的内容（回复上下文）
- 本轮新消息（上一条角色消息之后，最多 6 条）：语音先转文字并写回 media（`MediaTranscriptPort`）；图片走识图；表情包用库内含义，没有含义时识图概括，再不行按「发了一个表情」；链接读标题与摘要（摘要缺失时用 `LinkPreviewPort` 再读，读不到只按标题）。
- 旧消息只写占位文字（「[对方之前发过一张图片]」），不重复花钱。
- 另有任务 `ai.transcribe_voice`：用户语音（私聊和群聊）一到就转文字，供「转文字」按钮使用。
- 语音服务未开通：转写状态标为 `unavailable`（客户端显示「当前无法识别语音」），角色按「没听清」回应。

### 3.2 识图认人（MED-04）
1. 名单 = 角色本人（含别名）+ 关系网中有公开依据的关系（预设之间要求 `evidence`；用户自己为自定义角色设的关系也算）。
2. 识图模型按封闭名单输出 JSON（描述、名单内的人、图片类型、图中文字）；名单外的名字被丢弃。
3. 认出自己、真人角色、像杂志 / 新闻时联网搜索；有结果则只允许引用结果中的信息，没有结果则明确禁止说具体杂志名和日期；不得以本人身份确认未经官方公开的新闻。
4. 回复里出现已录入的真人姓名且不在名单、用户也没提到 → 重写一次，仍不行改发安全说法。

### 3.3 回复附加（只在日常范围、非安全关怀的普通回复）
- **语音**：用户要求（「发条语音」「想听你的声音」等）或规则版概率 6%，且该角色最近 100 条消息中语音占比加上这条不超过 10%；P-45 静默中、语音服务未开通、没有可用音色（陪伴设置 → 预设默认音色）、文字超过 120 字时不发。整段回复合成一条语音，`transcript` = 回复原文。发出后发 `ai_runtime.milestone`（voice_message_sent）。
- **表情包**（2026-11-03 T-20261103d 起由写回复的聊天模型自己决定）：
  - 提示词：能配时在动态结尾告诉模型可选情绪（离线标签的 10 个主标签的中文名：开心、喜欢、安慰、累了、赞同、打招呼、晚安、再见、谢谢、道歉；只列该角色这轮挑得出图的，严肃场景只列安慰）和标记写法 `[表情:情绪]`；连续 9 条角色消息没带表情且不严肃时加一句提醒（保底，不由服务端硬塞）。生态主动消息（未指定形式）同样提示。
  - 剥离：回复引擎 / 主动消息拆条前剥掉标记（`domain/sticker-marker.ts`；全角括号、「表情包」写法、没写情绪的、照聊天记录学写的「[你发了一个表情包：…]」都剥），用户正文不残留；清单外的情绪只剥不发。
  - 挑图：只用 `listStickersForCharacter` 返回的子集（标签排除的图已剔除），在主标签（`tags[0]`）等于该情绪的图里，按回复与使用意思、适合场合的本地字二元组相似度挑最贴切的几张，再按 seed 取一张；没标签的旧图退回 description 关键词判断（带数字的说明一律排除）。
  - 硬规则：用户说过不要就不发（suppressedForms）；私密 / 成人、涉及健康、树洞、关怀不发；严肃场景只允许安慰；不连发；每 10 条角色气泡软上限 3 个（PRD MED-01 第 4 条已同步为 3 个）；20 条内不重复同一张。
  - 已去掉：回复字面关键词闸门、28% 抽签、决策层 `keep_sticker` 审批。
  - 群聊（2026-11-03 T-20261103g）：群聊发言复用同一套标记与挑图（`MediaAiService.groupStickerPrompt` / `pickGroupSticker`）。防刷屏：同一轮（触发的用户消息之后）已有角色带过表情，别的角色这轮不给提示、写了也只剥不发；每个角色只数自己的消息，每 10 条软上限 3 个、不连发；20 条内不重复同一张按全群算；用户在群里说过不要、树洞不配；严肃场景只列安慰；群聊不加保底提醒。群聊一次发言含表情最多 3 条（带表情时文字最多 2 条），表情跟在文字后面发（幂等键 `…:sticker`），可靠回复计划重放时沿用已挑好的表情。群里库内表情在记录里显示为「[表情] 表情 12」，模型照着写时整段剥掉。
- **分享照片**（2026-11-03 T-20261103g，私聊回复与生态主动消息）：
  - 素材：只用已入库、已审核的微博素材图——角色最近 30 天、仍生效（`public_updates.status = 'effective'`）的最多 5 条微博公开动态里，已经转存进 `weibo_item_media` 的图（`WeiboMaterialService.shareable`，聊天时不抓页面）。不生图、不找网图、不用风景图；素材文字涉及健康隐私或过不了日常输出检查的不用；没有素材就不给提示也不发。
  - 选图：从最新那条微博起，排除这个用户收到过的图（聊天记录里角色发过的图 + 图片描述存档里这个用户已有记录的图），按「用户 + 素材」稳定挑一张（`weiboPickImage`）。
  - 提示词：规则允许且有图时，在动态结尾说明「这张照片是你 M月D日 发的微博里的配图，那条微博写的是：「…」」，看不到照片本身、不编造细节，想分享时正文最后另起一行写 `[照片]`；这轮也能配表情时提醒两样只选一样。
  - 剥离：回复引擎 / 主动消息拆条前剥掉 `[照片]` 类标记（全角括号、「图片」「分享照片」「photo」、带说明的、照聊天记录学写的「[你发了一张图片：…]」都剥；群聊只剥不发）。
  - 发送：模型写了标记才发提示里给的那张，发前复核仍在可分享素材里、媒体还在且是图片，跟在文字（或语音）后面；发出后存进图片描述存档（`微博配图（M月D日的微博：「…」）`），之后聊天记录显示「[你发了一张图片：…]」，这个用户不会再收到同一张。
  - 硬规则：用户说过不要图片就不发（suppressedForms 新增 `photo`；明确要「发张照片给我」恢复）；私密 / 成人、涉及健康、树洞、关怀、严肃场景不发；每 20 条角色消息软上限 2 张；不连发。
- **同一轮最多一种媒体附加**（T-20261103g）：作品链接 > 照片 > 表情包，语音不算附加；总条数仍按 P-02 封顶 4 条（合并文字后仍超出时，表情包、照片、链接从后往前去掉）。
- **作品链接**：用户想听 / 想看时，从作品链接库挑（标题出现在回复里的优先），发出前再做一次可访问性检查，打不开的回写检查结果并跳过。
- 行为规划决策层（T-090）就绪后，上述概率改由决策层选择，上限规则不变。表情包例外：2026-11-03 起不再经决策层（见上）。

### 3.4 主动分享（MED-05）
主动消息调度新增理由 `share_work`：每角色每周最多一次候选，计入 P-03 / P-04（走原有发送账本）；文字由模型写，链接卡片单独发出；链接临发前不可访问则整条放弃。
