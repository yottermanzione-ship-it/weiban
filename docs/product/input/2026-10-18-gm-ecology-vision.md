# 总经理对「角色生态」的构想（2026-10-18）

> 来源：2026-10-18 00:17–00:28 总经理原话与追问。本文只记录构想与约束，不代表已实现，也不替代 PRD。
> 相关：`docs/refactor/11-plan-and-open-topics.md` B2、`docs/refactor/12-model-call-scenes.md`、`docs/tasks/2026-10-16-model-routing-ecology-continuation.md`

## 一、目标形态

角色不是「被规则安排着发内容」，而是**像一个真人一样，隔一段时间自己想一想现在该做什么**。

原话要点：

- 「就像让一个 AI 扮演一个真正的人，每隔一段时间思考一次。」
- 「我前面提到的和没提到的各种 APP 上有的功能，AI 都能了解到，并根据所有场景做出合适的动作。」
- 「就像 grok bot 一样，或者 muse，这些云端 agent 会主动根据上下文进行一些主动消息的发送。」
- 「咱们的朋友圈、经期日记什么的，得让角色感知到，就像 AI 在调用 agent 的工具一样。」
- 「AI 定时执行生态，然后分析一通：角色该发个朋友圈，那他就能发；觉得该关心下用户，那就关心下。」

即：**定时唤醒 → 读取全局上下文 → 自己选一个动作 → 调用工具执行**。动作不是代码写死的流水线，而是模型从工具清单里挑。

## 二、必须有上下文

角色要「感知到」的东西至少包括：

- 聊天记录与最近对话摘要；
- 自己发过的朋友圈、别人（用户/其他角色）的评论；
- 经期日记与身体状态；
- 日程、共同事件、约定；
- 记忆（长期事实、称呼、偏好）；
- 自己的角色卡与人设、关系阶段；
- 积分余额与今天的后台预算。

## 三、动作清单（工具）

已确认要做、且现有代码有执行器的：发朋友圈、主动私聊、朋友圈评论/点赞、经期关怀、群聊自发、配图。

需要补能力才能做的：主动打电话（缺密钥/域名）、发语音消息（链路未验）。

现在明确做不到、必须补的：**用户说「你发个朋友圈」，角色真的发出去**（聊天链路没有动作执行，AI 只能嘴上答应）。

## 四、约束（总经理明确过的）

1. **不能假称**：说了发了就必须真的发了，做不到就别说。动作必须有真实返回值。
2. **不能刷屏**：每天条数、每角色次数要有硬上限。
3. **不能烧钱失控**：余额不足即停，不做透支。
4. **思考本身也要花钱**：总经理已了解「想但没做」也要付费，需要决定谁承担（用户 / 平台 / 分层）。
5. **会员相关的定价与权益暂缓**：方案未定，先做 UI，让总经理看着界面决定。

## 五、与现状的差距

| 环节 | 现状 | 目标 |
|---|---|---|
| 触发 | 各模块各自定时（朋友圈每小时、主动消息另有调度） | 一个统一的生态循环 |
| 决策 | 规则先定「发不发/几点」，决策层只在候选里挑 | 模型读全局后自己选动作 |
| 上下文 | 各模块只读自己需要的那一小块 | 统一快照 |
| 动作 | 代码里的固定函数 | 模型可调用的工具清单 |
| 用户指令 | 聊天里没有动作执行 | 「你发个朋友圈」→ 真发 |

## 六、落地顺序（当前决定）

1. **先做 UI**：生态设置页 + 全站 UI 对齐（总经理 2026-10-18 决定，UI 先于后端）。
2. 总经理看着界面定：要哪些动作、多久想一次、谁付思考费。
3. 再实现后端：上下文快照 → 动作工具 → 生态循环 → 计费与开关。
