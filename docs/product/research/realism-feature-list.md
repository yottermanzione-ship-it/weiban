## 怎么用这张表

- **最后一列「总经理勾选」请您填写**：写「要」「不要」或「改期到 X」，有想法可以直接写在格子里。
- **追星价值**：对「像加了爱豆的微信」这个体验的帮助程度，分高 / 中 / 低。
- **难度**：产品负责人的粗估，分高 / 中 / 低，**一律待架构确认**。技术方案不由产品负责人决定。
- **建议期次**：
  - 一期 = 第一个可用版本，核心目标是聊天链路稳定。
  - 二期 = 链路稳定后马上做的特色功能。
  - 以后 = 先不做，看情况再说。
- **⚠ 标记**：涉及法律风险或与 ADR-0001 有关，详见报告第 8 节。
- **iOS 提示**：iOS 走网页版（PWA），推送需要 iOS 16.4 以上并添加到主屏幕，后台运行和通话基本做不到（见 ADR-0001）。涉及推送和通话的功能在 iOS 上效果会打折。

## 建议一期范围汇总（供参考，不是定稿）

- 记忆：B1、B2（简版）、B5、B6（简版）

一期看起来项目不少，但大部分是「低难度」的节奏和细节类功能。真正吃工作量的是 **G7 消息可靠收发**和**主动消息的推送链路**，这两项与一期核心目标一致。如果架构评估后工作量过大，产品负责人建议按以下顺序往后挪：C2 → B6 → A3 → G4（G4 挪走后，C1 只保留「角色睡觉时不发主动消息」）。
