## 1. 产品与角色

| 标准用词 | 含义 | 不要用 | 备注 |
|---|---|---|---|
| 微伴 | 本产品名称 | — | |
| 用户 | 使用微伴的人（目标画像：追星女孩） | 玩家、粉丝（泛指时） | 「粉丝」只在说「粉丝名」时用 |
| 角色 | 用户在微伴里聊天的 AI 对象，包括预设角色和自定义角色 | 机器人、智能体、崽、AI 好友 | 界面上可直接显示角色名，不加「AI」字样 |
| 预设角色 | 由管理员蒸馏公开资料制作、在角色广场上架的角色（如杨幂、罗小黑、李白、江流儿） | 官方角色、系统角色 | |
| 自定义角色 | 用户自己创建的角色（导入聊天记录生成，或手动填写），以及从人设广场复制来的角色；未发布时只有本人可见 | 私人角色、捏的崽 | v1.3：可以发布到人设广场（PLZ-02） |
| 真人角色 | **以真实人物本人身份呈现**的角色：使用该人的真名，或包含可识别其真实身份的事实（真实作品、真实人际关系、真实经历等）。分公众人物、历史人物、基于身边真人三个子类 | 明星角色（泛指时） | 硬性边界按此分类执行，见 PRD 第 10 章 10.0。v1.2 收窄定义（总负责人 T-010 补充决定）：只借用真人性格、说话风格而用新名字的，不算真人 |
| 历史人物 | 真人角色的子类：去世超过 100 年、没有照片或录音资料的人物（如李白），由管理员在角色库标注 | 古人角色 | 与其他真人角色唯一的区别：允许生成古风插画形象（SAFE-01，产品规则） |
| 基于身边真人 | 真人角色的子类：用户以身边真实的人（朋友、家人）本人身份创建的自定义角色，导入聊天记录生成的角色默认属于此类 | 基于真人（单说时可用） | 与明星同样处理 |
| 虚构角色 | 出自影视、动画、小说、游戏等作品的虚构人物（如罗小黑、江流儿） | 二次元角色 | |
| 原创角色 | 用户或管理员原创、无作品出处、**不以任何真实人物本人身份呈现**的角色。以真人性格、说话风格为灵感，但用新名字、不带真实身份事实的角色（如「水芙兰」「兰溪」）也属于原创 | OC（口语可用，文档不用） | 自定义角色由用户在创建时自选分类（CHR-07） |
| 儿童角色 | 设定年龄未满 18 岁，或外表为儿童的角色（如江流儿、罗小黑） | 未成年角色（泛指时） | |

## 4a. 互动玩法（v1.3）

| 标准用词 | 含义 | 不要用 | 备注 |

| 共同领养宠物 | 用户和某个角色一起养的一只虚拟宠物 | 云养宠、电子宠物 | PLAY-02；宠物不会死、不会生病 |

## 5. 情景与边界

| 标准用词 | 含义 | 不要用 | 备注 |
|---|---|---|---|
| 情景模式 | 叠加在人设上的一层预设风格：日常（默认）、傲娇、恋爱、成人等 | 角色模式、剧本 | 新增需求 1 |
| 成人模式 | 允许成人内容的情景模式，只对有资格的角色开放 | 无审查模式、R18 | 资格规则见 PRD 第 10 章 |
| 成人模式资格 | 角色能否开启成人模式的系统判定：**不是真人角色并且不是儿童角色**即为「是」，没有其他条件 | | v1.2，SAFE-03；开启还需先选好成人模式模型（功能前提，不是资格条件，MODE-03） |
| 成人模式内容 | 在成人模式中产生的消息和记忆。只在同一角色内共享，不传给其他角色，不进朋友圈、时间线、非成人群聊、分享图，推送不显示内容 | 私密内容 | v1.3，MODE-05 |
| 人设贴合度 | 用户可调的「贴合人设 ↔ 顺从」滑杆，5 档 | 顺从度、听话程度 | F6 |
| 硬性边界 | 由项目总负责人设定、PRD 必须遵守、用户设置无法绕过的规则 | 红线、审核规则 | PRD 第 10 章 |
| 安全关怀 | 用户表达自伤、轻生等高危情绪时，角色以自己的口吻关心并自然告知求助方式 | 安全提示、风控弹窗 | F7 |
| 识图认人 | 角色在用户发来的图片里认出具体是谁。只限角色本人和与其有公开关系的人 | 人脸识别（泛指时） | E5 |

| 余额 | 用户账户里可用于模型调用的金额，以「元」显示。个人测试阶段由管理员手动加，不接真实支付 | 零钱、钱包、积分、额度（单说时有歧义） | MDL-07 |
| 余额明细 | 余额每一笔增加和扣减的记录，只增不改 | 流水（界面中）、账单 | MDL-08；文档中「流水」可作同义词 |
| 价目表 | 各模型、语音、图片、识图的单价表，由管理员维护 | 价格表（单说时可用） | MDL-09、ADM-05 |

| 低余额提醒线 / 后台功能保留线 | 余额低于 P-32 时提醒；低于 P-33 时后台功能停下、把余额留给聊天 | | MDL-10 |
| 后台预算 | 用户设置的「后台功能每天最多花费」，从余额扣，达到后当天停止部分后台功能，聊天不受影响 | 限额、额度（单说时有歧义） | 默认值见 `docs/ai/cost-estimate.md` 第 6 节 |
| 平台密钥 | 平台在各模型供应商处的 API 密钥，由管理员在后台维护，用户看不到也不需要 | 官方密钥 | ADM-05；保管方式以 T-009 为准 |
| 成人模式模型 | 用户为成人模式单独指定的模型；**不设置就不能开启成人模式**，系统不会改用聊天模型 | 无审查模型（界面中） | MDL-02、MODE-03；v1.3 按总负责人裁定 B2 改写 |
| 默认识图模型 | 管理员设定的识图模型；用户的聊天模型不支持识图时自动用它看图，费用照常从余额扣 | 备用模型 | v1.3，MDL-02 第 6 条、ADM-05 第 9 条 |
| 行为规划 | 在角色说话之前，先决定「用什么形式、什么时候做」（发语音、发图、晚点回、现在主动找等）的环节 | 导演模型、剧本 | v1.3，第 17 章；也是花费统计中的一种用途 |
| 决策层 | 行为规划的执行者，只输出决策、置信度和理由，不生成聊天内容；实现可替换（默认规则 + 便宜模型，候选 Jev） | 规划模型（单说时） | PLAN-03 |
| 用量与费用 | 管理后台中按用户、角色、模型、用途、时间汇总 token 和费用的页面 | 账单（单说时） | v1.3，ADM-08；用户侧对应「花费统计」 |
| 允许成人内容（标签） | 模型能力标签之一，表示该模型能生成成人内容，仅供筛选，不是开启成人模式的条件 | 无限制、无审查 | v1.2 改义，ADM-05 第 6 条 |
| 邀请码 | 注册账号时必须填写的一次性码，由管理员生成，可预设注册赠送余额 | 激活码 | ACC-01、ADM-01 |
| 注册赠送余额 | 管理员生成邀请码时预设的金额，用该码注册成功后自动到账，余额明细中记为「管理员加余额 · 注册赠送」 | 新人红包、充值 | v1.4 与契约 1.2 对齐，ADM-01 第 6 条 |
| 注销中 / 注销未完成 | 用户已申请注销、各部分数据还在删除的账号状态；管理员可在后台查看进度并重新触发删除 | 冻结、停用 | v1.4，ACC-06、ADM-10 |
| 模型排行榜 | 帮助用户挑选角色扮演模型的榜单页 | | 数据来源由 AI 系统负责人定 |
| 花费统计 | 按天、角色、用途汇总的实际扣费（用户侧） | 用量（v1.1 旧称） | MDL-05；v1.3 用途新增「行为规划」 |
