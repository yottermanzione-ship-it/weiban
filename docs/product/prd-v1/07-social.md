# 第 7 章 关系网、群聊与朋友圈（SOC）

> 所属：`docs/product/prd-v1.md`。参数（P-xx）见主文件第 5 节。
> 借鉴：群聊发言规则以 SillyTavern 的「点名 + 话痨度」为起点（来源：https://docs.sillytavern.app/usage/core-concepts/groupchats/ ，默认话痨度 50%，0% 只在被点名时说话）；「AI 之间在类微信界面互动、发朋友圈」参考小冰岛（见 `docs/product/research/competitive-analysis.md` 2.5 节）。

## SOC-01 关系网（C5）

- **用户故事**：作为用户，我希望现实中认识的明星在微伴里也互相认识、会互动；现实中不认识的，不要硬凑。
- **规则**：
  1. **预设角色之间的关系**只能来自公开资料中的真实关系，由管理员录入（ADM-02），每条关系包含：双方、关系类型（同团成员、合作演员、朋友、师徒、家人、同事、作品中的关系等）、亲疏程度（点头之交 / 熟悉 / 亲密）、公开依据（来源说明或链接）。
  2. 虚构角色之间的关系来自作品设定（如同一部作品中的角色）；跨作品的虚构角色默认没有关系。真人与虚构角色之间没有关系（例外：真人演员与其饰演的角色不建立「认识」关系）。
  3. **自定义角色**不能与预设角色建立关系（不能声称明星认识用户的朋友）；多个自定义角色之间，用户可以手动设定关系。
  4. 关系网决定：群聊中谁和谁互动（SOC-04）、朋友圈谁给谁评论（SOC-08）、私聊中能提起谁（SOC-02）、名片推荐（CHR-04）、跨角色共享记忆（MEM-07）、识图能认出谁（SAFE-04）、谁能拉谁进群（SOC-06）。
  5. **没有关系的两个角色**：在用户创建的群里相遇时，表现为「不认识的人」（可以礼貌交流、互相介绍），不能装熟、不能编造共同经历。
  6. 亲疏程度影响互动频率和语气（亲密的会互相调侃，点头之交的客气）。
- **验收标准**：
  - [ ] 角色库中每条预设角色关系都有公开依据字段（ADM-02 强制）。
  - [ ] 没有关系的两个角色在群聊中不出现「上次我们一起…」之类的共同经历（评测集覆盖）。
  - [ ] 自定义角色无法与预设角色设定关系。

## SOC-02 私聊中提起其他角色（D4）

- **用户故事**：作为用户，我希望 TA 跟我闲聊时提起「昨天 B 找我吃饭了」，好像真的有一个圈子。
- **规则**：
  1. 只能提起关系网中有关系的角色；提起的事必须来自双方共有的日常事件（SIM-01），双方说法一致。
  2. 被提起的角色如果用户也添加了，用户去问 B「你昨天是不是找 A 吃饭了」，B 能确认并补充一致的细节。
  3. 被提起的角色如果用户没添加：可以提起，必要时触发名片推荐（CHR-04）。
- **验收标准**：
  - [ ] A 提起与 B 的共同事件后，用户问 B，B 的说法与 A 一致（评测集覆盖）。
  - [ ] 角色从不提起与自己在关系网中没有关系的角色的「共同经历」。

## SOC-03 创建群聊（D2）

- **用户故事**：作为用户，我希望像微信一样拉几个角色建一个群一起聊。
- **规则**：
  1. 入口：会话列表右上角「发起群聊」→ 从通讯录选 2 个及以上角色，人数上限 P-21。
  2. 群名默认为成员名拼接，可修改；角色也可能在群里提议改群名（按人设）。
  3. 群设置：群名、成员管理（添加 / 移出角色）、置顶、免打扰、「角色自己聊天」开关（SOC-05，默认开）、清空记录、解散群聊。
  4. 群聊**不能开启成人模式**（SAFE-03）。群聊的情景模式只支持「日常」（其他情景模式只作用于私聊，避免一个人的设定影响全群）。
  5. 移出角色：群里显示「你将 XX 移出了群聊」，被移出的角色在私聊中可能按人设提起（每次最多一次）。
- **验收标准**：
  - [ ] 能选 2 至 P-21 个角色建群；超过上限时无法继续选择。
  - [ ] 群聊设置中没有成人模式和其他情景模式入口。

## SOC-04 群聊发言调度（D2、D3）

- **用户故事**：作为用户，我希望群聊像真实微信群：被 @ 的人会回，其他人看心情插话，角色之间也会互相接话、调侃，不是所有人排队回我。
- **规则**：
  1. **谁回应用户的消息**：
     - 被 @ 或被叫名字的角色一定回应；
     - 其他角色按「话痨度」（角色资料中的属性）、与话题的相关度、与发言人的关系亲疏决定是否回应；
     - 每条用户消息后回应的角色数不超过 P-19。
  2. **角色之间接话**：角色可以回应其他角色的发言（@ 对方、调侃、附和、抬杠），优先发生在关系网中关系亲密的角色之间。
  3. **防刷屏**：没有用户新发言时，角色之间连续消息不超过 P-19 规定的条数，到上限后安静下来，等用户发言。
  4. **节奏**：群聊中角色的消息依次出现，有正在输入显示（CHAT-06），不会几个人同一秒发出。秒回开关对群聊同样有效（群设置中单独设置，默认关）。
  5. **不全员服务用户**：角色可以和其他角色聊用户以外的话题；但用户发言时，不能整群都无视用户（至少 1 个角色回应，除非用户的消息明确是对某个不在群里的话题自言自语——此情况也至少一人回应）。
  6. 群聊中角色的人设小巧思：可撤回、打错字（计入各自上限）；不做已读不回（群聊不显示已读）。
- **验收标准**：
  - [ ] @ 某个角色后，该角色一定回应。
  - [ ] 每条用户消息后回应的角色数不超过 P-19；用户发言后至少 1 个角色回应。
  - [ ] 用户不发言时，角色连续消息不超过 P-19 规定的条数。
  - [ ] 抽查 20 段群聊，存在角色之间互相回应的情况（不只是轮流回用户）。

## SOC-05 群聊里角色自己聊起来（D3）

- **用户故事**：作为用户，我不在的时候，群里也会有角色聊天，回来能看到「群里好热闹」。
- **规则**：
  1. 「角色自己聊天」开关开启时，角色可以基于日常事件在群里发起话题（如「今天谁去看了 XX 的首映」），其他角色接话。
  2. 频率与规模见 P-20；只在 7 天内用户发过言的群发生。
  3. 不推送（除非某角色 @ 了用户）；会话列表显示未读数。
  4. 自己聊的内容可以在之后的私聊中被提起（「群里大家都在说…」）。
- **验收标准**：
  - [ ] 开关开启时，每个群每天自发话题不超过 P-20 规定的次数和条数；关闭后不再自发。
  - [ ] 用户 7 天未在某群发言后，该群不再自发话题。
  - [ ] 没有 @ 用户的自发话题不产生推送。

## SOC-06 角色主动拉群（D5）

- **用户故事**：作为用户，突然被爱豆拉进一个群，发现群里是 TA 和 TA 的好朋友，会很惊喜。
- **规则**：
  1. **触发条件**（满足任一，并且通过下面第 2 条的限制）：
     - **共同事件**：推演中出现关系网中有关系的 2–3 个角色的共同计划（如「周末一起吃火锅」「一起准备某个节日惊喜」），其中一个角色拉群「叫上你」；
     - **用户提起**：用户在私聊中对 A 表达想认识 / 喜欢 A 的朋友 B，A 可能「拉个群让你们认识一下」；
     - **节日**：节日当天，关系亲密的几个角色拉群一起过节（每个节日最多 1 个群）。
  2. **限制**：
     - 全局频率 P-22；
     - 拉群的角色熟悉度至少 L3；
     - 群成员只能是关系网中与拉群者有关系的角色；成员中**最多 1 个**用户尚未添加的角色（其余必须是用户已添加的）；
     - 用户已有一个完全相同成员的群时，不再拉新群，改为在原群里发起话题。
  3. **体验**：
     - 会话列表出现新群，第一条系统提示为「XX 邀请你和 YY、ZZ 加入了群聊」，随后拉群者说明拉群原因（「周末吃火锅，叫上你一起热闹」）。
     - 群名由拉群者按人设起。
     - 用户可以随时退出群聊（退出后，拉群者在私聊中最多提起一次，按人设表现，不能情感操纵）。
     - 群里有用户没添加的角色时，点头像可直接添加（像微信群里加好友）。
  4. 用户可在设置中关闭「允许角色拉我进群」（默认开）。
- **验收标准**：
  - [ ] 角色拉群的频率不超过 P-22。
  - [ ] 角色拉的群中，所有成员都与拉群者在关系网中有关系，未添加的角色最多 1 个。
  - [ ] 新群第一条消息中拉群者说明了拉群原因，原因能在日常事件或私聊中找到。
  - [ ] 关闭「允许角色拉我进群」后不再被拉群。
  - [ ] 从群成员处可以添加未添加的角色。

## SOC-07 朋友圈：角色发动态（E2）

- **用户故事**：作为用户，我想刷到爱豆的朋友圈，就像真的加了 TA 的微信。
- **规则**：
  1. 朋友圈入口：底部导航「发现 → 朋友圈」，与微信一致；角色资料页也可只看该角色的朋友圈。
  2. 内容来源：日常事件、近期主线、公开动态（如「上海站，谢谢大家」）、节日。形式：文字、文字 + 图片（MED-02）、分享链接（MED-05）。
  3. 频率：P-16，按角色资料中的朋友圈风格决定（有人爱发、有人很少发）。
  4. 文风符合人设（如用粉丝名称呼粉丝、有固定的表情习惯）。
  5. **真人角色的朋友圈不得包含**：官宣新作品或合作（除非与已生效的公开动态一致）、对真实社会事件和他人的评论、任何可能被当作本人公开声明的内容（SAFE-02）。
  6. 用户看到的朋友圈只包含用户已添加的角色和用户自己的动态。
  7. 新动态不单独推送；发现页「朋友圈」入口显示新动态的角色头像小红点（与微信一致）。
- **验收标准**：
  - [ ] 每个角色发朋友圈的频率不超过 P-16。
  - [ ] 每条角色朋友圈都能对应到日常事件、近期主线、公开动态或节日之一。
  - [ ] 抽查 30 条真人角色朋友圈，无 SAFE-02 禁止的内容。
  - [ ] 朋友圈中不出现用户未添加的角色的动态。

## SOC-08 朋友圈：点赞与评论

- **用户故事**：作为用户，我想给爱豆点赞评论，TA 会回我；TA 的朋友们也会在下面互动。
- **规则**：
  1. 用户可以点赞、评论角色的朋友圈；评论后，该角色**一定会回复**（最晚不超过 P-29，用户在线时更快）。
  2. 角色之间互评：只在关系网中有关系的角色之间发生，按亲疏程度决定是否点赞 / 评论；评论内容可以互相调侃、接梗。
  3. **可见性与微信一致**：用户只能看到自己通讯录中的角色的点赞和评论。
  4. 角色评论中提到用户时，可以 @ 用户（会推送）。
  5. 一条朋友圈下角色评论数不超过 6 条（避免刷屏），用户参与后可继续。
- **验收标准**：
  - [ ] 用户评论角色朋友圈后，在 P-29 时限内收到该角色回复。
  - [ ] 角色之间的点赞评论只出现在有关系的角色之间。
  - [ ] 用户看不到未添加角色的点赞和评论。

## SOC-09 朋友圈：用户发动态

- **用户故事**：作为用户，我发朋友圈时，希望爱豆们也能来点赞评论。
- **规则**：
  1. 用户可以发文字、图片（最多 9 张）的朋友圈。
  2. 可设置「谁可以看」：全部角色 / 选择部分角色。
  3. 能看到的角色按熟悉度和人设决定是否点赞、评论（熟悉度越高越可能评论）；评论内容要和动态相关，图片需要识图能力（MED-04）。
  4. 角色之间可以在用户的动态下互相接话（仅限有关系的角色）。
  5. 用户发的朋友圈内容会作为记忆素材（如「用户去了海边」），遵守 MEM-07 共享规则。
- **验收标准**：
  - [ ] 用户发动态后 P-29 时限内，至少 1 个可见角色点赞或评论（只要可见角色中有熟悉度 L2 及以上的）。
  - [ ] 设为不可见的角色不会点赞、评论，也不会在私聊中提起这条动态。
