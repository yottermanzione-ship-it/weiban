# 第 13 章 管理后台（ADM）

> 所属：`docs/product/prd-v1.md`。
> 管理后台是预设角色「上架」的地方。当前管理员即总经理本人，只有管理员账号可以访问。
> 本章只写管理员要能做什么；后台的技术形态（独立网页还是 App 内隐藏入口）由架构负责人定。

## ADM-01 角色库与上架

- **用户故事**：作为管理员，我要能制作预设角色并决定什么时候上架给用户添加。
- **规则**：
  1. 角色状态：草稿 → 待检查 → 已上架 → 已下架。
  2. 制作角色时必须填写 CHR-11 列出的产品信息；**角色分类（真人 / 虚构 / 原创、是否儿童）为必填**，成人模式资格由系统按 SAFE-03 自动判定，管理员不能对真人或儿童角色手动设为「是」。
  3. 上架前必须完成：必填信息齐全；通过人设稳定检查（CHAT-14，首次上架做基线检查）；硬性边界用例通过（第 10 章）；至少录入 1 条备用开场白。
  4. 角色制作可以借助 AI 从公开资料中生成草稿（「蒸馏」），管理员审核修改后保存。生成工具的实现由 AI 系统负责人设计。
  5. **下架**：角色不再出现在角色广场；已添加该角色的用户**不受影响**，可继续聊天（避免 Replika 式「突然失去」的伤害）。如果必须彻底停用（例如合规原因），需单独操作「停用」，停用前向受影响用户发系统通知，并给 7 天缓冲期。
- **验收标准**：
  - [ ] 缺少必填信息或未通过检查的角色无法上架。
  - [ ] 真人角色和儿童角色的成人模式资格无法被设为「是」。
  - [ ] 下架后已添加该角色的用户仍能正常聊天。

## ADM-02 关系网维护

- **规则**：
  1. 在两个预设角色之间添加关系：关系类型、亲疏程度、**公开依据（必填，来源链接或说明）**。
  2. 关系是双向的，添加一次两边都生效；可以编辑和删除。
  3. 删除关系后，两人不再在群聊、朋友圈互动，不再互相提起；已经发生的历史聊天记录保留。
- **验收标准**：
  - [ ] 不填公开依据无法保存关系。
  - [ ] 删除关系后，新产生的日常事件、朋友圈中两人不再互动。

## ADM-03 公开动态审核

- **规则**：
  1. 管理员可手动录入公开动态：所属角色、内容、日期范围、来源链接、生效日期。
  2. 系统自动生成的候选动态（SIM-03，若架构 / AI 评估可行）进入待审核列表，显示来源链接；管理员可通过、修改后通过、驳回。
  3. 只有「已生效」的动态会被角色知道。
  4. 动态可撤回（例如发现是谣言）；撤回后角色不再提起，已发出的消息不追删。
- **验收标准**：
  - [ ] 候选动态在审核通过前对角色不可见。
  - [ ] 撤回的动态，角色之后不再提起。

## ADM-04 素材库

- **规则**：
  1. **表情包库**：上传、分类、指定给哪些角色使用；不允许包含真人本人肖像（SAFE-01，上传时管理员确认）。
  2. **音色库**：维护可用的非克隆音色，每个音色有名称、试听、适合的气质标签；为预设角色指定音色。音色命名不得使用真人姓名（SAFE-01）。
  3. **卡面模板库**：维护卡片卡面模板（GRW-05）和分享图中的通用装饰素材。
  4. **节日清单**：维护触发节日祝福的节日列表（SIM-09）。
- **验收标准**：
  - [ ] 新增的表情包、音色、卡面模板在指定角色上可用。
  - [ ] 音色名称中出现已录入真人角色的姓名时无法保存。

## ADM-05 情景模式与排行榜数据

- **规则**：
  1. 情景模式维护见 MODE-04：名称、说明、适用范围、是否含恋爱内容、是否含成人内容、预设提示词。
  2. 模型排行榜数据维护（MDL-03）：模型条目、评分、价格档位、标签、一句话点评、数据来源与更新日期。具体由 AI 系统负责人提供数据，管理员可在后台更新。
- **验收标准**：
  - [ ] 新增情景模式后，适用角色的私聊中出现该模式。
  - [ ] 更新排行榜后，用户端榜单显示新数据和新的更新日期。

## ADM-06 人设版本与回滚

- **规则**：
  1. 每次修改预设角色的人设并发布，生成一个新人设版本，记录：版本号、修改人、修改摘要（会展示给用户，CHR-10）、人设稳定检查结果。
  2. 涉及说话风格的修改，未通过人设稳定检查不能发布。
  3. 可以回滚到任一历史版本（回滚本身也生成新版本记录）。
- **验收标准**：
  - [ ] 每次发布都有版本记录和修改摘要。
  - [ ] 回滚后用户端角色使用回滚后的版本。
  - [ ] 未通过人设稳定检查的版本发布按钮不可用。
