# 第 14 章 微伴服务入口（SVC）

> 所属：`docs/product/prd-v1.md`。v1.2 新增（T-010），依据：总经理第二轮意见第 5 节「界面尽可能与微信统一」「参照微信『我 → 服务』，换成微伴自己的服务入口，集中放置微伴专属功能的配置」。
> 本章只定**放什么、按什么规则放、从哪里进**；页面长什么样（卡片、图标、宫格排列）由设计负责人决定。界面不使用微信的名称和 logo（总负责人补充）。
> 本章不重新定义任何功能：每个入口指向的功能，规则都以对应章节为准（括号内编号）。
> v1.3 变更（T-017）：服务页新增「互动玩法」分组（经期日记 PLAY-01、宠物 PLAY-02），宫格从 10 个增至 12 个；人设广场放在「发现 → 角色广场」的分页里，不进服务页（SVC-02 新增行）。
> v1.4 变更（T-025）：5 个玩法（PLAY-03～07）已被采纳，「互动玩法」分组增加 5 个宫格，服务页宫格从 12 个增至 **17 个**，与设计 `docs/design/pages/me-and-services.md` 第 2 节一致（总负责人裁定 E1）；红点规则增加「信箱」；SVC-02 补 5 个玩法和心愿清单的入口。

## 设计思路（给总经理）

微信的「我」页里有一个「服务」入口，点进去顶部是钱包（零钱余额），下面是一格一格的服务图标。微伴照搬这个结构，把**微信没有、微伴独有**的功能都收进「服务」：

- **一条放置规则**：微信本来就有的功能，放在微信的老位置（例如收藏在「我」页、朋友圈在「发现」、置顶和免打扰在聊天的「聊天信息」页、通知设置在「设置」里）；**微信没有的微伴专属功能，统一收进「我 → 服务」**。这样用户凭微信的习惯就能找到大部分东西，剩下的「新东西」都在一个地方。
- **只针对某一个角色的设置**（例如给杨幂开傲娇模式），仍然在和 TA 的私聊里改（像微信里每个聊天单独设免打扰一样）；「服务」里提供的是**全局默认值和总览**，可以一眼看到所有角色的状态，点一下跳到对应角色去改。

## SVC-01 「我」页与服务页

- **用户故事**：作为用户，我希望微伴的「我」页和微信一样好找；微伴特有的功能，比如余额、模型、卡册，都集中在一个地方。
- **规则**：
  1. **「我」页结构**（对齐微信「我」页）：

     | 位置 | 内容 | 对应微信 | 需求 |
     |---|---|---|---|
     | 顶部 | 我的头像、昵称、用户名，点击进入「我的资料」 | 头像、昵称、微信号 | ACC-02 |
     | 列表第 1 项 | **服务** | 服务 | 本章 |
     | 列表 | 收藏 | 收藏 | CHAT-11 |
     | 列表 | 朋友圈（只看我自己发的） | 朋友圈 | SOC-09 |
     | 列表 | 表情（管理我添加的表情） | 表情 | MED-01 |
     | 列表最后 | 设置 | 设置 | 见第 3 条 |

     微信「我」页的视频号、订单与卡包不做。
  2. **服务页结构**：

     **顶部卡片**（对应微信服务页顶部的钱包卡片）：
     | 左 | 右 |
     |---|---|
     | 余额「¥ 12.34」→ 余额页（MDL-07） | 模型「当前聊天模型名」→ 模型页（MDL-02） |

     **下方分组宫格**：

     | 分组 | 入口 | 进去后是什么 | 需求 |
     |---|---|---|---|
     | 模型与花费 | 余额明细 | 余额明细列表 | MDL-08 |
     | | 价目表 | 价目表 | MDL-09 |
     | | 模型排行榜 | 排行榜 | MDL-03 |
     | | 后台预算 | 后台预算设置与今日已用 | MDL-05 |
     | 陪伴 | 卡册 | 所有角色的卡册列表（每个角色一本，显示已收集张数），点进某个角色的卡册 | GRW-05 |
     | | 成就 | 成就页（跨角色汇总） | GRW-06 |
     | | 熟悉度 | 所有角色的熟悉度总览（按等级从高到低：头像、名字、等级、到下一级的进度），点进角色资料页 | GRW-03 |
     | 互动偏好 | 情景模式 | 模式说明 + 每个角色当前的情景模式列表，点某个角色跳到该角色的情景模式选择 | MODE-01 |
     | | 主动消息与免打扰 | 主动消息总开关、主动来电总开关、允许角色拉我进群、免打扰时段；下方列出每个角色的主动消息设置，点击跳到该角色的设置 | ACC-03、SIM-10、MED-07、SOC-06 |
     | | 聊天偏好 | 新添加角色的默认值：秒回、拆条、人设贴合度；下方列出每个角色的当前设置，点击跳到该角色的设置 | CHAT-04、CHAT-05、CHAT-09 |
     | 互动玩法（v1.3） | 经期日记 | 记录、预测、「让谁知道」授权 | PLAY-01 |
     | | 宠物 | 所有共同领养的宠物（含「回忆」中已送养的），点进某只宠物的页面 | PLAY-02 |
     | | TA 的提醒（v1.4） | 提醒列表，新建 / 编辑提醒 | PLAY-07 |
     | | 心愿清单（v1.4） | 各角色的心愿清单总览，点进某个角色的清单 | PLAY-04 |
     | | 每日一问（v1.4） | 今天的问题、历史 | PLAY-03 |
     | | 信箱（v1.4） | 慢信的信箱（收到的 / 寄出的），写信 | PLAY-05 |
     | | 陪你专注（v1.4） | 先选角色，再设置专注 | PLAY-06 |

     共 17 个宫格（模型与花费 4、陪伴 3、互动偏好 3、互动玩法 7）。分组顺序按上表；组内排列、图标由设计负责人定（`docs/design/pages/me-and-services.md` 第 2 节）。

  3. **「设置」只保留微信设置里也有的同类项**（对齐微信「设置」页）：账号与安全（修改密码、登录设备，ACC-01）、新消息通知（推送声音、推送是否显示消息内容，ACC-03 第 1 条后半）、隐私（跨角色共享，MEM-07）、通用（深色模式、字体大小、**主题**、默认分享模板 EXP-02；主题见第 7 条）、添加到主屏幕（仅 iPhone 网页版，ACC-05）、退出登录、注销账号（ACC-06）。**模型、余额不再放在设置里。**
  4. **全局默认值与单个角色设置的关系**（适用于「聊天偏好」「主动消息」）：
     - 全局默认值只影响**之后新添加的角色**；已有角色保持各自当前设置，不被批量改写。
     - 服务页的总览列表里，提供一个「全部改为默认值」按钮，点了才批量改（二次确认）。
     - 「主动消息总开关」「主动来电总开关」是总闸，规则不变：关了就全部不发，单个角色的设置不能突破（ACC-03 第 3 条）。
  5. **红点规则**（与微信一致，红点只用于需要用户处理的事）：余额低于 P-32（MDL-10 第 1 条）时，「我」标签、「服务」入口、余额卡片显示红点；获得新卡片或新成就时，「卡册」「成就」宫格显示红点，查看后消失，「我」标签不显示（这类不需要处理）；v1.4：收到未读的慢信回信时，「信箱」宫格显示红点，规则同卡册。其他互动玩法宫格**不显示红点**（每日一问没答、宠物没照顾、提醒没设都不是需要处理的事，SAFE-08）。
  6. 宫格中某项功能所在的开发层尚未完成时，该宫格不显示（不显示「敬请期待」）。
  7. **主题配色**（总负责人 T-010 补充决定第 3 条）：默认主题接近微信（白 / 浅灰底 + 绿色强调色）；「微伴粉」作为可选主题，在「设置 → 通用 → 主题」中切换，切换后立即生效、所有设备同步。具体色值由设计负责人定，不得与微信品牌色完全相同（不使用微信的名称和 logo 的延伸）。分享图模板不跟随主题（EXP-02）。
- **边界情况**：
  - 用户还没有添加任何角色：「熟悉度」「情景模式」等总览页显示空状态「还没有角色，去添加一个吧」+ 跳转角色广场。
  - 管理员把某个情景模式下架（MODE-04）：总览列表中使用该模式的角色显示为「日常」。
- **验收标准**：
  - [ ] 「我」页从上到下为：头像区、服务、收藏、朋友圈、表情、设置。
  - [ ] 服务页顶部卡片显示余额和当前聊天模型，分别能进入余额页和模型页。
  - [ ] 上表列出的 17 个宫格入口都能打开对应功能页（未完成开发层的宫格按第 6 条不显示）。
  - [ ] 有未读回信时只有「信箱」宫格出现红点；其他互动玩法宫格在任何情况下都没有红点。
  - [ ] 设置页中没有模型、余额相关入口；模型、余额只能从服务页进入（单个角色的模型覆盖除外，CHAT-13）。
  - [ ] 在「聊天偏好」改全局默认值后，新添加的角色使用新默认值，已有角色不变；点「全部改为默认值」并确认后，已有角色也被改为默认值。
  - [ ] 在情景模式总览中点某个角色，直接进入该角色的情景模式选择，修改后总览同步更新。
  - [ ] 余额低于 P-32 时「我」标签和「服务」入口出现红点；获得新卡片时只有「卡册」宫格出现红点，「我」标签没有红点。
  - [ ] 新账号默认为接近微信的主题（浅色底 + 绿色强调）；在设置中切换为「微伴粉」后全部界面立即变化，另一台设备同步变化。
