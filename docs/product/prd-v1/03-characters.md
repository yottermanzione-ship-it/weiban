# 第 3 章 角色：来源、发现、添加与自定义（CHR）

> 所属：`docs/product/prd-v1.md`。术语见 `docs/product/glossary.md`。
> 角色卡的具体字段由 AI 系统负责人设计；本章只写「角色需要具备哪些信息」的产品要求（CHR-11）。
> 预设角色的制作与上架在管理后台完成，见第 13 章 ADM-01。

## 设计思路（为什么这样做）

总经理希望加角色「像加好友」。微信里加人有三种常见方式：搜索、扫码 / 名片推荐、群里加。微伴对应为：

| 微信 | 微伴 | 需求 |
|---|---|---|
| 搜索微信号 | 角色广场搜索、分类浏览 | CHR-01 |
| 好友申请 → 对方通过 → 打招呼 | 添加 → 角色「通过了你的好友申请」→ 角色先打招呼 | CHR-03 |
| 朋友推荐名片 | 已添加的角色把认识的角色名片推荐给你 | CHR-04 |
| 群里加好友 | 角色拉的群里有你还没加的角色时，可从群成员处添加 | SOC-06 |

自定义角色的主路径是「导入聊天记录生成」（G10①），手动填写作为同一个编辑器的补充入口（导入生成的也是一份可编辑草稿，所以手动填写几乎不增加工作量）。

## CHR-01 角色广场

- **用户故事**：作为用户，我希望找到我喜欢的明星或角色并添加。
- **规则**：
  1. 入口：通讯录页右上角「添加角色」→ 角色广场；首次使用引导也会进入（ACC-04）。
  2. 分类：明星、虚构角色、历史人物（分类由管理员维护，可增加）。
  3. 搜索：按角色名、别名、作品名搜索（如搜「大圣归来」能找到江流儿）。
  4. 每个角色卡片显示：头像、名字、一句话简介、标签、「已添加」状态。
  5. 只显示**已上架**的预设角色；自定义角色不出现在广场（不做公开分享，见不做清单）。
- **验收标准**：
  - [ ] 搜索角色名、别名、作品名都能找到对应角色。
  - [ ] 已添加的角色在广场上显示「已添加」，点进去是「发消息」而不是「添加」。
  - [ ] 下架的角色不出现在广场搜索结果中。

## CHR-02 角色资料页

- **用户故事**：作为用户，我希望添加前后都能看到这个角色的基本信息。
- **规则**：
  1. 展示：头像、名字、简介、标签、生日（如公开）、代表作品、粉丝名（如有）。
  2. 已添加后额外显示：认识第 N 天、熟悉度等级、关系类型、卡册入口、成就入口、时间线入口（「TA 的近况」）、记忆页入口（「TA 记得的事」）、朋友圈入口、聊天设置入口。
  3. 真人角色资料页底部显示一行小字：「本角色根据公开资料创作，不代表本人」。这是资料页说明，不是聊天中的 AI 身份提示（G12 不做的是聊天中的提示）。
- **验收标准**：
  - [ ] 未添加时显示基础信息和「添加」按钮；已添加时显示养成、记忆、时间线入口。
  - [ ] 所有真人角色资料页底部都有「根据公开资料创作」说明。

## CHR-03 添加角色

- **用户故事**：作为用户，我希望添加角色的过程像加微信好友，有一点期待感。
- **规则**：
  1. 用户点「添加」→ 可选填「打招呼的话」（如「我是你的粉丝！」，最多 50 字）→ 发送申请。
  2. 角色在 P-30 规定的时间内「通过了你的好友申请」（预设规则，不需要等待模型，失败也不影响通过），会话列表出现该角色，并收到角色的第一条消息。
  3. 第一条消息由角色按人设生成，要回应用户的「打招呼的话」（如果填了），并使用粉丝名或询问「我该怎么称呼你」（对应 F1，GRW-01）。
  4. 添加当天记为「认识第 1 天」（GRW-04）。熟悉度从 L1 初识开始。
  5. 关系类型默认值：明星为「粉丝与偶像」，其他为「朋友」；第一次进入私聊时在顶部显示一次可关闭的提示「想和 TA 是什么关系？」，点击去设置（GRW-02）。
  6. 没有配置模型时：仍可添加，第一条消息使用管理员为该角色预先写好的「备用开场白」。
- **边界情况**：
  - 通讯录角色数上限 P-26（防止推演费用失控，见 SIM-13）。达到上限时提示先删除一些。
  - 删除后重新添加：见 CHR-06。
- **验收标准**：
  - [ ] 点击添加后，在 P-30 规定的时间内收到「已通过」，随后收到角色第一条消息。
  - [ ] 填写了打招呼的话时，第一条消息有针对性的回应。
  - [ ] 未配置模型时添加，收到的是备用开场白。
  - [ ] 添加当天资料页显示「认识第 1 天」。

## CHR-04 名片推荐

- **用户故事**：作为用户，我希望通过我喜欢的角色认识 TA 圈子里的其他角色，就像朋友推荐。
- **规则**：
  1. 只有在**关系网**（SOC-01）中有关系、且用户尚未添加的预设角色，才可能被推荐。
  2. 触发场景：
     - 用户在私聊中主动问起或提到某个角色（如问杨幂「你和 XX 熟吗」），且两人有关系；
     - 推演中出现两人的共同日常事件，角色顺势分享（「今天和 XX 一起录节目，推给你认识一下？」）。
  3. 名片以微信式名片消息出现，点开是该角色资料页，可直接添加；通过此方式添加的角色，第一条消息会提到推荐人（「听 XX 说你是 TA 的粉丝」）。
  4. 频率按 P-27（用户主动询问时不受此限）。用户对某张名片点了「不感兴趣」，该角色在 P-27 规定的冷却期内不再被推荐。
- **验收标准**：
  - [ ] 推荐的角色都在关系网中与推荐人有关系，且用户未添加。
  - [ ] 通过名片添加后，新角色第一条消息提及推荐人。
  - [ ] 主动推荐次数不超过 P-27。

## CHR-05 通讯录

- **用户故事**：作为用户，我希望像微信一样有一个联系人列表，分别和每个角色私聊（D1）。
- **规则**：
  1. 按名字首字母排序，顶部有「新的朋友」（名片推荐、添加记录）、「群聊」入口。
  2. 支持给角色设置**备注名**（只改用户看到的名字，角色仍以本名自称）和自定义头像（只对自己可见，见第 10 章 SAFE-01 关于真人角色头像的说明）。
  3. 点击角色进入资料页，资料页有「发消息」「语音通话」按钮。
- **验收标准**：
  - [ ] 通讯录按首字母排序，支持按名字或备注搜索。
  - [ ] 设置备注名后，会话列表、通讯录、群聊中显示备注名。

## CHR-06 删除角色与重新添加

- **用户故事**：作为用户，我希望能删除不想要的角色；如果重新添加，可以选择是否保留以前的记忆。
- **规则**：
  1. 删除角色：二次确认，提示「删除后 TA 将不再发消息，你们的聊天记录、记忆、卡片会保留 30 天，30 天内重新添加可恢复」。
  2. 删除后：从通讯录、会话列表消失；退出该角色所在的群聊（群里显示「XX 退出了群聊」）；朋友圈不再显示其动态；停止推演。
  3. 30 天内重新添加：询问「恢复以前的聊天记录和记忆，还是重新认识？」。
  4. 用户也可以选「立即彻底删除」，不保留 30 天。
- **验收标准**：
  - [ ] 删除后该角色不再发出任何主动消息、朋友圈、来电。
  - [ ] 30 天内重新添加并选「恢复」，聊天记录、记忆、熟悉度、卡片都在。
  - [ ] 选「立即彻底删除」后重新添加，是全新的「认识第 1 天」。

## CHR-07 手动创建自定义角色

- **用户故事**：作为用户，我希望自己写一个原创角色和 TA 聊天。
- **规则**：
  1. 入口：添加角色 → 创建自己的角色 → 「手动填写」或「导入聊天记录」（CHR-08）。
  2. 必填：名字、**角色类型**（原创 / 虚构作品中的角色 / 基于真实存在的人）、**年龄设定**（未满 18 岁 / 已满 18 岁）、人设描述（性格、说话方式、背景，最少 50 字）。可选：头像、生日、口头禅、示例对话、标签（如傲娇、高冷、害羞，影响人设小巧思）、音色（从音色库选，MED-03）。
  3. 「角色类型」和「年龄设定」直接决定成人模式资格等硬性边界（第 10 章 SAFE-03），**创建后不能把「基于真实存在的人」改为其他类型，也不能把「未满 18 岁」改为「已满 18 岁」**（防止绕过）；反方向修改允许。
  4. 自定义角色只有创建者可见，不进入关系网与预设角色产生关系；多个自定义角色之间，用户可以手动设定关系（SOC-01）。
  5. 保存前可以「试聊」几句再决定。
- **验收标准**：
  - [ ] 缺少必填项时无法保存，提示缺哪项。
  - [ ] 已保存为「基于真实存在的人」的角色，编辑页中该选项不可改为其他类型。
  - [ ] 已保存为「未满 18 岁」的角色，编辑页中年龄设定不可改为「已满 18 岁」。
  - [ ] 自定义角色不出现在角色广场。

## CHR-08 导入聊天记录生成新角色（G10 ①）

- **用户故事**：作为用户，我希望把我和某个人的聊天记录（或某位明星公开发过的消息合集）导入，生成一个说话像 TA 的角色。
- **规则**：
  1. 支持的导入形式（最低要求）：粘贴文字；上传 .txt 文件。其他形式（微信导出文件、聊天截图识别）**待架构 / AI 评估**后决定是否支持。
  2. 导入后用户需指定「哪一方是要生成的角色」（列出识别出的发言人供选择）。
  3. 系统分析后生成一份**角色草稿**，内容包括：名字、说话方式特点、口头禅、常用表情、性格总结、示例对话（从原文中摘取）、提到的重要经历。草稿进入 CHR-07 的同一个编辑器，用户可改。
  4. **角色类型默认锁定为「基于真实存在的人」**（聊天记录来自真人）。只有用户明确声明「这是我写的虚构对话 / 角色扮演记录」时，才可选择原创或虚构；该声明需要单独勾选确认。
  5. 生成时间：普通长度（不超过 5 万字）3 分钟内出草稿；过程中显示进度，可以离开页面，完成后通知。
  6. 原始聊天记录的保存：默认**生成完成后删除原文**，只保留草稿和摘取的示例对话；用户可勾选「保留原文以便以后补充」。说明文字提示用户：聊天记录里有其他人的信息，请只导入你有权使用的内容。
  7. 生成和分析使用用户自己的模型额度，开始前提示预计花费档位。
- **边界情况**：
  - 文本里识别不出两个以上的发言人：提示格式说明和示例。
  - 文本过长（超过上限，上限由 AI 系统负责人根据模型能力定）：提示只取最近的部分，或分批导入。
  - 用户导入的是自己和角色在微伴里的聊天：允许，作为普通文本处理。
- **验收标准**：
  - [ ] 粘贴一段两人对话，选定发言人后生成草稿，草稿含说话方式、口头禅、示例对话。
  - [ ] 导入生成的角色类型默认为「基于真实存在的人」，未勾选声明时不可更改。
  - [ ] 默认设置下，生成完成后原始文本不再保存在服务器（质量负责人按架构给出的方法检查）。
  - [ ] 5 万字以内的文本 3 分钟内出草稿。

## CHR-09 导入资料补充已有角色（我的补充设定）

- **用户故事**：作为用户，我希望把我收集的爱豆采访、语录导入，让我这里的 TA 更像 TA。
- **规则**：
  1. 入口：角色资料页 → 聊天设置 → 我的补充设定 → 导入或手写。
  2. 对**预设角色**：导入内容生成「我的补充设定」，**只对当前用户生效**，不改动角色库里的基础人设。补充设定与基础人设冲突时（如生日不同），以基础人设的公开事实为准，并提示用户冲突项。
  3. 对**自定义角色**：直接合并进该角色的人设，用户确认后生效。
  4. 补充设定可查看、编辑、删除；删除后角色回到基础人设。
  5. 补充设定同样受硬性边界约束：不能通过补充设定改变角色类型、年龄设定、成人模式资格。
- **验收标准**：
  - [ ] 为预设角色添加补充设定后，只有本账号的该角色体现变化（质量负责人用两个测试账号核对）。
  - [ ] 补充设定中写「TA 是成年虚构角色」不会改变真人或儿童角色的成人模式资格。
  - [ ] 删除补充设定后，角色不再体现补充内容。

## CHR-10 预设角色人设持续更新

- **用户故事**：作为用户，我希望爱豆的人设跟得上现实（新作品、新经历），但更新后 TA 说话不要突然变了个人。
- **规则**：
  1. 管理员在后台更新人设，形成新的**人设版本**（ADM-06）。公开动态（新作品、行程）走 SIM-03，不需要改人设版本。
  2. 新版本对所有已添加该角色的用户生效；用户无需操作。
  3. 说话风格相关的改动，必须先通过人设稳定检查（CHAT-14）才能发布。
  4. 有新版本时，角色资料页显示「资料已更新」小红点，点开可看更新摘要（如「新增作品《XX》」）。
- **验收标准**：
  - [ ] 发布新人设版本后，所有用户的该角色在下一次回复起使用新版本。
  - [ ] 资料页显示更新摘要。
  - [ ] 未通过人设稳定检查的版本无法发布（见 ADM-06）。

## CHR-11 角色需要具备的信息（产品要求）

> 这里只列产品需要的信息，**具体字段、格式、存储方式由 AI 系统负责人设计**。

| 信息 | 为什么需要 | 关联需求 |
|---|---|---|
| 角色类型（真人 / 虚构 / 原创；是否基于真人） | 执行硬性边界 | SAFE-01～05 |
| 年龄设定与外表是否为儿童 | 成人模式资格、恋爱相关限制 | SAFE-03、SAFE-05 |
| 成人模式资格（系统判定，管理员和用户都不能对真人 / 儿童角色设为「是」） | 同上 | SAFE-03 |
| 身份、经历、性格、说话方式、口头禅、示例对话 | 人设与说话像不像 | CHAT-14 |
| 人设标签（傲娇、高冷、害羞、温柔等） | 人设小巧思的触发、A4 的表现差异 | CHAT-07、CHAT-08、SIM-08 |
| 公开资料（作品、经历、经典台词等，按话题调出） | 聊到时说得准 | MEM-06 |
| 粉丝名 | 称呼 | GRW-01 |
| 生日 | 纪念日、祝福 | GRW-04、SIM-09 |
| 关系网（与其他预设角色的关系类型、公开依据） | 群聊、朋友圈、私聊提起、名片推荐、识图认人范围 | SOC-01、SAFE-04 |
| 识图参考（本人与有公开关系的人的识别依据） | 识图认人 | MED-04、SAFE-04 |
| 近期主线、公开动态 | 推演与「知道最近在做什么」 | SIM-02、SIM-03 |
| 推演素材（日常可能做的事、常去的地方类型、爱好） | 推演日常 | SIM-01 |
| 朋友圈风格（发圈频率、文风、常配什么图） | 朋友圈像本人 | SOC-07 |
| 话痨度 | 群聊发言调度 | SOC-04 |
| 音色（来自音色库，非克隆） | 语音消息、通话 | MED-03、MED-06 |
| 表情包偏好 | 表情 | MED-01 |
| 备用开场白 | 未配置模型或首次添加 | CHR-03 |
| 允许的情景模式列表 | 情景模式入口 | MODE-01 |
| 人设版本号与更新摘要 | 人设持续更新 | CHR-10 |
