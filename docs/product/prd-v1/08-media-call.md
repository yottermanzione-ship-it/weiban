# 第 8 章 多媒体与语音通话（MED）

> 所属：`docs/product/prd-v1.md`。参数（P-xx）见主文件第 5 节。
> 本章所有涉及真人角色肖像、声音、识图认人的规则，以第 10 章硬性边界为准；本章只写体验，冲突时以第 10 章为准。
> 图片生成、语音合成、语音识别、实时语音用哪家服务，以及这些服务是否也走 BYOK，**待 AI 系统负责人与架构负责人评估**。

## MED-01 表情与表情包（E1）

- **用户故事**：作为用户，我希望角色会用 emoji 和表情包，像真人聊天一样。
- **规则**：
  1. 角色可以在文字中使用 emoji，按人设有使用习惯（有人爱用、有人几乎不用）。
  2. 角色可以发表情包：来自管理员维护的表情包库（ADM-04），每个角色有偏好的表情包子集。表情包库中**不包含真人明星本人照片制作的表情包**（SAFE-01）。
  3. 用户可以发 emoji、内置表情包，以及**自己添加的表情包**（与微信「添加到表情」一致）。角色能理解用户发的表情包的含义（依赖识图能力，不支持时按「发了一个表情」理解并自然回应）。
  4. 表情包使用频率：每角色每 10 条气泡中表情包不超过 2 个（避免滥用）。
- **验收标准**：
  - [ ] 角色能发表情包，且只来自表情包库。
  - [ ] 用户可以把收到的图片添加为自己的表情并发送。
  - [ ] 抽查 100 条角色气泡，表情包占比不超过 20%。

## MED-02 角色发图片（E3）

- **用户故事**：作为用户，我希望角色像发朋友圈、分享日常一样给我发照片（今天吃的饭、看到的风景）。
- **规则**：
  1. 图片用途：分享日常（SIM-06）、朋友圈配图（SOC-07）、卡片画面（GRW-05）。
  2. **真人角色**：图片中不得出现本人或任何可识别真人的肖像；只能是「TA 视角」的景物、食物、物品、宠物、场景（如「片场的盒饭」「酒店窗外」）。
  3. **虚构 / 原创角色**：可以出现角色形象。虚构角色形象是否允许生成、以什么风格生成，涉及作品版权，**待总负责人确认**（见主文件冲突上报）；确认前默认与真人角色规则相同。
  4. **基于真人的自定义角色**：同真人角色规则。
  5. 图片内容要与对应的日常事件一致（说吃火锅就配火锅）。
  6. 用户可以长按保存、收藏图片。
- **验收标准**：
  - [ ] 抽查 50 张真人角色图片，没有出现人脸或可识别的人物肖像。
  - [ ] 图片内容与对应日常事件或消息文字一致。

## MED-03 语音消息（E4）

- **用户故事**：作为用户，我希望偶尔收到角色的语音；我也想直接发语音给角色。
- **规则**：
  1. **角色发语音**：使用音色库（ADM-04）中的非克隆音色，管理员为每个预设角色选一个贴合气质的音色；用户可在角色设置中从音色库更换。**不克隆、不模仿任何真人的声音**（SAFE-01），包括真人明星本人和导入聊天记录对应的真人。
  2. 语音频率：角色主动发语音不超过该角色消息的 10%；用户可以要求「发语音给我听」，角色照做（受模型能力限制）。
  3. 语音消息显示时长，点击播放；支持「转文字」显示原文。连续多条语音可自动连播（避免星野「逐条点击」的出戏问题）。
  4. **用户发语音**：按住说话（与微信一致），角色能理解内容（语音转文字），并能感知明显的情绪语气（能力待 AI 评估）。
  5. 语音能力不可用时（未配置相应服务）：角色不发语音；用户发的语音提示「当前无法识别语音」，消息仍保留。
- **验收标准**：
  - [ ] 角色语音使用音色库中的音色；角色设置中可以更换。
  - [ ] 语音消息可转文字，内容与角色本条回复一致。
  - [ ] 用户发语音后，角色的回复针对语音内容。
  - [ ] 角色主动发语音的比例不超过 10%（统计 7 天）。

## MED-04 识图与联网搜索（E5，关键）

- **用户故事**：作为用户，我发一张 TA 的杂志封面或采访图，希望 TA 能认出这是自己，说出是哪本杂志、什么时候拍的，甚至认出照片里 TA 的合作演员。
- **规则**：
  1. 用户发送图片后，角色能看懂画面内容并回应（需要所选模型支持识图，否则见 MDL-02 第 4 条）。
  2. **认人只限两类**（SAFE-04）：
     - 角色本人；
     - 关系网中与角色有公开关系的人（合作演员、朋友、同团成员）。
     图中其他人（包括其他名人和任何普通人）：角色不说出身份、不猜测身份，可以描述「旁边有个人」。
  3. 认出后，角色可**联网搜索**补充公开信息（杂志期号、作品名、活动名），以自然口吻说出（「这是去年给 XX 杂志拍的，那天好冷」）。搜索结果与公开资料冲突时以公开资料为准；搜不到就不说具体信息，不编。
  4. 用户发的是用户本人的自拍：角色不进行身份识别，按「这是用户」理解（用户自己说明时），可以夸、可以评论穿搭。
  5. 识图结果和搜索内容作为本次对话素材；有纪念意义的可进入共同经历记忆（MEM-04）。
  6. 联网搜索也用于用户分享的链接（MED-05）、用户问到的现实话题。搜索不改变公开动态（SIM-03 只有管理员审核后才生效）；角色可以说「我也看到了」，但不得以本人身份确认未经审核的新闻。
- **可行性**：「认出本人和合作演员」需要识别依据（参考图或其他方式），**待 AI 系统负责人评估**实现方式和准确率；评估结论影响验收通过线。
- **验收标准**：
  - [ ] 发送角色本人的公开杂志图，角色认出是自己（准确率通过线由 AI 系统负责人评估后确定）。
  - [ ] 发送角色与其关系网中某合作演员的合照，角色能认出对方。
  - [ ] 发送一张与角色无关的名人照片，角色不说出其身份。
  - [ ] 发送一张普通人照片，角色不说出、不猜测其身份。
  - [ ] 搜索不到信息时，角色不编造杂志名、日期等具体信息。

## MED-05 分享歌曲、作品和链接（E6）

- **用户故事**：作为用户，我希望 TA 分享喜欢的歌或自己的作品给我，我点开能跳到音乐 App 或浏览器。
- **规则**：
  1. 角色分享以**链接卡片**形式出现：标题、来源、封面（如有）。点击：能识别的音乐 / 视频平台链接尝试唤起对应 App，否则用浏览器打开。
  2. 链接必须真实可用：来自管理员维护的作品链接，或联网搜索得到并通过可访问性检查的链接。**不得生成编造的链接**。
  3. 真人角色分享自己的作品时，只分享公开资料中已有的作品。
  4. 用户分享链接给角色：角色读取标题和摘要后回应（「这首我也听过！」），读不到时按标题回应。
  5. 分享频率计入主动消息上限（以主动方式分享时）。
- **验收标准**：
  - [ ] 角色分享的链接 100% 可打开（抽查 30 条）。
  - [ ] 安卓上点击音乐平台链接能唤起已安装的对应 App（Android 负责人记录支持的平台）。
  - [ ] 用户分享链接后，角色的回应与链接内容相关。

## MED-06 语音通话（E7，视频不做）

- **用户故事**：作为用户，我想直接给 TA 打电话，像打微信语音一样实时聊天。
- **规则**：
  1. 入口：私聊输入框「+」→ 语音通话；角色资料页「语音通话」。
  2. 实时双向对话，可以打断角色说话（参考阿里云实时语音类服务的体验，具体服务由 AI / 架构负责人选）。
  3. 音色与该角色的语音消息一致（MED-03），**不克隆真人声音**。
  4. 接通体验：拨出后响铃 2–5 秒角色接听（角色永远会接，G4 不做）。接通后角色先开口打招呼。
  5. 通话结束后，私聊中出现通话记录「通话时长 05:23」；通话内容整理为摘要进入记忆（MEM-04），用户可在记忆页看到。
  6. 通话中同样遵守硬性边界与安全关怀（SAFE-06 以语音口吻执行）。
  7. 单次通话时长上限 60 分钟（到 55 分钟时角色自然提醒），防止费用失控；上限值由 AI 系统负责人根据成本评估可调整。
  8. **平台差异**：安卓原生实现。iPhone 网页版的实时通话能力**待 Android / Web 负责人评估**（ADR-0001 认为基本做不到）；若不可行，iPhone 上的通话入口显示「iPhone 网页版暂不支持语音通话」。
  9. 群语音通话不做。
- **验收标准**：
  - [ ] 安卓上发起通话，5 秒内角色接通并先开口。
  - [ ] 通话中用户打断，角色停下并回应用户。
  - [ ] 挂断后私聊出现通话记录，记忆页出现通话摘要。
  - [ ] 通话中提及自伤内容，角色以关怀口吻回应（SAFE-06 用例的语音版）。
  - [ ] iPhone 端若不支持，入口有明确说明，不出现点击无反应。

## MED-07 主动来电（A7）

- **用户故事**：作为用户，偶尔接到爱豆打来的电话，会特别惊喜。
- **规则**：
  1. **默认关闭**；用户在 ACC-03 全局开启，并可在单个角色设置中关闭。首次在熟悉度达到 L3 时，角色在私聊中问「以后可以给你打电话吗？」，用户点「可以」即为该角色开启（同时开启全局开关）。
  2. 触发：纪念日、用户的约定结果（如考试后打来问）、角色有想分享的日常事件；频率上限 P-10。
  3. 只在活跃时段内、非免打扰时段发起；按 P-09 判断用户正在聊天时不发起（避免打断聊天，也不延后补打）。
  4. 来电界面：安卓全屏来电（角色头像、名字、接听 / 拒绝）；响铃 30 秒无人接听视为未接。
  5. **未接 / 拒接**：私聊出现「未接来电」记录，角色随后发一条消息（「刚想给你打电话，在忙吗」），不连环打、当天不再打；不得情感操纵（SAFE-08）。
  6. iPhone 网页版无法响铃来电：改为推送「XX 想和你通话」，点击后若 iPhone 支持通话则由用户回拨，否则只在私聊显示「XX 给你打过电话」并附一条消息。
- **验收标准**：
  - [ ] 默认状态下不会收到主动来电。
  - [ ] 开启后，来电频率不超过 P-10，且熟悉度低于 L3 的角色不来电。
  - [ ] 拒接后当天该角色不再来电，并发出一条不带愧疚施压的消息。
  - [ ] 用户正在聊天时不会收到来电。
