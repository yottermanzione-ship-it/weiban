# 第 2 章 模型配置与用户自付费用（MDL）

> 所属：`docs/product/prd-v1.md`。全局决策见 `docs/decisions/ADR-0002-product-positioning-and-byok.md`（BYOK、用户自选模型）。
> 供应商列表、模型能力标签、价格档位的唯一定义处是 `docs/ai/model-catalog.md`；费用数字的唯一定义处是 `docs/ai/cost-estimate.md`；费用归属见 ADR-0008（已采纳）。本章只定用户体验。
> v1.1 变更：MDL-01 供应商列表来源；MDL-02 新增语音 / 图片服务配置（第 5 条）和成人模式模型要求；MDL-03 数据来源结论；MDL-04 重试策略来源；MDL-05 后台预算默认值、达到预算后的处理、费用归属改为引用结论。

## MDL-01 填写密钥

- **用户故事**：作为用户，我希望把自己在模型供应商那里申请的密钥填进来，让角色用我的额度聊天。
- **规则**：
  1. 入口：设置 → 模型与密钥；首次使用引导中也会出现（ACC-04）。
  2. 用户先选供应商（列表见 `docs/ai/model-catalog.md` 第 1 节：6 家国内供应商 + 「自定义兼容地址」），再粘贴密钥。每个供应商旁边有「去哪里申请」的说明链接。选「自定义兼容地址」时，用户还需填写地址和模型名，并自行勾选该模型具备的能力。
  3. 保存前自动做一次**连通测试**：成功显示「可用」和该密钥能用的模型列表；失败显示原因（密钥错误 / 余额不足 / 网络不通 / 供应商故障），并且不保存。
  4. 可以同时保存多个供应商的密钥。
  5. 密钥保存后**界面上只显示前 4 位和后 4 位**，任何页面、日志、导出都不出现完整密钥。用户可以删除或替换，不能查看完整原文。
- **边界情况**：
  - 用户粘贴时带了空格或换行：自动去除首尾空白后再测试。
  - 同一供应商重复添加：提示「已存在，是否替换」。
- **验收标准**：
  - [ ] 填入有效密钥，10 秒内显示「可用」和模型列表。
  - [ ] 填入错误密钥，显示具体失败原因且不保存。
  - [ ] 保存后任何页面都看不到完整密钥（只显示前 4 后 4 位）。
  - [ ] 删除密钥后，依赖它的模型选择显示为「不可用」，并提示重新选择。

## MDL-02 选择模型

- **用户故事**：作为用户，我希望自己决定角色用哪个模型，不同角色可以用不同模型。
- **规则**：
  1. 三类模型选择（术语见术语表）：
     - **聊天模型**（必选）：生成私聊、群聊回复。
     - **后台模型**（可选，不选则沿用聊天模型）：推演、朋友圈、记忆整理等。界面说明「建议选便宜的模型」。
     - **成人模式模型**（可选）：只在成人模式下使用，**只能从带「允许成人内容」标签的模型中选**，见 MODE-03。
  2. 全局设一套默认，**单个角色可以覆盖聊天模型**（角色资料页 → 聊天设置 → 使用的模型）。
  3. 模型列表每项显示：模型名、供应商、排行榜名次（如有）、价格档位（便宜 / 中等 / 较贵）、标签（如「中文好」「长记忆」「支持识图」「支持语音」「允许成人内容」）。标签含义与数据见 `docs/ai/model-catalog.md` 第 2 节。
  4. 某些功能需要模型具备特定能力（识图 E5 需要视觉能力；语音见 MED-03、MED-06）。当前所选模型不具备时，该功能入口给出提示「当前模型不支持识图，可在设置中更换」，而不是静默失败。
  5. **语音与图片服务**：语音合成、语音识别、图片生成同样走 BYOK，用户在「模型与密钥」中配置对应的服务（同一个供应商的一把密钥可能同时覆盖多项，见 `docs/ai/runtime-overview.md` 第 11 节）。未配置时：角色不发语音、用户的语音提示「当前无法识别语音」（MED-03 第 5 条）；角色不生成图片，只从管理员素材库取图或不发图（MED-02）；语音通话入口提示先配置语音服务（MED-06）。
  6. 语音服务设置处常驻显示通话费用说明（文案与规则只在 MED-06 第 10 条定义）。
- **验收标准**：
  - [ ] 只配置聊天模型时，推演、朋友圈等后台功能正常运行（使用聊天模型）。
  - [ ] 给角色 A 单独设置模型后，A 的回复使用该模型，其他角色不受影响（质量负责人通过用量记录核对）。
  - [ ] 所选模型不支持识图时发送图片，用户能看到明确提示。
  - [ ] 未配置语音服务时，角色不发语音，语音通话入口提示先配置语音服务。
  - [ ] 成人模式模型的可选列表中只有带「允许成人内容」标签的模型。

## MDL-03 模型排行榜

- **用户故事**：作为不懂技术的用户，我希望看到「哪个模型角色扮演效果好、贵不贵」，帮我选。
- **规则**：
  1. 入口：模型选择页顶部「看排行榜」。
  2. 榜单每行：名次、模型名、供应商、综合评分、价格档位、标签、「一句话点评」（如「人设稳，回复偏长」）。
  3. 支持按「中文角色扮演」「性价比」「允许成人内容」筛选。
  4. 页面底部注明数据来源和更新日期。数据来源（AI 负责人已定，`docs/ai/runtime-overview.md` 2.6 节）：**以微伴自测评测集的分数为主**，RP-Bench、BenchLM 等公开榜单作参考，每月复核。自测分出来之前，页面写明「参考外部榜单，微伴自测进行中」（`docs/ai/model-catalog.md` 第 0 节）。
  5. 从榜单可以一键「用这个模型」：如果已有对应供应商密钥，直接设为聊天模型；没有则跳到填写密钥。
- **验收标准**：
  - [ ] 榜单页显示数据来源和更新日期。
  - [ ] 点击「用这个模型」：有密钥时直接生效，没有密钥时跳转填写页且供应商已预选。

## MDL-04 密钥失效、额度用完、供应商故障

- **用户故事**：作为用户，当我的密钥出问题时，我希望知道发生了什么，而且我发的消息不会丢。
- **规则**：
  1. **用户消息永不因模型问题丢失**：用户发出的消息照常送达服务器并显示「已送达」，只是角色暂时不能回复。
  2. 出问题时，相关会话顶部显示**系统横条**（不是角色口吻，因为这是工具问题）：「模型密钥失效 / 额度用完 / 供应商暂时不可用，角色暂时无法回复」+「去处理」按钮。
  3. 同时最多推送一次「模型不可用」通知，同一问题 24 小时内不重复推送。
  4. 供应商临时故障：自动重试（次数与间隔见 `docs/architecture/message-reliability.md` 第 6 节，总时长不超过 P-01 上限），重试期间正在输入状态不显示，避免「一直在输入」的假象。
  5. 问题修复后（换了密钥或额度恢复）：角色对等待中的最后一批用户消息**补一次回复**（合并回复，不逐条回复），回复里可以自然带一句「刚才信号不好」之类的人设化解释，但不提「模型」「密钥」。
  6. 故障期间：主动消息、推演、朋友圈暂停；恢复后**不补发**故障期间错过的主动消息。
- **边界情况**：
  - 角色单独设置的模型失效，但全局模型正常：只有该角色显示横条，**不会自动切换**到其他模型（避免人设变化），横条中提供「临时改用默认模型」按钮。
- **验收标准**：
  - [ ] 用无效密钥时发送消息，消息显示已送达，会话顶部出现横条。
  - [ ] 修复密钥后，角色对等待中的消息补一次合并回复，回复中不出现「模型」「密钥」「API」字样。
  - [ ] 故障期间错过的主动消息在恢复后不补发。
  - [ ] 同一故障 24 小时内最多推送一次通知。

## MDL-05 用量查看与后台预算

- **用户故事**：作为自己付钱的用户，我希望知道钱花在哪，并能限制后台功能的花费。
- **规则**：
  1. 用量页：按天、按角色、按用途（聊天 / 推演 / 朋友圈 / 记忆整理 / 主动消息 / 识图 / 语音 / 图片 / 导入）显示调用次数和估算花费。估算方法见 `docs/ai/cost-estimate.md` 第 7 节，界面注明「估算值，以供应商账单为准」。
  2. **后台预算**：用户可设「后台功能每天最多花费」，按用户时区自然日计算。默认值、哪些用途计入、达到上限后哪些功能当天停止 / 延后 / 不停，唯一定义在 `docs/ai/cost-estimate.md` 第 6 节，本文不重复。产品要求：**聊天回复永远不受后台预算影响**；被延后的工作（如记忆整理）不能丢；安全相关的调用不能因预算停下。
  3. 推演可按角色关闭（SIM-13）。
  4. **费用归属（ADR-0008，已采纳）**：用户世界里的所有模型调用（含推演、朋友圈、记忆整理、安全检查、识图、语音、图片、导入）都记在用户自己的密钥上，用量页把后台费用单独列为一栏；管理员侧任务（角色蒸馏、评测、公开动态候选搜索、排行榜自测）记在平台密钥上，不出现在用户用量页。用户密钥出问题时，**不会偷偷改用平台密钥**。
- **验收标准**：
  - [ ] 用量页能按角色和用途筛选，后台费用单独一栏。
  - [ ] 新账号的后台预算显示为 `cost-estimate.md` 第 6 节规定的默认值。
  - [ ] 把后台预算设为很低的值，达到后当天按 `cost-estimate.md` 第 6 节列出的「停止」项逐项核对均已停止，聊天回复正常。
  - [ ] 达到后台预算当天被延后的工作，次日补做（用用量记录核对）。
  - [ ] 用户密钥失效期间，用量记录中没有任何一条记在平台密钥上的用户侧调用。

## MDL-06 换模型提醒（人设稳定）

- **用户故事**：作为用户，我希望换模型前知道角色说话可能会变。
- **规则**：更换某个角色正在使用的聊天模型时，弹出一次确认：「换模型后，TA 的说话风格可能有变化」。确认后生效。人设稳定的技术保障见 CHAT-14。
- **验收标准**：
  - [ ] 更换角色的聊天模型时出现确认提示；取消则不更换。
