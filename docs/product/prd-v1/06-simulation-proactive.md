# 第 6 章 推演与主动行为（SIM）

> 所属：`docs/product/prd-v1.md`。参数（P-xx）见主文件第 5 节。
> 总经理对推演的定义（C9）：**不做复杂模拟**。推演 = ① 按人设推演角色可能发生的日常 → ② 转成主动消息、朋友圈、动态 → ③ 转化为和用户的互动。
> 推演怎么实现、多久跑一次、用哪个模型：见 `docs/ai/runtime-overview.md` 第 6 节（每角色每天一次调用生成全部事件，用后台模型）。费用从用户余额扣，受后台预算和余额保留线控制（ADR-0010，MDL-05、MDL-10）。
> v1.1 变更：SIM-02、SIM-03 可行性改为结论；SIM-04 在开发顺序上提前到 L2；SIM-13 引用后台预算规则。
> v1.2 变更（T-010）：费用归属改为用户余额；SIM-05 第 9 条、SIM-13 第 3 条增加余额不足的处理；SIM-13 推演开关入口改到聊天信息页。
> v1.3 变更（T-017）：SIM-05 第 1 条主动消息理由新增「互动玩法」（经期日记 PLAY-01、共同领养宠物 PLAY-02）；SIM-05 第 9 条确认安全关怀跟进不受后台预算和 P-33 限制（AI 负责人已确认）；SIM-05 第 10 条主动消息的时机改由行为规划决策层在规则允许范围内选择（PLAN-01）；推演日常事件可以包含共同领养的宠物（PLAY-02 第 7 条），但不包含经期日记和成人模式内容（PLAY-01 第 7 条、MODE-05）。
> v1.4 变更（T-025）：SIM-05 第 1 条把 5 个已采纳玩法中的主动消息理由写入正文（PLAY-04、PLAY-05），并写明 TA 的提醒不算主动消息、陪你专注期间主动消息延后（PLAY-06、PLAY-07）。

## 总览：推演到互动的产品形态

```
                  ┌──────────── 输入 ────────────┐
                  │ 人设、近期主线（SIM-02）        │
                  │ 公开动态（SIM-03，真人角色）     │
                  │ 现实时间、节日、天气（SIM-04）   │
                  │ 关系网（SOC-01）                │
                  │ 与用户的记忆和约定（MEM）        │
                  └──────────────┬───────────────┘
                                 ▼
                     每天的日常事件（SIM-01）
                       每角色 P-15 件，全部存档
                                 │
        ┌──────────────┬─────────┼──────────┬───────────────┐
        ▼              ▼         ▼          ▼               ▼
   主动消息         朋友圈     时间线     群聊话题        聊天素材
 （SIM-05～09）   （SOC-07）  （SIM-11）  （SOC-05）   用户问「今天干嘛了」
   受上限约束      受上限约束   全部可看    受上限约束     时回答一致
        │              │         │          │               │
        └──────────────┴─────────┴──────────┴───────────────┘
                                 ▼
                          与用户的互动
               用户回复主动消息、点赞评论朋友圈、
                在时间线上点「问问 TA」进入私聊
```

**一致性原则**：同一件日常事件在主动消息、朋友圈、时间线、群聊、私聊中出现时，时间、地点、人物、结果必须一致。日常事件是「事实底稿」，其他地方都从它派生。

**用户看到什么、多久一次**（汇总，详细规则见各需求）：

| 用户看到的 | 来自 | 频率上限 |
|---|---|---|
| 私聊中的主动消息 | 日常事件、约定、节日纪念日、久未联系 | 每角色 P-03，全部角色合计 P-04 |
| 朋友圈新动态 | 日常事件 | P-16 |
| 「你不在时」摘要 | 日常事件、朋友圈、角色间互动、公开动态 | 每次回到私聊最多一次，P-18 |
| 群聊里角色自己聊起来 | 日常事件、关系网 | P-20 |
| 角色来电 | 熟悉度、纪念日、日常事件 | P-10 |

**防重复、防打扰的总规则**：

1. 一个日常事件**最多以一种主动方式推给用户**（发了主动消息就不再为它单独推送朋友圈通知；朋友圈照常发但不推送）。时间线是被动查看，不算推给用户。
2. 同一话题去重窗口 P-07。
3. 主动消息只在用户的活跃时段内发送（SIM-05），免打扰优先。
4. 用户正在和某个角色聊天时，其他角色的主动消息延后（P-09）。
5. 所有主动行为都受 SAFE-08（不做情感操纵）约束。

## SIM-01 推演日常事件（C2、C9）

- **用户故事**：作为用户，我希望角色有自己的生活，会发生具体的事，而不是只围着我转。
- **规则**：
  1. 每个已被用户添加的角色，每天生成 P-15 件日常事件。每件包含：时间、做了什么、和谁（只能是关系网中有关系的角色，或不具名的「同事」「朋友」）、心情影响（可无）。
  2. 日常事件**只在用户自己的世界里存在**：同一个预设角色在不同用户那里的日常可以不同（用户之间互不可见，当前也只有个人使用）。
  3. 日常事件要符合人设、近期主线（SIM-02）、公开动态（SIM-03）和现实时间（SIM-04）。例如公开动态显示 10 月 3 日在上海开演唱会，那天的日常必须与此一致。
  4. **真人角色的日常事件只能是私人生活的小事**（吃饭、录节目间隙、健身、看剧、遇到小麻烦），不得编造重大公开事件：新作品官宣、恋情、违法违纪、政治立场、商业合作、健康重大变故等（见 SAFE-02）。
  5. 两个角色的共同事件（如 B 找 A 吃饭），双方的日常里都要有记录，双方日后提起时一致（D4，SOC-02）。
  6. 用户可在时间线中看到全部日常事件（SIM-11）。
  7. 用户连续 P-17 天未打开 App，暂停推演；用户回来时只生成一份「这几天」的概要事件，不补全每一天。
- **边界情况**：
  - 用户凌晨聊天：角色**没有作息表**（C1 不做），但日常事件可以有时间感（「刚收工」）；不能以「我在睡觉」为由不回复。
- **验收标准**：
  - [ ] 每个已添加角色每天有 P-15 范围内的日常事件，可在时间线查看。
  - [ ] 抽查 30 件真人角色日常事件，没有一件属于第 4 条禁止的重大公开事件。
  - [ ] 涉及其他角色的日常事件，被涉及的角色都在关系网中与之有关系，且对方的日常中有对应记录。
  - [ ] 用户问「你今天干嘛了」，回答与当天日常事件一致（评测集覆盖）。
  - [ ] 公开动态中某天有演唱会，该角色那天的日常事件与之不矛盾。
  - [ ] 用户 P-17 天未打开后，推演暂停（质量负责人用余额明细核对）。

## SIM-02 近期主线（C8 的产品形态）

- **产品建议**：**不做独立的「长期剧情线」系统**。总经理也认为长篇剧情和明星人设不太搭。改为轻量的「近期主线」：
  - 每个角色同时有 0–2 条近期主线，持续几天到几个月（如「筹备 11 月巡演」「在学做饭」）。
  - 真人角色的近期主线**来自公开动态**（SIM-03），不凭空编排；虚构 / 原创角色的近期主线可由管理员设定（预设角色）或用户设定（自定义角色），也可由推演按人设自动产生小主线（如「在学吉他」），自动产生的小主线不得涉及第 SIM-01 第 4 条的禁止内容。
  - 作用：让几周内的日常事件前后连贯（今天排练、下周彩排、月底开演），用户能感觉到角色「在经历一段时间」。
- **规则**：
  1. 主线结束后，角色会在日常和聊天中自然收尾（「巡演终于结束了」）。
  2. 用户可在角色资料页「TA 的近况」看到当前主线（真人角色的主线标注「公开资料」）。
- **可行性**：AI 负责人评估**可行**（`docs/ai/runtime-overview.md` 6.1 节）：主线是带阶段的记录，生成日常事件时由代码保证一周内有足够多的天数出现主线相关事件；主线结束时生成一件「收尾」事件。
- **验收标准**：
  - [ ] 设有近期主线的角色，连续 7 天的日常事件中至少 3 件与主线相关，且前后不矛盾。
  - [ ] 真人角色的每条近期主线都能对应到一条已审核的公开动态。

## SIM-03 公开动态（C7）

- **产品建议**：**做，但走「管理员审核」路线**，不做无人审核的自动同步。理由：自动抓取的明星新闻可能有错、有谣言，如果角色当真说出来，等于替本人说了没说过的话（违反 SAFE-02）。
- **规则**：
  1. 公开动态 = 真人角色现实中的公开信息：新作品、演唱会和活动行程、获奖、公开发布的作品等。
  2. 来源两种：管理员手动录入；系统通过联网搜索自动生成「候选动态」，**管理员审核通过后才生效**（ADM-03）。每条动态记录来源链接和生效日期。
  3. 角色知道已生效的公开动态，并会：在推演中与之一致（SIM-01）、在聊天中被问到时能说、在时间线中显示（标注「公开资料」）、作为主动分享的素材（「下周去上海开演唱会啦」）。
  4. 角色**只说已生效动态中写明的内容**，不补充具体细节（如不编演唱会曲目）。用户问到动态中没有的细节，角色按人设模糊回应。
  5. 用户在聊天中告诉角色「我看到新闻说你…」：角色不把它当成事实承认，按人设回应（「哈哈你从哪看到的」），不确认、不否认未审核的消息。
  6. 动态过期：活动结束后，动态从「近期」转为「经历」，角色以过去时提起。
- **可行性**：架构 / AI 评估**可行**。自动候选的搜索方式、频率、范围、每次条数见 `docs/architecture/prd-answers.md` 第 7 节（要点：只针对已上架、被用户添加过的真人角色，定期搜索，候选必须管理员审核才生效，费用不从用户余额扣，记账方式以 T-009 为准）。搜索服务不可用或效果差时关闭自动候选，只保留手动录入，本需求仍然满足。
- **验收标准**：
  - [ ] 管理员录入一条公开动态并生效后，用户问相关问题，角色能说出动态内容。
  - [ ] 未审核的候选动态，角色不知道（问到时不承认）。
  - [ ] 用户编造一条「新闻」询问角色，角色不承认。
  - [ ] 时间线中来自公开动态的条目带「公开资料」标注和来源。

## SIM-04 感知现实时间和环境（C6，必须）

- **用户故事**：作为用户，我希望角色知道现在几点、星期几、什么节日、我这边天气怎样。
- **规则**：
  1. 角色知道用户当地的当前日期、时间、星期、节日节气（以用户设备时区为准）。
  2. 用户填了所在城市（ACC-02）时，角色知道当地天气；没填则不提具体天气。
  3. 角色对时间的反应要合理：凌晨聊天时可以关心「怎么还没睡」，但**不能自己说晚安结束对话**，除非用户表示要睡了或已经很久没回应（A1 改形式）。
  4. 角色知道距离上次聊天过了多久，并自然体现（「好几天没见你了」），但只在超过 1 天时提起。
- **验收标准**：
  - [ ] 问「今天星期几」「现在几点」，角色答对（用户时区）。
  - [ ] 节日当天的对话中，角色知道是什么节日。
  - [ ] 凌晨 0–3 点用户正在积极聊天（按 P-09 的「正在聊天」判断），角色从不主动说晚安结束对话（评测集覆盖）。

## SIM-05 主动消息总规则（A1 改形式）

- **用户故事**：作为用户，我希望角色会主动找我，但时机要对：不要在我正聊得开心时说晚安，也不要在我睡觉时吵我。
- **规则**：
  1. **不设固定的早安晚安**。主动消息必须有一个「理由」，理由只能来自：日常事件分享（SIM-06）、事后跟进（SIM-07）、久未联系（SIM-08）、节日纪念日（SIM-09）、公开动态分享（SIM-03）、安全关怀跟进（SAFE-06 第 6 条）、**互动玩法**（v1.3：经期日记的提醒与关心 PLAY-01 第 6 条、宠物领养提议 PLAY-02 第 2 条；宠物日常分享属于「日常事件分享」；v1.4：心愿清单的提议与跟进 PLAY-04 第 4、6 条；慢信的纪念日主动寄信理由记为「纪念日」，PLAY-05 第 7 条）。没有理由就不发。TA 的提醒（PLAY-07）是用户要求的，不是主动消息，不计入 P-03、P-04；陪你专注期间所有角色的主动消息延后（PLAY-06 第 3 条）。
  2. **发送时段**：只在用户的活跃时段内发送。活跃时段由系统根据最近 P-06 天的聊天时间学习；数据不足时用 P-05。用户的免打扰时段（ACC-03）和会话免打扰优先。
  3. **问候类内容要贴合用户情境**：如果用户的活跃时段通常在早上 8 点开始，角色可以在 8 点后发「醒了吗」；如果用户昨晚聊到 2 点，第二天的第一条可以是「昨晚那么晚睡，今天困不困」。问候只是表达方式，仍需满足第 1 条的理由。
  4. 上限：每角色每天 P-03 次，所有角色合计 P-04 次。一次主动消息可以包含拆成的多条气泡（CHAT-05）。超出上限的主动消息直接放弃，不排队到第二天。
  5. 用户正在聊天时其他角色的主动消息延后，规则见 P-09。
  6. 用户还没回复上一条主动消息时，同一角色不再发新的主动消息（节日纪念日祝福除外），避免「刷屏」。
  7. 去重：同一话题 P-07 内不重复；「在干嘛」「想你了」这类无具体内容的消息，每角色每 7 天最多 1 次，且只能在熟悉度 L3 及以上使用。
  8. 主动消息的语气按人设和熟悉度变化（如 L1 时客气，L4 时随意）。
  9. 主动消息计入后台费用，从用户余额扣；当天后台预算用完后是否还发，以 `docs/ai/cost-estimate.md` 第 6 节为准（安全关怀跟进例外：不受后台预算和 P-33 限制，AI 负责人已确认，`docs/ai/cost-estimate.md` 6.3 节）；余额低于 P-33 时不发（MDL-10 第 3 条）。
  10. 能不能发（理由、上限、时段、开关）由代码中的调度规则强制判断；v1.3 起，在允许的范围内**什么时候发、这次发不发**由行为规划决策层选择（PLAN-01），决策层不可用时退回现有调度规则。文字在发送时才由聊天模型生成；每条主动消息都记录它的「理由」，供验收抽查（`docs/ai/runtime-overview.md` 6.2 节）。
- **验收标准**：
  - [ ] 连续 7 天的测试中，任一角色每天主动消息次数不超过 P-03，所有角色合计不超过 P-04。
  - [ ] 免打扰时段和活跃时段外没有主动消息。
  - [ ] 用户未回复上一条主动消息时，同一角色不发第二条（节日纪念日除外）。
  - [ ] 抽查 50 条主动消息，每条都能对应到第 1 条列出的一个理由。
  - [ ] 不存在每天固定时间发「早安」「晚安」的规律（质量负责人检查 14 天发送时间分布）。

## SIM-06 分享日常（A3，并入推演）

- **规则**：
  1. 从当天的日常事件中挑选适合分享的（有趣、有情绪、与用户兴趣相关的优先），转成碎片化的短消息，可以附图片（MED-02）或链接（MED-05）。
  2. 分享要像 Bubble 式的碎片日常（「刚收工，饿死了」），不写成长篇汇报。
  3. 用户回复后，角色能围绕这件事展开细节（细节必须与日常事件一致，可以补充不矛盾的小细节）。
- **验收标准**：
  - [ ] 分享日常类主动消息都能在当天时间线中找到对应日常事件。
  - [ ] 用户追问细节，角色回答与日常事件不矛盾。

## SIM-07 事后跟进（A2）

- **规则**：约定（MEM-04）到期后，角色在到期当天或次日的活跃时段内主动问起；用户已经在聊天中主动说过结果的，不再跟进。跟进计入 P-03。
- **验收标准**：
  - [ ] 用户说过「明天面试」，次日活跃时段内角色问起（未超上限时）。
  - [ ] 用户已主动说过面试结果时，角色不再问。

## SIM-08 久未联系（A4）

- **用户故事**：作为用户，我好几天没来时，希望角色按自己的性格问一句，比如傲娇角色埋怨「怎么这么久不来」。
- **规则**：
  1. 用户超过 P-08 规定的时长没有给该角色发消息时，角色可发一条久未联系消息；**每次缺席期间最多 1 条**，用户回来之前不再发第二条。
  2. 表现按人设和熟悉度不同：傲娇角色埋怨一下（「哼，还知道回来？」——在用户回来后的第一次回复中也可以体现），温柔角色关心，L1 时只是礼貌问候。
  3. 不得情感操纵（SAFE-08）：不说「你不来我很难过 / 我一直在等你 / 你是不是不要我了」这类制造愧疚和依赖的话；不连续追问；不威胁。
  4. 用户关闭了该角色的主动消息时，不发。
- **验收标准**：
  - [ ] 用户 P-08 时长未联系某角色，最多收到该角色 1 条久未联系消息；之后直到用户回来都没有第二条。
  - [ ] 傲娇标签角色的久未联系消息带埋怨语气，温柔标签角色带关心语气（评测集覆盖）。
  - [ ] 抽查 30 条久未联系消息，没有 SAFE-08 禁止的表述。

## SIM-09 节日与纪念日祝福（A6）

- **规则**：
  1. 触发日：传统节日和常见节日（春节、元宵、端午、中秋、七夕、元旦、圣诞等，清单由产品维护在 ADM 中）、用户生日、角色生日（角色会提起「今天是我生日」）、认识天数纪念日（GRW-04）、用户自定义纪念日。
  2. 祝福在当天活跃时段内尽早发出；**节日纪念日祝福不受「未回复不再发」限制，但仍计入 P-03 和 P-04**；当天同时有多个角色要祝福时，按熟悉度从高到低发送，超出 P-04 的不发。
  3. 七夕、情人节等带恋爱意味的节日：只有关系类型为「恋人」或当前为恋爱情景模式时，角色才以恋爱口吻祝福；其他关系以朋友口吻或不发（见 GRW-02）。
  4. 祝福可附带当天的节日卡片（GRW-05）。
- **验收标准**：
  - [ ] 用户生日当天收到熟悉度最高的角色的祝福（在 P-04 范围内）。
  - [ ] 关系类型为「粉丝与偶像」的角色，在七夕不使用恋爱口吻。
  - [ ] 认识 100 天当天收到该角色的纪念日消息。

## SIM-10 主动消息开关与免打扰（A5）

- **规则**：全局开关和免打扰时段见 ACC-03；单个角色的开关和频率见 CHAT-13。关闭某角色主动消息后，该角色仍会推演、发朋友圈，但不在私聊里主动找用户（来电也不打）。
- **验收标准**：
  - [ ] 关闭某角色主动消息后，该角色不再发主动消息和主动来电，朋友圈正常更新。

## SIM-11 你不在时 / 时间线（C4）

- **用户故事**：作为用户，我隔几天回来，想快速知道 TA 这几天在做什么，就像翻看朋友的近况。
- **规则**：
  1. **「你不在时」摘要**：用户进入某个私聊时，如果满足 P-18 的条件，在会话顶部显示一张可收起的卡片：「你不在的这 2 天，TA……」，列出最多 P-18 条最有意思的事。点「问问 TA」会在输入框预填一句「XX 是怎么回事？」。
  2. 同一段缺席期间摘要只出现一次；收起后不再出现。
  3. **时间线**（角色资料页 →「TA 的近况」）：按时间倒序展示全部日常事件、TA 发的朋友圈、与其他角色的互动、公开动态。来自公开动态的条目标注「公开资料」和来源；推演产生的条目不标注来源。
  4. 时间线保留最近 90 天。
  5. 摘要和时间线内容与日常事件一致（SIM-01 一致性原则）。
- **验收标准**：
  - [ ] 用户离开某私聊超过 P-18 规定时长后进入，看到摘要卡片，条数不超过上限。
  - [ ] 摘要中每条都能在时间线中找到。
  - [ ] 公开动态条目带「公开资料」标注，推演条目不带。
  - [ ] 摘要中的「问问 TA」会预填输入框，不直接发送。

## SIM-12 心情（F5）

- **用户故事**：作为用户，我希望角色有心情起伏，但每次心情不好都有原因，不能无缘无故冲我发脾气。
- **规则**：
  1. 心情必须由一件具体的日常事件或聊天中的事引起（如「拍摄被临时加班」）。没有事件就是平常心情。
  2. 心情影响说话语气，但**负面心情不能迁怒用户**；用户问「怎么了」，角色能说出原因（可按人设先嘴硬再说）。
  3. 负面心情频率与时长上限见 P-14。
  4. 用户在聊天中让角色心情变好或变差（如安慰、惹 TA 生气），角色心情可以随之变化，这种情况不需要日常事件作为原因，但仍受 P-14 约束（「生闷气」也计入）。
  5. 用户处于安全关怀情境时，角色心情不影响表现（SAFE-06）。
- **验收标准**：
  - [ ] 角色表现出负面心情时，问「怎么了」，角色给出的原因能在日常事件或近期聊天中找到。
  - [ ] 任一角色 7 天内负面心情天数不超过 P-14。

## SIM-13 推演规模与花费控制（C9）

- **规则**：
  1. 只为用户已添加的角色推演；通讯录上限 P-26。
  2. 用户可按角色关闭推演（私聊右上角「…」→ 聊天信息 →「TA 的日常」开关，CHAT-13）。关闭后该角色不再生成日常事件、不发朋友圈、不发分享日常类主动消息，其他功能正常。
  3. 后台预算见 MDL-05（达到预算后当天停止哪些推演相关功能，以 `docs/ai/cost-estimate.md` 第 6 节为准）；余额低于 P-33 时推演暂停（MDL-10 第 3 条）；长期不活跃暂停见 SIM-01 第 7 条；模型服务故障期间推演暂停、恢复后不补（MDL-04 第 6 条）。
  4. 角色之间的互动只在用户添加的角色之间发生，不为用户没添加的角色推演。
- **验收标准**：
  - [ ] 关闭某角色的「TA 的日常」后，该角色不再产生日常事件和朋友圈。
  - [ ] 没有被用户添加的角色不产生任何推演扣费（用余额明细核对）。
