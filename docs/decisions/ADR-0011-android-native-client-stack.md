# ADR-0011 安卓原生客户端技术选型：Kotlin + Jetpack Compose

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-04 |
| 提出人 | 架构负责人（T-009） |
| 批准人 | 架构负责人 |
| 关联 | ADR-0010 第 1 条（总经理决定：安卓做原生客户端）；取代 ADR-0003 中「Android 壳：Capacitor 8」一项 |

## 背景

总经理体验过 WebView 套壳 App，认为网页体验差，决定安卓做**完整原生客户端**（ADR-0010）。iOS 仍走网页版 PWA，电脑浏览器也用网页版，所以网页端 `apps/web` 继续存在，安卓是**第二套界面**。

评估约束：

1. **原生体验是核心诉求**：界面要「像在用真的微信」（总经理第二轮意见第 5 条），长列表滑动、键盘弹出、输入法、通知、来电都要像系统原生 App。
2. 和网页端能复用多少（契约、业务逻辑、界面）。
3. AI 负责人写这门技术的熟练度（代码主要由 AI 写）。
4. 原生能力：推送、后台保活、全屏来电、语音通话、前台服务。
5. 国内厂商推送（小米、华为、荣耀、OPPO、vivo 等）的接入难度。
6. 对零基础总经理：调试、打包、安装是否简单。

## 方案对比

### 先说三个方案分别是什么

- **Kotlin + Jetpack Compose**：谷歌官方的安卓开发语言和官方界面框架，微信这类 App 的「正统」做法。界面直接由系统原生组件画出。
- **React Native**：用 TypeScript / React 写，运行时把界面翻译成安卓原生组件。2026 年起只剩「新架构」（不再经过旧的 JSON 桥），Expo 是它的主流工具链。
- **Flutter**：谷歌的另一个框架，用 Dart 语言写，**界面不用系统组件，而是自己画**（像游戏引擎一样逐帧绘制），所以在各平台长得一样。

### 逐项对比

| 维度 | A. Kotlin + Jetpack Compose（选） | B. React Native（+ Expo） | C. Flutter |
|---|---|---|---|
| **原生体验**（权重最高） | **最好**：就是原生 App；滑动、输入法、键盘动画、深色模式、系统字体缩放与系统行为完全一致 | 好：界面是真的原生组件；但手势、动画、键盘联动跨 JS 与原生两边，复杂交互需要额外调优 | 较好：自己绘制界面，流畅；但输入框、中文输入法、文本选择、无障碍等是「模仿」系统行为，细节与原生有差别，最容易被感觉出「不是原生」 |
| **与网页端复用** | 契约复用：由 Zod 导出 JSON Schema 再生成 Kotlin 数据类；**业务逻辑和界面都不复用**（同步引擎、发件队列要用 Kotlin 再写一遍） | **最多**：契约（Zod 直接用）、同步引擎、发件队列、状态管理可写成共享 TypeScript 包；界面不复用（DOM 与原生组件不同） | 契约同 A 需生成 Dart 类；逻辑和界面都不复用 |
| **AI 写代码熟练度** | 高：Kotlin / Compose 是安卓官方路线，资料最多 | **最高**：TypeScript / React 是 AI 最熟的组合 | 中：Dart 资料少于前两者 |
| **推送、保活、前台服务** | 直接调用，无中间层 | 要写或引入原生模块（Kotlin），出问题要在 JS 与原生两边排查 | 同 B，通过平台通道调用原生代码 |
| **全屏来电、语音通话** | 直接使用系统 API（通话样式通知、全屏意图、前台服务、音频焦点、WebRTC 安卓库） | 有社区库，但来电和通话属于「原生重区」，最终仍以 Kotlin 原生模块为主 | 同 B |
| **国内厂商推送** | 各厂商 SDK 本身就是安卓库，按官方文档接入；聚合推送（极光、个推）也提供原生 SDK | 极光有官方 React Native 插件，其他厂商需要自己包一层 | 有社区插件，质量参差 |
| **调试与打包（对总经理）** | 装 Android Studio，一个「运行」按钮装到手机；打包用 Gradle，CI 自动出 APK。工具只有一套 | 需要 Node + Metro（JS 打包服务）+ Gradle 两套工具；云打包服务 EAS 在境外，国内网络不稳；出问题时报错可能来自任意一层 | 需要 Flutter SDK + Android Studio；`flutter run` 简单，但遇到原生问题仍要进安卓工程 |
| **语言种类** | 新增 Kotlin（只在 `apps/android/`） | 不新增（TypeScript），少量 Kotlin 原生模块 | 新增 Dart，另加少量 Kotlin |
| **长期维护** | 谷歌官方主推，稳定；2026 年 8 月 Compose 1.12 稳定版 | 2025-10 起只有新架构，生态仍在调整期（部分老库不兼容新架构） | 稳定 |

### 关于「复用」这一项为什么没有赢

React Native 的最大好处是**同步引擎（发件队列、缺口补拉）只写一份**。这对「消息不丢不重」有实际价值。但：

1. 总经理已经因为「为了复用而牺牲体验」否定过 WebView 方案；再选一个「为复用而多一层」的方案，与这次决定的出发点相反。
2. 同步引擎的规则已经在 `message-reliability.md` 写成了**协议**（序号、幂等、补拉），不是网页私有的实现。两端按同一份协议各写一遍，再用**同一套协议测试用例**验证（见结论第 4 条），可以把「两份实现不一致」的风险控制住。
3. 推送、保活、来电、通话这些安卓上最难、最容易出问题的部分，三个方案最后都落在 Kotlin 原生代码上。选 Compose，这部分没有中间层，Android 负责人排查问题最直接。

## 结论

**选 A：Kotlin + Jetpack Compose。** 一句话理由：**总经理要的是原生体验，Compose 就是安卓原生本身；最难的推送、保活、来电、通话本来就要写 Kotlin，选它没有中间层。**

具体约定：

1. **技术组合**（具体小版本由 Android 负责人在骨架任务中锁定）：
   - 语言 Kotlin 2.x；界面 Jetpack Compose（Material 3 只用作基础组件，外观按设计令牌定制成微伴风格）；
   - 本地数据库 Room（SQLite），实现「本地优先」：所有服务器数据先写本地再显示，断网能看历史；
   - 网络 OkHttp（HTTP + WebSocket），JSON 用 kotlinx.serialization；
   - 后台发送与重试 WorkManager（App 被杀后待发消息仍会发出）；
   - 会话令牌存加密存储（Android Keystore 保护），不写日志；
   - minSdk 26（Android 8.0，系统通知渠道从这一版开始），targetSdk 跟随当年谷歌要求（2026 年为 36）。
2. **契约**：仍以 `packages/contracts`（Zod）为唯一源头。构建时导出 JSON Schema，再由脚本生成 Kotlin 数据类放在 `apps/android` 的独立目录；**生成代码不手改**，CI 检查「重新生成后无差异」。生成工具由 Android 负责人在骨架任务中选定并记录。
3. **协议与网页端完全相同**：同一套 HTTP 接口、WebSocket 帧、`seq` / `clientMsgId` / `updateSeq` 规则。服务器不区分客户端是网页还是安卓（只在设备信息里记录平台）。
4. **协议一致性测试**：契约包新增 `test-vectors/`（JSON 格式的场景用例：断网连发、重复 ack、缺口补拉、游标过期、未知消息类型降级等），网页端和安卓端的同步引擎都必须跑通同一套用例。由架构负责人定义格式，两端负责人各自接入（dev-plan 任务）。
5. **原生桥 `bridge.ts` 删除**：没有「网页装在壳里」这件事了，网页和安卓之间不再有桥。推送凭证登记、通知载荷照常走 `http/push.ts`。
6. **iOS 不变**：仍是网页版 PWA（ADR-0001、ADR-0010）。
7. **代码位置**：全部在 `apps/android/`（标准 Android Studio / Gradle 工程），结构见 `docs/architecture/repo-structure.md` 第 5 节。不使用 Kotlin Multiplatform（网页端是 TypeScript，共享 Kotlin 代码没有收益）。

## 代价

- **「全栈一种语言」被打破**：安卓端是 Kotlin。控制办法：Kotlin 只出现在 `apps/android/`；接口一律从契约生成，不手写。
- **界面和客户端逻辑写两遍**：网页、安卓各一套，前端工作量约翻倍（ADR-0010 已接受）。dev-plan 中网页与安卓任务并行排期。
- **同步引擎两份实现**：靠协议文档 + 共享测试用例 + 契约测试保证一致；任何一端发现协议歧义，先改协议文档和用例，再改两端。
- **设计令牌要在 Compose 中再落地一次**：设计令牌源头仍是 `docs/design/tokens.json`，安卓构建时用脚本把它转成 Kotlin 常量，不手抄。
- **总经理需要安装 Android Studio**（较大，约数 GB）：在安卓骨架任务开始时由运维 / Android 负责人写安装说明。
- 需要重新评估的情况：安卓与网页的客户端逻辑差异导致反复出现同步问题；或将来要做 iOS 原生（届时再评估 Kotlin Multiplatform 共享数据层，或改用 React Native 统一两端）。
