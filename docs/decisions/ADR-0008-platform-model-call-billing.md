## 背景

ADR-0002 规定模型费用由用户自带密钥（BYOK）支付，总经理只承担开发和服务器费用；但「平台自己发起的模型调用」（推演、朋友圈、记忆整理、导入分析等）记在谁身上，留给 AI 与架构负责人设计。约束：

1. 用户看不见的花费不能失控（MDL-05 要求后台预算）。
2. 角色说话不能因为换了付费方而换模型（MDL-04「不自动切换」、CHAT-14「不变脸」）。
3. 当前唯一用户就是总经理，但要「按成熟产品设计」，账要算得清。
4. 有些调用不属于任何一个普通用户（角色蒸馏、人设稳定检查、公开动态候选搜索、排行榜自测）。

估算（`cost-estimate.md`）：典型用户（10 个角色）后台全部费用便宜模型约 0.55 元 / 天、中档模型约 2.3 元 / 天；聊天本身约 0.9–4 元 / 天。

## 方案对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 用户世界里的一切调用都记用户密钥；管理员侧任务记平台密钥 | 与 ADR-0002 一致；只有一种主计费路径，实现最简单；用户能在用量页看到并用预算控制；后台用的是用户选的模型，人设一致 | 后台费用由用户承担（用量页必须单独列出，MDL-05-4）；用户没配密钥时后台功能也不跑（但此时聊天也不能用，影响很小） |
| B. 后台调用全部由平台密钥承担 | 用户只为聊天付费，体验「更省心」 | 违背 ADR-0002「总经理不承担模型费」；平台费用随用户数线性增长、难以控制；平台模型与用户聊天模型不同，推演文风和聊天人设可能不一致 |
| C. 混合：推演、朋友圈记平台；记忆整理、导入记用户 | 平台承担「角色有生活」的成本 | 两套计费路径、两套预算，复杂；同样违背 ADR-0002；用户难以理解为什么有的算自己有的不算 |
| D. 安全检查（guard）单独记平台 | 安全检查不受用户余额影响 | 规则预筛已让 guard 调用很少；用户余额耗尽时聊天本身也停了，guard 记平台意义不大，却多一条计费路径 |

## 结论

**选 A。** 用户世界里的所有模型调用（聊天、主动消息、推演、朋友圈、记忆整理、安全检查、识图、语音、图片生成、导入分析、聊天中的联网搜索）都记在**用户自己的密钥**上；管理员侧任务（蒸馏、评测、公开动态候选搜索、排行榜自测）记**平台密钥**（即管理员在后台配置的密钥）。

配套规则：

1. 用量页按用途单独列出后台费用（MDL-05-4），标注「估算值，以供应商账单为准」。
2. **默认后台预算每天 3 元**，用户可改；达到后停止推演、朋友圈、群聊自发、主动消息，记忆整理延后到次日，安全检查不停（`cost-estimate.md` 第 6 节）。
3. 不调用模型就能完成的部分一律用代码完成：人设小巧思、群聊发言调度、主动消息调度、「你不在时」摘要、时间线展示。
4. 向量检索用服务器本地小模型，不产生模型调用费（服务器费用由总经理承担，符合 ADR-0002）。
5. 遵守架构系统约束：一次调用一个计费归属、禁止用户密钥失败时静默改用平台密钥、预算在网关执行（`prd-answers.md` 4.1）。

理由一句话：**与 ADR-0002 一致、实现最简单、用户能看见也能控制，且后台与聊天用同一套用户选择的模型，人设不分裂。**

## 代价

- 后台功能的费用落在用户身上；若用户选了贵的后台模型，费用约为便宜模型的 4 倍。应对：后台模型选择页提示「建议选便宜的模型」，默认预算兜底。
- 用户密钥失效期间，推演、朋友圈、记忆整理全部暂停（MDL-04-6 已接受「故障期间暂停、恢复后不补发」）；记忆整理恢复后补做。
- 平台密钥仍有少量费用（管理员侧任务，每月约十几元量级），由总经理承担。

需要重新评估的情况：微伴开放给其他用户使用（届时可能需要平台承担部分体验性成本以降低门槛）；或出现按次计费的平台级能力（如付费搜索 API 费用显著增加）。
