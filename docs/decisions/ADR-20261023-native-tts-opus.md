# ADR：原生TTS使用系统编码器生成真正的Ogg/Opus

- 日期：2026-10-23。
- 状态：本批开发决定；实现、实测和发布证据另记，不由本文推导验收通过。
- 范围：已授权的语音协议适配；不迁密钥、不做克隆、不改生态/模型选择/价目，不新增HTTP契约，不构建APK。

## 背景

应用既有语音消息调用要求ogg_opus，但MiMo/百炼原生路径目前只提供WAV及校验后的24kHz mono PCM16，明确拒绝OGG，不能把WAV改MIME冒充。[现有媒体契约](../../packages/contracts/src/ports/model-gateway.ts#L285-L291)已经包含ogg_opus，缺的是实现，不是新增客户端格式。

公开第一方示例支持WAV工作流（[MiMo](https://mimo.mi.com/models/en-US/mimo-v2.5-tts)、[百炼](https://www.alibabacloud.com/help/en/model-studio/qwen-audio-tts-http-api)）；没有据此推断它们不支持任何其他格式。完整文档抓取被工具DNS安全校验拒绝，本批不绕过，也不根据搜索摘要猜一个原生OGG字段；沿用已实现的WAV→PCM路径，在本地做明确编码。

## 方案对比

| 方案 | 优点 | 代价/问题 |
|---|---|---|
| 改MIME或只手写Ogg外壳 | 看似简单 | 没有Opus编码，不能播放；拒绝 |
| 新增JS/WASM Opus依赖并自封装 | 镜像可能较小 | 需自己正确处理编码器延迟、Ogg CRC/粒度/EOS，还增加依赖审计；本批不选 |
| Debian系统FFmpeg/libopus | 成熟编码和封装，能用ffprobe及解码验证 | Linux运行镜像增加依赖和少量子进程开销；须限流、限时、限字节，不能接受任意URL/文件参数 |

## 决定

选择系统FFmpeg/libopus，只处理合成接口已经解析出的24kHz/单声道/16位PCM，不把供应商WAV、用户文件、网页或URL交给子进程解析。

- 固定`/usr/bin/ffmpeg`及固定参数；无shell，不从用户或模型读取命令、路径、选项。管道输入/输出，不落地原始音频。
- 只允许pipe协议，移除元数据，以libopus编码并封装为Ogg；不自写容器、不静默重采样其他输入格式。
- 在向供应商发请求前先取得可用编码租约；无二进制或两份租约均在用时本地拒绝、标zeroCost，不先合成再发现根本不能编码。
- 最多2份租约，释放幂等；每份编码限输入12MB、输出10MB、stderr计数64KiB和15秒，异常终止子进程，不记录stderr正文。
- 供应商已经成功后编码失败，只返回明确失败，不谎称免费、不自动重试、不换用户模型；供应商失败计费对账仍单独保留缺口。
- 对外时长使用PCM样本数计算，不拿字符数估时；编码器负责Opus预跳过、Ogg粒度和结束页。成功路径至少检查OggS/OpusHead；真正有效性另用独立ffprobe及解码检查，不把魔数检查当完整解码。
- 只接现有原生synthesize的ogg_opus请求，WAV/PCM和通话流式路径保持原状。已有音色/用户模型路由不在此批擅改。

## 部署与验证边界

生产Linux镜像安装Debian ffmpeg包，继续非root、只读根目录及既有资源约束。Windows本机没有固定Linux二进制时不伪造支持；离线单测用模拟进程，实际编解码在同一候选Linux镜像内、禁网、合成音频下验证一次。

新增系统包会增加镜像体积；构建前保留磁盘闸门，不为腾空间擅自删除备份/回退镜像。源码按本地优先闸门、完整线上SHA与Git对象校验，备份后才发布；不为了编码改客户端契约或语音售价。

真实供应商音色、用户登录后消息发送/播放、实际usage和账单、真正低延迟流式与打断、实时/Omni仍不由本批合成音频测试代替。
