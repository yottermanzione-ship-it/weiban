## 背景

CHAT-12 要会话内搜索和全局搜索（D-L6-03「中文检索方案评估」，技术债 TD-010 相关）。个人测试规模，单用户消息量预计在数万条以内。

## 方案对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. PostgreSQL `pg_trgm` 三元组索引 + `ILIKE` | 中文按字切分可用，不需要分词器；无新组件 | 大数据量时索引变大、慢 |
| B. 中文分词插件（zhparser 等） | 相关性更好 | 要定制数据库镜像，部署复杂 |
| C. 独立搜索引擎（Meilisearch / Elasticsearch） | 快、功能全 | 多一个服务、数据双写 |

## 结论

选 A：chat 在 `messages` 的可搜索文字（文字、链接标题、信件、每日一问、角色语音原文）上建 `pg_trgm` GIN 索引；接口见 `http/chat-groups.ts` 的 `ChatSearchEndpoints`。已撤回、本人删除、已清空的消息不返回。广场搜索（plaza）同样用 `pg_trgm`。

## 代价

- 单用户消息超过约 50 万条或搜索明显变慢时，再评估 B / C（登记在技术债）。
