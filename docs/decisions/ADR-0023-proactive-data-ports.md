# ADR-0023 主动消息数据端口与事务配额

日期：2026-10-09；状态：开发接管决定，待独立审查。

T-052 的 Claude 未提交实现把计数查询和写入分离，不能阻止并发调度突破 P03/P04；日报写入也没有幂等键。按总经理的开发接管授权，先登记契约变更申请并在本任务实现。

- 新增 proactive 模块到模块名和删除清单；迁移使用 0021，避开 growth 0018、simulation 0019、health 0020。
- 日报写入必须携带来源事件 UUID；保存为 proactive 的发布记录，来源仍由 ai-runtime 或公开动态拥有。T-053 必须用来源 UUID 通过端口发布，不创建第二次推演。T-051 暂存事件不会自动出现在本模块，接线前不能宣称完整时间线已交付。
- `recordSent` 必须接收平台 Tx，与 ChatWritePort 消息写入共用事务；先登记账本获取用户级锁，再写消息，检查 P03=3、P04=8、待回复和幂等。失败抛错，事务回滚消息与账本。`canSendProactive` 只是预检，不能代替最终写入闸门。
- 账本与待回复状态采用相同用户级锁，删除账号、联系人清理也使用此锁；调用方发消息前仍需校验关系 epoch，避免恢复关系后的迟到消息。
- 日报仅保存公开时间线的结构化字段，不接受任意 raw 原始模型输出；用户读接口检查有效联系人，不能读其他账户数据。
- 节日端口新增按用户 IANA 时区推导今天的方法；固定公历年周期不冒充农历。农历节日由管理员维护当年一次性日期，暂不实现农历转换。

备选方案：仅查询计数成本较低，但存在竞态；另建发送预留表可覆盖生成阶段，不过需超时释放和消息原子确认。本任务采用发送事务闸门，生成阶段预算及调度策略由 T-053 实现。

代价：T-053 必须把 Tx 传给端口；模块发布记录与推演暂存的接线及清理应分别验证。管理员批量 HTTP 写入用于纠错和测试，服务器内部消费方使用端口。
