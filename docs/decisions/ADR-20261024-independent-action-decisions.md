# ADR：独立动作评估与批量决策

- 日期：2026-10-24
- 授权：总经理确认“用户开启动作分别判断；规则预筛、批量判断、冲突协调”的建议。
- 状态：接受；先实施聊天回复的语音/表情，生态主循环另批接线。

## 背景与取舍

每轮只能选择一个生态动作会错误排斥互不冲突的行为；反过来，每个动作单独付费问一次模型会增加费用和时延。允许动作、能力可用、此刻适宜应分离，用户开启功能并不等于每轮必须执行。

采用：硬规则预筛 → 有具体对象的独立问题 → 同情境同配置批量决策 → 排除冲突/重复 → 受控执行。无需文字的工具不增加写手调用；用户明确要求语音，不额外询问是否应当服从。语音替代同段文字，表情允许与语音共存。普通聊天主动图片已取消，不恢复。

## 本批范围与既有文档差异

- `PlannerService.decideBatch` 是内部方法，复用现有 decide 网关与 planner_config，无公共契约或数据库迁移。
- 同一批次问题使用一个路由；Jev一次原生decide，rules_model一次文本请求，rules不请求供应商，不暗换模型。
- 每个问题独立通过或拒绝，故障/低把握/余额闸/超时不以概率批准额外动作。这覆盖旧 behavior-planning.md 中“所有故障可回积极规则动作”的规定，仅针对新批量入口；旧单题调用保持原行为。
- 成功批次的各决策行共享 usageRecordId；整个调用金额仅记在一行，避免决策统计重复计费，实际扣费仍由网关负责。
- 稳定批次ID与问题ID关联重放与记录；不盲重试。超时后供应商可能仍结算，不能宣称超时免费。
- 普通回复不向Jev发送当前用户/角色原文，只给白名单事实和本地识别的枚举含义；新增白名单 replyLength、replyTone、stickerMeaning 均为长度/固定枚举，不携带自由文本。adult/health标记的回复不进入这条自主附加动作链；其他单题调用方不在本批修改。
- 库内表情先按描述中的已知含义匹配，再问是否发送；系列名+编号不是可信含义，不随机凑图。这不是视觉识别或已完成全库标注，无可解释含义的素材暂不进入自动候选。
- 保留现有语音10%、表情每10气泡最多2个、不方便静默及上游网关计费约束，不新增每日次数上限。

## 代价及未覆盖项

本地语义词表只能覆盖部分表达，不冒充完整语义理解；全库描述补齐需另做。语音能力预筛只能使用现有服务/音色端口，实际模型选择、兼容性、余额仍由执行网关最终校验，已有音色可能覆盖用户模型的问题尚需单独修复。生态仍使用旧单动作JSON，不因本批代码而启用；正式切Jev需既有评测/路由计费验收，不能把离线用例当作供应商质量或账单验收。
