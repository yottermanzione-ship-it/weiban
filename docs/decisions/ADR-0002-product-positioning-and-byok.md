## 背景

ADR-0001 把项目定为「个人使用」，没有明确目标用户和费用模式。T-002 调研后，总经理明确了产品定位、成本模式和开发方式。

## 结论

1. **定位**：实际使用范围仍是个人测试，但**按成熟产品的标准设计**。目标用户是追星女孩，核心体验是「像加上了自己爱豆的微信」。项目目的是让总经理深度学习。
2. **合规功能**：因为是个人测试，法规对「向公众提供」服务的要求（AI 身份提示、使用时长提醒、备案等）不实现。ADR-0001 第 4 条继续有效。
3. **模型费用由用户自付**（BYOK，Bring Your Own Key，即用户自带 API 密钥）：
   - 总经理只承担软件开发和服务器费用。
   - AI 模型的 API 费用由用户填入自己的密钥支付，平台只做中转：负责转发请求、组装上下文、管理角色和记忆。
4. **模型由用户自选**：提供角色扮演模型排行榜等信息，帮助用户挑选。
   - ADR-0001 第 3 条「国内模型为主，多供应商路由」修订为「**支持多家供应商，由用户选择**」。默认推荐和排行榜覆盖哪些模型，由 AI 系统负责人评估。
   - 如果平台自身也要调用模型（离线推演、生成朋友圈），由 AI 系统负责人与架构负责人设计方案：费用是记到用户自己的密钥上，还是由平台承担，需要在方案中写明。
5. **一次性完整开发**：不按「一期、二期」分批上线，PRD 覆盖完整产品范围。
   - 开发仍按依赖顺序推进，例如聊天链路在前，群聊、朋友圈在后。这是内部的开发顺序，不是分批上线。

## 代价

- **范围大**：完整产品一次做完周期长，中途很久看不到「完整可用」的版本。应对办法是开发按依赖顺序推进，每完成一块就能在本机试用。
- **密钥安全**：BYOK 意味着服务器上保存用户的 API 密钥，必须加密存储，并防止在日志中泄露。
- **体验依赖用户选的模型**：模型选得差，人设和记忆效果也会差，需要排行榜和推荐引导用户。
- **定位与实际使用不一致**：若将来真要开放给他人使用，第 2 条需重新评估（参考 `docs/product/research/competitive-analysis.md` 第 8 节的法规梳理）。
