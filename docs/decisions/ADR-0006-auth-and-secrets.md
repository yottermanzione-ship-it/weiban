# ADR-0006 账号登录方式与 BYOK 密钥安全

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-04 |
| 提出人 | 架构负责人（T-004） |
| 批准人 | 架构负责人 |

## 背景

- PRD ACC-01：登录不依赖手机号实名、不依赖第三方社交账号；多设备同时登录；退出后不再推送。
- ADR-0002：BYOK，服务器要保存用户的模型 API 密钥，必须加密存储、日志不泄露；ACC-06 要求注销时彻底删除。
- 服务器在公网上，单机部署；实际只有总经理一个用户。
- 详细规则见 `docs/architecture/security-and-privacy.md`。

## 方案对比

### 登录方式

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 用户名 + 密码 + 邀请码注册**（选） | 不依赖任何外部服务；实现最简单、AI 最熟；邀请码挡住陌生人 | 忘记密码只能管理员重置 |
| B. 邮箱 + 密码（邮件验证） | 可自助找回密码 | 要配置发信服务；邮件常进垃圾箱 |
| C. 通行密钥 Passkey | 无密码、最安全 | 安卓 WebView 需要额外原生适配；iPhone PWA 与安卓壳两套行为，调试成本高 |
| D. 手机号 / 微信 QQ 登录 | 用户熟悉 | PRD 明确排除 |

### 会话令牌

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 随机不透明令牌，服务器存哈希**（选） | 可随时作废（踢设备、退出即失效）；简单 | 每次请求查一次库（单用户无压力） |
| B. JWT（自带签名的令牌） | 不查库 | 作废困难，要额外黑名单；对单用户没有收益 |

### 密钥存储

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 明文存数据库 | 简单 | 不可接受 |
| B. 用一把主密钥直接加密所有 API 密钥 | 简单 | 换主密钥要重新加密全部数据 |
| **C. 信封加密：主密钥（服务器机密文件）→ 每用户数据密钥 → API 密钥 / 导入原文**（选） | 数据库或备份单独泄露也安全；换主密钥只需重新包装数据密钥；导入原文复用同一机制 | 多一层密钥管理；主密钥必须单独离线备份，丢了全部密钥不可恢复（用户需重新填写） |
| D. 云厂商密钥管理服务（KMS） | 主密钥不落盘 | 绑定云厂商、增加费用和网络依赖，单机个人项目不值得 |

## 结论

1. 用户名 + 密码（argon2id）+ 邀请码注册；不透明会话令牌，库内只存 SHA-256 哈希，90 天滑动续期；令牌经 `Authorization` 请求头或 WebSocket 首帧传递。
2. 信封加密（AES-256-GCM，AAD 绑定记录）；主密钥只在服务器机密文件中，由运维单独离线备份；解密只在模型网关调用瞬间进行。
3. 日志三道防线：源头不写、日志器字段与正则打码、模型错误消毒。
4. 注销：立即删密钥并下线全部设备，其余由各模块「删除清单」物理删除并回报；用金丝雀值验证。

## 代价

- 忘记密码要管理员在服务器上执行脚本重置（个人测试可接受，登记技术债）。
- 主密钥丢失 = 所有已保存密钥作废，用户需重新填写（聊天数据不受影响）。运维必须把主密钥离线备份纳入恢复演练。
- 服务器被完全攻破时密钥可被读取，单机部署无法避免；应对是服务器加固和用户可随时作废密钥。
- 备份中的已注销数据在保留期内仍存在（建议保留期 ≤ 14 天）。
- 若开放给他人使用：需重新评估找回密码、通行密钥、KMS、备份内数据删除。
