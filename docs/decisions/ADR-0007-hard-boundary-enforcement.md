# ADR-0007 硬性边界的系统级执行

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-04 |
| 提出人 | 架构负责人（T-004） |
| 批准人 | 架构负责人 |

## 背景

PRD 第 10 章要求硬性边界「在系统层面执行，不能只靠提示词」，并且「用户设置、补充设定、情景模式、贴合度、提示词、所选模型都不能绕过」；SAFE-03 验收要求质量负责人通过直接调用接口等方式尝试绕过，必须全部失败。大模型会被诱导，提示词不可作为唯一防线。详细执行点见 `docs/architecture/hard-boundaries.md`。

## 方案对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 只在提示词中约束 | 实现最快 | 可被诱导；接口层完全没有拦截；不满足 PRD |
| B. 各模块自己写判断 | 不需要新模块 | 规则散落多处，必然出现不一致，难以测试和审计 |
| **C. 集中的 `policy` 模块（纯函数）+ 推导字段不可写 + 所有入口调用 + 生成前二次检查 + 能力缺席**（选） | 规则只在一处定义、一处测试；接口、数据、生成三层都有闸；越界能力根本不存在 | 每个相关接口都要接入 policy，增加少量调用；分类字段必须结构化 |

## 结论

1. 新增 `policy` 模块：输入角色分类等结构化事实，输出判定和原因码；无业务表，拒绝写审计日志。
2. 成人模式资格、是否儿童、能否恋爱、能否生成形象等**全部是推导值**，任何接口都不能写入；自定义角色的 `real_person`、`minor` 只能单向修改，应用层和数据库触发器双重校验。
3. 所有可能越界的写操作（切换情景模式、设置关系类型、图片 / 语音生成、分享数据）在服务器端调用 `policy`。
4. 模型网关对成人生成、图片生成**自行再查一次** policy，不信任上游。
5. 内容隔离用服务器盖章的 `scope` 标签实现，读取接口必须显式声明范围。
6. 不接入声音克隆与通用人脸搜索能力。
7. 自由文本（补充设定、人设描述、聊天）永不作为分类依据。

## 代价

- 角色卡中与边界相关的字段必须是结构化字段，限制了角色卡设计的自由度（已在交接中告知 AI 负责人）。
- 每个相关接口多一次 policy 调用和审计写入，性能可忽略。
- 依赖 AI 的检测项（人设文本儿童特征、生成图片是否含人脸、恋爱含义）存在误判；误判时一律按更严格的一侧处理（宁可拒绝）。
- 若 PRD 第 10 章新增规则，只需修改 policy 并补测试；若出现需要「人工豁免」的场景，必须新开 ADR，不允许在代码里加后门开关。
