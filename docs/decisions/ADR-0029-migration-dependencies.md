# ADR-0029 迁移显式依赖与安装顺序修复

- 日期：2026-10-11；状态：本开发分支采用，独立复核待交付。
- 背景：全新数据库执行 `0056_account_deletion` 时引用 `plaza.adoptions`，但该表在 `0060_plaza` 才创建。全量开发测试因此在初始化失败，不能进入业务验证。
- 方案：不修改旧迁移 SQL 或校验和，不重用编号；迁移清单支持可选 `dependsOn`，按原编号稳定遍历并先执行显式依赖。
- 选择理由：修改旧 SQL 会破坏已执行数据库的校验和；仅增加后续修复迁移不能修复此前已经失败的安装步骤；重编号会破坏编号登记。显式依赖同时保留现有 SQL、tag 与执行记录。
- 当前依赖：`0056_account_deletion` → `0060_plaza`。重复 tag、依赖缺失和循环在执行 SQL 前拒绝。回滚仍按实际执行时间逆序。
- 代价：迁移编号不再总是等同执行顺序，运维需以执行器输出及 `schema_migrations` 为准；原先无依赖的顺序不变。
- 验证：开发自测中全部迁移执行、完整回滚、再次执行通过；新增依赖错误拒绝测试。不是独立验收结论。
